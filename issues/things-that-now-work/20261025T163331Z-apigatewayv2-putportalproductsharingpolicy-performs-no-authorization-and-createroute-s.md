=== Cause 1 of 2: PutPortalProductSharingPolicy does not authorize the caller, so a principal carrying an explicit Deny is served 200 instead of refused ===
AWS: Smithy (services/service-com-amazonaws-apigatewayv2-apigatewayv2/smithy-model/com-amazonaws-apigatewayv2-apigatewayv2.json): PutPortalProductSharingPolicy -> PUT /v2/portalproducts/{PortalProductId}/sharingpolicy, success code 200 with an empty output shape; modeled errors AccessDeniedException (httpError 403), BadRequestException (400), NotFoundException (404), TooManyRequestsException (429). Input members PortalProductId (httpLabel, required) and PolicyDocument (required, @length min 1 max 307200). A caller whose identity-based policy carries an explicit Deny on apigateway:PutPortalProductSharingPolicy must be refused with error code AccessDeniedException / HTTP 403, and the product's sharing-policy state must be unchanged; an unrestricted principal must still succeed with 200 and the policy must read back byte-equivalent through GetPortalProductSharingPolicy. The message is AWS's documented authorization form, whose fixed text is 'User: <arn> is not authorized to perform: <action> on resource: <resource> with an explicit deny in an identity-based policy' — the fixed parts are 'User: ', ' is not authorized to perform: ', ' on resource: ' and ' with an explicit deny in an identity-based policy'; the variable parts are taken from the request and state: the caller's STS assumed-role ARN, the action apigateway:PutPortalProductSharingPolicy, and the PortalProductArn of the addressed product. That rule is the requirement; no single run's ARN/id is part of it.
Emulator: the restricted principal's PutPortalProductSharingPolicy SUCCEEDS with HTTP 200 and an empty body (observed ResponseMetadata HTTPStatusCode 200, content-length 2), identical to the unrestricted path. No IAM evaluation happens for this operation at all, so the AccessDeniedException branch the model declares is unreachable.
Why: a client cannot rely on the emulator to model least privilege for portal products. Least-privilege regression tests that assert a denied principal is refused pass against the emulator and fail on AWS; an agent or harness that probes its permissions by attempting the call concludes it is authorized when AWS would deny it; and because the write is actually applied, a sharing policy that AWS would never have accepted is persisted and visible to later reads.
Fix: the authorization path of the PutPortalProductSharingPolicy handler (services/service-com-amazonaws-apigatewayv2-apigatewayv2/src/ops/put_portal_product_sharing_policy.rs) must evaluate the caller's identity-based policy for apigateway:PutPortalProductSharingPolicy against the product ARN and return AccessDeniedException / 403 without mutating sharing-policy state. The same gate belongs on the sibling GetPortalProductSharingPolicy / DeletePortalProductSharingPolicy operations.
Traces: apigatewayv2.put-portal-product-sharing-policy-access-denied.

=== Cause 2 of 2: CreateRoute's rejection of the WebSocket-only RouteResponseSelectionExpression on an HTTP API uses the emulator's own wording, not AWS's ===
AWS: Smithy: CreateRoute -> POST /v2/apis/{ApiId}/routes, success code 201, modeled errors BadRequestException (httpError 400), ConflictException (409), NotFoundException (404), TooManyRequestsException (429); the input member RouteResponseSelectionExpression (jsonName routeResponseSelectionExpression, target SelectionExpression) is one of the members the model documents as supported only for WebSocket APIs. Recorded behavior for the message: supplying RouteResponseSelectionExpression on a route of an API whose ProtocolType is HTTP is refused with BadRequestException / HTTP 400 whose text is entirely fixed prose with one variable token - 'Currently, a route response selection expression is not necessary for APIs with  a protocol type of HTTP', where everything is fixed text (including the doubled space before 'a protocol type') and only the trailing protocol-type token is taken from the API's ProtocolType. The same protocol gate's two sibling messages are already correct in this emulator, which is how this one stands out: CreateModel on an HTTP API answers 'Currently, Models are not permitted for APIs with a protocol type of HTTP' and CreateIntegration(IntegrationType=MOCK) answers 'Currently, an API with a protocol type of HTTP may only be associated with proxy integrations (AWS_PROXY, HTTP_PROXY)', both of which passed in this same check.
Emulator: the status and code are right (BadRequestException, 400) and nothing is persisted, but the message is 'Currently, RouteResponseSelectionExpression is not permitted for APIs with a protocol type of HTTP' - it names the wire member instead of 'a route response selection expression', says 'are not permitted' instead of 'is not necessary', and omits the doubled space. So the emulator has its own generic template for this protocol gate rather than AWS's per-member text.
Why: a client that classifies apigatewayv2 400s by message (the only discriminator AWS gives here, since every protocol-gate violation shares BadRequestException/400) cannot tell which member it violated, and error-message assertions and log/alarm patterns written against AWS do not match. The divergence is in the fixed prose, not in a per-run value, so it reproduces on every call.
Fix: the per-protocol member allowlist in the CreateRoute handler's validation (services/service-com-amazonaws-apigatewayv2-apigatewayv2/src/ops/create_route.rs) - emit AWS's message for the RouteResponseSelectionExpression-on-HTTP case, and carry the same per-member texts on UpdateRoute.
Traces: apigatewayv2.protocol-type-illegal-attributes-rejected (its WEBSOCKET positive controls for CreateModel, a MOCK integration and a route with RouteResponseSelectionExpression all passed, as did the CreateModel-on-HTTP and MOCK-on-HTTP rejections; the run stopped at this third message, so the later 'effect absent' and control-route legs were never reached).
