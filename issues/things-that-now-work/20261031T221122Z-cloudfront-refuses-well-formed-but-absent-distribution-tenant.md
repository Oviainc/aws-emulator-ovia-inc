# CloudFront refuses well-formed-but-absent distribution-tenant and Anycast-IP-list ids as malformed: 400 InvalidArgument "Id format is invalid" instead of 404 EntityNotFound

> _Note: this issue was identified against the code base at commit `f5bcb0a946788170dc0fa0f931c1e9072e8c121c`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
AssociateDistributionTenantWebACL

## Description
Two causes, both in the pre-lookup identifier-format gate CloudFront operations run before they resolve an id against the store. In each the emulator REFUSES the call (so it is not an over-permissive accept) but with the wrong status, the wrong error code and its own sentence, which is exactly what a client's error handling branches on (retry/create-vs-404). Related open issues describe other refusal-wording gaps on these surfaces but carry neither of these causes: 20261029T212223Z-cloudfront-refusal-codes-and-messages-diverge-from-aws.md (not-found/invalid-argument message wording for public keys, FLE, resource policies, GetInvalidationForDistributionTenant) and 20261023T140640Z-cloudfront-9-fidelity-divergences-19-control-plane-operations.md (which owns the MALFORMED-id Anycast check, i.e. the opposite side of cause 2). This issue is the absent-but-well-formed side.

Cause 1 of 2: the distribution-tenant `Id`/`Identifier` format gate rejects tenant ids CloudFront itself would carry into the lookup.
AWS: a distribution-tenant id is an opaque `dt_`-prefixed base62 token — observed real ids are `dt_` followed by 27 mixed-case alphanumerics (e.g. `dt_3JO1OQa51Jb3BZh7XQh6pbvF3Wa`). An id of that space that was never issued is a tenant that is ABSENT: AssociateDistributionTenantWebACL, CreateInvalidationForDistributionTenant, DeleteDistributionTenant and GetDistributionTenant all answer 404 `EntityNotFound` with the fixed message `The specified distribution tenant doesn't exist.` (the message states the condition and echoes no part of the request). Smithy: AssociateDistributionTenantWebACL errors = AccessDenied 403, EntityLimitExceeded 400, EntityNotFound 404, InvalidArgument 400, InvalidIfMatchVersion 400, PreconditionFailed 412; CreateInvalidationForDistributionTenant errors include EntityNotFound 404; GetDistributionTenant models ONLY AccessDenied 403 and EntityNotFound 404; DeleteDistributionTenant models AccessDenied 403, EntityNotFound 404, InvalidIfMatchVersion 400, PreconditionFailed 412 and does NOT model InvalidArgument at all — so the code the emulator returns there is not even a declared error of that operation.
Emulator: the gate `crate::state::is_distribution_tenant_id` accepts only the ids this emulator mints — `DISTRIBUTION_TENANT_ID_PREFIX` ("dt_") followed by exactly `ID_BODY_LEN` = 13 characters drawn from digits + UPPERCASE ASCII only (`is_token_body`/`is_token_byte`). Anything else is refused BEFORE the store is consulted with 400 `InvalidArgument` and the emulator-authored message `Id format is invalid` (built by `crate::state::invalid_id_format("Id")` / `id_format_invalid_message`). Both an AWS-shaped id (`dt_` + 27 mixed-case chars) and an id with the same length/character-class shape as a real emulator tenant id but a different two-letter prefix therefore come back 400 InvalidArgument instead of 404 EntityNotFound.
Why: a client that distinguishes "this tenant is gone" from "you sent me garbage" mis-routes every absent-tenant answer — a 404/EntityNotFound branch (treat as deleted, re-create, stop polling) never runs, and callers that surface InvalidArgument as a programming error fail hard on an ordinary not-found. On DeleteDistributionTenant the returned error is outside the operation's modelled error set, so a generated SDK's typed error union cannot represent it.
Fix: the identifier-format gate and its EntityNotFound ordering in the distribution-tenant handlers' validation (services/service-com-amazonaws-cloudfront-cloudfront2020-05-31/src/ops/associate_distribution_tenant_web_acl.rs, create_invalidation_for_distribution_tenant.rs, delete_distribution_tenant.rs, get_distribution_tenant.rs) together with the shared predicate in src/state.rs. A value in the tenant-id namespace that is simply unknown must reach the store lookup and be answered EntityNotFound with `The specified distribution tenant doesn't exist.`; the fixed text is that whole sentence and it takes no values from the request.
Traces: cloudfront.associate-distribution-tenant-web-acl-entity-not-found-rejected, cloudfront.associate-distribution-tenant-web-acl-nonexistent-tenant-rejected, cloudfront.distribution-tenant-web-acl-association-entity-not-found-rejected, cloudfront.op-contract-createInvalidationForDistributionTenant, cloudfront.op-contract-deleteDistributionTenant.

Cause 2 of 2: GetAnycastIpList rejects a well-formed-but-absent Anycast-IP-list id as malformed.
AWS: an Anycast IP list id is `aip_` followed by 22 alphanumerics. A GROSSLY malformed Id (e.g. 512 'A's) is 400 `InvalidArgument` with `Id format is invalid`, but an id of the real shape that does not exist falls through to the lookup and is 404 `EntityNotFound` with the message `The specified Anycast IP list does not exist` — two distinct codes for the two distinct conditions. Smithy: GetAnycastIpList errors = AccessDenied 403, EntityNotFound 404, InvalidArgument 400, UnsupportedOperation 400.
Emulator: `is_anycast_ip_list_id` requires `ANYCAST_IP_LIST_ID_PREFIX` = "ipl-" (ids are minted as `ipl-` + 17 lowercase hex digits), so `aip_`-prefixed ids are refused by the format gate with 400 `InvalidArgument` / `Id format is invalid`; the malformed and the absent case collapse onto the same code and message, and EntityNotFound is unreachable for this operation.
Why: a caller cannot tell a mistyped id from a list that was deleted, and the modelled 404 branch for this resource never fires.
Fix: GetAnycastIpList's validation and the Anycast id namespace constant (services/service-com-amazonaws-cloudfront-cloudfront2020-05-31/src/ops/get_anycast_ip_list.rs; ANYCAST_IP_LIST_ID_PREFIX / is_anycast_ip_list_id in src/state.rs). An id in the Anycast-IP-list namespace that is unknown must be answered 404 EntityNotFound with the fixed sentence `The specified Anycast IP list does not exist`.
Traces: cloudfront.get-anycast-ip-list-invalid-argument-rejected.
