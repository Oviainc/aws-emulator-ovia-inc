# RDS Data API behavioral surface entirely unreachable: RDS DescribeDBClusters and CreateDBCluster answer 501 NotImplemented

> _Note: this issue was identified against the code base at commit `ead37dd00922f5e8ae35cfd4d29cc6e26f23d78c`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
DescribeDBClusters (bundle also covers CreateDBCluster)

## Description
All 28 rds-data behavioral checks abort during cluster provisioning, before any rds-data call is made. The defective handlers live in the rds crate but every failing check id is an rds-data.* one, so they are filed under service rds-data. This issue bundles TWO root causes that must both be closed before submitting.

Cause 1 of 2: RDS DescribeDBClusters is an unimplemented scaffold stub.
AWS: Smithy (services/service-com-amazonaws-rds-amazonrdsv19/smithy-model): DescribeDBClusters input {DBClusterIdentifier, Filters, MaxRecords, Marker, IncludeShared}, output DBClusterMessage {Marker, DBClusters: DBClusterList}, paginated (inputToken Marker / outputToken Marker / items DBClusters), and the ONLY modeled error is DBClusterNotFoundFault (awsQueryError code DBClusterNotFoundFault, HTTP 404). So a describe of an existing cluster must return HTTP 200 with a DBClusters list carrying the cluster's Status/Endpoint/HttpEndpointEnabled, and a describe of an absent identifier must return 404 DBClusterNotFoundFault. NotImplemented is not in the operation's error set.
Emulator: the handler answers HTTP 501 with error code NotImplemented and message "operation DescribeDBClusters is scaffolded but not implemented in this emulator" (services/service-com-amazonaws-rds-amazonrdsv19/src/ops/describe_db_clusters.rs still carries the `SCAFFOLDED, NOT IMPLEMENTED` marker and returns Err for every request).
Why: a client cannot discover or wait on an Aurora cluster at all. Every Data API consumer first resolves the cluster ARN/status (and whether the HTTP endpoint is enabled) through DescribeDBClusters; it receives an unmodeled error code with a 501 status, which is not retryable, not in the modeled error union, and indistinguishable from a transport fault, so no waiter can converge and the whole rds-data data plane is unreachable.
Fix: the operation's handler plus the DB-cluster state it reads (services/service-com-amazonaws-rds-amazonrdsv19/src/ops/describe_db_clusters.rs and the cluster store in that crate's state), including identifier/filter lookup and the DBClusterNotFoundFault path.

Cause 2 of 2: RDS CreateDBCluster is an unimplemented scaffold stub.
AWS: Smithy: CreateDBCluster requires DBClusterIdentifier and Engine, accepts EnableHttpEndpoint, ServerlessV2ScalingConfiguration, DatabaseName, MasterUsername/MasterUserPassword, StorageEncrypted, Tags, and returns CreateDBClusterResult {DBCluster} (DBClusterArn populated) on HTTP 200. Its modeled failures are the awsQuery faults DBClusterAlreadyExistsFault (400), InvalidParameterCombination-class faults, DBSubnetGroupNotFoundFault (404), etc.; NotImplemented is not among them.
Emulator: answers HTTP 501 NotImplemented ("operation CreateDBCluster is scaffolded but not implemented in this emulator") from services/service-com-amazonaws-rds-amazonrdsv19/src/ops/create_db_cluster.rs.
Why: no Aurora Serverless v2 cluster with EnableHttpEndpoint can be created, so no resourceArn exists for rds-data ExecuteStatement/BatchExecuteStatement/BeginTransaction to address. A client gets an unmodeled 501 for a provisioning call AWS answers 200 on. NOTE: the replay report auto-filed a stub issue for CreateDBCluster against the single rds.* check it blocked; that issue does not carry these rds-data replay keys, so this cause is listed here for the rds-data checks it blocks and may be closed together with it.
