## Description
BUNDLE OF 8 CAUSES (one per ServiceCode). ListAWSDefaultServiceQuotas answers HTTP 200 but the Quotas list it serves is produced from a hand-written static default-quota table in the service-quotas crate rather than from AWS's published default-quota catalog. For each ServiceCode below the table holds only a handful of rows, so most of that service's real default quotas are absent from a successful response, and the row set additionally contains CamelCase quota codes that appear in no recorded AWS response for the ServiceCode.

This is the SAME component as open issue 20261029T192055Z-service-quotas-listawsdefaultservicequotas-serves-a-hand-written-default-quota-table.md, but that issue's replay keys cover a DISJOINT set of 27 ServiceCodes (access-analyzer, acm, acm-pca, airflow, kinesis, shield, ...). None of the 8 ServiceCodes below is carried by it, so each needs its own fixture replayed before it can be closed.

Shared statement of the defect, applied per cause below -- AWS: ListAWSDefaultServiceQuotas returns the complete AWS default-quota set for the requested ServiceCode (Smithy: ListAWSDefaultServiceQuotas.ServiceCode required, @length 1..63, @pattern ^[a-zA-Z][a-zA-Z0-9-]{1,63}$; output Quotas -> ServiceQuotaListDefinition; paginated inputToken/outputToken NextToken, pageSize MaxResults; ServiceQuota.QuotaCode @length 1..128, ServiceQuota.Description @length 0..350, ServiceQuota.Adjustable default false). Each row is keyed on the quota code AWS assigns -- in every recording in this corpus an L-XXXXXXXX code. Why (applies to every cause): a client enumerating a service's default quotas to resolve a quota code, read its default Value or test its Adjustable flag is told the quota does not exist, so capacity logic and any follow-up GetServiceQuota / RequestServiceQuotaIncrease keyed on a real AWS quota code cannot be reached; and a client that reads one of the CamelCase codes back out passes an identifier real AWS rejects. Fix (applies to every cause): the static default-quota catalog data that the ListAWSDefaultServiceQuotas handler reads in the service-quotas crate -- the table must be populated from AWS's catalog for these ServiceCodes and keyed on the real quota codes; this is not a paging or serialization defect, status and envelope already match.
