# DynamoDB table description responses omit TableId, NumberOfDecreasesToday and throughput summaries

> _Note: this issue was identified against the code base at commit `38aaeb6c250810a0cf0ab5b6ac35c7222e2099c5`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
DescribeTable

## Description
Every operation that returns a TableDescription (CreateTable, DescribeTable, UpdateTable, DeleteTable) serializes an incomplete structure: the emulator never populates TableId, ProvisionedThroughput.NumberOfDecreasesToday, ProvisionedThroughput.LastDecreaseDateTime, BillingModeSummary.LastUpdateToPayPerRequestDateTime, TableThroughputModeSummary or WarmThroughput. The same omission set repeats across 10 independent clusters, which is why they are bundled as one serializer/state defect. This bundle has 10 causes; all 10 must be closed.

Cause 1 of 10: DescribeTable omits TableId, ProvisionedThroughput.NumberOfDecreasesToday, BillingModeSummary.LastUpdateToPayPerRequestDateTime, TableThroughputModeSummary and WarmThroughput.
AWS: Smithy: DescribeTable -> output Table: TableDescription; TableDescription.TableId is 'a unique identifier for the table, in UUID format, generated by DynamoDB when the table is created' (pattern ^[0-9a-f]{8}-...$), TableDescription.WarmThroughput targets TableWarmThroughputDescription, TableDescription.ProvisionedThroughput targets ProvisionedThroughputDescription (which carries NumberOfDecreasesToday), and BillingModeSummary carries LastUpdateToPayPerRequestDateTime. The recording shows all of these present on an on-demand table (NumberOfDecreasesToday 0, TableThroughputMode PAY_PER_REQUEST, WarmThroughput ACTIVE).
Emulator: those members are absent from the response body (replay reports each as 'missing ... got None'), status 200 otherwise.
Why: a client that reads Table.TableId to key its own records, or inspects WarmThroughput/TableThroughputModeSummary/NumberOfDecreasesToday to decide whether a throughput change is settled, gets a null and either crashes on deserialization of a required local field or loops forever waiting for a summary that never appears.
Fix: the DescribeTable handler's TableDescription serializer and the table state record it reads from (a per-table UUID and throughput-mode/warm-throughput summary must be stored at CreateTable time and echoed on every describe).
Traces: ddbctl-backup-on-creating-table-and-restore-name-collision#task#5 (also affects ddbctl-backup-on-creating-table-and-restore-name-collision#task#7, dynamodb-table-control-plane-lifecycle#task#5).

Cause 2 of 10: DeleteTable's TableDescription omits TableId, NumberOfDecreasesToday, BillingModeSummary.LastUpdateToPayPerRequestDateTime and TableThroughputModeSummary. AWS: Smithy: DeleteTable -> output TableDescription, same members as above. Emulator: members missing, status 200. Why: a client that records the deleted table's TableId for audit gets nothing. Fix: DeleteTable handler's TableDescription serializer. Traces: ddbctl-delete-table-in-transitional-state-conflict#task#5 (8 steps in cluster, incl. dynamodb-table-tagging-lifecycle#teardown#12).

Cause 3 of 10: DescribeTable of a table in a transitional state omits the same four members. AWS: as Cause 1. Emulator: members missing. Why: same as Cause 1. Fix: DescribeTable serializer. Traces: ddbctl-delete-table-in-transitional-state-conflict#task#7.

Cause 4 of 10: DescribeTable omits the same members AND reports live ItemCount/TableSizeBytes. AWS: Smithy: TableDescription.ItemCount/TableSizeBytes docs state 'DynamoDB updates this value approximately every six hours. Recent changes might not be reflected in this value' - the recording shows 0 right after two writes. Emulator: ItemCount 2 and TableSizeBytes 22 immediately after the writes, plus the missing members. Why: a client that uses ItemCount as a cheap exact count learns an answer AWS never gives, and tests that assert the lagging value fail against real AWS. Fix: DescribeTable serializer plus the table state's counter update policy (counters must not be refreshed synchronously on the write path). Traces: ddbctl-resource-policy-deny-vs-not-found#task#10.

Cause 5 of 10: DescribeTable omits NumberOfDecreasesToday and TableThroughputModeSummary. AWS: as Cause 1. Emulator: both missing. Why: as Cause 1. Fix: DescribeTable serializer. Traces: dynamodb-export-lifecycle#task#7 (also dynamodb-table-lifecycle-core#task#3, #task#6).

Cause 6 of 10: CreateTable's TableDescription omits TableId, NumberOfDecreasesToday and TableThroughputModeSummary. AWS: Smithy: CreateTable -> output TableDescription; TableId is generated at create time. Emulator: members missing, status 200. Why: a client that captures TableId from the create response (the only place it is cheap to get) has nothing to store. Fix: CreateTable handler - mint and persist the table UUID and throughput-mode summary, then serialize them. Traces: dynamodb-import-table-pipeline#task#1 (9 steps in cluster, incl. dynamodb-transactional-operations#setup#1).

Cause 7 of 10: CreateTable omits TableId and NumberOfDecreasesToday. AWS/Emulator/Why/Fix as Cause 6. Traces: dynamodb-table-billing-mode-update#setup#1.

Cause 8 of 10: UpdateTable's TableDescription omits TableId, NumberOfDecreasesToday, ProvisionedThroughput.LastDecreaseDateTime, TableThroughputModeSummary and WarmThroughput. AWS: Smithy: UpdateTable -> output TableDescription; a billing-mode change to PAY_PER_REQUEST is reflected in TableThroughputModeSummary and, per the recording, WarmThroughput. Emulator: members missing. Why: a client that polls UpdateTable's echo to confirm the new throughput mode never sees it applied. Fix: UpdateTable handler's TableDescription serializer and the throughput-mode state it writes. Traces: dynamodb-table-billing-mode-update#task#3.

Cause 9 of 10: UpdateTable omits NumberOfDecreasesToday and TableThroughputModeSummary when switching to PROVISIONED. AWS/Emulator/Why/Fix as Cause 8 (recorded TableThroughputMode PROVISIONED). Traces: dynamodb-table-lifecycle-core#task#5.

Cause 10 of 10: DeleteTable omits TableId and NumberOfDecreasesToday on a GSI-bearing table. AWS/Emulator/Why/Fix as Cause 2. Traces: dynamodb-table-lifecycle-with-gsi-and-ttl#teardown#10.
