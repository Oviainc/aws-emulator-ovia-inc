# Every CloudTrail operation answers HTTP 501 NotImplemented from the dispatcher, including the ones whose handlers are fully implemented

> _Note: this issue was identified against the code base at commit `c50178ef0adb9f41de3fed65acf95f496e080c81`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateTrail

## Description
ONE root cause (Cause 1 of 1), reached by every CloudTrail behavioral check in this suite.

Cause 1 of 1: the CloudTrail service is mounted and claims its requests, but no operation is bound to a handler, so every operation is refused with HTTP 501 `NotImplemented` even when its handler exists and is complete.

AWS: Smithy (services/service-com-amazonaws-cloudtrail-cloudtrail-20131101/smithy-model/com-amazonaws-cloudtrail-cloudtrail-20131101.json): service `CloudTrail_20131101`, apiVersion 2013-11-01, protocol awsJson1_1, sigv4Name `cloudtrail`, 60 bound operations. `CreateTrail` returns HTTP 200 with a CreateTrailResponse (Name, TrailARN, S3BucketName, IncludeGlobalServiceEvents, IsMultiRegionTrail, LogFileValidationEnabled, ...) and models only client/server errors such as TrailAlreadyExistsException, InvalidTrailNameException, S3BucketDoesNotExistException, InsufficientS3BucketPolicyException, TrailNotProvidedException; the same holds for DescribeTrails, GetTrail, GetTrailStatus, AddTags/RemoveTags/ListTags, Put/GetEventSelectors, Put/GetInsightSelectors, Start/StopLogging, UpdateTrail, DeleteTrail, Create/Get/Update/DeleteChannel, CreateEventDataStore and the query/import operations. `NotImplemented` is NOT a modeled error of any CloudTrail operation, and 501 is not a status any of them can return.

Emulator: every CloudTrail operation returns HTTP 501, error code `NotImplemented`, message of the form `operation amazonaws.cloudtrail.v20131101.CloudTrail_20131101.<Operation> is not implemented in this emulator`. This is NOT the scaffold-stub channel: `crate::scaffolded::NotImplemented::new` (services/service-com-amazonaws-cloudtrail-cloudtrail-20131101/src/scaffolded.rs:93-99) words its 501 as `operation <Op> is scaffolded but not implemented in this emulator` and names the operation by its SHORT name — which is exactly what the other services in this suite emit (e.g. `operation CreateSubnet is scaffolded but not implemented in this emulator`). The CloudTrail text instead names the operation by its full model id (namespace + service shape + operation), i.e. the dispatcher RESOLVED the operation and then found nothing bound to it. Operations whose handler is written are refused the same way: services/service-com-amazonaws-cloudtrail-cloudtrail-20131101/src/ops/create_trail.rs is a complete implementation (it reads the request region, enforces the documented trail-name rules, builds the record, `store.trails.insert(key, record)` and returns `Ok(output)` at line 502) and carries no `SCAFFOLDED, NOT IMPLEMENTED` marker, yet `CreateTrail` answers 501. The same is true of DescribeTrails, GetTrail, AddTags, PutEventSelectors, GetTrailStatus, StartLogging/StopLogging, UpdateTrail, CreateChannel/GetChannel/UpdateChannel/DeleteChannel, CreateEventDataStore, StartQuery/DescribeQuery/GetQueryResults/CancelQuery/ListQueries, StartImport, StartEventDataStoreIngestion, GetResourcePolicy and ListInsightsMetricData.

Why: CloudTrail is completely unusable. A client cannot create, read, tag, configure, start or stop a trail; every negative class the service owns (TrailAlreadyExistsException on a duplicate name, InvalidTrailNameException, S3BucketDoesNotExistException / InsufficientS3BucketPolicyException on a bucket with no delivery policy, TrailNotFoundException on an unknown trail, ChannelARNInvalidException / ChannelNotFoundException, EventDataStoreNotFoundException, QueryIdNotFoundException, InvalidQueryStatementException) comes back as 501 NotImplemented instead. Worse, 501 with an unmodeled error code defeats SDK error handling: code that branches on `TrailAlreadyExistsException` or `ResourceNotFoundException` sees a code its model does not contain, and every cross-service audit scenario (CloudTrail + IAM/S3/DynamoDB/SFN/Lambda/EventBridge/Cognito) fails at trail setup before it can exercise anything else.

Fix: the operation binding/dispatch for this service crate — the generated `ServiceDefinition` and the generated op table included from OUT_DIR (`com_amazonaws_cloudtrail_cloudtrail_20131101_service_decl.rs` via src/lib.rs:21 and `com_amazonaws_cloudtrail_cloudtrail_20131101_ops_generated.rs` via src/ops/mod.rs:4), not the individual `src/ops/*.rs` handlers, which are already written. Note: the nine CloudTrail operations that are genuine scaffold stubs (ListEventDataStores, ListChannels, CreateDashboard, ListDashboards, ListInsightsMetricData, ListPublicKeys, LookupEvents, SearchSampleQueries, ListImports) already have their own filed issues and are excluded from this one's traces; they will still answer 501 after this dispatch defect is fixed, which is a separate work item.

Traces: the ~120 CloudTrail checks listed in trace_ids, each of which fails on the first CloudTrail call it makes.
