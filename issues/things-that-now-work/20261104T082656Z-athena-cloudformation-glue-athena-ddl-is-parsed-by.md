# athena__cloudformation__glue: Athena DDL is parsed by a SQLite engine — CREATE EXTERNAL TABLE and CREATE VIEW are refused as syntax errors and SELECT cannot resolve a Glue catalog table (3 causes)

> _Note: this issue was identified against the code base at commit `ed67363a200a02a71118cd5e7b7585c85db4efeb`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
StartQueryExecution

## Description
Every Athena statement in this group is handed to the emulator's local SQLite engine instead of Athena's Hive/Presto statement engine, so Hive DDL is reported as a parse error and catalog tables are invisible to DML. 3 causes.

Cause 1 of 3: CREATE EXTERNAL TABLE is refused as a syntax error.
AWS: Smithy: StartQueryExecution.QueryString (required, @length 1..262144); QueryExecutionStatus.State enum QUEUED/RUNNING/SUCCEEDED/FAILED/CANCELLED; QueryExecutionStatus.AthenaError (AthenaError.ErrorCategory @range 1..3, ErrorType @range 0..9999, ErrorMessage). Athena accepts Hive DDL of the form `CREATE EXTERNAL TABLE [IF NOT EXISTS] `<db>`.`<tbl>` (<columns>) [ROW FORMAT ...] LOCATION 's3://<bucket>/<prefix>/' [TBLPROPERTIES (...)]`: the execution reaches State SUCCEEDED, StatementType DDL, and the statement registers the table in the Glue Data Catalog (TableType EXTERNAL_TABLE, Owner hadoop, Parameters EXTERNAL=TRUE, StorageDescriptor.Location with the trailing slash dropped). `IF NOT EXISTS` over an existing catalog entry also SUCCEEDS and changes nothing, while the same statement WITHOUT `IF NOT EXISTS` over an existing table fails with AthenaError.ErrorCategory 2 and ErrorType 1006 (already-exists class) and leaves the entry untouched. Only the database, table, column list, location and properties come from the request.
Emulator: every such statement terminates State FAILED with StateChangeReason == AthenaError.ErrorMessage == 'near "EXTERNAL": syntax error in <the submitted statement> at offset 7', ErrorCategory 2, no ErrorType at all — i.e. the SQLite parser's diagnostic, with the fixed text 'near "EXTERNAL": syntax error in ' and 'at offset 7' being emulator-authored and absent from AWS.
Why: a client cannot create a table through Athena DDL at all, and cannot distinguish 'table already exists' (ErrorType 1006) from a genuine SQL syntax error, because both arrive as the same syntax message with no ErrorType.
Fix: the athena crate's query-execution engine — the DDL statement parser/executor behind StartQueryExecution, plus the AthenaError population in the GetQueryExecution path.
Traces: athena__cloudformation__glue.athena-create-table-if-not-exists-keeps-the-api-table-and-plain-create-fails, athena__cloudformation__glue.athena-ddl-location-drops-trailing-slash, athena__cloudformation__glue.athena-ddl-table-carries-external-table-type-api-table-omits-it.

Cause 2 of 3: CREATE VIEW / CREATE OR REPLACE VIEW is refused with an 'unknown database' error for a database that exists.
AWS: `CREATE [OR REPLACE] VIEW "<db>"."<view>" AS SELECT ... FROM "<db>"."<table>" [WHERE ...]` reaches State SUCCEEDED with StatementType DDL and SubstatementType CREATE_VIEW, and writes a Glue entry with TableType VIRTUAL_VIEW, ViewExpandedText '/* Presto View */', Parameters presto_view='true' and an empty StorageDescriptor.Location. A plain CREATE VIEW over an existing view fails with AthenaError.ErrorCategory 1 / ErrorType 1502, a CREATE VIEW whose source table does not exist fails with ErrorCategory 2 / ErrorType 1301, and DROP VIEW / SHOW CREATE VIEW applied to a non-view fail with ErrorCategory 1 / ErrorType 1502. SHOW VIEWS, SHOW TABLES and information_schema.tables then classify the entries (VIEW vs BASE TABLE).
Emulator: the control CREATE VIEW itself terminates FAILED with StateChangeReason == AthenaError.ErrorMessage == 'unknown database "<db>" in CREATE VIEW <the submitted statement> at offset 12', ErrorCategory 2, no ErrorType — for a database that was just created and that Glue serves. No VIRTUAL_VIEW catalog entry is ever written, so every downstream view assertion (ViewOriginalText/ViewExpandedText, presto_view, SHOW VIEWS, information_schema, ListTableMetadata Expression narrowing) is unreachable.
Why: views cannot be created through Athena, and the refusal blames a missing database rather than reporting the modeled view error classes, so a client cannot branch on ErrorType 1502/1301.
Fix: the athena crate's query-execution engine — view DDL handling (CREATE/REPLACE/DROP/SHOW CREATE VIEW) and its catalog resolution of the QueryExecutionContext database.
Traces: athena__cloudformation__glue.athena-create-view-over-absent-table-rejected, athena__cloudformation__glue.athena-create-view-over-existing-view-rejected, athena__cloudformation__glue.athena-create-view-writes-presto-view-catalog-entry, athena__cloudformation__glue.athena-ddl-view-physical-id-rejected-by-cloudformation, athena__cloudformation__glue.athena-drop-view-on-a-table-rejected, athena__cloudformation__glue.athena-information-schema-classifies-table-and-view, athena__cloudformation__glue.athena-list-table-metadata-expression-narrows-to-views, athena__cloudformation__glue.athena-show-create-view-on-a-table-rejected, athena__cloudformation__glue.athena-show-views-lists-only-views-show-tables-lists-both, athena__cloudformation__glue.cfn-glue-table-omits-table-type-and-view-fields.

Cause 3 of 3: a SELECT over a table that exists in the Glue Data Catalog fails with a SQLite 'no such table'.
AWS: Athena resolves <catalog>.<database>.<table> through the data catalog (awsdatacatalog -> Glue) and reads the objects under the table's StorageDescriptor.Location, so the query reaches SUCCEEDED and returns the rows (for the default LazySimpleSerDe, fields split on \001). When the entity genuinely does not exist the query fails with AthenaError.ErrorCategory 2 / ErrorType 1301 and a message of the fixed form "TABLE_NOT_FOUND: line <l>:<c>: Table 'awsdatacatalog.<db>.<table>' does not exist" (or SCHEMA_NOT_FOUND for a missing database), where only the identifiers and the line/column come from the request.
Emulator: State FAILED with StateChangeReason == AthenaError.ErrorMessage == 'no such table: <db>.<table>', ErrorCategory 2, ErrorType absent — for tables the Glue API served in the same check.
Why: no data can be read through Athena, and the not-found refusal carries neither AWS's ErrorType nor AWS's message, so a client cannot tell a missing table from a missing database or from an engine fault.
Fix: the athena crate's query-execution engine — catalog/table resolution for DML and the AthenaError classification of not-found failures.
Traces: athena__cloudformation__glue.athena-default-lazysimpleserde-splits-on-ctrl-a, athena__cloudformation__glue.athena-select-from-absent-table-rejected.
