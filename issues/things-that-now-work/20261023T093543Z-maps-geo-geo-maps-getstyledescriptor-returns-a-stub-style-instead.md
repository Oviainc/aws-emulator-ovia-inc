GetStyleDescriptor answers 200 with a reduced, locally-shaped style document: the canonical style name is replaced by a short display name, the top-level style metadata/light/sky/projection/id/created/modified blocks are absent, the 'aws' vector source is absent, the sprite/glyphs/tile URLs are emitted relative instead of absolute, and the overwhelming majority of the modelled layers are missing. Three causes, all on service maps.geo, all GetStyleDescriptor.

Cause 1 of 3: Standard / Dark / Default with rich options (terrain, traffic, travel-modes, poi) — descriptor is a stub.
  AWS: Smithy (com-amazonaws-geomaps-mapsservice) GetStyleDescriptor GET /v2/styles/{Style}/descriptor, Style @httpLabel required (MapStyle enum), with query inputs ColorScheme, PoliticalView, Terrain, ContourDensity, Traffic, TravelModes (@length max 2, uniqueItems), Buildings, PoiDensity, PoiCategories (@length max 9), Key; output is a @httpPayload Blob plus Content-Type/Cache-Control/ETag. The model does not describe the body, so recorded behavior only: the payload is a MapLibre style JSON whose 'name' is the canonical style id of the form AmazonLocation-<Style>-Global-<ColorScheme>-<Variant>, which carries 'id', 'created', 'modified', 'metadata' (including 'version' and 'aws:virtual-variant' when terrain is requested), 'light', 'sky', 'projection', a 'sources.aws' vector source with attribution/maxzoom/tiles, a 'sources.traffic' source with attribution and maxzoom 17 when traffic is requested, absolute 'sprite' and 'glyphs' URLs rooted at the service endpoint, and the full layer list (land as a 'background' layer with paint.background-color, plus the road/bridge/tunnel/rail/traffic/shield/poi/water/admin layer families).
  Emulator: 'name' is the display string 'Standard Dark'; metadata.version and metadata['aws:virtual-variant'] missing; sources.aws missing entirely; sources.traffic.attribution missing and sources.traffic.maxzoom 16 instead of 17; sources.traffic.tiles[0] and glyphs are relative ('/v2/tiles/vector.traffic/{z}/{x}/{y}', '/v2/glyphs/{fontstack}/{range}.pbf') where the recording has absolute URLs; sprite is '/v2/styles/Standard/Dark/Default/sprites/sprites' (relative, and without the file base the recording uses); the 'land' layer has type 'fill' with no paint.background-color instead of type 'background'; and several hundred layers ($.layers[id="rail_tunnel"], the bridge_*, tunnel_*, road_traffic_*, shield_*, poi_*, water_*, admin_* families, travel-mode-truck, traffic-flow, traffic-incidents, ...) are absent, as are $.light, $.sky, $.projection, $.id, $.created, $.modified.
  Why: this document IS the client contract — a MapLibre/GL client loads it and resolves everything else from it. With 'sources.aws' absent no basemap tiles are ever requested; with relative sprite/glyphs URLs a client that does not resolve against the request base fetches nothing; with the land layer typed 'fill' and no background paint the map has no base fill; and with the layer families missing the requested options (terrain, traffic, travel-modes, poi categories) have no effect on the rendered style even though the request was accepted. Traffic maxzoom 16 vs 17 silently drops the top traffic zoom level.
  Fix: the GetStyleDescriptor handler and the style-descriptor document it builds in the geo-maps service crate — emit the canonical style name, the metadata/light/sky/projection/id/created/modified blocks, the 'aws' vector source, absolute sprite/glyphs/tiles URLs rooted at the service endpoint, and the option-dependent layer set (host and port of those URLs are environment-specific and not themselves the requirement; being absolute is).
  Traces: geo-maps-style-descriptor-rich-options#task#1.

Cause 2 of 3: Monochrome / Light / Default — same stub shape, so it is not specific to one style's fixture.
  AWS: as cause 1; recorded 'name' is 'AmazonLocation-Monochrome-Global-Light-Default', the land layer is a 'background' layer whose paint.background-color is a zoom interpolate expression, and sources.aws carries the vector tiles URL plus attribution and maxzoom 17.
  Emulator: 'name' 'Monochrome Light'; metadata.version and metadata['aws:virtual-variant'] missing; sources.aws missing; sprite and glyphs relative; land typed 'fill' with no paint.background-color; $.layers[id="rail_tunnel"], $.layers[id="rail_tie_tunnel"] and the bridge_*/tunnel_*/road_*/poi_*/water_*/place_* families missing, along with $.light, $.sky, $.projection, $.id, $.created, $.modified.
  Why: a client switching color scheme/style gets the same unusable stub, so no style selection produces a renderable basemap.
  Fix: same component as cause 1 — the descriptor must be generated per Style/ColorScheme/Variant rather than from a single reduced template.
  Traces: geo-maps-style-descriptor-rich-options#task#2.

Cause 3 of 3: Standard / Light / Default in the vector-basemap workflow — top-level style blocks and the aws source are absent.
  AWS: as cause 1; recorded 'name' is 'AmazonLocation-Standard-Global-Light-Default', with 'light' ({anchor: viewport, intensity, position}), 'sky' (sky-color/horizon/fog/atmosphere blend members), 'projection' ({type: globe}), 'id', 'created', 'modified', metadata.version, metadata['aws:virtual-variant'], and sources.aws (type vector, attribution, maxzoom 17, absolute tiles URL).
  Emulator: 200 with 'name' 'Standard Light', and $.light, $.sky, $.projection, $.created, $.modified, $.id, $.metadata.version, $.metadata['aws:virtual-variant'] and $.sources.aws all missing; glyphs and sprite relative.
  Why: a client that drives the recorded workflow (descriptor -> sprites -> glyphs) gets a style with no vector source and no globe projection/light/sky, so the subsequent tile and asset requests it would derive are never issued; the specific id/created/modified values are environment-generated and quoted only as examples, but their absence changes the document's shape.
  Fix: same component as cause 1.
  Traces: geo-maps-vector-basemap-style-workflow#task#1.
