# signer-data revocation writers: RevokeSignature and RevokeSigningProfile word their not-found refusals themselves, and the profile refusal drops the version it was asked about

> _Note: this issue was identified against the code base at commit `712591afcbaa8fe04acc2e16b4d0dd73e216350b`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
RevokeSignature

## Description
Two net-new root causes on ONE service, both on the not-found refusal of a revocation WRITER, each witnessed by a different behavioral check. They are independent and BOTH must be closed before this issue is submitted. Each check is a multi-leg revocation-lifecycle check whose negative sub-test runs FIRST, so both checks abort on the refusal text and never reach the revocation/propagation assertions that follow — closing these two causes is also what unblocks the rest of each check.

Cause 1 of 2: RevokeSignature's unknown-job refusal is emulator prose instead of AWS's sentence.
AWS: 404 ResourceNotFoundException (Smithy, com.amazonaws.signer#WallabyService: RevokeSignature errors include ResourceNotFoundException errorKind client httpError 404, members {message, code}; RevokeSignature input jobId @httpLabel @required, reason @required @length 1..500, PUT /signing-jobs/{jobId}/revoke) with message "Signing Job with id <jobId> does not exist." Fixed text: "Signing Job with id " … " does not exist." — capitalised "Signing Job", and the trailing period is part of it. The single variable part is the jobId path label from the request. The failed attempt is also a no-op on state: a real, succeeded job in the same account gains no revocationRecord from it.
Emulator: right status and right error class, but message "Signing job not found for id <jobId>" — lower-case "job", "not found for id" instead of "with id … does not exist", and no trailing period.
Why: the message is part of the error contract; a client or test that matches AWS's wording does not match, and nothing else in the 404 distinguishes a job that never existed.
Fix: the not-found path of the RevokeSignature handler in the signer crate (services/service-com-amazonaws-signer-wallabyservice/src/ops/revoke_signature.rs) and the shared message it should compose from, next to the other refusal wording in src/state.rs.
Note on prior art: this is the SAME defect as cause 3 of the open issue 20261029T191542Z-signer-error-paths-diverge-from-aws-in-message.md, which was filed from the WIRE corpus under service token `signer` and carries only that corpus's replay keys. It does not carry this behavioral check's key, so the check is recorded here to make it replayable; closing one closes both, and the fixer should re-replay signer-data.revoke-signature-marks-job-revoked to confirm.
Traces: signer-data.revoke-signature-marks-job-revoked.

Cause 2 of 2: RevokeSigningProfile's unknown-profile refusal is misworded AND withholds the profileVersion the request named.
AWS: 404 ResourceNotFoundException (Smithy: RevokeSigningProfile errors include ResourceNotFoundException httpError 404, members {message, code}; input profileName @httpLabel @required @length 2..64 @pattern ^[a-zA-Z0-9_]{2,}$, profileVersion @required @length 10..10 @pattern ^[a-zA-Z0-9]{10}$, reason @required, effectiveTime Timestamp @required; PUT /signing-profiles/{profileName}/revoke) with message "Signing Profile with name <profileName> and version <profileVersion> does not exist." Fixed text: "Signing Profile with name " … " and version " … " does not exist." — capitalised "Signing Profile", trailing period included. Variable parts: the profileName path label and the profileVersion member, both taken from the request. The refusal names BOTH halves of the resource the request addressed, because the operation revokes one VERSION of a profile and either half can be the one that does not resolve.
Emulator: right status and error class, message "profile with name <profileName> does not exist**s**" — lower-case "profile", ungrammatical "does not exists", no trailing period, and the profileVersion the caller asked about is dropped entirely.
Why: beyond the wording break, dropping the version makes the refusal ambiguous in exactly the case the operation exists for: a caller that revokes a specific version cannot tell from the message whether the profile is unknown or only that version is, so it cannot decide between re-creating the profile and re-reading its versions. (The crate already has a version-aware sibling, crate::state::profile_version_not_found_message — "profile with name {p} has no version {v}" at src/state.rs:1508-1510 — which is likewise not AWS's wording; the two conditions must converge on the one sentence above.)
Fix: the not-found path of the RevokeSigningProfile handler in the signer crate (src/ops/revoke_signing_profile.rs) plus the shared profile/version not-found wording in src/state.rs — compose AWS's sentence from the request's profileName and profileVersion for both the unknown-profile and the unknown-version condition.
Traces: signer-data.revoke-signing-profile-effective-time-boundary.

## Evidence
Behavioral suite replay against the emulator built from mainline: 8/18 passed (44.4%), 10 mismatched, 0 errored; the only service exercised was signer-data. Both failures below are [mismatch] lines from that report, and in both the asserted Error.Code matched — only the message diverged.

Cause 1 — signer-data.revoke-signature-marks-job-revoked. The check creates a signing profile, a versioned source bucket and a destination bucket, runs a signing job to Succeeded, and then issues its negative sub-test: RevokeSignature(jobId=<a fresh uuid4 that was never a job>, reason='probe-nonexistent-job'). Error.Code 'ResourceNotFoundException' matched; the message did not:
  AssertionError: expected message 'Signing Job with id 449dd784-867e-4c32-9dbc-d724d57d7fca does not exist.', got 'Signing job not found for id 449dd784-867e-4c32-9dbc-d724d57d7fca'
  (that uuid is the run's generated jobId filling the template, not part of it.)
  The check aborts here, so its remaining legs never run: that the failed attempt leaves the real job without a revocationRecord, that RevokeSignature on the real job makes the job's ARN appear in GetRevocationStatus' revokedEntities, and that an unrelated profileVersionArn queried in the same request does NOT.

Cause 2 — signer-data.revoke-signing-profile-effective-time-boundary. Its first leg is the negative sub-test: RevokeSigningProfile(profileName=<a name never created>, profileVersion='AAAAAAAAAA', effectiveTime=now, reason='probe-nonexistent-profile'). Error.Code 'ResourceNotFoundException' matched; the message did not:
  AssertionError: expected message 'Signing Profile with name sim2real_signer_nope_25bffae9fa40 and version AAAAAAAAAA does not exist.', got 'profile with name sim2real_signer_nope_25bffae9fa40 does not exists'
  (the profile name is the run's generated value; 'AAAAAAAAAA' is the 10-character profileVersion the request carried. Both fill the template. Note the emulator's text omits the version entirely and reads 'does not exists'.)
  The check aborts here, so its effectiveTime-boundary legs never run: revoking a real profile version with effectiveTime one hour in the past, then proving GetRevocationStatus reports that profileVersionArn revoked for a signatureTimestamp AFTER the effective time and not revoked for one BEFORE it, before and after propagation.

Model facts used — smithy_query on services/service-com-amazonaws-signer-wallabyservice/smithy-model/com-amazonaws-signer-wallabyservice.json: RevokeSignature PUT /signing-jobs/{jobId}/revoke, input {jobId JobId @httpLabel @required, jobOwner AccountId @length 12..12 @pattern ^[0-9]{12}$, reason RevocationReasonString @required @length 1..500}, output Unit, errors AccessDeniedException(403), InternalServiceErrorException(500), ResourceNotFoundException(404), TooManyRequestsException(429), ValidationException(400). RevokeSigningProfile PUT /signing-profiles/{profileName}/revoke, input {profileName ProfileName @httpLabel @required @length 2..64 @pattern ^[a-zA-Z0-9_]{2,}$, profileVersion @required @length 10..10 @pattern ^[a-zA-Z0-9]{10}$, reason @required @length 1..500, effectiveTime Timestamp @required}, output Unit, same error set. ResourceNotFoundException is a structure with members {message, code}; neither message text is modelled, so both templates above are recorded behavior.
