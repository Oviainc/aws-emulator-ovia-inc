# Enforce the activation-code lifetime (12 hours) and the five-attempt limit

_Filed: 2026-10-24T05:23:11Z_
_Operation: ActivateEmailContact | Class: wrong-behavior_

> _Note: this issue was identified against the code base at commit `7eba44b4c78724d09fd14d928dd44bf5d39abe6e`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Description

The model documents two limits on an activation code: "An email contact has a maximum of five activation attempts. Activation codes expire after 12 hours and are generated by the SendActivationCode API action."

The emulator implements neither:
- `EmailContactRecord` (`src/state.rs`) stores only `pending_activation_code: Option<String>` — no issue timestamp and no attempt counter — so a code issued by SendActivationCode stays valid forever. After 12 hours AWS refuses it (a new SendActivationCode is required) while the emulator still activates the contact and flips its status to `active`.
- `src/ops/activate_email_contact.rs` lets a caller submit wrong codes without bound. AWS stops honouring the outstanding code after five attempts; the emulator will accept a correct code on the 6th, 100th or 10,000th try, which also removes the brute-force ceiling on a 7-character code space.

Expected: an attempt with a code older than 12 hours, or after the fifth activation attempt on the same code, fails and leaves the contact `inactive` until a new code is sent. Actual: both succeed indefinitely.

## Evidence

Spec: smithy_query(query="doc", shape="ActivateEmailContactRequest", member="code") -> "An email contact has a maximum of five activation attempts. Activation codes expire after 12 hours..." (also reproduced in the handler's own doc header, src/ops/activate_email_contact.rs lines 59-60). State: src/state.rs lines 87-109 — the record carries no code-issue time and no attempt count; src/ops/send_activation_code.rs line 184 just overwrites `pending_activation_code`. Test coverage: grep for attempt/expir/12 hour across the crate's tests finds nothing — tests/all/email_contacts.rs::activation_turns_only_on_the_code_this_service_issued exercises wrong codes but never a 6th attempt or an aged code.

## Steps to Reproduce

1. CreateEmailContact -> arn; SendActivationCode(arn)
2. Submit ActivateEmailContact(arn, code="0000000") five times (all wrong) -> five refusals
3. Submit ActivateEmailContact(arn, <the real issued code>) -> the emulator activates the contact; AWS refuses because the five-attempt budget for that code is spent
4. Separately: SendActivationCode(arn), advance the clock past 12 hours, then ActivateEmailContact(arn, <the issued code>) -> the emulator still activates; AWS refuses the expired code
