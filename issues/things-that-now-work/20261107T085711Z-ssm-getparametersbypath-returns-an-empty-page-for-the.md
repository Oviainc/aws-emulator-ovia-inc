# SSM GetParametersByPath returns an empty page for the public /aws/service/ami-amazon-linux-latest hierarchy

> _Note: this issue was identified against the code base at commit `9ae19e0eca83af3a9e4c3dd8e20d1f4043458c83`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
GetParametersByPath

## Description
1 CAUSE. The emulator serves no AWS-published public Parameter Store entries under the /aws/service/ami-amazon-linux-latest hierarchy, so a recursive GetParametersByPath over that path answers 200 with an empty Parameters list. The requirement here is the SHAPE and the POPULATION of the public catalog, not any single recorded image id, version or timestamp: those are per-environment.

Note on related open issues: 20261103T173026Z-ssm-public-aws-published-aws-service-parameter-hierarchy-is.md, 20261030T030533Z-ssm-getparameter-cannot-resolve-aws-published-aws-parameters.md and 20261103T154947Z-ssm-getparameter-cannot-resolve-aws-published-public-aws.md describe the same family of gap, but the replay reports THIS cluster as unowned (its divergence key names a different, refreshed set of alias names than any open issue's key), so it is filed net-new and must be closed on its own replay.

Cause 1 of 1: GetParametersByPath over the public Amazon Linux AMI alias hierarchy enumerates nothing.
AWS: 200 with one Parameter per published alias in the hierarchy (the recording enumerates the whole /aws/service/ami-amazon-linux-latest namespace - al2023-ami-kernel-*-{arm64,x86_64}, al2023-ami-minimal-kernel-*, al2027-preview-ami-*, amzn-ami-{hvm,pv,minimal}-x86_64-{ebs,gp2,s3}, amzn2-ami-kernel-*-hvm-* and siblings). Each entry is shaped Name = the full public path beginning with a forward slash, Type 'String', DataType 'text', a Version, a LastModifiedDate, and ARN of the form arn:aws:ssm:<region>::parameter<name> - public parameters use an EMPTY account segment. Smithy: GetParametersByPath output Parameters: ParameterList; com.amazonaws.ssm#Parameter members Name, Type (ParameterType enum String|StringList|SecureString), Value, Version, LastModifiedDate, ARN, DataType (default 'text'). The contents of the public catalog itself are service-published data and not modelled: recorded behavior only, and the per-alias Value/Version/LastModifiedDate are asserted only as shaped, not as literal values.
Emulator: 200, but every expected entry of the hierarchy is reported missing - $.Parameters carries none of the public alias names.
Why: every client that discovers a current Amazon-published AMI through the Parameter Store alias hierarchy - EC2 RunInstances or a launch template with a resolve:ssm: ImageId, a CloudFormation AWS::SSM::Parameter::Value<AWS::EC2::Image::Id> template parameter, CDK context lookups, ECS/Bottlerocket AMI discovery - enumerates zero candidates and cannot pick an image, so the launch path fails before it starts rather than resolving an AMI.
Fix: the SSM public-parameter catalog in the service's state (seed the /aws/service hierarchy) and the GetParametersByPath handler's resolution of it, including the account-less public ARN form and recursive path matching.
Traces: ssm-catalog-get-parameters-by-path#task#1.
