=== Cause 1 of 2: PutDestinationPolicy refuses an unknown destination with an emulator-authored message instead of AWS's ===
AWS: Smithy (cloudwatchlogs) PutDestinationPolicy takes destinationName (@required, @length 1..512, @pattern ^[^:*]*$) and accessPolicy (@required, @length min 1) and models exactly InvalidParameterException (HTTP 400), OperationAbortedException (400) and ServiceUnavailableException (500) — there is NO ResourceNotFoundException on this operation, so the missing-destination case is reported as InvalidParameterException. Recorded behavior: calling PutDestinationPolicy with a destinationName the account does not hold (in the recording, a destination that was just deleted with DeleteDestination) answers HTTP 400 InvalidParameterException with the message "Destination with name <destinationName> does not exist". Message rule: the fixed text is "Destination with name " … " does not exist"; the one variable part is the destinationName taken verbatim from the request (the suite's concrete name, e.g. 'sim2real-behav-dest-12aa459822dc', is one run's value filling that slot, not part of the template).
Emulator: the same call answers HTTP 400 InvalidParameterException with the generic sentence 'The specified destination does not exist.' — AWS's fixed text is not reproduced and the request's destinationName is not named at all. The handler reaches this through the service-wide missing-resource sentence helper rather than a destination-specific message.
Why: the status and error code are right, so a client's error-class handling works, but the message is part of the contract. A client, CLI user or log-parsing tool keyed on AWS's wording does not match, and in a flow that manages several destinations the emulator's message does not say WHICH destination name was rejected, so the failure cannot be attributed to a request.
Fix: the missing-destination branch of the PutDestinationPolicy handler (`services/service-com-amazonaws-cloudwatchlogs-logs-20140328/src/ops/put_destination_policy.rs`, the `store.destinations.get_mut(&input.destination_name)` else-branch at ~line 223, which calls `crate::state::resource_not_found_message("destination")` in `crate::state`): build the InvalidParameterException message from AWS's template, interpolating `input.destination_name`.
Traces: logs.put-destination-then-get.

=== Cause 2 of 2: the Kinesis GetRecords scaffold stub makes four CloudWatch Logs subscription-delivery contracts ungradeable ===
AWS: recorded behavior only (no logs-model statement covers the delivered payload). The recordings show CloudWatch Logs writing a subscription filter's matches to the destination Kinesis stream, and the consumer reading them with kinesis GetShardIterator/GetRecords, which answers HTTP 200 with records whose Data (after the SDK's base64 decode) is raw GZIP (magic 0x1f 0x8b) wrapping a JSON envelope carrying owner, logGroup, logStream, messageType, subscriptionFilters and logEvents; AWS/Logs ForwardedLogEvents and DeliveryErrors are published alongside under {LogGroupName, DestinationType, FilterName}.
Emulator: every one of those reads is refused — kinesis GetRecords answers HTTP 501 with code NotImplemented and the message "operation GetRecords is scaffolded but not implemented in this emulator". All four checks below abort on that call, so the emulator is never asked anything about the CloudWatch Logs side: the DeliveryErrors datapoint on a dead destination, the ForwardedLogEvents count equalling only the filter's matches, the delivered record envelope (owner/logGroup/logStream/subscriptionFilters and exactly the matching events, gzip-framed), and parseVPC's transformed event reaching a subscription with applyOnTransformedLogs=true are all ungraded.
Why: a client cannot CONSUME a CloudWatch Logs subscription at all against this emulator — the delivery exists, if it exists, with no readable sink — and the whole subscription-delivery data plane of `logs` is left unverified, so regressions in it cannot be detected.
Fix: implement the Kinesis data-plane read in `services/service-com-amazonaws-kinesis-kinesis-20131202/src/ops/get_records.rs` (it still carries the `//! SCAFFOLDED, NOT IMPLEMENTED:` marker) over the shard state its writers populate; the `logs` side then needs the subscription-filter delivery path to actually put the gzip envelopes onto that stream. Note that `kinesis` is not a bootstrapped service in this checkout, so these four `logs.` checks stay red until that data plane answers.
Traces: logs.subscription-filter-delivery-failure-counts-a-deliveryerrors-datapoint, logs.subscription-filter-forwardedlogevents-counts-only-the-matching-events, logs.subscription-filter-record-envelope-carries-owner-stream-and-only-matching-events, logs.deep-logs-3-logacct-transformer-parsevpc-extracts-typed-flow-fields-on-ingest.

## Evidence
Cause 1 — logs.put-destination-then-get [mismatch]: the check creates a Kinesis stream + a role trusted by logs.amazonaws.com, calls PutDestination, asserts DescribeDestinations echoes targetArn/roleArn, calls PutDestinationPolicy (accepted, policy echoed verbatim by DescribeDestinations), calls DeleteDestination (destination gone from DescribeDestinations), then re-issues PutDestinationPolicy with the same accessPolicy. Emulator answer: 400 InvalidParameterException, message 'The specified destination does not exist.'. Cause 2 — all four checks abort with the identical exception: "botocore.exceptions.ClientError: An error occurred (NotImplemented) when calling the GetRecords operation: operation GetRecords is scaffolded but not implemented in this emulator" (HTTP 501), raised from the shard-drain / envelope-collector step after PutSubscriptionFilter and PutLogEvents were accepted. Expected: GetRecords answers 200 and the drained records carry the GZIP'd CloudWatch Logs envelopes, after which each check grades its own logs-side claim (DeliveryErrors >= 1 on a deleted destination; ForwardedLogEvents Sum == number of MATCHING events, not events written; envelope header naming the caller's account, the log group and the log stream with exactly one subscriptionFilters entry; parseVPC emitting camelCase typed JSON with '-' placeholders dropped). The stub file still carries the marker: services/service-com-amazonaws-kinesis-kinesis-20131202/src/ops/get_records.rs line 4: "SCAFFOLDED, NOT IMPLEMENTED: this operation answers HTTP 501 NotImplemented".
