## Description

Cause 1 of 3: EC2 DescribeImages is an unimplemented scaffold, so no Auto Scaling check can resolve an AMI for a launch template or launch configuration.
AWS: DescribeImages is a plain read that returns the AMIs matching the given Owners/Filters with HTTP 200 and no precondition; it is the account-independent way to pick an ImageId before CreateLaunchTemplate/CreateLaunchConfiguration/RunInstances. The autoscaling checks call it as the documented fallback after the SSM public AMI alias lookup fails. Smithy: the op exists in the emulator's own EC2 model and its handler file carries the generator's SCAFFOLDED marker.
Emulator: the call is refused with HTTP 501 and error code 'NotImplemented' (message example: 'operation DescribeImages is scaffolded but not implemented in this emulator'), aborting the check during setup before any autoscaling API is exercised.
Why: a client cannot discover an image id at all, so every emulated Auto Scaling workflow that has to launch or describe a launch-template-backed group fails at the first call — 58 of this suite's autoscaling checks never reach the behavior they grade, which makes the whole group-lifecycle/scaling/lifecycle-hook surface untestable rather than merely wrong.
Fix: implement the DescribeImages handler over the emulated EC2 image state and delete the SCAFFOLDED marker (services/service-com-amazonaws-ec2-amazonec2/src/ops/describe_images.rs:3-12 is the stub header).

Cause 2 of 3: EC2 CreateSecurityGroup is an unimplemented scaffold, so no check can build the network prerequisites of an ASG attached to an ELBv2 target group.
AWS: CreateSecurityGroup creates a security group in the given VPC and returns HTTP 200 with the new GroupId; it is a precondition for launch templates and target-group registration, with no account-specific precondition.
Emulator: the call is refused with HTTP 501 'NotImplemented' (message example: 'operation CreateSecurityGroup is scaffolded but not implemented in this emulator').
Why: an Auto Scaling group cannot be given the security group its instances need, so the ASG/target-group CLI workflows abort in setup and the attach/register behavior they grade is never reached.
Fix: implement the CreateSecurityGroup handler over the emulated EC2 network state (services/service-com-amazonaws-ec2-amazonec2/src/ops/create_security_group.rs, same SCAFFOLDED stub shape as describe_images.rs).

Cause 3 of 3: IAM CreateInstanceProfile is an unimplemented scaffold, so no check can give an ASG-launched instance an instance profile.
AWS: CreateInstanceProfile creates the profile and returns HTTP 200 with the InstanceProfile (name, id, ARN, empty Roles); AddRoleToInstanceProfile then binds the role that a launch template's IamInstanceProfile references.
Emulator: the call is refused with HTTP 501 'NotImplemented' (message example: 'operation CreateInstanceProfile is scaffolded but not implemented in this emulator').
Why: instances launched by a group can never carry a role, so every scoped-credential behavior of an ASG instance (what it may and may not do with S3, STS identity) is unreachable and a permission test passes vacuously.
Fix: implement the CreateInstanceProfile handler over the emulated IAM state (services/service-com-amazonaws-iam-awsidentitymanagementv20100508/src/ops/create_instance_profile.rs).
