# An ACTIVE managed endpoint reports no serverUrl, certificateAuthority, securityGroup or subnetIds

_Filed: 2026-10-24T18:50:50Z_
_Operation: DescribeManagedEndpoint | Class: wrong-behavior_

> _Note: this issue was identified against the code base at commit `5e76d9058893794719deef102d36e8b94e082214`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Description

Expected: once a managed endpoint reaches ACTIVE, DescribeManagedEndpoint (and ListManagedEndpoints) report the endpoint's connection metadata the model declares — `serverUrl` (and `authProxyUrl` where applicable), `certificateAuthority`, `securityGroup` and `subnetIds`. These are the members every client (EMR Studio, the livy/JEG clients, Terraform's `aws_emrcontainers_virtual_cluster` style consumers) reads to actually reach the endpoint, and in real recordings an ACTIVE endpoint always carries at least `serverUrl` and `certificateAuthority`.

Actual: `ManagedEndpointRecord::to_endpoint` hardcodes `server_url: None`, `auth_proxy_url: None`, `certificate_authority: None`, `security_group: None`, `subnet_ids: None`, so the endpoint object is permanently missing its connection information on every read path, for every endpoint state. Nothing in the create request or state is used to derive even a deterministic emulator-local URL.

## Evidence

Spec: Smithy `Endpoint` shape declares `serverUrl` ("The server URL of the endpoint"), `authProxyUrl`, `certificateAuthority` ("The certificate generated by emr control plane on customer behalf to secure the managed endpoint"), `securityGroup` and `subnetIds`, all returned by DescribeManagedEndpoint/ListManagedEndpoints. Handler/state: src/state.rs `ManagedEndpointRecord::to_endpoint` (lines ~927-948) sets each of those members to None (with a comment acknowledging they are deliberately omitted); src/ops/describe_managed_endpoint.rs line ~173 returns that rendering unchanged, and src/ops/list_managed_endpoints.rs line ~303 uses the same renderer. Test coverage: tests/all/managed_endpoint_listing.rs asserts the stored members round-trip but never asserts serverUrl/certificateAuthority/securityGroup/subnetIds.

## Steps to Reproduce

1. POST /virtualclusters to create a cluster
2. POST /virtualclusters/{clusterId}/endpoints with {name:"jeg", clientToken:"t1", type:"JUPYTER_ENTERPRISE_GATEWAY", releaseLabel:"emr-6.10.0-latest", executionRoleArn:"arn:aws:iam::000000000000:role/EMRJobRole", sessionIdleTimeoutInMinutes:30}
3. Wait for the endpoint to reach ACTIVE, then GET /virtualclusters/{clusterId}/endpoints/{endpointId}
4. Observe `endpoint.state == "ACTIVE"` but `serverUrl`, `certificateAuthority`, `securityGroup` and `subnetIds` all absent/null
5. GET /virtualclusters/{clusterId}/endpoints — the listed endpoint is missing the same members
