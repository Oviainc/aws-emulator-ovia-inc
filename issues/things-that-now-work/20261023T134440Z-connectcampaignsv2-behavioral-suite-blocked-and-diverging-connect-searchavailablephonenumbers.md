# ConnectCampaignsV2 behavioral suite blocked and diverging: connect SearchAvailablePhoneNumbers is a 501 stub (17 checks), DeleteInstanceOnboardingJob is a 501 stub, and DescribeCampaign's not-found message is emulator-authored (3 causes)

SearchAvailablePhoneNumbers

## Description
Three distinct net-new root causes behind the remaining connectcampaignsv2 failures in suite simparity-behavioral-aws-v1 (connectcampaignsv2 scored 0/25). Already-covered failures are excluded: connectcampaignsv2.get-campaign-state-batch-invalid-id-pattern-rejected is ALREADY FILED against the GetCampaignStateBatch stub issue (20261023T034742Z-connectcampaignsv2-getcampaignstatebatch-stub.md), and the five checks OWNED by 20261023T034742Z-connectcampaignsv2-createcampaign-skips-the-connect-instance-existence-check.md (CreateCampaign instance-existence, PutOutboundRequestBatch over-validation, GetConnectInstanceConfig / TagResource / ListTagsForResource stubs) are not re-filed here. The open router issue 20261022T145747Z-connectcampaigns-is-entirely-unreachable-router-resolves-services-by covers service token `connectcampaigns` (v1) only and does not cover any of these: ConnectCampaignsV2 IS routed and answering.

Cause 1 of 3 — Amazon Connect SearchAvailablePhoneNumbers answers 501 NotImplemented, which aborts 17 of the 25 connectcampaignsv2 checks during their Connect-instance setup, before any ConnectCampaignsV2 operation is exercised.
AWS: Smithy (connect model) SearchAvailablePhoneNumbers — POST /phone-number/search-available, input TargetArn (ARN) | InstanceId (len 1..100), PhoneNumberCountryCode (enum, required), PhoneNumberType (enum, required), MaxResults (range 1..10); output AvailableNumbersList (list) + NextToken; modeled errors AccessDeniedException 403, InvalidParameterException 400, ThrottlingException 429, InternalServiceException 500. There is NO NotImplemented error in the model. Recorded behavior: the call returns HTTP 200 with an AvailableNumbersList of claimable DID numbers for the instance/traffic-distribution-group target (the individual phone numbers returned are account- and pool-specific and are NOT a requirement — only that a 200 with a non-empty AvailableNumbersList is returned for a valid instance target).
Emulator: HTTP 501 with error code `NotImplemented`, message example "operation SearchAvailablePhoneNumbers is scaffolded but not implemented in this emulator". services/service-com-amazonaws-connect-amazonconnectservice/src/ops/search_available_phone_numbers.rs still carries the `SCAFFOLDED, NOT IMPLEMENTED` marker and its handle() returns Scaffolded::not_implemented("SearchAvailablePhoneNumbers").
Why: `NotImplemented` exists in no AWS model, so no SDK error branch matches it and clients cannot retry or degrade. Concretely, every telephony-channel workflow is unusable: a caller cannot discover a claimable number, so ClaimPhoneNumber and therefore any ConnectCampaignsV2 campaign with a telephony defaultOutboundConfig.connectSourcePhoneNumber can never be built. This single stub makes 17/25 of this service's behavioral surface (campaign lifecycle, campaign CRUD/persistence, pause/resume/stop refusals, tagging round trip, all five Update* round trips) unreachable, so their fidelity is entirely unmeasured.
Fix: implement the operation in its own handler file services/service-com-amazonaws-connect-amazonconnectservice/src/ops/search_available_phone_numbers.rs against the connect crate's phone-number state — resolve the InstanceId/TargetArn, return a page of available numbers honouring PhoneNumberCountryCode / PhoneNumberType / MaxResults and the paginated NextToken, use the modeled InvalidParameterException (400) for a bad target, and remove the SCAFFOLDED marker. The numbers it hands out must be claimable by ClaimPhoneNumber and must stop being advertised once claimed.
Traces: connectcampaignsv2.campaign-lifecycle-start-pause-resume-stop-transitions, connectcampaignsv2.concurrent-create-campaign-same-name-one-winner, connectcampaignsv2.create-campaign-nonexistent-instance-not-found, connectcampaignsv2.create-campaign-persists-full-config, connectcampaignsv2.delete-campaign-removes-resource, connectcampaignsv2.delete-connect-instance-config-blocked-by-active-campaign-rejected, connectcampaignsv2.pause-initialized-campaign-rejected, connectcampaignsv2.put-outbound-request-batch-on-initialized-campaign-rejected, connectcampaignsv2.resume-initialized-campaign-rejected, connectcampaignsv2.stop-initialized-campaign-rejected, connectcampaignsv2.tag-resource-and-list-tags-round-trip, connectcampaignsv2.update-campaign-channel-subtype-config-round-trip, connectcampaignsv2.update-campaign-communication-limits-override-round-trip, connectcampaignsv2.update-campaign-entry-limits-persists, connectcampaignsv2.update-campaign-name-persists, connectcampaignsv2.update-campaign-schedule-persists, connectcampaignsv2.update-campaign-source-succeeds-while-initialized (all 17 abort with ClientError NotImplemented on SearchAvailablePhoneNumbers).

Cause 2 of 3 — ConnectCampaignsV2 DeleteInstanceOnboardingJob is an unimplemented scaffold (501 NotImplemented), so the "only a FAILED onboarding job may be deleted" refusal does not exist.
AWS: Smithy DeleteInstanceOnboardingJob — DELETE /v2/connect-instance/{connectInstanceId}/onboarding, input connectInstanceId (InstanceId, len 1..256, pattern ^[-_.a-zA-Z0-9]+$, required), empty output; modeled errors AccessDeniedException 403, InvalidStateException 409, ResourceNotFoundException 404, ValidationException 400, InternalServerException 500. The model documents InvalidStateException as "The request could not be processed because of conflict in the current state". Recorded behavior: against an instance whose onboarding job is SUCCEEDED, the delete is refused with HTTP 409 and error code InvalidStateException (recorded message example: "Instance onboarding job is not in failed status. Only failed job can be deleted."), the job record is NOT removed (GetInstanceOnboardingJobStatus still reports SUCCEEDED afterwards), and the unaffected GetConnectInstanceConfig read on the same instance still succeeds.
Emulator: error code `NotImplemented` (HTTP 501, message example "operation DeleteInstanceOnboardingJob is scaffolded but not implemented in this emulator"). services/service-com-amazonaws-connectcampaignsv2-amazonconnectcampaignservicev2/src/ops/delete_instance_onboarding_job.rs still carries the SCAFFOLDED marker and returns Scaffolded::not_implemented at the end of handle().
Why: the onboarding state machine has no delete edge at all. A client cannot tear down a FAILED onboarding job and retry onboarding, and the guard that protects a SUCCEEDED job is unobservable — the SDK sees an unmodeled code no error branch matches, so code written against InvalidStateException is dead and a caller cannot tell "refused because the job succeeded" from "the service is broken".
Fix: implement DeleteInstanceOnboardingJob in its handler file against the instance-onboarding state shared with StartInstanceOnboardingJob / GetInstanceOnboardingJobStatus — 404 ResourceNotFoundException when the instance has no onboarding record, 409 InvalidStateException (leaving the record untouched) when the job's status is anything other than FAILED, and an empty 200 with the record removed when it is FAILED; then delete the SCAFFOLDED marker.
Traces: connectcampaignsv2.delete-instance-onboarding-job-rejected-while-succeeded (AssertionError: expected InvalidStateException, got NotImplemented).

Cause 3 of 3 — DescribeCampaign's ResourceNotFoundException carries an emulator-authored message built from the requested id instead of the service's fixed not-found text.
AWS: Smithy DescribeCampaign — GET /v2/campaigns/{id}, input id (CampaignId, len 1..256, pattern ^[-:/a-zA-Z0-9]+$, required); modeled errors include ResourceNotFoundException (HTTP 404). Recorded behavior for a well-formed campaign id that was never created: HTTP 404, error code ResourceNotFoundException, with the service's FIXED message "CampaignId not found." — a constant that does not embed the requested id, so the rule producing it is known (a fixed service string, not a per-request composition).
Emulator: the status and code are correct (404 / ResourceNotFoundException) but the message is composed from the request: "No campaign found for id dd584dec-fcfd-444b-93bc-1af01b2b3b1b".
Why: a client that matches or logs on the documented fixed not-found text (and any assertion or alarm keyed to it) does not match, and leaking the requested id into the message makes the response non-deterministic where AWS's is constant.
Fix: DescribeCampaign's handler/not-found path in services/service-com-amazonaws-connectcampaignsv2-amazonconnectcampaignservicev2/src/ops/describe_campaign.rs — raise the modeled ResourceNotFoundException with the service's fixed message rather than a formatted one.
Traces: connectcampaignsv2.describe-campaign-nonexistent-id-not-found (AssertionError: expected message 'CampaignId not found.', got 'No campaign found for id dd584dec-fcfd-444b-93bc-1af01b2b3b1b').
