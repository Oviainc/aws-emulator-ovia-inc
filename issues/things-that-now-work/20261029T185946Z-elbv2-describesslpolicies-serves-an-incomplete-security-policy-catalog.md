# ELBv2 DescribeSSLPolicies serves an incomplete security policy catalog with wrong cipher priorities

> _Note: this issue was identified against the code base at commit `611eef386f1100e1b77f5a1515bab52b7a7a6aeb`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
DescribeSSLPolicies

## Description
1 cause.

Cause 1 of 1: DescribeSSLPolicies with no filters.
AWS: returns the complete catalog of ELB security policies. Each entry carries Name, SslProtocols.member (e.g. TLSv1.2, TLSv1.3), Ciphers.member as {Name, Priority} pairs numbered from 1 in the policy's documented preference order, and SupportedLoadBalancerTypes.member ('application', 'network'). The catalog is a fixed, service-published list — the recording includes the TLS13 FIPS families (ELBSecurityPolicy-TLS13-1-0-FIPS-2023-04, -1-1-FIPS-2023-04, -1-2-FIPS-2023-04, -1-3-FIPS-2023-04, the Ext0/Ext1/Ext2/Res FIPS variants), the 2025-09 post-quantum families (ELBSecurityPolicy-TLS13-1-0-PQ-2025-09, -1-2-PQ-2025-09, -1-2-Res-PQ-2025-09, -1-2-Ext0/Ext1/Ext2-PQ-2025-09, -1-3-PQ-2025-09 and their FIPS-PQ counterparts) and the RFC9151 families (ELBSecurityPolicy-TLS13-1-2-RFC9151-FIPS-2023-07 and its INTEROP1..4 variants). Names and cipher membership/priority are the contract, not per-run values.
Emulator: those policies are absent from SslPolicies.member entirely, and for the policies it does serve it returns a different cipher list and priority numbering — ELBSecurityPolicy-TLS13-1-2-Ext1-2021-06 and ELBSecurityPolicy-TLS13-1-2-Ext2-2021-06 diverge on Ciphers.member entries 7..20 and their Priority values.
Why: a client that selects or validates an SslPolicy by name (CreateListener/ModifySslPolicy with any FIPS, PQ or RFC9151 policy) finds it missing from the catalog and either fails its pre-flight check or picks a fallback policy; a client that asserts a policy's cipher preference order reads the wrong suite.
Fix: the static SSL-policy catalog seeded into the ELBv2 service state, read by the DescribeSSLPolicies handler.
Traces: elbv2-catalog-describe-ssl-policies#task#1.
