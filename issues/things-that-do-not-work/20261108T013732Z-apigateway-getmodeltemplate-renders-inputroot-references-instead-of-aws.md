# apigateway GetModelTemplate renders $inputRoot references instead of AWS's type-derived sample values

> _Note: this issue was identified against the code base at commit `034d67882baedb5546cc15e58be35e810f93ad27`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
GetModelTemplate

## Description
Cause 1 of 1: the default mapping template generated by GetModelTemplate substitutes a VTL dereference of the request payload for every property of the model's JSON schema, where AWS substitutes a literal sample value derived from the property's declared JSON-schema type.

AWS: GetModelTemplate (Smithy: apigateway BackplaneControlService, GET /restapis/{restApiId}/models/{modelName}/default_template, 200, output shape Template with the single member `value`; Template.value is documented only as "The Apache Velocity Template Language (VTL) template content used for the template resource.") generates a sample mapping template that transforms a payload into the structure of the named model. The model says nothing about how the sample is rendered, so for that part this is recorded behavior only: for a model whose schema declares a single string property `id`, AWS answers 200 with

  #set($inputRoot = $input.path('$'))
  {
    "id" : "foo"
  }

The fixed text of this payload is the `#set($inputRoot = $input.path('$'))` preamble line, the brace-delimited object body, the two-space indent and the ` : ` name/value separator. The variable parts are the property NAMES, which come from the stored model's schema, and the per-property sample VALUE, which AWS derives from that property's declared JSON-schema type (a string property is rendered as the quoted sample literal `"foo"`). The property values are NOT taken from the request and are NOT references into the incoming payload.

Emulator: the same step answers 200 with

  #set($inputRoot = $input.path('$'))
  {
    "id" : "$inputRoot.id"
  }

so each property's value slot is filled with `"$inputRoot.<propertyName>"` — a VTL dereference synthesized from the property name — instead of a type-derived sample literal. Because the substitution is driven by the property name only, it is also type-blind: the same quoted `$inputRoot.<name>` text is emitted whatever JSON-schema type the property declares, which is exactly what the apigatewayv2-model-template-by-schema-type fixture exercises (steps task#4 and task#6 of that fixture diverge identically).

Why: the default template is what a client copies into an integration's requestTemplates or diffs against a checked-in template. A client that takes the emulator's template gets VTL that re-reads the inbound payload rather than AWS's type-illustrating sample, so generated integrations and any assertion or diff against the AWS-shaped default template are wrong, and nothing in the emulator's output reveals the property's declared type.

Fix: the GetModelTemplate handler's template generator in the apigateway service crate — walk the stored model's JSON schema and emit, for each property, a sample literal chosen by that property's declared type, rather than interpolating `$inputRoot.<propertyName>` into the value slot. The preamble, indentation and separator the emulator already emits are correct.

Traces: apigatewayv2-model-lifecycle#task#5 (representative), apigatewayv2-model-template-by-schema-type#task#4, apigatewayv2-model-template-by-schema-type#task#6. No open issue covers this: the apigateway model-plane issues still open concern 204 Content-Length framing (20261031T154120Z-apigateway-content-length-0-missing-on-204-deletes-for.md) and CreateModel's duplicate-name wording (20261029T220031Z-apigateway-400-class-refusals-use-the-wrong-error.md), and the GetModelTemplate scaffold-stub issue (20261027T101902Z-apigateway-getmodeltemplate-stub.md) is already resolved.

The status (200), the response shape (a single `value` member) and the preamble line all match; only the per-property value slot diverges. Expected renders a type-derived sample literal for the schema's string property; the emulator renders a quoted VTL dereference built from the property name.
