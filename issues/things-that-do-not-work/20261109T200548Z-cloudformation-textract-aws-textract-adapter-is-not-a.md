# cloudformation__textract: AWS::Textract::Adapter is not a registered resource type — CreateStack refuses every Textract adapter template as "Unrecognized resource types"

> _Note: this issue was identified against the code base at commit `1793706895cc87acc2112e1210fbb2da9ff5c952`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateStack

## Description
Cause 1 of 1: CloudFormation's template processor has no registration for the resource type AWS::Textract::Adapter, so a template that declares one is refused at CreateStack and no Textract adapter is ever provisioned, updated or deleted through CloudFormation. Failing checks: cloudformation__textract.deploy-cfn-textract-adapter-round-trip-then-update-and-delete, cloudformation__textract.deploy-cfn-textract-adapter-invalid-feature-type-rejected.

AWS: AWS::Textract::Adapter is a supported CloudFormation resource type. CreateStack with a template whose only resource is of that type is accepted (HTTP 200, a StackId is returned) and the stack reaches CREATE_COMPLETE, creating the adapter in Textract. The resource is backed by the Textract adapter API (Smithy, services/service-com-amazonaws-textract-textract: CreateAdapter{AdapterName required @length 1..128 @pattern ^[a-zA-Z0-9-_]+$, FeatureTypes required, AutoUpdate enum, Description @length 1..256, Tags map 0..200} -> CreateAdapterResponse{AdapterId @length 12..1011}; GetAdapter -> {AdapterId, AdapterName, CreationTime, Description, FeatureTypes, AutoUpdate, Tags}; UpdateAdapter{AdapterId required, Description, AdapterName, AutoUpdate} — note FeatureTypes is NOT updatable, matching the type's create-only FeatureTypes; DeleteAdapter; ListAdapters paginated on Adapters/NextToken). Recorded behavior for the CloudFormation surface of the type: Ref and GetAtt Arn both yield the adapter ARN in the documented form arn:<partition>:textract:<region>:<account>:/adapters/<AdapterId> (partition, region, account and AdapterId are values from the request/state, the literal segments ':textract:' and ':/adapters/' are fixed text); GetAtt exposes the read-only attributes AdapterId, Arn and CreationTime, and GetAtt CreationTime equals the CreationTime GetAdapter reports for the same adapter; the stack's taggable resource carries both the stack-level tags and the Tags property, so ListTagsForResource(ResourceARN=<the GetAtt Arn>) returns them; an UpdateStack that changes only Description, AutoUpdate and Tags updates the adapter in place (same AdapterId, unchanged CreationTime); DeleteStack removes the adapter, after which GetAdapter(AdapterId=...) is refused with ResourceNotFoundException and ListAdapters no longer lists it. Recorded behavior for the negative class: a FeatureTypes element the type's schema does not allow is caught by early property validation before any adapter is created — the stack settles ROLLBACK_COMPLETE and DescribeEvents records an OperationEvents row with EventType=VALIDATION_ERROR carrying (LogicalResourceId=<the resource's logical id>, ValidationName=PROPERTY_VALIDATION, ValidationStatus=FAILED, ValidationFailureMode=FAIL, ValidationStatusReason="<value> is not a valid enum value. Supported values: [QUERIES]", ValidationPath="/Resources/<logical id>/Properties/FeatureTypes/<index>"). In that message only the offending value and the supported-values list are variable; "is not a valid enum value. Supported values:" is fixed text. The adapter named by the rejected template must not appear in ListAdapters.

Emulator: CreateStack is refused outright. botocore reports An error occurred (ValidationError) when calling the CreateStack operation: Template format error: Unrecognized resource types: [AWS::Textract::Adapter] — i.e. error code ValidationError with the message "Template format error: Unrecognized resource types: [<types>]" (the bracketed type list is the variable part), on a non-2xx response, where AWS answers 200 with a StackId. Because the call never succeeds, none of the downstream behavior above is reachable: no adapter is created, no Ref/GetAtt value is produced, no in-place update or delete happens, and the invalid-FeatureTypes template produces no PROPERTY_VALIDATION event at all (it is rejected for the wrong reason, at the wrong place, with the wrong error).

Why: any client that manages Textract adapters as infrastructure — a CloudFormation template, a CDK app or a nested stack that includes one — cannot deploy at all against the emulator. The failure is also misleading: a client is told its template is malformed ("Template format error") when the template is valid AWS, so retries, template linting and rollback handling all take the wrong branch. The adapter's ARN/Ref contract and the create-only FeatureTypes validation are likewise untestable.

Fix: CloudFormation's template resource-type registry plus a resource handler for AWS::Textract::Adapter. The registry entry must declare the type and its property schema (AdapterName, FeatureTypes create-only with the schema's supported enum values, AutoUpdate, Description, Tags) and its read-only attributes (AdapterId, Arn, CreationTime) so early property validation can emit the PROPERTY_VALIDATION event for a bad FeatureTypes element; the handler must call through to the Textract adapter state (CreateAdapter/GetAdapter/UpdateAdapter/DeleteAdapter) for create/read/update/delete, publish the adapter ARN as Ref/PhysicalResourceId and GetAtt Arn, and propagate stack and property tags.

Traces: cloudformation__textract.deploy-cfn-textract-adapter-round-trip-then-update-and-delete (fails on the first CreateStack of the round-trip template, which also asserts Ref/GetAtt Arn/GetAtt AdapterId/GetAtt CreationTime, GetAdapter read-back, ListTagsForResource by the GetAtt ARN, in-place update and delete-removes-adapter); cloudformation__textract.deploy-cfn-textract-adapter-invalid-feature-type-rejected (fails on the positive-control CreateStack, before it can assert the PROPERTY_VALIDATION row for FeatureTypes=["BOGUS"] and the absence of the adapter after rollback).

## Evidence
Expected (AWS): cf.create_stack(StackName=..., TemplateBody=<template whose Resources contain {"Type": "AWS::Textract::Adapter", "Properties": {"AdapterName": <name>, "FeatureTypes": ["QUERIES"], "AutoUpdate": "DISABLED", ...}}>) -> HTTP 200 with a StackId; DescribeStacks reaches CREATE_COMPLETE; Outputs give Ref == GetAtt Arn == arn:<partition>:textract:<region>:<account>:/adapters/<AdapterId>; textract.get_adapter(AdapterId=<GetAtt AdapterId>) returns the templated AdapterName/Description/FeatureTypes/AutoUpdate/Tags.

Actual (emulator): the CreateStack call is refused — botocore.exceptions.ClientError: An error occurred (ValidationError) when calling the CreateStack operation: Template format error: Unrecognized resource types: [AWS::Textract::Adapter]. Both failing checks abort on this one call (verdict 'error'), so no adapter, no Ref/GetAtt value, no update and no PROPERTY_VALIDATION event are produced.

Fixed text vs variable parts of the emulator's message: "Template format error: Unrecognized resource types: [" + <comma-separated type names from the template> + "]" — the type list is the only variable part. AWS emits no such error for this type at all.

## Steps to Reproduce
1. Build and boot the emulator from the checkout.
2. cf = client("cloudformation"); textract = client("textract").
3. template = {"AWSTemplateFormatVersion": "2010-09-09", "Resources": {"Adapter": {"Type": "AWS::Textract::Adapter", "Properties": {"AdapterName": "<unique-name>", "FeatureTypes": ["QUERIES"], "AutoUpdate": "DISABLED", "Description": "v1 description", "Tags": [{"Key": "k", "Value": "v1"}]}}}, "Outputs": {"AdapterRef": {"Value": {"Ref": "Adapter"}}, "AdapterArn": {"Value": {"Fn::GetAtt": ["Adapter", "Arn"]}}, "AdapterId": {"Value": {"Fn::GetAtt": ["Adapter", "AdapterId"]}}, "AdapterCreationTime": {"Value": {"Fn::GetAtt": ["Adapter", "CreationTime"]}}}}
4. cf.create_stack(StackName="<unique-stack>", TemplateBody=json.dumps(template), Tags=[{"Key": "sim2real", "Value": "<unique-stack>"}]) -> observe ValidationError "Template format error: Unrecognized resource types: [AWS::Textract::Adapter]" instead of a StackId.
5. Repeat step 4 with FeatureTypes=["BOGUS"]: AWS accepts the CreateStack and settles the stack ROLLBACK_COMPLETE with a VALIDATION_ERROR/PROPERTY_VALIDATION event at /Resources/Adapter/Properties/FeatureTypes/0; the emulator refuses the call with the same unrecognized-resource-type ValidationError.
6. After a successful create, also check: textract.list_adapters / textract.get_adapter(AdapterId=<GetAtt AdapterId>), textract.list_tags_for_resource(ResourceARN=<GetAtt Arn>), cf.update_stack with only Description/AutoUpdate/Tags changed (same AdapterId and CreationTime expected), then cf.delete_stack and expect GetAdapter to answer ResourceNotFoundException.
