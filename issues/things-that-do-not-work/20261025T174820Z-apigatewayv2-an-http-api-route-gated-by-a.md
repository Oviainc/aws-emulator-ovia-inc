=== Cause 1 of 1: a CUSTOM-authorized HTTP API route on a deployed stage never serves, so the REQUEST authorizer result cache and its TTL are never exercised ===
AWS: Smithy (apigatewayv2): CreateAuthorizer input AuthorizerResultTtlInSeconds targets IntegerWithLengthBetween0And3600 (@range min 0, max 3600), with AuthorizerType (REQUEST), AuthorizerUri, AuthorizerPayloadFormatVersion, EnableSimpleResponses and IdentitySource; CreateAuthorizer POST /v2/apis/{ApiId}/authorizers success code 201. CreateDeployment POST /v2/apis/{ApiId}/deployments 201 and CreateStage POST /v2/apis/{ApiId}/stages 201 (DeploymentId member) are the control-plane calls that publish the stage. The data-plane behaviour itself is recorded behavior only (not modeled in Smithy): after CreateApi(ProtocolType=HTTP) -> CreateAuthorizer(AuthorizerType=REQUEST, IdentitySource=["$request.header.Authorization"], AuthorizerResultTtlInSeconds=N) -> CreateIntegration(AWS_PROXY, PayloadFormatVersion 2.0) -> CreateRoute(AuthorizationType=CUSTOM, AuthorizerId=...) -> CreateDeployment -> CreateStage(StageName="$default", DeploymentId=...), a GET of the stage's own invoke URL carrying the identity-source header is served HTTP 200 with the integration's response body. On that served traffic AWS then applies the documented cache semantics (https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api-lambda-authorizer.html, authorizerResultTtlInSeconds): with a non-zero TTL the authorizer Lambda is invoked once for a cold request, zero times for repeats with the same identity-source value inside the TTL window, once more on the first request after the TTL elapses (which re-caches), and with a TTL of 0 caching is disabled so the authorizer is invoked on every single request.
Emulator: the invoke URL the emulator itself announces for that api id and stage never serves the expected response. The check's readiness gate requires both authorizer-protected routes (the TTL route and its TTL=0 twin, same API, same Lambda, same identity source) to answer 200 with the integration's body continuously before it starts measuring; that gate never goes clean, so the check spins in its poll loop (0.5 s interval) and is killed at the suite's 60 s cap, reported as `Error: Check timed out after 60.0s`. Because nothing is ever served, not one authorizer invocation reaches the independent side channel, and the cache legs (cold = 1 invocation, inside-TTL = 0 invocations, first request after expiry = exactly 1 invocation, then cached again, TTL=0 twin = 1 invocation per request) cannot be observed at all.
Why: a client that sizes AuthorizerResultTtlInSeconds to trade authorizer cost against credential-revocation latency gets no observable behaviour from the emulator — an emulator that caches forever, never caches, or ignores the TTL value entirely is indistinguishable from a correct one, and the control plane's echoed authorizerResultTtlInSeconds is the only evidence the setting exists. Any request to a CUSTOM-authorized HTTP API route gets no answer at all, so authorization gating, denial, and backend dispatch for that route are all unreachable.
Fix: the execute-api data-plane listener for HTTP APIs and the invoke-URL host/path the control plane announces for a stage — specifically route-key matching and stage resolution for a route whose AuthorizationType is CUSTOM, invocation of the REQUEST authorizer with its IdentitySource values, and the authorizer-result cache keyed per identity-source value whose entries must expire after AuthorizerResultTtlInSeconds and must not be written at all when that value is 0.
Traces: apigatewayv2.deep-apigatewayv2-3-stagesem-request-authorizer-cache-expires-after-ttl.

1. Boot the emulator from this checkout and point an SDK/CLI at it.
2. Create a Lambda that returns {"isAuthorized": true} when event["type"] == "REQUEST" and otherwise returns {"statusCode": 200, "body": <marker>}, and allow apigateway.amazonaws.com to invoke it for arn:aws:execute-api:<region>:<account>:<api-id>/*.
3. apigatewayv2 CreateApi(Name=..., ProtocolType="HTTP").

6. apigatewayv2 CreateRoute(ApiId=<api>, RouteKey="GET /ttl", Target=integrations/<id>, AuthorizationType="CUSTOM", AuthorizerId=<ttl-20 authorizer>) and CreateRoute(RouteKey="GET /nottl", ..., AuthorizerId=<ttl-0 authorizer>).
