# bedrock: an evaluation job reports Completed but performs no evaluation — nothing is ever written under outputDataConfig.s3Uri, so the enforced guardrail's blocked-output message never appears in the results

> _Note: this issue was identified against the code base at commit `5c5f06f6d31e143100ebeb43c7fd4bbab24c7d6b`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateEvaluationJob

## Description
ONE net-new root cause on the Bedrock control plane's evaluation-job execution path.

Scope notes, so this is not closed as a duplicate: it is NOT 20261026T032047Z-bedrock-batch-inference-job-performs-no-inference-nothing-is.md (that issue is CreateModelInvocationJob / ModelInvocationJobRecord — a different operation, a different state record and a different output contract), and it is NOT cause 1 of 20261024T175106Z-bedrock-the-account-enforced-guardrail-configuration-is-stored.md (that cause is the bedrock-runtime InvokeModel/Converse path not consulting the account-enforced guardrail singleton and not emitting amazon-bedrock-guardrailAction). Fixing either of those leaves the cause below exactly as it is: an evaluation job has no work step at all, so there is no inference for any guardrail — per-request or account-enforced — to be applied to, and no result file for a caller to read.

Cause 1 of 1: a submitted evaluation job is a status record and nothing else. It never runs its configured datasetMetricConfigs against the model named in inferenceConfig, never writes any object under outputDataConfig.s3Uri, and still advances to status 'Completed' on a timer.

AWS: Smithy com.amazonaws.bedrock#CreateEvaluationJob takes a required outputDataConfig -> EvaluationOutputDataConfig whose required s3Uri is documented "The Amazon S3 URI where the results of the evaluation job are saved" (the structure itself: "The Amazon S3 location where the results of your evaluation job are saved"), and the request member is documented "Contains the configuration details of the Amazon S3 bucket for storing the results of the evaluation job". The required evaluationConfig -> AutomatedEvaluationConfig carries a required datasetMetricConfigs (EvaluationDatasetMetricConfig: required taskType, required dataset, required metricNames, e.g. Builtin.Toxicity over Builtin.RealToxicityPrompts), and the required inferenceConfig names the model whose responses are scored. EvaluationJobStatus is [InProgress, Completed, Failed, Stopping, Stopped, Deleting]; a job AWS reports 'Completed' has run the dataset through the model, scored the configured metrics, and left result objects under the output prefix. Recorded behavior: with an account-enforced guardrail installed over the evaluated model (PutEnforcedGuardrailConfiguration with modelEnforcement.includedModels naming it), the guardrail is applied to the job's inference, so records it intervened on carry the guardrail's configured blockedOutputsMessaging string VERBATIM in the job's S3 output — the string is the caller's own configured text, not model-generated content.

Emulator: CreateEvaluationJob validates the request, mints a job id/ARN and stores an EvaluationJobRecord holding only identity, description, roleArn, key id, applicationType, job type, the echoed evaluationConfig/inferenceConfig/outputDataConfig, tags, status=InProgress and the due-instants for the Completed/Stopped/deleted transitions (services/service-com-amazonaws-bedrock-amazonbedrockcontrolplaneservice/src/ops/create_evaluation_job.rs:294-326). Nothing on that path, and nothing in the clock-driven transition to 'Completed', opens the dataset, invokes the evaluated model, scores a metric, or PUTs a single object under outputDataConfig.s3Uri. Replay symptom: after the job reaches 'Completed' (that assertion passed), ListObjectsV2/GetObject over the configured eval-output/ prefix yields nothing containing the configured blockedOutputsMessaging, and the check fails with "AssertionError: expected the enforced guardrail's blocked-output message to appear in the evaluation job's S3 output at least once, indicating the guardrail intervened during evaluation". The emulator answered 2xx at every step; the output side is simply empty.

Why: for evaluation jobs the result IS the S3 output, not the response body. A client that waits for 'Completed' and then reads the report out of its output prefix finds nothing there — every downstream step (parsing the per-metric jsonl report, reading scores, comparing two models, gating a release on Builtin.Toxicity) silently processes zero rows instead of failing loudly, and a job that did no work is indistinguishable from a job that evaluated the whole dataset perfectly. Worse for safety review: an operator verifying that an account-enforced guardrail actually intervened during an evaluation sees no intervention evidence at all, which reads as "the guardrail found nothing to block" rather than "no inference happened".

Fix: the evaluation-job execution step in this crate — the CreateEvaluationJob handler's job submission plus EvaluationJobRecord and the settle/clock path in state.rs that moves the job to a terminal status. The transition into 'Completed' must actually run the configured dataset through the model named in inferenceConfig (applying any account-enforced guardrail, so intervened records carry the configured blockedOutputsMessaging verbatim) and write the result objects under outputDataConfig.s3Uri, so that a job reported 'Completed' has output that agrees with its configuration; a job whose dataset or output location cannot be used should take the modelled 'Failed' path with failureMessages rather than reporting 'Completed' with nothing done.

Traces: failing check bedrock.e2e-evaluation-job-with-guardrail-results-teardown (GROUP e2e). Code for the fixer: services/service-com-amazonaws-bedrock-amazonbedrockcontrolplaneservice/src/ops/create_evaluation_job.rs:294-336 (the stored record — no dataset read, no inference, no S3 write) and the EvaluationJobRecord / evaluation-job clock in services/service-com-amazonaws-bedrock-amazonbedrockcontrolplaneservice/src/state.rs (the status move is the only thing the completion does).
