# Elastic Beanstalk application versions stay Status='Unprocessed' forever, so no version is ever deployable (15 more checks blocked)

> _Note: this issue was identified against the code base at commit `9ba218dfac78ec8aaaf32d0b8457457c6bd04b91`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateApplicationVersion

## Description
ONE root cause, grounded in 15 failing behavioral checks of this suite that no filed issue carries. NOTE: three open issues describe the SAME fault for other checks — 20261024T015947Z-elasticbeanstalk-elastic-beanstalk-application-version-environment-state-machines-never.md (its Cause 1), 20261025T051801Z-elasticbeanstalk-elastic-beanstalk-createapplicationversion-process-true-leaves-the-version.md and 20261029T065537Z-elasticbeanstalk-elastic-beanstalk-createapplicationversion-process-true-still-leaves-the.md. The suite did not mark any of the 15 checks below as OWNED by them, so their replay keys are unclaimed and are filed here; a fixer closing this issue must make all 15 pass, and should expect the fix to be the same code path as those issues.

Cause 1 of 1: CreateApplicationVersion leaves the version permanently at Status='Unprocessed', with or without Process=true.
AWS: Smithy: CreateApplicationVersion -> ApplicationVersionDescriptionMessage{ApplicationVersion}, whose Status targets the enum ApplicationVersionStatus with values Processed | Unprocessed | Failed | Processing | Building. Recorded behavior: a version created from a valid source bundle advances to 'Processed' (promptly, and immediately when Process=true is requested), and only a Processed version can be deployed to an environment; DescribeApplicationVersions reports that terminal status.
Emulator: DescribeApplicationVersions keeps reporting Status='Unprocessed' for the whole poll window of every one of these checks — the status never leaves its initial value, so no version ever becomes deployable. Two of the 15 checks do not even reach an assertion: their version-processed wait (180s, 5s interval) is still polling when the harness kills the check at its 60s budget.
Why: every client that uploads a bundle and waits for the version to become deployable hangs forever. Downstream of it NOTHING works: deploying a version, replacing the served content, eb-extensions, option settings becoming environment variables, enhanced health, CNAME swaps, concurrent-update arbitration, ComposeEnvironments and terminate-frees-the-prefix all depend on a Processed version and are blocked by this single cause.
Fix: the application-version processing state transition in the CreateApplicationVersion handler and the version state it writes (services/service-com-amazonaws-elasticbeanstalk-awselasticbeanstalkservice/src/ops/create_application_version.rs plus the clock-owed transitions in the service's state module, alongside STATUS_TRANSITION_SPAN which already models the environment-status equivalents).
Traces: elasticbeanstalk.compose-environments-concurrent-launch-no-duplicate-envs, elasticbeanstalk.compose-environments-insufficient-privileges-denied (harness timeout inside _wait_for_version_processed), elasticbeanstalk.e2e-compose-multi-tier-application-environments (harness timeout inside _wait_for_version_processed), elasticbeanstalk.e2e-compose-swap-cnames-traffic-consequence, elasticbeanstalk.eb-abort-environment-update-withholds-the-instance-replacement, elasticbeanstalk.eb-concurrent-update-environment-yields-a-single-winner, elasticbeanstalk.eb-deployed-application-serves-its-own-content-over-http, elasticbeanstalk.eb-deploying-a-new-application-version-replaces-the-served-content, elasticbeanstalk.eb-ebextensions-config-files-really-run-on-the-instance, elasticbeanstalk.eb-ebextensions-option-setting-loses-to-the-direct-environment-setting, elasticbeanstalk.eb-enhanced-health-degrades-when-the-application-returns-http-500, elasticbeanstalk.eb-failed-version-deploy-leaves-the-previous-version-serving, elasticbeanstalk.eb-option-setting-becomes-a-real-environment-variable-in-the-application, elasticbeanstalk.eb-swap-environment-cnames-swaps-which-application-answers, elasticbeanstalk.eb-terminated-environment-stops-serving-and-frees-its-cname-prefix.
