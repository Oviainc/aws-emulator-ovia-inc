# Redshift namespace/reserved-node/IdC-application/HSM refusals are emulator-authored or missing: wrong not-found and already-exists wording, wrong tag fault, an accepted IdC create AWS denies, duplicate tag keys accepted and no HSM configuration quota (8 causes)

> _Note: this issue was identified against the code base at commit `5b71589754f95f05f88c1a0ee9ccd691bbc5f701`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateHsmConfiguration

## Description
Eight distinct root causes, all in the redshift service. Six are refusals whose code or message text the emulator authors itself instead of reproducing AWS's; two are requests AWS refuses that the emulator accepts (over-permissive). Each cause is a separate handler/validation site and must be closed separately. Open issues 20261029T192501Z-redshift-cluster-not-found-refusals-render-one-generic.md, 20261029T192501Z-redshift-reserved-node-and-catalog-refusals-wrong-wording.md, 20261029T192501Z-redshift-parameter-group-hsm-snapshot-copy-grant-and.md and 20261029T192501Z-redshift-resource-policy-idc-application-and-event-subscription.md describe neighbouring families but carry none of the replay keys below.

Cause 1 of 8: RegisterNamespace/DeregisterNamespace render the generic cluster-not-found template instead of their own wording. AWS: for a ClusterIdentifier that does not exist both fail `ClusterNotFound` with a message whose fixed text is "Cluster " + the requested cluster identifier + " can't be found." — note this differs from DescribeClusters' "Cluster <id> not found." Smithy: RegisterNamespace/DeregisterNamespace errors = ClusterNotFoundFault (errorKind client, httpError 404, awsQueryError code `ClusterNotFound`, 404), InvalidClusterStateFault, InvalidNamespaceFault. Emulator: the right code with one generic message, "Cluster not found: <id>" — different fixed text, identifier in a different position. Why: a client (or operator runbook) matching the operation's documented wording never matches, and the emulator cannot be used to validate message-driven error handling. Fix: the RegisterNamespace and DeregisterNamespace handlers' not-found refusal, which must carry this operation family's wording rather than the shared template. Traces: redshift.namespace-deregister-invalid-namespace-blocked, redshift.namespace-error-semantics, redshift.namespace-invalid-state-and-namespace-errors.

Cause 2 of 8: the ReservedNodeOfferingNotFound message is emulator-authored. AWS: PurchaseReservedNodeOffering with a syntactically valid but unknown ReservedNodeOfferingId fails `ReservedNodeOfferingNotFound` with a message whose fixed text is "ReservedNodeOfferingId " + the requested offering id + " not found." Smithy: PurchaseReservedNodeOffering errors include ReservedNodeOfferingNotFoundFault (errorKind client, httpError 404, awsQueryError code `ReservedNodeOfferingNotFound`, 404). Emulator: the right code with "Reserved node offering not found: '<id>'." — different fixed text and the id quoted. Why: wording is the only thing a caller can key on to tell this refusal apart from the other reserved-node faults; four separate purchase/lookup checks all diverge on it. Fix: the PurchaseReservedNodeOffering (and reserved-node-offering lookup) handler's not-found refusal message. Traces: redshift.purchase-reserved-node-offering-duplicate-rejected, redshift.purchase-reserved-node-offering-invalid-id-rejected, redshift.purchase-reserved-node-offering-not-found-rejected, redshift.reserved-node-offering-not-found-rejected.

Cause 3 of 8: GetReservedNodeExchangeOfferings' identifier-format refusal is emulator-authored. AWS: a ReservedNodeId that is not a UUID is rejected at parameter validation with `InvalidParameterValue` and the fixed message "The parameter ReservedNodeId is not a valid identifier. Identifiers must be valid UUID strings of the form 'xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx' where 'x' is an ASCII character a-f or 0-9." (fixed text only — the offending value is NOT interpolated). Smithy: GetReservedNodeExchangeOfferings input ReservedNodeId is a plain required String with no pattern, and the modeled errors are DependentServiceUnavailableFault/InvalidReservedNodeStateFault/ReservedNodeAlreadyMigratedFault/ReservedNodeNotFoundFault/ReservedNodeOfferingNotFoundFault/UnsupportedOperationFault, so this is the service's own parameter refusal (recorded behavior). Emulator: the right code with "Invalid value for ReservedNodeId: '<id>'. ReservedNodeId must be a universally unique identifier." Fix: the GetReservedNodeExchangeOfferings handler's ReservedNodeId validation message. Traces: redshift.reserved-node-exchange-offerings-and-config-options.

Cause 4 of 8: Qev2IdcApplicationAlreadyExists is keyed on the name and its message is emulator-authored. AWS: an account holds at most ONE Query Editor v2 IdC application, so while one exists every CreateQev2IdcApplication — same name or a fresh one — fails `Qev2IdcApplicationAlreadyExists` with the fixed message "You already have a Qev2IdcApplication." (no variable parts), and succeeds again once the existing one is deleted. Smithy: CreateQev2IdcApplication errors include Qev2IdcApplicationAlreadyExistsFault (httpError 400, awsQueryError code `Qev2IdcApplicationAlreadyExists`). Emulator: the right code but the message "Amazon Redshift Query Editor (QEV2) IAM Identity Center application already exists: <name>", i.e. a name-keyed refusal rather than the account-singleton one. Why: a client reading the message (or probing with a fresh name) concludes the name is taken and retries with another, which AWS also refuses — the singleton semantics are unobservable. Fix: the CreateQev2IdcApplication handler — refuse on the existence of any Qev2 application for the account and emit AWS's fixed text. Traces: redshift.qev2-idc-application-duplicate-create-rejected.

Cause 5 of 8: a reserved `aws:`-prefixed tag key on CreateRedshiftIdcApplication gets the wrong fault. AWS: a tag whose key uses the reserved `aws:` prefix is rejected with `InvalidParameterValue` and the fixed message "Caller is an end user and not allowed to mutate system tags", and no application is created. Smithy: CreateRedshiftIdcApplication models InvalidTagFault (awsQueryError code `InvalidTagFault`, 400) among its errors, but the reserved-prefix case is the service's InvalidParameterValue (recorded behavior) — the two are distinct refusals. Emulator: `InvalidTagFault`. Why: a caller distinguishing "your tag set is malformed" from "you may not write system tags" branches wrongly, e.g. by retrying with a sanitized value instead of dropping the key. Fix: the reserved-tag-prefix check in the CreateRedshiftIdcApplication handler's tag validation. Traces: redshift.redshift-idc-application-invalid-tag-rejected.

Cause 6 of 8: CreateRedshiftIdcApplication accepts a nonexistent IAM Identity Center instance. AWS: Redshift calls into IAM Identity Center to resolve IdcInstanceArn; for a well-formed but nonexistent instance the call is denied and surfaces as `DependentServiceAccessDenied` (Smithy: DependentServiceAccessDeniedFault, errorKind client, httpError 403, awsQueryError code `DependentServiceAccessDenied`, 403), relaying the IdC denial — message template: "User: " + the caller's own principal ARN + " is not authorized to perform: sso:CreateApplication on resource: arn:aws:sso::*:application/<instance-suffix>/* because no resource-based policy allows the sso:CreateApplication action" (the principal and instance suffix come from the request/caller; the per-request "(Service: ..., Request ID: ...)" suffix is not part of it) — and no RedshiftIdcApplication is left behind. Emulator: the call SUCCEEDS (HTTP 200) and creates the application. Why: an over-permissive create: the emulator fabricates an IdC-backed application with no backing instance, so a client's IdC wiring appears to work and every downstream auth flow against it silently diverges. Fix: the CreateRedshiftIdcApplication handler must resolve IdcInstanceArn against IAM Identity Center state and refuse with DependentServiceAccessDenied when it cannot. Traces: redshift.create-redshift-idc-application-dependent-service-rejected.

Cause 7 of 8: CreateHsmConfiguration accepts duplicate tag keys. AWS: a request carrying the same tag Key twice is rejected with `InvalidTagFault` (Smithy: CreateHsmConfiguration errors include InvalidTagFault, httpError 400, awsQueryError code `InvalidTagFault`) and the message template "Tag key: '" + the duplicated key from the request + "' has been used more than once. You must use a unique set of keys per api call."; the configuration is never created, so DescribeHsmConfigurations for it raises HsmConfigurationNotFoundFault with "HSM configuration '<id>' not found." Emulator: HTTP 200 with both duplicate tags echoed in the HsmConfiguration payload. Why: the request is stored with a tag set AWS would never persist, so tag-driven cost allocation and policy conditions differ from production, and the modeled InvalidTagFault leg is dead code. Fix: duplicate-key tag validation in the CreateHsmConfiguration handler (shared Redshift tag validation). Traces: redshift.hsm-configuration-duplicate-and-quota-errors, redshift.hsm-configuration-error-semantics.

Cause 8 of 8: HSM configurations have no account quota. AWS: once the account's HSM configuration quota is exhausted, CreateHsmConfiguration fails `HsmConfigurationQuotaExceededFault` (Smithy: HsmConfigurationQuotaExceededFault, httpError 400, awsQueryError code `HsmConfigurationQuotaExceededFault`) with the message template "Cannot create more than " + the number of configurations the account holds at the moment of refusal + " HSM configurations.", the over-quota configuration is NOT visible in DescribeHsmConfigurations, and a create succeeds again after one is deleted. Emulator: creates are accepted without bound — 40 and 60 consecutive creates never produce the fault. Why: an emulator with no quota lets capacity-planning and quota-handling code paths (catch the fault, delete, retry) go untested and silently diverge from production. Fix: an HSM-configuration quota in the redshift service state plus the quota check in the CreateHsmConfiguration handler. Traces: redshift.hsm-configuration-quota-exceeded-blocked, redshift.hsm-configuration-duplicate-and-quota-errors.
