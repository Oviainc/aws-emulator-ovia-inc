# events__lambda__sns: a Lambda handler cannot call EventBridge — the python runtime provides no AWS SDK, so the events:PutEvents permission-boundary differential never resolves and the check exhausts its budget

> _Note: this issue was identified against the code base at commit `4ea4135ffc45124de73d742abfb17fa157c26a91`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
Invoke

## Description
This issue carries 1 net-new root cause. It must be closed before submitting.

Cause 1 of 1: a python3.x Lambda handler that imports the AWS SDK and calls EventBridge PutEvents never runs its SDK call, so neither the permitted leg (role WITH events:PutEvents) nor the denied leg (role WITHOUT it) ever produces the outcome AWS produces, and the check runs out its 60s budget inside the positive control's retry loop.

AWS: the managed Python runtimes (python3.12 here) bundle boto3/botocore in the runtime image, so `import boto3` resolves for a deployment package that contains only the handler module, and the runtime injects the function's execution-role credentials into the handler's environment. A handler running under a role whose inline policy allows `events:PutEvents` on `*` therefore gets a successful PutEvents: Smithy (com-amazonaws-eventbridge-awsevents, PutEvents) models `Entries` @required with @length min 1 max 10 and an output carrying `FailedEntryCount` (default 0) plus one `PutEventsResultEntry` per entry, so an accepted entry yields FailedEntryCount 0 and an `EventId`, and the event is then matched against the bus's rules and delivered to the rule's SQS target. Under a role that does NOT allow `events:PutEvents`, the same call is refused by IAM: PutEvents models no authorization error of its own (its only modeled error is InternalException, 500), so the refusal is EventBridge's service-common IAM denial — HTTP 400 with error code `AccessDeniedException` and an implicit-deny message whose fixed text is `User: <principal-arn> is not authorized to perform: events:PutEvents on resource: <bus-arn> because no identity-based policy allows the events:PutEvents action`, where the principal ARN (the assumed-role session of the function's execution role), the action `events:PutEvents` and the bus ARN are values taken from the request and the caller's identity, not literals. botocore surfaces that as a ClientError whose `response['Error']['Code']` is `AccessDeniedException`; the handler catches it and reports it in its own payload, and the Invoke itself still answers 200 with no `x-amz-function-error` header. No event reaches the bus on that leg, so the denied rule's queue stays empty. Recorded behavior: on AWS both legs settle well inside the suite's 60s budget — the permitted invoke returns {"ok": true, "failed_count": 0}, the denied invoke returns {"ok": false, "error_code": "AccessDeniedException"}, the permitted marker appears in the allowed rule's queue, and the denied marker never appears.

Emulator: the check is cut off with `Error: Check timed out after 60.0s`. CreateRole, AttachRolePolicy, PutRolePolicy, CreateFunction (python3.12), PutRule, PutTargets and SetQueueAttributes are all accepted, and Invoke answers 200, but the handler's `import boto3` is not satisfiable in the emulator's guest interpreter: the invocation comes back with `FunctionError: Unhandled` and the payload `{"errorMessage": "Unable to import module '<handler-module>': No module named 'boto3'", "errorType": "Runtime.ImportModuleError", "requestId": "<uuid>", "stackTrace": []}` — fixed text `Unable to import module '` … `': No module named 'boto3'` and `Runtime.ImportModuleError`, with the module name taken from the request's `Handler` and the requestId a per-invocation value. Because that payload carries no `ok` key, the check's positive control `_invoke_with_retry` re-invokes every 5s for its full 60s window and never sees `ok` true, so the run budget ends before the denied leg or either queue poll is ever reached: the permitted PutEvents, the AccessDeniedException refusal of the unpermitted one, and the EventBridge→SQS marker differential are all ungraded.

Why: a client relying on AWS's behavior gets two things wrong. First, no emulated function can call any AWS service from inside the handler, so every in-function integration (PutEvents to a bus, SNS Publish, SQS SendMessage) fails with an import crash instead of doing the work — the function appears to run and return 200 while performing nothing. Second, and worse for authorization testing, a negative IAM test cannot distinguish "the call was refused with AccessDeniedException" from "the call was never made": both the role that should be denied and the role that should be allowed produce the identical Runtime.ImportModuleError payload, so a least-privilege execution role can neither be validated nor falsified against this emulator, and the absence of the event on the denied rule's queue is indistinguishable from a dead delivery path.

Fix: the Lambda execution engine's guest environment — the python runtime's module allow-list and import path, and the invocation bootstrap that builds the handler's environment, under services/service-com-amazonaws-lambda-awsgirapiservice/src/state/execution/ (python guest + bootstrap) — must expose an AWS SDK surface that dispatches to the emulator's own front doors under the function's execution-role identity, and that dispatch must pass through the normal IAM authorization of the called operation (here EventBridge PutEvents) so an un-permitted call is refused with code AccessDeniedException rather than silently succeeding. The same underlying cause is already filed for other headings; the closest open issue under THIS heading is 20261105T081727Z-events-lambda-sns-an-invoked-function-writes-nothing.md, whose Cause 2 names this check, but its replay key points at a different frame and the suite does not treat this failure as covered by it — related open issues 20261105T081225Z-events-lambda-ssm-the-lambda-python-runtime-has.md and 20261105T094343Z-events-lambda-sqs-the-lambda-python-runtime-provides.md describe the same guest-runtime gap for other service headings. Fixing the guest SDK alone is not sufficient for this check: the permitted leg's event must also be matched by the rule and delivered to the SQS target (see open issue 20261104T044826Z-events-lambda-sns-eventbridge-rules-and-sns-subscriptions-never-deliver-to.md for that delivery path), so both must hold before the marker differential grades.

## Evidence
Cause 1 — events__lambda__sns.lambda-role-missing-events-permission-putevents-denied: `Error: Check timed out after 60.0s`.

Expected (AWS): the function invoked under the role with the inline `{"Effect":"Allow","Action":"events:PutEvents","Resource":"*"}` statement returns 200 with no FunctionError and the payload {"ok": true, "failed_count": 0}; the twin function invoked under the role with only AWSLambdaBasicExecutionRole returns 200 with no FunctionError and the payload {"ok": false, "error_code": "AccessDeniedException"} (HTTP 400 / `AccessDeniedException` on the inner PutEvents, message fixed text `User: <arn> is not authorized to perform: events:PutEvents on resource: <bus-arn> because no identity-based policy allows the events:PutEvents action`, with principal ARN and bus ARN taken from the caller and request); the permitted marker then appears in the allowed rule's queue and the denied marker never appears in the denied rule's queue.

Actual (emulator): Invoke answers 200 but with `FunctionError: Unhandled` and the payload {"errorMessage": "Unable to import module '<handler-module>': No module named 'boto3'", "errorType": "Runtime.ImportModuleError", "requestId": "<uuid>", "stackTrace": []}. That payload has no `ok` member, so the check's `_invoke_with_retry` loop (re-invoking every 5s for 60s) never satisfies `last.get("ok")` and the 60s check budget expires there — the denied-leg assertion on error_code == "AccessDeniedException" and both queue polls are never executed. The identical Runtime.ImportModuleError text is captured verbatim on the lambda__sns__sqs and events__lambda__sns__sqs in-function SDK checks of this same suite, confirming the guest runtime, not this check, is the blocker.

Smithy consulted: com-amazonaws-eventbridge-awsevents PutEvents — input Entries @required @length(min 1, max 10), output FailedEntryCount (Integer, default 0) + Entries (PutEventsResultEntryList); modeled errors: InternalException only (server, 500), so the authorization refusal is the service-common IAM denial rather than an operation-modeled error.
