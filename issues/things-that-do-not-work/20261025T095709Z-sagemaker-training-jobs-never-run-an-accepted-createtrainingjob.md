# SageMaker training jobs never run: an accepted CreateTrainingJob ends Failed with a no-container-runtime reason and writes no model artifact, blocking every train-then-deploy flow

> _Note: this issue was identified against the code base at commit `a348f7a60ca5edb956d11f71c3f040d86e771b20`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateTrainingJob

## Description
This issue bundles ONE root cause; it must be closed before submitting.

Cause 1 of 1: a well-formed CreateTrainingJob is accepted and the job is describable, but it is never executed — DescribeTrainingJob reports TrainingJobStatus 'Failed' and no model artifact is written under OutputDataConfig.S3OutputPath, so no SageMaker flow that depends on a trained model (CreateModel from the artifact, EndpointConfig/Endpoint deploy, InvokeEndpoint, batch transform, inference-recommender scaling advice, model-package registration) can reach its first observable step.

AWS: Smithy (services/service-com-amazonaws-sagemaker-sagemaker): CreateTrainingJob requires TrainingJobName (@length 1-63, pattern ^[a-zA-Z0-9](-*[a-zA-Z0-9]){0,62}$), RoleArn, OutputDataConfig and takes AlgorithmSpecification/ResourceConfig/StoppingCondition/InputDataConfig/HyperParameters; it returns only TrainingJobArn and models ResourceInUse, ResourceLimitExceeded and ResourceNotFound (all 400). DescribeTrainingJob models ModelArtifacts, TrainingJobStatus and SecondaryStatus as REQUIRED output members, plus TrainingStartTime/TrainingEndTime/TrainingTimeInSeconds/FinalMetricDataList and an optional FailureReason. Recorded behavior: AWS drives an accepted, well-formed job through InProgress to TrainingJobStatus 'Completed' (SecondaryStatus 'Completed'), materializes the model artifact object under the declared OutputDataConfig.S3OutputPath, and DescribeTrainingJob returns ModelArtifacts.S3ModelArtifacts pointing at that object (an s3:// URI under the caller's own output bucket/prefix). Downstream, CreateModel referencing that artifact plus the algorithm/serving image yields an Endpoint that reaches InService and serves InvokeEndpoint predictions.

Emulator: the Create call succeeds, then the job goes straight to a terminal TrainingJobStatus 'Failed' with FailureReason (example text) "This emulator has no container runtime, so the training job's algorithm image was never started and no model artifacts were written to the output S3 location". No object appears under the declared S3 output prefix, so ModelArtifacts carries no usable artifact and every subsequent step of each check is unreachable.

Why: a client that polls DescribeTrainingJob for 'Completed' (the documented happy path, and what every SDK waiter and the SageMaker Python SDK's Estimator.fit does) always takes the failure branch, so the entire train -> CreateModel -> CreateEndpointConfig -> CreateEndpoint -> InvokeEndpoint path is unusable. Worse for test fidelity: because the terminal status is 'Failed' for a perfectly valid request, a scenario that deliberately breaks something (an unsupported ContentType the container must refuse, a deleted model artifact that must surface an S3 failure reason, an under-permissioned role) cannot establish its positive control, so a REAL refusal and a never-executed job are indistinguishable. Inference Recommender / scaling-configuration advice likewise has no endpoint to reference.

Fix: the training-job execution path in SageMaker state — the CreateTrainingJob handler and the job state machine read back by DescribeTrainingJob must advance an accepted job through InProgress to Completed (setting SecondaryStatus, SecondaryStatusTransitions, TrainingStartTime/TrainingEndTime), synthesize a model artifact object at the declared OutputDataConfig.S3OutputPath in S3, and return ModelArtifacts.S3ModelArtifacts pointing at it, so that CreateModel/CreateEndpoint and the runtime serving path downstream have a real artifact to consume. Files: services/service-com-amazonaws-sagemaker-sagemaker/src/ops/create_training_job.rs, .../src/ops/describe_training_job.rs, .../src/state.rs. Related but NOT the same cause: 20261022T120642Z-sagemaker-createtrainingjob-stub.md asserts CreateTrainingJob is an unimplemented scaffold stub — in this replay the handler answered and persisted the job, so what is missing is its execution, not its acceptance; and 20261024T160943Z-sagemaker-runs-no-job-work-processing-pipeline-step.md covers processing / pipeline-step / hyperparameter-tuning / AutoML execution and explicitly excludes the training-job surface.

Traces: sagemaker.deploy-endpoint-cfn-then-invoke-succeeds, sagemaker.deploy-model-endpoint-cfn-serves-inference, sagemaker.e2e-model-package-to-endpoint-serving-flow, sagemaker.get-scaling-configuration-recommendation-references-endpoint, sagemaker.sagemaker-invoke-with-an-unsupported-content-type-rejected-by-the-model-container.

## Evidence
All five surviving sagemaker checks stop at the same assertion on the training job's terminal status, with the emulator's own FailureReason as the message:
- sagemaker.deploy-endpoint-cfn-then-invoke-succeeds: `assert train_desc["TrainingJobStatus"] == "Completed", train_desc.get("FailureReason")` -> AssertionError: This emulator has no container runtime, so the training job's algorithm image was never started and no model artifacts were written to the output S3 location
- sagemaker.deploy-model-endpoint-cfn-serves-inference: `assert job["TrainingJobStatus"] == "Completed"` in _train_xgboost_model -> AssertionError: training job <name> did not complete: Failed / This emulator has no container runtime, so the training job's algorithm image was never started and no model artifacts were written to the output S3 location
- sagemaker.e2e-model-package-to-endpoint-serving-flow: `assert train_status == "Completed"` -> AssertionError: training job did not complete: This emulator has no container runtime, ...
- sagemaker.get-scaling-configuration-recommendation-references-endpoint: `assert training_job["TrainingJobStatus"] == "Completed"` -> AssertionError: training job did not complete: Failed (This emulator has no container runtime, ...)
- sagemaker.sagemaker-invoke-with-an-unsupported-content-type-rejected-by-the-model-container: `assert train_desc["TrainingJobStatus"] == "Completed"` -> AssertionError: prerequisite training job failed, so there is no container to interrogate: "This emulator has no container runtime, ..."

Expected (AWS): TrainingJobStatus 'Completed' and DescribeTrainingJob.ModelArtifacts.S3ModelArtifacts naming an object that exists under the request's OutputDataConfig.S3OutputPath. Actual (emulator): TrainingJobStatus 'Failed', FailureReason as above, output prefix empty. Status/code note: the Create and Describe calls themselves return 200 — the divergence is in the job's terminal status value and the missing artifact, not in an error code.

## Steps to Reproduce
1. Create an S3 bucket and a SageMaker execution role (directly or via a CloudFormation stack), and upload a small CSV training file under s3://<bucket>/train/.
2. CreateTrainingJob(TrainingJobName=<name>, AlgorithmSpecification={'TrainingImage': <a built-in algorithm ECR image URI for the region>, 'TrainingInputMode': 'File'}, RoleArn=<role arn>, InputDataConfig=[{'ChannelName': 'train', 'DataSource': {'S3DataSource': {'S3DataType': 'S3Prefix', 'S3Uri': 's3://<bucket>/train/', 'S3DataDistributionType': 'FullyReplicated'}}, 'ContentType': 'text/csv'}], OutputDataConfig={'S3OutputPath': 's3://<bucket>/output/'}, ResourceConfig={'InstanceType': 'ml.m5.large', 'InstanceCount': 1, 'VolumeSizeInGB': 5}, StoppingCondition={'MaxRuntimeInSeconds': 900}, HyperParameters={...}).
3. Poll DescribeTrainingJob(TrainingJobName=<name>) until the status is terminal. Expect TrainingJobStatus 'Completed' and ModelArtifacts.S3ModelArtifacts under s3://<bucket>/output/; observe TrainingJobStatus 'Failed' with FailureReason "This emulator has no container runtime, so the training job's algorithm image was never started and no model artifacts were written to the output S3 location", and no object under s3://<bucket>/output/ (HeadObject/ListObjectsV2 on that prefix is empty).
4. Consequence to confirm after the fix: CreateModel with PrimaryContainer.ModelDataUrl set to that artifact, then CreateEndpointConfig + CreateEndpoint, poll to InService, and InvokeEndpoint with a supported ContentType -> expect a prediction body; and InvokeEndpoint with an unsupported ContentType -> expect the container's refusal rather than an unreachable step.
