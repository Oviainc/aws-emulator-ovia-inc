# GreengrassV2: every request rejected with AmbiguousService because Greengrass v1 and v2 share endpointPrefix 'greengrass'

> _Note: this issue was identified against the code base at commit `0b8884c4ab978d23b4fe746f795a1277a2a36df3`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateComponentVersion

## Description
Cause 1 of 1: the emulator's request router keys emulated services by endpoint prefix alone and refuses to serve a prefix claimed by more than one registered service. Greengrass (2017-06-07) and GreengrassV2 (2020-11-30) are two distinct APIs that AWS serves on the SAME endpoint, so both register the same prefix and the router rejects 100% of GreengrassV2 traffic before any handler runs. All 59 non-deferred GreengrassV2 checks in this suite fail on this one refusal; the remaining 8 are blocked by the already-filed unimplemented iot CreateThingGroup stub.

AWS: Smithy service com.amazonaws.greengrassv2#GreengrassV2 (version 2020-11-30, restJson1) declares awsService.endpointPrefix = "greengrass", arnNamespace = "greengrass", sigv4Name = "greengrass" — identical to com.amazonaws.greengrass#Greengrass (version 2017-06-07, restJson1), which declares the same endpointPrefix/arnNamespace/sigv4Name. AWS therefore serves both API versions from greengrass.<region>.amazonaws.com and disambiguates them by the HTTP request itself (each operation's restJson1 @http method+uri binding — v2 operations live under the /greengrass/v2/... path space), never by refusing the request. A well-formed GreengrassV2 call returns that operation's modeled success shape, or one of its modeled errors (ValidationException 400, ResourceNotFoundException 404, AccessDeniedException 403, ConflictException 409, InternalServerException 500). "AmbiguousService" is not a modeled error of either service and is not an AWS error code.

Emulator: every GreengrassV2 operation returns an error with code 'AmbiguousService' and the message (example, recorded) "2 emulated services all claim requests for 'greengrass': greengrass, greengrass; the request is rejected rather than served by an arbitrary one". It is returned as a retryable condition, so botocore exhausts its retries first ("reached max retries: 3"). Observed on CreateComponentVersion, CreateDeployment, GetServiceRoleForAccount, AssociateServiceRoleToAccount, UpdateConnectivityInfo, ListComponentVersions, ListEffectiveDeployments, ListClientDevicesAssociatedWithCoreDevice, BatchDisassociateClientDeviceFromCoreDevice, and every other operation the suite touches — i.e. the whole service surface, read and write, happy path and rejection path. Note the diagnostic names the SAME token twice ('greengrass, greengrass'), so the two registrations are not even distinguished from each other in the routing table.

Why: a client cannot use GreengrassV2 against this emulator at all. Nothing can be created, read, deployed, tagged or deleted. Worse than a plain failure, the refusal is mis-classified: it surfaces as a non-AWS error code that no SDK error handler or exception-matching code recognises, and it is treated as retryable, so every call burns the full retry budget and the latency of 4 attempts before failing. Checks that assert AWS's rejection behavior (ValidationException on a malformed ARN, ResourceNotFoundException on a nonexistent core device or deployment, NotFoundException on an untagged ARN, AccessDeniedException for an unauthorised role) all receive 'AmbiguousService' instead, so a client cannot distinguish "bad request" from "missing resource" from "not permitted".

Fix: the request router / service-registry dispatch layer, not any GreengrassV2 operation handler (no handler is reached). Registration must be keyed by something that actually identifies the service — the sigv4 credential scope plus the operation's resolved @http method+uri binding (and/or the API version) — so that two services legitimately sharing an endpointPrefix both resolve. Shared-prefix co-residency is normal on AWS (greengrass/greengrassv2 here) and must route rather than refuse; a genuinely unresolvable request should fall back to a modeled error of the resolved service, never to an invented 'AmbiguousService' code, and never to a retryable classification.

Traces: all 59 failing check ids listed in trace_ids; representative examples greengrassv2.component-version-create-describe-get-delete-lifecycle (error on CreateComponentVersion), greengrassv2.service-role-association-lifecycle (error on AssociateServiceRoleToAccount), greengrassv2.get-component-malformed-arn-rejected (mismatch: expected ValidationException, got 'AmbiguousService'), greengrassv2.untag-resource-nonexistent-arn-rejected (mismatch: expected NotFoundException, got 'AmbiguousService').

## Evidence
Expected (AWS): each GreengrassV2 operation returns its modeled restJson1 success shape, or a modeled error — ValidationException (400), ResourceNotFoundException (404) / NotFoundException, AccessDeniedException (403), ConflictException (409), InternalServerException (500). GreengrassV2 and Greengrass coexist on endpointPrefix 'greengrass' and are routed by HTTP method+uri.

Actual (emulator): every GreengrassV2 request is refused before dispatch with error code 'AmbiguousService', classified retryable. Recorded message (example only): "An error occurred (AmbiguousService) when calling the GetServiceRoleForAccount operation (reached max retries: 3): 2 emulated services all claim requests for 'greengrass': greengrass, greengrass; the request is rejected rather than served by an arbitrary one".

Aggregate: greengrassv2 scored 0/67 (0%) in this suite. 53 checks surfaced it as a raised ClientError, 14 as an assertion mismatch where the expected AWS error code was replaced by 'AmbiguousService' (e.g. "expected ValidationException, got 'AmbiguousService'", "expected ResourceNotFoundException, got 'AmbiguousService'", "expected AccessDeniedException from the no-permission role, got 'AmbiguousService'", "expected exactly one winner, got 0: [('AmbiguousService', None), ...]").

Model citation: smithy_query service_info on services/service-com-amazonaws-greengrassv2-greengrassv2 -> endpointPrefix 'greengrass', arnNamespace 'greengrass', sigv4Name 'greengrass', restJson1, version 2020-11-30; on services/service-com-amazonaws-greengrass-greengrass -> endpointPrefix 'greengrass', arnNamespace 'greengrass', sigv4Name 'greengrass', restJson1, version 2017-06-07.
