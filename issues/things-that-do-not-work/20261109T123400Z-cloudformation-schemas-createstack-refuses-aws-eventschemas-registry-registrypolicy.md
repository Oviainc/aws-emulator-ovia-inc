# cloudformation__schemas: CreateStack refuses AWS::EventSchemas::Registry, ::RegistryPolicy and ::Schema as unrecognized resource types, so no schema-registry template can be deployed (2 checks)

> _Note: this issue was identified against the code base at commit `e2ad54ee7b8ee1b2faa65791f8cb738708e5249b`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateStack

## Description
One net-new root cause behind both surviving cloudformation__schemas failures.

Cause 1 of 1: the CloudFormation resource-type registry does not know the types AWS::EventSchemas::Registry, AWS::EventSchemas::RegistryPolicy or AWS::EventSchemas::Schema, so CreateStack is refused up-front with a template-format ValidationError and no stack is ever created. Failing checks: cloudformation__schemas.deploy-eventschemas-registry-policy-schema-round-trip-and-delete, cloudformation__schemas.deploy-eventschemas-schema-invalid-content-rejected-and-rolled-back.

AWS: all three are CloudFormation-supported resource types whose providers drive the Schemas control plane, which this emulator models. Smithy (com-amazonaws-schemas-schemas): CreateRegistry POST /v1/registries/name/{RegistryName} (201) with optional Description (@length 0..256) and Tags, returning RegistryArn/RegistryName/Description; CreateSchema POST /v1/registries/name/{RegistryName}/schemas/name/{SchemaName} (201) with required Content (@length 1..100000) and required Type (enum Type, e.g. OpenApi3), returning SchemaArn/SchemaName/SchemaVersion, and refusing a bad request with BadRequestException (400); PutResourcePolicy PUT /v1/policy with required Policy (mediaType application/json) and RegistryName; DescribeRegistry/ListRegistries/ListSchemas/DescribeSchema/GetResourcePolicy/ListTagsForResource all bound. So AWS accepts such a template: CreateStack returns a StackId, the stack reaches CREATE_COMPLETE, Ref/GetAtt on the Registry resolve to arn:<partition>:schemas:<region>:<account>:registry/<RegistryName> (and GetAtt RegistryName to the name), Ref on the RegistryPolicy resolves to the registry name, Ref/GetAtt on the Schema resolve to arn:<partition>:schemas:<region>:<account>:schema/<RegistryName>/<SchemaName> (plus GetAtt SchemaName and SchemaVersion), the stack's own tags propagate to the taggable Schemas resources, an update that drops the Schema empties the registry while the registry still answers DescribeRegistry, and the stack delete removes the registry so DescribeRegistry is then refused NotFoundException 'Registry with name <RegistryName> does not exist.' (fixed text 'Registry with name ' + the requested name + ' does not exist.'). For the negative check AWS also ACCEPTS the template — the types are recognized — and fails the RESOURCE: the stack goes CREATE_FAILED then ROLLBACK_COMPLETE, DescribeStackEvents carries no template-validation row, and the Schema resource's ResourceStatusReason is the provider wrapper 'Resource handler returned message: "<service message>" (RequestToken: <token>, HandlerErrorCode: <code>)' whose inner message is Schemas' own 400 refusal — recorded behavior: 'Content is not valid JSON: invalid character '<char>' looking for beginning of object key string at offset <n> (Service: Schemas, Status Code: 400, Request ID: <id>) (SDK Attempt Count: <n>)' with HandlerErrorCode InvalidRequest; the offending character and offset come from the submitted Content, the request id and attempt count are per-run values. The rollback then removes the registry, so DescribeRegistry is refused NotFoundException with the same sentence above.

Emulator: CreateStack answers HTTP 400 with error code ValidationError and the message 'Template format error: Unrecognized resource types: [<types>]'. The fixed text is 'Template format error: Unrecognized resource types: ' followed by the bracketed list of the template's unknown types taken from the request — observed as [AWS::EventSchemas::Registry, AWS::EventSchemas::RegistryPolicy, AWS::EventSchemas::Schema] for the round-trip template and [AWS::EventSchemas::Registry, AWS::EventSchemas::Schema] for the invalid-Content template. No StackId is minted, so DescribeStacks, DescribeStackEvents, the Outputs, the ListRegistries/ListSchemas/DescribeSchema/GetResourcePolicy round-trips, the schema-dropping UpdateStack, the rollback assertions and the delete are all unreachable.

Why: a client cannot manage an EventBridge schema registry, its resource policy or its schemas as infrastructure as code at all — the stack fails at CreateStack with a message that reads as 'my template is malformed' rather than 'these providers are missing'. The rejection path is additionally mis-shaped: a template-format refusal is a different failure class, at a different time, from a resource-level provider failure, so a client testing invalid Content never reaches CREATE_FAILED/ROLLBACK_COMPLETE, never sees the Schemas 400 carried as the failing resource's ResourceStatusReason, and cannot distinguish a bad property value from an unparsable template.

Fix: the CloudFormation resource-type registry and its provisioners — register AWS::EventSchemas::Registry, ::RegistryPolicy and ::Schema and wire their create/read/update/delete to the Schemas control plane (CreateRegistry/DescribeRegistry/UpdateRegistry/DeleteRegistry, PutResourcePolicy/GetResourcePolicy/DeleteResourcePolicy, CreateSchema/DescribeSchema/UpdateSchema/DeleteSchema), publishing the registry and schema ARNs as the physical resource ids (and the registry name as the RegistryPolicy's) so Ref/GetAtt resolve, propagating stack tags to the created resources, and surfacing the Schemas 400 refusal as the resource's handler failure reason instead of pre-validating the types away.

Traces: cloudformation__schemas.deploy-eventschemas-registry-policy-schema-round-trip-and-delete, cloudformation__schemas.deploy-eventschemas-schema-invalid-content-rejected-and-rolled-back.

Note: no open issue covers these types. The nearest open issues report the same CLASS of gap for other providers (e.g. 20261109T113214Z-cloudformation-mediatailor-createstack-refuses-every-aws-mediatailor-resource.md) and name no AWS::EventSchemas::* type.

- cloudformation__schemas.deploy-eventschemas-schema-invalid-content-rejected-and-rolled-back: botocore.exceptions.ClientError: An error occurred (ValidationError) when calling the CreateStack operation: Template format error: Unrecognized resource types: [AWS::EventSchemas::Registry, AWS::EventSchemas::Schema]

Expected (round-trip check): CreateStack returns a StackId; CREATE_COMPLETE; Registry Ref and GetAtt RegistryArn both equal arn:<partition>:schemas:<region>:<account>:registry/<registry>, GetAtt RegistryName equals <registry>; DescribeRegistry reports that ARN and the templated Description; the stack tag is readable through ListTagsForResource on the registry and the schema; RegistryPolicy Ref equals <registry> and GetResourcePolicy returns the templated policy document verbatim; Schema Ref and GetAtt SchemaArn equal arn:<partition>:schemas:<region>:<account>:schema/<registry>/<schema>, DescribeSchema reports Type OpenApi3, the templated Description, the GetAtt SchemaVersion and the exact Content; an UpdateStack dropping the Schema reaches UPDATE_COMPLETE and leaves ListSchemas empty while DescribeRegistry still answers; after DeleteStack, DescribeRegistry is refused ('NotFoundException', 'Registry with name <registry> does not exist.').

Actual: ValidationError 'Template format error: Unrecognized resource types: [...]' at CreateStack; no stack exists and nothing downstream is exercised.
