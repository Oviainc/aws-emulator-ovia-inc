# cloudformation__connecthealth: AWS::HealthAgent::Domain is not a registered resource type — CreateStack refuses every ConnectHealth Domain template with "Template format error: Unrecognized resource types"

> _Note: this issue was identified against the code base at commit `b00bffca1001eed9eb3256fe81ec389ea90933f7`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateStack

## Description
One root cause, reported under the suite heading '### cloudformation__connecthealth' (0/2 passed; both checks fail on the very first CreateStack).

Cause 1 of 1: CloudFormation does not know the resource type AWS::HealthAgent::Domain, so no ConnectHealth (HealthAgent) Domain can be deployed by a template and neither the happy path nor the property-validation path of that resource is reachable.
Failing checks: cloudformation__connecthealth.deploy-healthagent-domain-round-trip-and-delete, cloudformation__connecthealth.deploy-healthagent-domain-name-too-long-rejected-and-rolled-back.
AWS: CloudFormation's resource-type registry is not part of the Smithy model (the cloudformation model only declares CreateStack/DescribeStacks/DescribeStackEvents/DescribeEvents and their shapes), so this is recorded behavior only, corroborated by the type's public template reference (AWS::HealthAgent::Domain, https://docs.aws.amazon.com/AWSCloudFormation/latest/TemplateReference/aws-resource-healthagent-domain.html). Recorded behavior: (a) CreateStack ACCEPTS a template declaring Resources.Domain = {"Type": "AWS::HealthAgent::Domain", "Properties": {"Name": <name>, "Tags": [...]}} and the stack reaches CREATE_COMPLETE, having created a real Domain — Ref of the resource and the stack resource's PhysicalResourceId are the Domain's ARN, GetAtt exposes DomainId, Arn, Status ('ACTIVE') and CreatedAt (an ISO-8601 instant equal to connecthealth GetDomain's createdAt), connecthealth ListDomains/GetDomain report that domainId/arn/name with encryptionContext.encryptionType 'AWS_OWNED_KEY' when no KmsKeyArn is declared, ListTagsForResource returns the template's Tags, and DeleteStack removes the Domain so GetDomain then reports it gone. (b) A Name one character over the resource schema's 64-character maximum is refused by resource-schema property validation BEFORE any Domain is created: the stack settles ROLLBACK_COMPLETE, its stack-level CREATE_FAILED event carries the fixed reason "Validation failed with 1 error(s). Call DescribeEvents to retrieve the full list of issues with resource and property details, resolve each error, then retry the operation.", DescribeEvents returns a VALIDATION_ERROR event whose ResourceType is "AWS::HealthAgent::Domain" with ValidationName 'PROPERTY_VALIDATION', Status 'FAILED', FailureMode 'FAIL', Path "/Resources/Domain/Properties/Name" and Reason "#/Name: expected maxLength: 64, actual: <the submitted length>" (fixed text "#/Name: expected maxLength: 64, actual: " plus the request's actual length), and DescribeStackResources returns an empty list.
Emulator: CreateStack never gets that far. It refuses the template outright with HTTP 400 ValidationError and message "Template format error: Unrecognized resource types: [AWS::HealthAgent::Domain]" — fixed text "Template format error: Unrecognized resource types: [" with the unrecognized type names from the submitted template listed inside the brackets. Both checks therefore die on their first call and assert nothing about the stack, the resource or ConnectHealth.
Why: a client cannot provision ConnectHealth/HealthAgent infrastructure as code at all — every CloudFormation, CDK or SAM template that declares a Domain is rejected at submission, which a user reads as 'my template is malformed' rather than 'this emulator has no handler'. Because the type is unknown, the entire contract around it is also unverifiable: Ref/PhysicalResourceId == the Domain ARN, the four GetAtt attributes, tag propagation to the Domain, delete-on-stack-delete, and the whole property-validation/rollback path with its stack reason and VALIDATION_ERROR event.
Fix: register AWS::HealthAgent::Domain in the CloudFormation crate's resource-type registry/schema table and add its resource handler, delegating to connecthealth CreateDomain / GetDomain / DeleteDomain / TagResource: carry the schema (Name with maxLength 64, Tags as a key/value list) so property validation fails the resource with CloudFormation's own PROPERTY_VALIDATION event and reason rather than at template parse, make Ref and PhysicalResourceId the Domain ARN, expose GetAtt DomainId/Arn/Status/CreatedAt from the created Domain, propagate the template's Tags plus the stack tags, and delete the Domain on stack delete.
Traces: cloudformation__connecthealth.deploy-healthagent-domain-round-trip-and-delete, cloudformation__connecthealth.deploy-healthagent-domain-name-too-long-rejected-and-rolled-back.
