# cloudformation__ec2__redshift-serverless: CreateStack refuses AWS::RedshiftServerless::Namespace/Workgroup/Snapshot as unrecognized resource types, so no workgroup or snapshot can be deployed

> _Note: this issue was identified against the code base at commit `ab58585e96332c13ed2b8d30023e29e5d03b1c39`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateStack

## Description
Cause 1 of 1: CloudFormation's template resource-type registry contains none of AWS::RedshiftServerless::Namespace, AWS::RedshiftServerless::Workgroup or AWS::RedshiftServerless::Snapshot, so any template that declares them is refused at CreateStack. A Redshift Serverless compute estate (VPC + subnets + security group + namespace + workgroup + snapshot) can therefore never be deployed, read back, updated or rolled back from a stack. Failing checks: cloudformation__ec2__redshift-serverless.deploy-redshift-serverless-workgroup-snapshot-provisions-and-tombstones, cloudformation__ec2__redshift-serverless.deploy-redshift-serverless-workgroup-invalid-base-capacity-rejected.

AWS: all three are first-class, registry-backed CloudFormation resource types. CreateStack with a well-formed template declaring them is ACCEPTED (HTTP 200 with a StackId) and reaches CREATE_COMPLETE; none is ever reported as unrecognized. Their handlers provision through Redshift Serverless (Smithy: CreateWorkgroup.workgroupName and .namespaceName required, @length 3-64, @pattern ^[a-z0-9-]+$, plus baseCapacity, subnetIds, securityGroupIds, publiclyAccessible; errors ConflictException, InsufficientCapacityException, ResourceNotFoundException, ValidationException; CreateSnapshot.namespaceName and .snapshotName required, retentionPeriod optional). Ref on each resolves to the declared name; Fn::GetAtt Workgroup.WorkgroupId / Workgroup.WorkgroupArn / Namespace.NamespaceId / Namespace.NamespaceArn / Snapshot.SnapshotArn resolve to the service's own values, and those same values come back from ListWorkgroups/GetWorkgroup, ListNamespaces/GetNamespace and ListSnapshots/GetSnapshot (workgroup status AVAILABLE, baseCapacity, subnetIds, securityGroupIds and publiclyAccessible equal to the templated values; snapshot status AVAILABLE with the templated snapshotRetentionPeriod). An invalid BaseCapacity is refused by the service and relayed by the registry handler: the stack ends ROLLBACK_COMPLETE and the Workgroup resource's CREATE_FAILED ResourceStatusReason is 'Resource handler returned message: "<service message>" (RequestToken: <token>, HandlerErrorCode: <code>)', where for BaseCapacity 7 the service message is "The base capacity must be 2 or 4 in tiny RPU range. (Service: RedshiftServerless, Status Code: 400, Request ID: <id>) (SDK Attempt Count: <n>)" and the HandlerErrorCode is InvalidRequest — fixed text is the sentence "The base capacity must be 2 or 4 in tiny RPU range." and the "(Service: RedshiftServerless, Status Code: 400, ...)" envelope; the request id, request token and attempt count are per-run values. After the rollback neither workgroup nor namespace exists: GetWorkgroup answers ResourceNotFoundException (404) "Serverless workgroup <name> not found." and GetNamespace answers ResourceNotFoundException (404) "Serverless namespace <name> not found.". An UpdateStack that drops the Workgroup and Snapshot removes both (reaching UPDATE_COMPLETE) while the Namespace survives, GetWorkgroup then answering "Serverless workgroup <name> not found." and GetSnapshot answering ResourceNotFoundException "The snapshot <name> was not found. Please Check whether the snapshot exists and is owned by or shared with account <account>." — fixed text as worded, with the snapshot name from the request and the account from the caller. The workgroup's endpoint ENIs are released from the VPC before the stack delete completes.

Emulator: CreateStack is REFUSED with HTTP 400 ValidationError "Template format error: Unrecognized resource types: [AWS::RedshiftServerless::Namespace, AWS::RedshiftServerless::Workgroup, AWS::RedshiftServerless::Snapshot]" (and "[AWS::RedshiftServerless::Namespace, AWS::RedshiftServerless::Workgroup]" for the workgroup-only template). No StackId is returned and no stack exists, so the provisioning, every Ref/GetAtt, the service round trips, the BaseCapacity refusal relay, the child-removing update and the ENI drain are all unreachable.

Why: a client cannot stand up Redshift Serverless compute by template at all, and the refusal is phrased as a template-format error, so the client is told its own template is malformed rather than that the provider is absent — no amount of template correction can make the deploy succeed. The negative path inverts too: a request AWS surfaces as a per-resource CREATE_FAILED handler reason after a rollback is instead rejected before the stack exists, with a different code, status and message.

Fix: the CloudFormation service's template resource-type registry must register AWS::RedshiftServerless::Namespace, ::Workgroup and ::Snapshot, and provisioning handlers must be added for each that call redshift-serverless CreateNamespace/CreateWorkgroup/CreateSnapshot and the matching Get/List/Delete operations, publish Ref and the Namespace.*/Workgroup.*/Snapshot.* GetAtt attributes from the service's state, resolve SubnetIds/SecurityGroupIds through the EC2 resources in the same stack, relay a service refusal into the resource's CREATE_FAILED ResourceStatusReason in CloudFormation's registry-handler form, and release the workgroup's VPC ENIs on delete so the stack's EC2 resources can be torn down.

Traces: see trace_ids; both checks fail identically on the first CreateStack call, before any Redshift Serverless or EC2 call is made.

## Evidence
Expected (AWS): cfn.create_stack with a template declaring AWS::EC2::VPC/Subnet/SecurityGroup plus AWS::RedshiftServerless::Namespace, ::Workgroup (BaseCapacity 8) and ::Snapshot -> HTTP 200 with a StackId, stack reaches CREATE_COMPLETE; GetWorkgroup shows status AVAILABLE, baseCapacity 8, the templated namespaceName/subnetIds/securityGroupIds and publiclyAccessible false; GetSnapshot shows status AVAILABLE with the templated retention. With BaseCapacity 7 the stack reaches ROLLBACK_COMPLETE and the Workgroup CREATE_FAILED reason is 'Resource handler returned message: "The base capacity must be 2 or 4 in tiny RPU range. (Service: RedshiftServerless, Status Code: 400, Request ID: <id>) (SDK Attempt Count: <n>)" (RequestToken: <token>, HandlerErrorCode: InvalidRequest)'.

Actual (emulator):
- botocore.exceptions.ClientError: An error occurred (ValidationError) when calling the CreateStack operation: Template format error: Unrecognized resource types: [AWS::RedshiftServerless::Namespace, AWS::RedshiftServerless::Workgroup, AWS::RedshiftServerless::Snapshot]
- botocore.exceptions.ClientError: An error occurred (ValidationError) when calling the CreateStack operation: Template format error: Unrecognized resource types: [AWS::RedshiftServerless::Namespace, AWS::RedshiftServerless::Workgroup]

No stack is created in either case.

## Steps to Reproduce
1. Build and boot the emulator.
2. Submit a CreateStack whose Resources declare an AWS::EC2::VPC, three AWS::EC2::Subnet, an AWS::EC2::SecurityGroup, an AWS::RedshiftServerless::Namespace, an AWS::RedshiftServerless::Workgroup (NamespaceName Ref'ing the namespace, BaseCapacity 8, SubnetIds Ref'ing the subnets, SecurityGroupIds Ref'ing the SG, PubliclyAccessible false) and an AWS::RedshiftServerless::Snapshot (DependsOn the workgroup, RetentionPeriod 1).
3. Observe HTTP 400 ValidationError "Template format error: Unrecognized resource types: [AWS::RedshiftServerless::Namespace, AWS::RedshiftServerless::Workgroup, AWS::RedshiftServerless::Snapshot]" instead of an accepted CreateStack that reaches CREATE_COMPLETE.
4. Repeat the same template without the Snapshot and with BaseCapacity 7: AWS reaches ROLLBACK_COMPLETE with the Workgroup's handler reason relaying "The base capacity must be 2 or 4 in tiny RPU range." / HandlerErrorCode InvalidRequest; the emulator refuses the CreateStack with the unrecognized-type error instead.
