# A managed relational database announces a masterEndpoint.address the emulator is not reachable on (rds.lightsail.local), so the database data plane can never be reached

> _Note: this issue was identified against the code base at commit `bf05938345e3744e1c8e3343a2f8d43b66feefe9`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
GetRelationalDatabase

## Description
Cause 1 of 1: CreateRelationalDatabase / GetRelationalDatabase project a masterEndpoint whose `address` is a synthetic host label that is NOT an address this emulator answers on, so a client that follows the advertised contract (create -> wait for `available` -> connect to masterEndpoint) is sent to a host other than the endpoint the emulator is reached on. This is a distinct, currently-live signal from the two issues that already carry this check: the open 20261030T034918Z-lightsail-serves-no-instance-metric-datapoints-and-no.md holds this trace under a *connect-timeout* key (its cause 2, 'serves no SQL'), and the resolved 20261022T213651Z-lightsail-detachdisk-answers-501-notimplemented-and-a-managed.md declined its cause 2 as a core listener blocker while explicitly keeping the announced `.local` address; neither covers the ADDRESS-announcement half, which is what the replay now fails on. The check no longer hangs: the harness refuses the egress the moment the emulator hands out that address, before any SQL is attempted.
AWS: Smithy (com.amazonaws.lightsail#RelationalDatabase.masterEndpoint -> RelationalDatabaseEndpoint{address: NonEmptyString pattern \S, doc 'Specifies the DNS address of the database'; port: integer, doc 'Specifies the port that the database is listening on'}). AWS returns, for a database reported `state: available`, an address that RESOLVES to the host serving that database and a port that host is listening on; recorded behavior only for the engine protocol itself (the model describes the address, not MySQL) — the recording shows a client resolving and connecting to the announced address:port and round-tripping CREATE TABLE / INSERT / SELECT with the master credentials. The requirement an emulator inherits is the resolvable, reachable part: the announced address must be the endpoint the service is reached on, with the engine's port.
Emulator: `GetRelationalDatabase` answers 200 with `masterEndpoint.address` of the form `ls-<id-without-dashes>.<12-char label>.<region>.rds.lightsail.local`, minted by `relational_database_endpoint_address` from `RELATIONAL_DATABASE_INSTANCE_ID_PREFIX` + `RELATIONAL_DATABASE_HOST_LABEL_LEN` + `RELATIONAL_DATABASE_ENDPOINT_SUFFIX = "rds.lightsail.local"`, and nothing in the emulator is reachable at that name. The replay's egress guard rejects the connection outright: "egress refused: 'ls-52f97e741de45bea3121b3335c662164.pqvmv7e28va7.us-west-2.rds.lightsail.local' is not the endpoint under test (127.0.0.1); an emulator run may reach only the emulator. If the host came from a URL the emulator returned, the emulator announces an address other than the endpoint it is reached on" (the host is a per-run minted value; the fixed part is the `.rds.lightsail.local` suffix and the fact that it is not the endpoint under test). No error code or non-2xx is involved — the control plane reports success and hands out an unreachable address.
Why: every client that provisions a Lightsail database and then USES it — migrations, seeding, ORM boot, health checks — is pointed at a host it cannot reach, while the control plane reports the database `available` and authoritative. That is strictly worse than an honest refusal: the client's own DNS/connect failure looks like a local network problem, not an emulator gap, and a sandboxed client is cut off from the emulator entirely because the announced name leaves the emulator's address space.
Fix: the relational-database endpoint projection in state — `relational_database_endpoint_address` and the `masterEndpoint` projection on the stored database record (services/service-com-amazonaws-lightsail-lightsail-20161128/src/state.rs) — must announce the host/port the emulator is actually reached on for the database's data plane, and that data plane must be served there for the blueprint's engine (MySQL on 3306, PostgreSQL on 5432). If the engine protocol genuinely cannot be served (the recorded resolution note cites the core's TLS-only `engine.listeners().tcp` seam), the endpoint must still name an address inside the emulator rather than a host it does not answer on, and the gap belongs on the core listener seam, not in the announced address. File/line citations are under Traces.
Traces: lightsail.relational-database-native-sql-roundtrip.

## Steps to Reproduce
Boot the emulator and point a botocore lightsail client at its data listener in the emulator's region.
1. blueprint = get_relational_database_blueprints() -> the mysql blueprint with isEngineDefault=true; bundle = cheapest active get_relational_database_bundles() bundleId.
2. create_relational_database(relationalDatabaseName=D, relationalDatabaseBlueprintId=blueprint, relationalDatabaseBundleId=bundle, masterDatabaseName="roundtripdb", masterUsername="dbadmin", masterUserPassword=<valid password>, publiclyAccessible=True).
3. Poll get_relational_database(relationalDatabaseName=D) until relationalDatabase.state == "available"; read relationalDatabase.masterEndpoint.
4. Compare masterEndpoint.address to the host the lightsail client is talking to. Expected: an address the emulator answers on (and a port its engine listens on). Observed: `ls-<id>.<label>.<region>.rds.lightsail.local`, which is neither resolvable nor the endpoint under test — a sandboxed client's connection is refused as off-endpoint egress.
5. Connect to (address, port) with pymysql using the master credentials and run CREATE TABLE sim2real_roundtrip (id INT PRIMARY KEY, val VARCHAR(64)); INSERT VALUES (1,'hello-lightsail'); commit; SELECT val WHERE id=1. Expected: the row 'hello-lightsail'. Observed: the connection never reaches the emulator at all.
