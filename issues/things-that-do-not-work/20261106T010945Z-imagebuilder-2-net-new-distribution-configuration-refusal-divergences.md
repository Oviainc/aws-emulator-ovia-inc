# imagebuilder: 2 net-new distribution-configuration refusal divergences — duplicate-region uses the wrong error class/message, and UpdateDistributionConfiguration never applies the output-less-entry refusal

> _Note: this issue was identified against the code base at commit `ed195bdda9ffdbdf051f799fc5087e4de9084b05`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateDistributionConfiguration

## Description
This bundle carries TWO distinct net-new root causes on the Image Builder distribution-configuration refusal paths. Both must be closed before this issue is submitted.

(Related but NOT covering: 20261105T162014Z-imagebuilder-image-builder-distribution-configuration-validation-deletion-and-update.md — that wire issue covers the CREATE path's missing output-less-entry check, the delete/get state and the update-persistence cause, but carries neither of the two causes below. 20261105T162014Z-imagebuilder-image-builder-refusal-error-types-and-messages-are.md likewise does not carry either replay key.)

Cause 1 of 2: CreateDistributionConfiguration refuses a duplicate target Region with the wrong error class and an emulator-authored message.
AWS: a distributions list naming the same target Region more than once is refused with HTTP 400, error code InvalidParameterValueException and the message "The value supplied for parameter 'distributions' is not valid. A region may appear in a distribution configuration at most once." The whole text is fixed for this error class except the quoted parameter name, which is the member path of the offending input member taken from the request ('distributions' here). Smithy: CreateDistributionConfiguration.distributions -> DistributionList (required); Distribution.region (required) documented as "Each entry defines how output images are distributed in one target Amazon Web Services Region. A Region can appear at most once in the list." The model declares InvalidParameterValueException (client, httpError 400, "The value that you provided for the specified parameter is invalid.") on the service, though it is not listed among this operation's errors — recorded behavior shows AWS answering that code here, with the generic "The value supplied for parameter '<member>' is not valid. <rule>" message class Image Builder uses for every parameter refusal.
Emulator: refuses with its own error class and wording — code InvalidParameterCombinationException, message "The distributions list can name each target Region at most once, and it names us-east-2 more than once." (the Region name is substituted from the request; the rest is emulator-authored text that appears nowhere in AWS).
Why: a client that branches on the error code sees a parameter-combination failure rather than a parameter-value failure, so retry/validation logic keyed to InvalidParameterValueException (the code every other Image Builder parameter refusal uses) does not match; and any client or test matching the documented message text fails. The refusal is also indistinguishable from genuine mutually-exclusive-parameter failures.
Fix: the duplicate-target-Region branch of the CreateDistributionConfiguration handler and the message helper it calls — return the InvalidParameterValueException class with the AWS message template instead of InvalidParameterCombinationException with emulator wording. The same message class must be shared with the other distributions-list refusals so one wording rule is applied on every path.
Traces: imagebuilder.ibp-create-distribution-configuration-rejects-a-region-listed-twice.

Cause 2 of 2: UpdateDistributionConfiguration never reaches any validation — it answers 501 NotImplemented, so the output-less region entry is neither refused nor rejected without mutating state.
AWS: UpdateDistributionConfiguration applies the same per-entry validation the create path does. A distributions entry carrying a region but no output member (amiDistributionConfiguration, containerDistributionConfiguration, fastLaunchConfigurations, launchTemplateConfigurations, s3ExportConfiguration, ssmParameterConfigurations, licenseConfigurationArns) is refused with HTTP 400, code InvalidParameterValueException and the message "The value supplied for parameter 'distributions[0]' is not valid. One or more outputs should be provided for each region in a distribution configuration." Fixed text is "The value supplied for parameter '" ... "' is not valid. One or more outputs should be provided for each region in a distribution configuration."; the variable part is the indexed member path of the offending entry, taken from the request. The refused update must store nothing, so a following GetDistributionConfiguration returns the distributions list exactly as it was before the attempt; a subsequent valid update then replaces the whole list (Smithy: UpdateDistributionConfiguration.distributions -> DistributionList, required; success http code 200).
Emulator: every UpdateDistributionConfiguration request is answered with error code 'NotImplemented' from the unimplemented scaffold stub (services/service-com-amazonaws-imagebuilder-imagebuilder/src/ops/update_distribution_configuration.rs returns crate::scaffolded::Scaffolded::not_implemented("UpdateDistributionConfiguration")), so neither the refusal nor the no-mutation guarantee nor the following valid update is observable.
Why: a client cannot update a distribution configuration at all, and a client probing its own input validity gets a 501 server-side "not written yet" instead of the 400 parameter refusal, so it treats a bad request as a transient service failure and retries it forever.
Fix: implement the UpdateDistributionConfiguration handler, including the per-entry output-presence validation (shared with CreateDistributionConfiguration's validation so both paths emit one message class) and a validate-before-write order so a refused update leaves the stored distributions list untouched. The companion issue that merely stands the stub up does not state this validation rule or the no-mutation requirement; both are required here.
Traces: imagebuilder.ibp-update-distribution-configuration-rejects-a-region-entry-with-no-outputs.
