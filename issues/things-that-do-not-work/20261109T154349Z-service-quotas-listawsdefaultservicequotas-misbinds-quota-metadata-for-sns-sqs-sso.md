# ListAWSDefaultServiceQuotas misbinds quota metadata for sns sqs sso storagegateway timestream vpc vpc-lattice wafv2 workspaces xray

> _Note: this issue was identified against the code base at commit `5b2a9eedb8fa287cac2318fd09ae07f52de03ab6`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
ListAWSDefaultServiceQuotas

## Description
ListAWSDefaultServiceQuotas answers 200 with a `Quotas` list whose `QuotaCode` values are AWS's, but whose per-row metadata belongs to a DIFFERENT quota of the same service code. The emulator's default-quota catalog is evidently a positional list of quota rows onto which AWS's QuotaCode strings are zipped, so `QuotaName`, `Description`, `Value`, `Unit`, `Adjustable`, `ServiceName`, `Period`, `UsageMetric` and `QuotaContext` are served for the wrong code; where AWS's row has `Period`/`UsageMetric` and the substituted row does not, those members disappear altogether. This is one defect in the catalog's keying, reproduced below on ten service codes. Each cause is its own service code and its own fixture, and all ten must be closed.

General requirement for every cause: for a given `ServiceCode`, every `QuotaCode` AWS returns must carry AWS's own `QuotaName`, `Description`, `Value`, `Unit`, `Adjustable`, `GlobalQuota`, `ServiceName`, `QuotaArn`, and — when AWS models them for that quota — `Period`, `UsageMetric` and `QuotaContext`. Only the ARN's partition/region segment and pagination tokens are environment-dependent; the quota metadata is not.

------------------------------------------------------------
Cause 1 of 10: ServiceCode `sns` — AWS rate-limit rows bound to the wrong QuotaCode.
AWS: recorded behavior only (the Smithy model types these members but does not enumerate quota values). The recording shows L-4738DDCE = QuotaName 'CreatePlatformApplication Transactions per Second', Description 'The maximum number of times the CreatePlatformApplication action can be called per second.', Value 900.0, UsageMetric.MetricDimensions.Resource 'CreatePlatformApplication'; L-FF07E5EA = 'ConfirmSubscription Transactions per Second', Value 900.0, Resource 'ConfirmSubscription'; L-390AADBE = 'ListSubscriptionsByTopic Transactions per Second', Adjustable false, Resource 'ListSubscriptionsByTopic'.
Emulator: serves 200 with those same codes carrying other SNS quotas — L-4738DDCE as 'GetEndpointAttributes Transactions per Second' Value 15.0, L-FF07E5EA as 'VerifySMSSandboxPhoneNumber Transactions per Second' Value 30.0, L-390AADBE as 'DeleteSMSSandboxPhoneNumber Transactions per Second' with Adjustable true.
Why: a client that resolves an SNS throttling limit by QuotaCode (the only stable key AWS offers) reads a value and adjustability for an unrelated API action, so capacity planning and RequestServiceQuotaIncrease targeting are wrong while the call looks successful.
Fix: the service-quotas default-quota catalog data/lookup behind the ListAWSDefaultServiceQuotas handler — key catalog rows by QuotaCode instead of by position.
Traces: service-quotas-catalog-list-aws-default-service-quotas-sns#task#1.

Cause 2 of 10: ServiceCode `sqs` — quota rows shifted, so Unit and Value describe another quota.
AWS: recorded behavior only. L-98134C75 = 'Attributes per Message', Description 'The number of attributes added to a message.', Unit 'None', Value 10.0; L-81970B52 = 'Message Size in S3 Bucket', Unit 'Gigabytes', Value 2.0; L-BBEFA6CF = 'Queue Policy Size', Unit 'Bytes', Value 8192.0, Adjustable false; L-BF2A6161 = 'UTF-8 Queue Tag Value Length', Value 256.0.

Why: the Unit changes with the substituted row, so a client reading an SQS limit by code gets a number in the wrong dimension (bytes where AWS reports a count, days where AWS reports gigabytes) and silently mis-sizes messages, retention and policies.
Fix: same catalog/lookup component as Cause 1, sqs rows.
Traces: service-quotas-catalog-list-aws-default-service-quotas-sqs#task#1.

Fix: same catalog/lookup component as Cause 1, sso rows; ServiceName must be the catalog's AWS value, not a re-authored one.

Cause 6 of 10: ServiceCode `vpc` — shifted rows plus a diverging QuotaContext.AdjustableAtLevel.
AWS: recorded behavior only. L-5F53652F = 'Elastic IP address quota per NAT gateway', Value 2.0; L-42B9C2CA = 'VPC Block Public Access exclusions per account per Region', Value 50.0, Adjustable false; L-CA6CC422 = "VPC endpoints of type 'resource' per VPC", Value 500.0; L-8312C5BB = the unaccepted-peering-request expiry in hours, Adjustable false.
