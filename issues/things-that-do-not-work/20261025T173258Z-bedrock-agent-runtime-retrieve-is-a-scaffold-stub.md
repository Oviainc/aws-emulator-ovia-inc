# bedrock-agent-runtime: Retrieve is a scaffold stub, so a citation's s3Location.uri can never be resolved back to the ingested S3 object

> _Note: this issue was identified against the code base at commit `8fdd90c15790d38aa3c5d0088f99b03c79823121`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

Retrieve

## Description
One root cause. NOTE: open issue 20261023T004328Z-bedrock-agent-runtime-retrieve-optimizeprompt-getagentmemory-deleteagentmemory-and.md (Cause 1 of 9) already reports that Retrieve answers NotImplemented on the not-found path; it does NOT carry this check's replay key and the replay report did not mark this check as owned by it, so it is filed here with the additional, stronger success-path contract that issue does not state. === Cause 1 of 1: Retrieve answers NotImplemented (501) instead of serving a retrieval result whose location provenance resolves at S3 ===
AWS: Smithy: Retrieve is bound to the service as POST /knowledgebases/{knowledgeBaseId}/retrieve, @readonly, http code 200. Input: knowledgeBaseId (@httpLabel, @required, @length 10-2048, @pattern ^[0-9a-zA-Z]{10}$|^arn:aws(-[^:]+)?:bedrock:[a-z0-9-]{1,20}:[0-9]{12}:knowledge-base/[0-9a-zA-Z]{10}$), retrievalQuery (@required), retrievalConfiguration, guardrailConfiguration, nextToken (@length 1-2048, @pattern ^\S*$), userContext. Output: retrievalResults (@required, list of KnowledgeBaseRetrievalResult), guardrailAction, nextToken; the operation is @paginated (inputToken/outputToken nextToken, items retrievalResults). KnowledgeBaseRetrievalResult.content is @required; location -> RetrievalResultLocation whose type member is @required (enum RetrievalResultLocationType) and whose s3Location -> RetrievalResultS3Location.uri is a String. Modeled errors: AccessDeniedException 403, BadGatewayException 502, ConflictException 409, DependencyFailedException 424, InternalServerException 500, ResourceNotFoundException 404, ServiceQuotaExceededException 400, ThrottlingException 429, ValidationException 400 — NotImplemented is not among them. Recorded behavior (this check's hypotheses, one leg H5 already confirmed against real AWS us-west-2 2026-09-17): for a knowledge base ingesting S3 objects, each result carries location.type == "S3" and location.s3Location.uri formatted s3://<bucket>/<key> naming the exact ingested object (bucket and key are values taken from the caller's own data source, never fabricated); the chunk's content.text is a whitespace-collapsed substring of that object's real bytes; and RetrievalResultMetadata for an S3 data source carries exactly x-amz-bedrock-kb-chunk-id, x-amz-bedrock-kb-data-source-id (the id of the data source the caller created) and x-amz-bedrock-kb-source-file-modality ("TEXT" for a text/plain object), with chunk-id non-empty and distinct across the results of one Retrieve call.
Emulator: the call is refused outright with HTTP 501, error code 'NotImplemented', message "operation Retrieve is scaffolded but not implemented in this emulator". Fixed text of that message is "operation " + <OperationName> + " is scaffolded but not implemented in this emulator"; the only variable part is the operation name taken from the request. The setup the check performs before it (S3 bucket + two text objects, S3 Vectors bucket/index, IAM role, knowledge base and data source, ingestion) completed, so the stub is the sole blocker.
Why: no knowledge-base retrieval client works at all. Worse for fidelity, because the handler is absent there is no implementation that produces a result location, so the provenance contract is unimplemented rather than merely untested: a client that follows a citation (HeadObject/GetObject on location.s3Location.uri, or correlates x-amz-bedrock-kb-data-source-id) has nothing to follow, and a later stub that returns plausible-looking but fabricated s3:// URIs would be silently wrong. A caller also cannot tell 'knowledge base does not exist' (404 ResourceNotFoundException) from 'operation missing' (501), and 501 is not a modeled error, so SDK error-handling branches never match.
Fix: implement the Retrieve handler and its serializer in the bedrock-agent-runtime crate (services/service-com-amazonaws-bedrockagentruntime-amazonbedrockagentruntimeservice/src/ops/retrieve.rs plus the router binding for POST /knowledgebases/{knowledgeBaseId}/retrieve), backed by knowledge-base/data-source state so that each returned KnowledgeBaseRetrievalResult's location is derived from the object actually ingested (location.type = "S3", s3Location.uri = s3://<bucket>/<key> of that object) and content.text is a span of that object's stored bytes; populate RetrievalResultMetadata's chunk-id / data-source-id / source-file-modality from that same state, and keep the ResourceNotFoundException (404) branch for an unknown knowledgeBaseId and the ValidationException (400) branch for an input violating the modeled constraints.

## Evidence
Expected: HTTP 200 from POST /knowledgebases/{knowledgeBaseId}/retrieve with retrievalResults non-empty; for each result location.type == "S3", location.s3Location.uri matching ^s3://(?P<bucket>[^/]+)/(?P<key>.+)$ where bucket/key name an object the caller ingested, HeadObject/GetObject on that URI succeeding with bytes whose MD5 matches what was uploaded, and content.text a whitespace-collapsed substring of those bytes.
Actual: botocore.exceptions.ClientError: An error occurred (NotImplemented) when calling the Retrieve operation: operation Retrieve is scaffolded but not implemented in this emulator (HTTP 501). The check never reaches any of its location assertions. 'NotImplemented' is not a modeled error for Retrieve (modeled: AccessDeniedException, BadGatewayException, ConflictException, DependencyFailedException, InternalServerException, ResourceNotFoundException, ServiceQuotaExceededException, ThrottlingException, ValidationException).

## Steps to Reproduce
1. Create an S3 bucket and put two small text/plain objects into it.
2. Stand up an S3 Vectors vector bucket and index, an IAM role for ingestion, then a bedrock-agent knowledge base over the S3 bucket with a data source, and run an ingestion job to completion.
3. Call bedrock-agent-runtime Retrieve(knowledgeBaseId=<kb id>, retrievalQuery={'text': 'Which launch code belongs to which project?'}, retrievalConfiguration={'vectorSearchConfiguration': {'numberOfResults': 5}}).
4. Observe HTTP 501 / error code NotImplemented with message 'operation Retrieve is scaffolded but not implemented in this emulator' instead of a 200 carrying retrievalResults whose location.s3Location.uri resolves at S3.
