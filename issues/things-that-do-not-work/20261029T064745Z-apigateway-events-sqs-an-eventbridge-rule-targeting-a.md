# apigateway__events__sqs: an EventBridge rule targeting a deployed REST stage never delivers — the InputTransformer payload, PathParameterValues substitution and HeaderParameters never reach the stage's AWS-type SQS integration

> _Note: this issue was identified against the code base at commit `595d3d5604be8cb7f050ded6602d61000805e4f4`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
PutTargets

## Description
One net-new root cause, grounded in one failing behavioral check that the replay report marks neither ALREADY FILED nor OWNED. Cause count: 1.

=== Cause 1 of 1: an EventBridge rule whose target is an execute-api ARN produces no request at the REST stage, so the transformed detail, the substituted path parameter and the mapped header are never delivered ===
AWS: Smithy (com.amazonaws.eventbridge#PutTargets) accepts a Target with Arn, RoleArn, HttpParameters{PathParameterValues, HeaderParameters, QueryStringParameters} and InputTransformer{InputPathsMap, InputTemplate}; PutEvents answers FailedEntryCount 0 for an accepted entry. Recorded behavior for an API Gateway target (the model documents the members but not the delivery semantics): a target ARN of the form arn:aws:execute-api:<region>:<account>:<api-id>/<stage>/<METHOD>/<path with a * wildcard> makes EventBridge sign and issue that HTTP request against the deployed stage using RoleArn; InputTransformer renders the request BODY from the InputTemplate with <d>/<t> substituted from InputPathsMap (so the body carries exactly the template's keys, here `wrapped` and `kind`); each value in HttpParameters.PathParameterValues replaces one `*` in the target ARN's path in order; each HeaderParameters entry is sent as that request header with its JSON-path value resolved from the event. The stage then runs its method's integration — here an AWS-type SQS SendMessage integration whose mapping template records the body plus $input.params().path.get('id'), the x-order-src header and $context.resourcePath as message attributes.
Emulator: nothing is delivered and the check never terminates — the runner kills it at the 60 s cap with no response recorded. The check's own direct, SigV4-signed POST to the same stage path is polled first precisely so the stage is proven to record what it receives independently of EventBridge, and the EventBridge leg then polls the sink queue for up to 180 s across retried PutEvents attempts; neither the warm-up nor the rule delivery reaches a terminal answer inside the cap. Hypothesis: either the stage's AWS-type SQS integration never answers (so the warm-up poll spins) or the EventBridge rule with an execute-api target never issues the signed request (so the sink poll spins); the report's single detail ("Check timed out after 60.0s") does not distinguish them, and both are the emulator's own.
Why: a client that routes events to a REST API through EventBridge gets PutEvents FailedEntryCount 0 — an accepted publish — and no request at the API and no error anywhere. The event is lost silently; there is no way to tell "the rule did not match", "the role was denied" (which AWS surfaces as a delivery failure, not a silent drop) and "delivery is not implemented" apart. Every InputTransformer/HttpParameters mapping a caller configures is unverifiable, and a caller's readiness poll blocks instead of failing.
Fix: the EventBridge target-delivery path for execute-api target ARNs (building and SigV4-signing the request with RoleArn, applying InputTransformer to the body and HttpParameters' PathParameterValues/HeaderParameters to the path and headers) and the API Gateway stage's AWS-type SQS integration request path (the Action=SendMessage mapping template, including $input.params().path, $input.params().header and $context.resourcePath) — each must produce a terminal answer in bounded time so a caller sees either delivery or a reported delivery failure.
Traces: apigateway__events__sqs.xsvc-apigateway-1-rule-delivers-transformed-detail-with-path-and-header-to-rest-stage.
