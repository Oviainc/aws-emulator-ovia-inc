# Default quota catalog misbinds QuotaCodes and drops Description for events, firehose, fms and seven more ServiceCodes

> _Note: this issue was identified against the code base at commit `7c1c192a4be1fd26f3761e762e61646b8dff0eae`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
ListAWSDefaultServiceQuotas

## Description
TEN net-new root causes, one per ServiceCode, all in the same component: the emulator's seeded default-quota catalog that ListAWSDefaultServiceQuotas reads. In every case the HTTP status is correct (200 expected, 200 served) and the envelope (Quotas list, pagination) is correct, so the defect is purely the catalog DATA: a QuotaCode is bound to a DIFFERENT quota's QuotaName/Value/Unit/Adjustable/Period/UsageMetric, and the modeled Description member is omitted. Smithy: ListAWSDefaultServiceQuotas -> ListAWSDefaultServiceQuotasResponse.Quotas: ServiceQuotaListDefinition of ServiceQuota; ServiceQuota members QuotaCode (@length 1-128, @pattern ^[a-zA-Z][a-zA-Z0-9-]{1,128}$), QuotaName, Value (QuotaValue double @range 0-10000000000), Unit, Adjustable (boolean, default false), GlobalQuota, Period (QuotaPeriod), UsageMetric (MetricInfo), Description (QuotaDescription @length 0-350). QuotaCode is the stable identity a caller resolves a limit by, and Description is a modeled member AWS populates for these catalogs, so a row whose code points at another quota's numbers is a wrong answer served with a success status.

Cause 1 of 10: ServiceCode events (Amazon EventBridge).
AWS: each default quota carries its own Description and its own QuotaCode binding - L-664C5505 is 'Event pattern size' (Description 'Maximum size of an event pattern, in characters.', Value 2048), L-388D1D08 is 'Targets per rule' (Value 5), L-DF788473 is '[EventsV2] Event Buses' (Value 5, Period PeriodUnit MINUTE / PeriodValue 5, UsageMetric MetricName ResourceCount with MetricDimensions.Resource 'EventsV2/EventBus' and Type 'Resource', MetricStatisticRecommendation 'Maximum'), and L-CB72B930 is non-adjustable (Adjustable false).
Emulator: Description is absent on these entries; L-664C5505 comes back as 'Invocations throttle limit in transactions per second' with Value 18750; L-388D1D08 as 'Connections' with Value 3000; L-DF788473 as 'EnableRule throttle limit in transactions per second' with Period SECOND/1 and an API-shaped UsageMetric (Resource 'EnableRule', Type 'API', MetricName 'CallCount', MetricStatisticRecommendation 'Sum') and Value 50; L-CB72B930 reports Adjustable true. The same name/value/Description drift repeats on L-244521F2, L-39263BDC, L-3C47459F, L-5425B7E9, L-5540C5E3, L-595D6D42, L-5D1D13E3, L-658A4FD9, L-755FD01C, L-8331B29E, L-9B653E91, L-A8AFA624, L-D082A4F6, L-E2110C81, L-FB1C3A6D and L-FC354966.
Why: a client sizing an event pattern from L-664C5505 reads 18750 instead of 2048 and builds patterns the real service rejects; utilization tooling that keys off UsageMetric/Period builds a CloudWatch query for an API call count where AWS reports a resource count.
Fix: the default-quota catalog data for ServiceCode events in the service-quotas crate (the seed table the ListAWSDefaultServiceQuotas handler reads), not the handler, its pagination or its serializer, which frame the list correctly.
