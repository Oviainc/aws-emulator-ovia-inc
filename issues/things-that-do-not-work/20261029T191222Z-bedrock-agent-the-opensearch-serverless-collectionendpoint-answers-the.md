# bedrock-agent: the OpenSearch Serverless collectionEndpoint answers the AWS-JSON front door (400 SerializationException 'missing required header x-amz-target'), so no vector knowledge base can be built and 11 knowledge-base / data-source / ingestion-job checks never reach their assertions

> _Note: this issue was identified against the code base at commit `92c3b140342b1bc1fab2a232b8cee3f25ea78ff5`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateKnowledgeBase

## Description
ONE root cause, reached through 11 bedrock-agent behavioral checks (service token = leading segment of the check ids).

=== Cause 1 of 1: a VECTORSEARCH collection's published collectionEndpoint serves the AWS-JSON RPC dispatcher instead of the OpenSearch REST data plane, so the vector index every bedrock-agent knowledge base requires can never be created ===
AWS: recorded behavior only for the collection data plane (the opensearchserverless Smithy model covers the control plane; a collection's data plane is the OpenSearch REST API and is not modeled). Smithy consulted on the Bedrock side: bedrock-agent CreateKnowledgeBase (PUT /knowledgebases/, success 202, errors AccessDeniedException 403 / ConflictException 409 / ValidationException 400 / ThrottlingException 429 / ServiceQuotaExceededException 402) takes a required roleArn plus a storageConfiguration of type OPENSEARCH_SERVERLESS carrying collectionArn + vectorIndexName + fieldMapping — i.e. the index must already exist in the collection before the knowledge base is created; StartIngestionJob (PUT /knowledgebases/{knowledgeBaseId}/datasources/{dataSourceId}/ingestionjobs/, 202) can only be reached once that knowledge base exists. Recorded behavior: once CreateCollection(type='VECTORSEARCH') is ACTIVE, BatchGetCollection publishes a collectionEndpoint, and a SigV4-signed (signing service name `aoss`) `PUT https://<collectionEndpoint>/<indexName>` carrying a knn_vector mapping — exactly the request opensearch-py's `indices.create` issues, which carries NO `x-amz-target` header because the OpenSearch REST API has no RPC target — is accepted.
Emulator: that request is answered HTTP 400 with body {"__type":"SerializationException","message":"missing required header `x-amz-target`"} (all fixed text, no variable part), i.e. the published collectionEndpoint host falls through to the emulator's AWS-JSON protocol front door, which demands an X-Amz-Target header. No OpenSearch REST verb is servable on a collection endpoint for any principal.
Why: a client that provisions a Bedrock knowledge base the documented way is stopped at step one. Nothing downstream is observable: knowledge-base and data-source lifecycle (status transitions, 404-not-500 on a deleted resource), ingestion-job lifecycle/FIFO ordering/async completion/stop semantics, StartIngestionJob's ConflictException under concurrency, timestamp precision and resource-policy enforcement are all unreachable, so every one of these guarantees is unverified in the emulator.
Fix: the opensearchserverless collection data plane plus the emulator's host/endpoint routing table — route the published collectionEndpoint host to an OpenSearch REST handler (index create/get/delete, document index/search) that authorises SigV4 `aoss` requests against the collection's data-access policy, instead of letting the host reach the AWS-JSON `x-amz-target` dispatcher. NOTE for the fixer: the open issue 20261029T171944Z-bedrock-agent-the-opensearch-serverless-collection-endpoint-answers.md records this same wall but carries only the replay key of bedrock-agent.knowledge-base-document-blob-round-trip; the 11 checks below were NOT marked owned by it, so they are recorded here and must be re-replayed. If that issue's fix lands first this cause should close with it rather than be fixed twice.
Traces: 9 checks surface the 400 directly as opensearchpy.exceptions.RequestError(400, '{"__type":"SerializationException",...}') — bedrock-agent.concurrent-start-ingestion-job-same-datasource, .data-source-lifecycle, .get-deleted-resource-returns-404-not-500, .ingestion-job-async-completion-timing, .ingestion-job-fifo-per-datasource, .ingestion-job-lifecycle, .knowledge-base-lifecycle, .stop-ingestion-job-halts-progress, .stop-ingestion-job-on-terminal-job-rejected. 2 more are reported as 'Check timed out after 60.0s' because their `_create_vector_index` helper retries the same failing PUT 12–30 times at 10s intervals: bedrock-agent.ingestion-job-timestamp-precision-preserved and .resource-policy-round-trip-enforced.

## Evidence
Expected: SigV4-'aoss'-signed `PUT https://<collectionEndpoint>/<indexName>` (body {'settings':{'index.knn':true},'mappings':{'properties':{'<vector field>':{'type':'knn_vector','dimension':<dims>},...}}}) accepted with 200/201, then bedrock-agent create_knowledge_base(storageConfiguration OPENSEARCH_SERVERLESS) / create_data_source / start_ingestion_job proceed.
Actual: HTTP 400 `{"__type":"SerializationException","message":"missing required header `x-amz-target`"}` from the published endpoint on every attempt, surfaced by opensearch-py as `opensearchpy.exceptions.RequestError(400, '{"__type":"SerializationException","message":"missing required header `x-amz-target`"}')`. The error status (400), the __type (SerializationException) and that message are entirely fixed text emitted by the JSON protocol front door; nothing in it is derived from the request, which is what shows the request was never routed to a data-plane handler. Two sibling checks instead report 'Error: Check timed out after 60.0s', which is this same 400 inside their retry loop.

## Steps to Reproduce
1) opensearchserverless: create_security_policy(type='encryption'), create_security_policy(type='network', AllowFromPublic=true), create_access_policy(type='data', Principal=[<kb role arn>, <caller arn>], Rules granting aoss:* on collection/<c> and index/<c>/*), create_collection(name=<c>, type='VECTORSEARCH'). 2) Poll batch_get_collection(ids=[<id>]) until status=='ACTIVE' and read collectionDetails[0].collectionEndpoint. 3) SigV4-sign with service name 'aoss' and send `PUT https://<collectionEndpoint>/<indexName>` with the knn_vector mapping body (e.g. opensearch-py OpenSearch(...).indices.create(index=<indexName>, body=<body>)) -> emulator answers 400 SerializationException 'missing required header `x-amz-target`' instead of creating the index. 4) Because the index never exists, bedrock-agent create_knowledge_base / create_data_source / start_ingestion_job / get_ingestion_job / stop_ingestion_job are never reached.
