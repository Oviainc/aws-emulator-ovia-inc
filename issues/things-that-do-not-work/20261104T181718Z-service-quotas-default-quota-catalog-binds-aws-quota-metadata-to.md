# Default quota catalog binds AWS quota metadata to wrong QuotaCodes for events, firehose and eight more service codes

> _Note: this issue was identified against the code base at commit `41f2e9525c7487ad1fe04cb3242a50ad61bb0d09`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
ListAWSDefaultServiceQuotas

## Description
TEN net-new root causes, one per ServiceCode, all of the same shape: `ListAWSDefaultServiceQuotas` answers 200 with the right number of rows and the right `QuotaCode` strings, but the metadata attached to those codes is NOT the AWS quota catalog. Two distinct faults recur in every cause: (a) MISBINDING - the QuotaName/Value/Unit/Period/UsageMetric of one AWS quota are attached to a DIFFERENT QuotaCode, so a code resolves to another quota's limit; (b) RE-AUTHORED `Description` - AWS's catalog text is replaced by an emulator-generated template, most often "The maximum number of <Api> requests you can make per second in this account in the current Region."

Shared AWS reference for all ten causes - Smithy `ListAWSDefaultServiceQuotas` (services/service-com-amazonaws-servicequotas-servicequotasv20190624) returns `Quotas: ServiceQuotaListDefinition` of `ServiceQuota{ServiceCode, ServiceName, QuotaArn, QuotaCode, QuotaName, Value (QuotaValue, @range 0..10000000000), Unit, Adjustable, GlobalQuota, UsageMetric (MetricInfo), Period (QuotaPeriod), QuotaContext, Description (@length 0..350)}`. The model does NOT enumerate the catalog rows themselves, so for the row CONTENT this is recorded behavior only: the requirement is that for a given `ServiceCode`, each `QuotaCode` carries AWS's own `QuotaName`, `Description`, `Value`, `Unit`, `Period` and `UsageMetric` for THAT code. Shared Why: Service Quotas is a discovery API. A client that reads a default limit (capacity planners, Terraform/CDK pre-flight checks, quota-increase tooling, `aws service-quotas list-aws-default-service-quotas`) gets a number that belongs to an unrelated quota, so it sizes against the wrong limit and the quota it then requests an increase for is not the quota it meant. Re-worded Descriptions additionally break the console/CLI text and, where the re-wording inverts the meaning (minimum presented as maximum), mislead a human reader. Shared Fix: the default-quota catalog data behind the `ListAWSDefaultServiceQuotas` handler in the service-quotas crate - the per-ServiceCode catalog must be keyed by AWS `QuotaCode` and carry AWS's verbatim row for that code, instead of generating rows positionally and synthesising Description text from the API name.

Cause 1 of 10: ServiceCode `events` (EventBridge). Fixture service-quotas-catalog-list-aws-default-service-quotas-events, step task#1 - 64 diverging keys. AWS: `L-755FD01C` is QuotaName 'Rate of invocations per API destination', Value 300.0, Description 'The maximum number of invocations per second to send to each API destination endpoint per account per Region. Once the quota is met, future invocations to that API endpoint are throttled. The invocations will still occur, but are delayed.'; `L-244521F2` is QuotaName 'Number of rules', Value 300.0, Description 'Maximum number of rules an account can have per event bus'; `L-CB72B930`.Description is 'The maximum number of requests per second for CreateEndpoint API. Additional requests are throttled.'; `L-A8AFA624` is the UpdateEndpoint API rate. Emulator: `L-755FD01C` -> QuotaName 'PutRule throttle limit in transactions per second', Value 50.0; `L-244521F2` -> QuotaName 'API destinations', Value 3000.0; `L-CB72B930`.Description -> 'The maximum number of CreateEndpoint requests you can make per second in this account in the current Region.'; `L-A8AFA624` -> the DeleteRule rate; `L-5540C5E3` (Invocations) Description replaced by the same per-API template. `L-39263BDC` and `L-D082A4F6` also diverge on Period, QuotaContext and UsageMetric.

Cause 2 of 10: ServiceCode `firehose`. Fixture service-quotas-catalog-list-aws-default-service-quotas-firehose, step task#1 - 25 diverging keys.
