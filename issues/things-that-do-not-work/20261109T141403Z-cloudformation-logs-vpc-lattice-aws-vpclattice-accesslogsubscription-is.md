# cloudformation__logs__vpc-lattice: AWS::VpcLattice::AccessLogSubscription is refused as an unrecognized resource type, so no VPC Lattice access-log subscription can be deployed from a template

> _Note: this issue was identified against the code base at commit `22941ee6d43df66d29bcadd7a62b7906e5868e84`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateStack

## Description
Cause 1 of 1: CloudFormation's template resource-type registry does not carry the AWS::VpcLattice::AccessLogSubscription resource type, so CreateStack refuses at template-format validation any stack that declares one. Failing check ids: cloudformation__logs__vpc-lattice.deploy-vpclattice-access-log-subscription-round-trip-and-delete, cloudformation__logs__vpc-lattice.deploy-vpclattice-access-log-subscription-missing-log-group-rejected.

AWS: AWS CloudFormation registers AWS::VpcLattice::AccessLogSubscription as a supported resource type (https://docs.aws.amazon.com/AWSCloudFormation/latest/TemplateReference/aws-resource-vpclattice-accesslogsubscription.html), so CreateStack ACCEPTS a template declaring it and answers 200 with a StackId; provisioning or refusal is then decided by its registry handler DURING the stack operation, not by template-format validation. Smithy (services/service-com-amazonaws-cloudformation-cloudformation/smithy-model/com-amazonaws-cloudformation-cloudformation.json): CreateStack input TemplateBody (@length min 1), output StackId; modeled errors are only AlreadyExistsException, InsufficientCapabilitiesException, LimitExceededException and TokenAlreadyExistsException — none of which is this refusal. The 'Template format error: Unrecognized resource types: [...]' ValidationError is recorded behavior only: HTTP 400, Code ValidationError, with fixed text 'Template format error: Unrecognized resource types: [' ... ']' and the comma-separated list of genuinely unregistered type names as the variable part; AWS raises it only for a type it does not register, which excludes this one. Downstream of acceptance the recordings show: (a) a service network + AWS::Logs::LogGroup + AccessLogSubscription stack reaches CREATE_COMPLETE, the subscription's Ref is its ARN and VPC Lattice ListAccessLogSubscriptions for the network reports that ARN with destinationArn equal to the log group's ARN suffixed ':*' (arn:<partition>:logs:<region>:<account>:log-group:<name>:*), the network's Ref equals the ARN ListServiceNetworks reports, an update dropping the subscription removes it (GetAccessLogSubscription then answers ResourceNotFoundException 'AccessLogSubscription <id> cannot be found.') while the network answers, and after stack delete GetServiceNetwork answers 'ServiceNetwork <id> cannot be found.' and the log group is gone from Logs; (b) a subscription whose DestinationArn names a log group that does not exist is refused by the VPC LATTICE HANDLER, not by early validation — DescribeEvents carries NO VALIDATION_ERROR row — driving the stack to ROLLBACK_COMPLETE with a CREATE_FAILED ResourceStatusReason of the form 'Resource handler returned message: "AccessLogSubscription destination <destination-arn> cannot be found. (Service: VpcLattice, Status Code: 404, Request ID: <id>) (SDK Attempt Count: <n>)" (RequestToken: <token>, HandlerErrorCode: NotFound)', where the fixed text is 'AccessLogSubscription destination ' ... ' cannot be found.' plus the envelope, the destination ARN comes from the template and the request id/token/attempt count are per-run; the rolled-back service network and log group are then absent from ListServiceNetworks and DescribeLogGroups.

Emulator: CreateStack is refused outright with HTTP 400 ValidationError 'Template format error: Unrecognized resource types: [AWS::VpcLattice::AccessLogSubscription]' for both checks. AWS::VpcLattice::ServiceNetwork and AWS::Logs::LogGroup are absent from that list, so they are registered and the gap is exactly AWS::VpcLattice::AccessLogSubscription. Because the call raises at CreateStack, no stack is created and every downstream assertion of both checks (CREATE_COMPLETE/ROLLBACK_COMPLETE, the handler's 404 NotFound reason, the absence of a VALIDATION_ERROR row, Ref agreement, the destinationArn ':*' suffix, the subscription-dropping update and the post-rollback/post-delete absence in VPC Lattice and Logs) is unreachable.

Why: a client that enables VPC Lattice access logging declaratively — any CloudFormation, SAM or CDK stack with an AWS::VpcLattice::AccessLogSubscription — cannot deploy at all against the emulator. The refusal arrives as a template-format ValidationError at submit time, which a client reads as 'my template is malformed' and will neither retry nor poll, instead of as a stack operation whose outcome it can observe. The emulator also cannot reproduce AWS's path for a missing log-group destination, which must surface as a resource-handler CREATE_FAILED reason with HTTP 404 and HandlerErrorCode NotFound followed by a rollback, not as an up-front template error.

Fix: CloudFormation's template resource-type registry and the VPC Lattice resource-type handler it dispatches to. Register AWS::VpcLattice::AccessLogSubscription so template-format validation accepts it, and implement its create/update/delete handler against VPC Lattice state so Ref is the subscription ARN, destinationArn is normalised to the log group's ARN with the ':*' suffix, a destination log group that does not exist is refused by the handler with the NotFound reason above (rolling the stack back rather than emitting a VALIDATION_ERROR event), and stack delete/an update dropping the subscription removes it.

Traces: cloudformation__logs__vpc-lattice.deploy-vpclattice-access-log-subscription-round-trip-and-delete, cloudformation__logs__vpc-lattice.deploy-vpclattice-access-log-subscription-missing-log-group-rejected (both refused with '[AWS::VpcLattice::AccessLogSubscription]').

## Evidence

Expected (AWS): CreateStack returns a StackId; the stack whose Als DestinationArn names a nonexistent log group reaches ROLLBACK_COMPLETE with NO VALIDATION_ERROR event row; the Als CREATE_FAILED reason parses to message 'AccessLogSubscription destination arn:<partition>:logs:<region>:<account>:log-group:<missing-name> cannot be found. (Service: VpcLattice, Status Code: 404, Request ID: <id>) (SDK Attempt Count: <n>)' with HandlerErrorCode 'NotFound'; ListServiceNetworks then shows no network with the rolled-back name and DescribeLogGroups no log group with the rolled-back name; the same template pointing at its real log group reaches CREATE_COMPLETE and ListAccessLogSubscriptions reports (Ref, 'arn:<partition>:logs:<region>:<account>:log-group:<name>:*').
Actual (emulator): botocore.exceptions.ClientError: An error occurred (ValidationError) when calling the CreateStack operation: Template format error: Unrecognized resource types: [AWS::VpcLattice::AccessLogSubscription]  (HTTP 400, Code ValidationError)

Check cloudformation__logs__vpc-lattice.deploy-vpclattice-access-log-subscription-round-trip-and-delete
Expected (AWS): CreateStack returns a StackId; CREATE_COMPLETE; the subscription reads back through VPC Lattice with the declared network, destination and tags; an UpdateStack dropping the subscription removes it so GetAccessLogSubscription answers ResourceNotFoundException 'AccessLogSubscription <id> cannot be found.'; after delete_stack GetServiceNetwork answers 'ServiceNetwork <id> cannot be found.' and the log group no longer exists in Logs.
Actual (emulator): ClientError (ValidationError) on CreateStack: Template format error: Unrecognized resource types: [AWS::VpcLattice::AccessLogSubscription]  (HTTP 400). AWS::VpcLattice::ServiceNetwork and AWS::Logs::LogGroup are absent from the list, so only the subscription type is unregistered.

Message anatomy: 'Template format error: Unrecognized resource types: [' and ']' are fixed text and the type-name list comes from the submitted template's Resources; for a template AWS accepts, the message must not be emitted at all. In the expected handler reason, 'Resource handler returned message: "..." (RequestToken: <token>, HandlerErrorCode: NotFound)' and 'AccessLogSubscription destination ' / ' cannot be found.' are fixed text, the destination ARN is the value from the template, and Request ID / RequestToken / SDK Attempt Count are per-run values.

## Steps to Reproduce
1. Point a boto3/botocore cloudformation client at the emulator.
2. Submit a template declaring a service network, a log group and an access-log subscription:
   cf.create_stack(StackName='t1', TemplateBody=json.dumps({'AWSTemplateFormatVersion':'2010-09-09','Resources':{
     'Sn':{'Type':'AWS::VpcLattice::ServiceNetwork','Properties':{'Name':'sn1'}},
     'Lg':{'Type':'AWS::Logs::LogGroup','Properties':{'LogGroupName':'/sim2real/lg1','RetentionInDays':1}},
     'Als':{'Type':'AWS::VpcLattice::AccessLogSubscription','Properties':{'ResourceIdentifier':{'Ref':'Sn'},'DestinationArn':{'Fn::GetAtt':['Lg','Arn']}}}}}))
   Observe HTTP 400 ValidationError 'Template format error: Unrecognized resource types: [AWS::VpcLattice::AccessLogSubscription]' instead of a 200 with a StackId.
3. Repeat with DestinationArn pointing at a log group that does not exist: AWS would accept the template and roll the stack back with the handler's 404 NotFound reason; the emulator refuses at CreateStack identically.
4. Replay both behavioral checks listed in Issue-Trace-Ids; both abort at their first create_stack call.
