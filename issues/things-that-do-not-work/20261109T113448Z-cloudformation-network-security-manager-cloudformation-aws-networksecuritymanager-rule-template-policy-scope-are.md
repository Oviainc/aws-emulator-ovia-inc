# cloudformation: AWS::NetworkSecurityManager::{Rule,Template,Policy,Scope} are not registered resource types — CreateStack refuses every NSM template with ValidationError "Unrecognized resource types"

> _Note: this issue was identified against the code base at commit `e38416fc0970ac2ae0c65df6bda0d7aff4be2337`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateStack

## Description
Cause 1 of 1: CloudFormation's template resource-type registry does not know the AWS::NetworkSecurityManager::* resource types, so no Network Security Manager estate can be deployed as infrastructure-as-code at all. Failing checks: cloudformation__network-security-manager.deploy-network-security-manager-waf-stack-reads-back-then-removed, cloudformation__network-security-manager.deploy-network-security-manager-policy-ambiguous-reference-rejected.

AWS: recorded behavior only (CloudFormation's supported-resource set is not expressed in the Smithy model; the Network Security Manager control plane that backs these types IS modeled in this repo — services/service-com-amazonaws-networksecuritymanager-piccolocustomerapiservice declares CreateRule, CreateTemplate, CreatePolicy, CreateScope, Get*/List*/Delete* for exactly those resources). In the recording, CreateStack with a TemplateBody whose Resources declare Type AWS::NetworkSecurityManager::Rule, AWS::NetworkSecurityManager::Template, AWS::NetworkSecurityManager::Policy and AWS::NetworkSecurityManager::Scope is ACCEPTED: it returns 200 with a StackId, the stack then walks to a terminal status (CREATE_COMPLETE for a valid template, ROLLBACK_COMPLETE when a resource handler refuses), the created rules/templates/policies are readable through Network Security Manager's own ListRules/ListTemplates/ListPolicies/GetPolicy by the names the template declared, and DeleteStack removes them so GetPolicy afterwards answers ResourceNotFoundException "Policy not found: <policy id>". AWS reserves the ValidationError "Unrecognized resource types" refusal for types it genuinely does not support.

Emulator: CreateStack is refused up-front. HTTP 400, Error.Code=ValidationError, Error.Message="Template format error: Unrecognized resource types: [AWS::NetworkSecurityManager::Rule, AWS::NetworkSecurityManager::Template, AWS::NetworkSecurityManager::Policy]" for the policy check, and "Template format error: Unrecognized resource types: [AWS::NetworkSecurityManager::Rule, AWS::NetworkSecurityManager::Template, AWS::NetworkSecurityManager::Policy, AWS::NetworkSecurityManager::Scope]" for the WAF-stack check. In that message the fixed text is "Template format error: Unrecognized resource types: [" … "]"; the bracketed list is a value taken from the request's template (the set of declared Types the registry did not resolve), so the specific type names and their order are not part of the requirement — the defect is that these types appear in the list at all, when AWS resolves them.

Why: a client deploying Network Security Manager through CloudFormation, CDK or SAM never gets a stack. The call fails at CreateStack, so nothing downstream is reachable: no stack events, no resource-handler failure reason for an invalid Policy (AWS reports it as 'Resource handler returned message: "Each AssociatedTemplateAndRuleList entry must specify exactly one of TemplateArn or RuleArn." (RequestToken: <token>, HandlerErrorCode: InvalidRequest)' on the Policy resource's CREATE_FAILED event), no ROLLBACK_COMPLETE, no rollback-absence check through ListPolicies/ListTemplates/ListRules, and no delete-propagation to Network Security Manager. IaC is the only supported way to manage these resources for many users, so the whole service is undeployable even though its own API is present.

Fix: CloudFormation's template resource-type registry (the table that decides which Type strings validate) plus the resource provisioner that maps each type to its backing control-plane calls — register AWS::NetworkSecurityManager::Rule, ::Template, ::Policy and ::Scope and wire their Create/Read/Update/Delete to the networksecuritymanager operations CreateRule/CreateTemplate/CreatePolicy/CreateScope, Get*, Update*, Delete*, including the Fn::GetAtt attributes the templates read (Rule.RuleArn, Template.TemplateArn) and propagation of the resource handler's refusal into the resource's CREATE_FAILED ResourceStatusReason envelope. Note the analogous open issue 20261103T041241Z-ec2-ecs-elasticache-cloudformation-rejects-aws-ec2-transitgatewayroutetableassociation-and-aws-ec2.md (same unrecognized-type refusal, different types); it does not cover these types. Separately, the Network Security Manager control plane itself is still scaffolded — CreateRule answers NotImplemented — which is already filed and is a prerequisite for the provisioner to succeed.

Traces: cloudformation__network-security-manager.deploy-network-security-manager-waf-stack-reads-back-then-removed, cloudformation__network-security-manager.deploy-network-security-manager-policy-ambiguous-reference-rejected.

## Evidence
Expected (AWS): CreateStack(TemplateBody=<Resources declaring AWS::NetworkSecurityManager::Rule/::Template/::Policy[/::Scope]>) -> HTTP 200 with a StackId; the stack reaches CREATE_COMPLETE (valid template) or ROLLBACK_COMPLETE with the Policy resource's CREATE_FAILED ResourceStatusReason = 'Resource handler returned message: "Each AssociatedTemplateAndRuleList entry must specify exactly one of TemplateArn or RuleArn." (RequestToken: <token>, HandlerErrorCode: InvalidRequest)'; the declared resources then read back through nsm ListRules/ListTemplates/ListPolicies/GetPolicy (status ACTIVE, associatedTemplateAndRuleList [{templateArn: <arn>}]) and disappear after DeleteStack (GetPolicy -> ResourceNotFoundException "Policy not found: <id>").

Actual (emulator): both checks die on the first CreateStack call:
  botocore.exceptions.ClientError: An error occurred (ValidationError) when calling the CreateStack operation: Template format error: Unrecognized resource types: [AWS::NetworkSecurityManager::Rule, AWS::NetworkSecurityManager::Template, AWS::NetworkSecurityManager::Policy]
  botocore.exceptions.ClientError: An error occurred (ValidationError) when calling the CreateStack operation: Template format error: Unrecognized resource types: [AWS::NetworkSecurityManager::Rule, AWS::NetworkSecurityManager::Template, AWS::NetworkSecurityManager::Policy, AWS::NetworkSecurityManager::Scope]
No StackId is minted, so no stack, event, rollback or read-back is observable.
