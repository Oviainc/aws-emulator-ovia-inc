# CreatePackagingConfiguration duplicate-Id refusal says "PackagingConfiguration with id=..." where AWS says "PackagingConfig with id=... already exists"

> _Note: this issue was identified against the code base at commit `eb700133cb06fc392969a2d3238587da7167d6ed`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreatePackagingConfiguration

## Description
One net-new root cause on the MediaPackage VOD (restJson1, sdkId "MediaPackage Vod") control plane: the duplicate-Id refusal of CreatePackagingConfiguration carries the wrong entity noun in its message text. The uniqueness semantics themselves are correct under contention — exactly one of 8 concurrent racers won and the other 7 were each refused with UnprocessableEntityException — so what diverges is only the message string.

=== Cause 1 of 1: duplicate-Id UnprocessableEntityException message uses the full shape name "PackagingConfiguration" instead of AWS's "PackagingConfig" ===
AWS: Smithy (services/service-com-amazonaws-mediapackagevod-mediapackagevod/smithy-model/com-amazonaws-mediapackagevod-mediapackagevod.json): CreatePackagingConfiguration POST /packaging_configurations, code 200, input {Id @required jsonName "id", PackagingGroupId @required jsonName "packagingGroupId", HlsPackage/DashPackage/CmafPackage/MssPackage, Tags}, modeled errors ForbiddenException(403), NotFoundException(404), UnprocessableEntityException(errorKind client, httpError 422), TooManyRequestsException(429), InternalServerErrorException(500), ServiceUnavailableException(503). The model does not state the message text, so for the wording this is recorded behavior only: creating a packaging configuration whose Id already exists under the account/region is refused with error code UnprocessableEntityException (HTTP 422) and the message "PackagingConfig with id=<Id> already exists". In that template the fixed text is "PackagingConfig with id=" and " already exists"; the single variable part is <Id>, taken verbatim from the request's Id input member. Note the entity noun is the abbreviated "PackagingConfig", not the shape/operation noun "PackagingConfiguration" — the same abbreviation style this API uses in its create/describe refusals for this resource. This holds under concurrency: of N racers posting the same Id, exactly one succeeds and every loser gets this same 422/UnprocessableEntityException with this same message.
Emulator: returns the right error code and status for every loser (7 of 8 racers got UnprocessableEntityException, 1 won, and the resource is afterwards describable), but words the message as "PackagingConfiguration with id=<Id> already exists" — it interpolates the Id correctly and uses the correct "... with id=... already exists" frame, but spells the entity as "PackagingConfiguration". Replay detail: AssertionError: unexpected losing-racer message 'PackagingConfiguration with id=<generated-id> already exists'; all 7 loser tuples in the result list carry that identical code/message pair, so this is a single wording defect in the shared refusal builder, not a race artifact.
Why: the error message is part of the contract a client observes. MediaPackage VOD clients, idempotent-create wrappers, CDK/Terraform-style provisioners and log scrapers that recognise AWS's "PackagingConfig with id=... already exists" to treat the 422 as "already exists, adopt it" never match the emulator's string and fall through to a generic failure branch; conversely any test asserting AWS's wording gets a false failure. Because the code and status are already right, the divergence is silent except in message-matching paths — the worst case for debugging.
Fix: the duplicate-Id (already-exists) refusal branch of the CreatePackagingConfiguration handler in the mediapackagevod service crate — specifically the refusal/message builder it shares with the other packaging-configuration refusals, which currently derives the entity noun from the shape or operation name. It must emit "PackagingConfig with id=<requested Id> already exists" while keeping error code UnprocessableEntityException and HTTP 422, and must keep emitting it for every loser when the create is attempted concurrently (the existence check and the insert must stay atomic so exactly one racer wins). Audit the sibling noun usages in this crate for the same shape-name-derived wording (the packaging-group and asset already-exists refusals) so the abbreviation rule is applied wherever the recordings show it.
Traces: mediapackage-vod.concurrent-packaging-configuration-duplicate-id-contention. The check's trailing positive control (DescribePackagingConfiguration returning the winner's Id) was not reached because the message assertion aborts first, so it is unverified rather than known-good.
