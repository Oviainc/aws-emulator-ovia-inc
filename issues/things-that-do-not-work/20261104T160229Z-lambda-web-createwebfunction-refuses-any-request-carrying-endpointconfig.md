# lambda-web CreateWebFunction refuses any request carrying endpointConfig with 501 NotImplemented, so no web function can be created through the documented create path (1 cause)

> _Note: this issue was identified against the code base at commit `f5f38caeaa03e56870175fb074275b9cd1e72c06`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateWebFunction

## Description
Cause 1 of 1: `CreateWebFunction` answers HTTP 501 `NotImplemented` whenever the request carries the optional `endpointConfig` member, and stores nothing. This blocks every behavioral check of this service's resource-policy and tagging planes, because each of them creates its fixture function the way the API documents it — with an initial endpoint.

Failing check ids for this cause: lambda-web.delete-resource-policy-with-stale-revision-leaves-policy-unchanged, lambda-web.delete-web-function-cascades-tags-and-resource-policy, lambda-web.get-resource-policy-revision-id-is-stable-until-the-next-mutation, lambda-web.put-resource-policy-rejects-malformed-policy-without-disturbing-existing-policy, lambda-web.put-resource-policy-revision-chain-rejects-stale-revision-at-each-generation, lambda-web.tag-resource-merges-new-keys-without-removing-existing-tags, lambda-web.tag-resource-rejects-reserved-aws-prefix-key-and-applies-no-tags, lambda-web.untag-resource-is-idempotent-for-a-key-that-was-never-set.

AWS: Smithy (services/service-com-amazonaws-lambdaweb-lambdaweb/smithy-model/com-amazonaws-lambdaweb-lambdaweb.json), service LambdaWeb (sdkId "Lambda Web", restJson1). `CreateWebFunction` is `PUT /2025-03-07/web-functions`, success code 202, and its documentation reads "Creates a web function with an initial revision and endpoint. To create a web function, you provide the function name, revision configuration (code and service settings), and endpoint configuration." Its input member `endpointConfig` targets `EndpointConfig` (required members `endpointName`, `endpointType` one of HomeRegion|MultiRegion|PerRegion, `authType` one of ApplicationManaged|IamAuth; optional `description`, `autoDeploymentMode`, `regions`, `scalingConfig`, `throttleConfig`) and is documented as "The configuration for the initial endpoint of the web function." The output member `endpoint` targets `FunctionEndpointSummary` — "A summary of the initial endpoint created with the web function" — whose required members are endpointArn, endpointName, endpointType, domainName (pattern ^([a-z0-9-]+\.)+[a-z]+$), authType, autoDeploymentMode, revisionWeights, regions, state, stateReason, createdAt, updatedAt. The operation's only modeled errors are AccessDeniedException (403), ConflictException (409), InternalServerException (500), ResourceNotFoundException (404), ServiceQuotaExceededException (402), ThrottlingException (429) and ValidationException (400); 501 / `NotImplemented` is not among them and is not a shape in this model. So for a well-formed request that names a fresh function, a valid `revisionConfig` and a valid `endpointConfig`, AWS returns 202 with the function Pending, the initial revision summary, and the initial endpoint summary — it never refuses the call for supplying `endpointConfig`.

Emulator: the handler refuses the request before touching state whenever `endpointConfig` is present, returning the synthetic scaffold error — HTTP 501, error code `NotImplemented`, message `operation CreateWebFunction's endpointConfig is scaffolded but not implemented in this emulator`. In that message the only variable part is the operation/member label `CreateWebFunction's endpointConfig`; the rest is the scaffold's fixed text, and neither the code nor the status nor the wording corresponds to anything AWS returns for this request class. Requests without `endpointConfig` are served normally, so the function store itself works; it is only the documented create-with-endpoint path that is refused. Because nothing is stored, the subsequent PutResourcePolicy / GetResourcePolicy / DeleteResourcePolicy / TagResource / UntagResource / DeleteWebFunction behavior these checks assert is never reached at all.

Why: a client following the API documentation (and every SDK example, which passes functionName + revisionConfig + endpointConfig in one call) cannot create a web function in this emulator. It receives a non-modeled 501 with error code `NotImplemented`, which no SDK error matcher for this service handles: it is not a modeled exception, so code branching on ValidationException/ConflictException/ServiceQuotaExceededException falls through to a generic failure, and retry classifiers see a 501 the call can never satisfy. The entire resource-policy, tagging and endpoint surface of the service is therefore unreachable for any caller that asks for an initial endpoint, and a caller cannot discover that the function was not created from the error class.

Fix: belongs in the CreateWebFunction handler and in the endpoint slice of the service state it delegates to. The handler must accept `endpointConfig`, validate it as the model and the member docs require (endpointName naming rule, endpointType/authType enums, and the `regions` rule — required and containing at least one non-home Region for MultiRegion/PerRegion, omitted-or-home-Region-only for HomeRegion — refused as ValidationException/400, not 501), create the initial endpoint in state alongside the function and its initial revision, and populate the response's `endpoint` member with a complete FunctionEndpointSummary (all required members, including a domainName matching the modeled pattern and revisionWeights pointing at the initial revision) so that the endpoint read/list/update/delete operations of the same service can see it. The scaffold's `NotImplemented` channel must not be used to refuse a modeled, well-formed request.

Traces: the eight failing check ids listed above; file and line citations: services/service-com-amazonaws-lambdaweb-lambdaweb/src/ops/create_web_function.rs lines 198-205 (the `endpoint_config.is_some()` refusal) and line 311 (`endpoint: None`), with the endpoint slice still scaffolded at services/service-com-amazonaws-lambdaweb-lambdaweb/src/ops/create_web_function_endpoint.rs line 255.

## Evidence
Expected (AWS): PUT /2025-03-07/web-functions with {functionName, revisionConfig:{buildConfig:{codeConfig:{s3Object:{bucket,key}},runtimeConfig:{runtime:"nodejs24.x"}},serviceConfig:{executionRoleArn}}, endpointConfig:{endpointName,endpointType:"HomeRegion",authType:"IamAuth"}} -> HTTP 202 with functionName, functionArn, state (Pending), stateReason, createdAt, updatedAt, revision (FunctionRevisionSummary) and endpoint (FunctionEndpointSummary for the initial endpoint).

Actual (emulator): HTTP 501, Error.Code "NotImplemented", Error.Message "operation CreateWebFunction's endpointConfig is scaffolded but not implemented in this emulator"; nothing is stored, so the function does not exist afterwards. Observed identically in all eight checks, e.g. botocore raised: ClientError: An error occurred (NotImplemented) when calling the CreateWebFunction operation: operation CreateWebFunction's endpointConfig is scaffolded but not implemented in this emulator.

Source: services/service-com-amazonaws-lambdaweb-lambdaweb/src/ops/create_web_function.rs:201-205 returns crate::scaffolded::Scaffolded::not_implemented("CreateWebFunction's endpointConfig"), which crate::scaffolded renders as 501 with shape_name "NotImplemented" (scaffolded.rs:275, 286).

## Steps to Reproduce
1. Boot the emulator and point a botocore/SDK lambda-web client at it.
2. Create an IAM role and an S3 bucket holding a zipped Node.js handler (any valid code object).
3. Call CreateWebFunction with functionName=<fresh name>, revisionConfig={buildConfig:{codeConfig:{s3Object:{bucket,key}},runtimeConfig:{runtime:"nodejs24.x"}},serviceConfig:{executionRoleArn:<role arn>}} and endpointConfig={endpointName:"ep",endpointType:"HomeRegion",authType:"IamAuth"}.
4. Observe HTTP 501 with error code NotImplemented instead of HTTP 202 with the function, its initial revision and its initial endpoint summary.
5. Call GetWebFunction with the same functionName: it answers ResourceNotFoundException, confirming the create stored nothing.
6. Repeat step 3 without endpointConfig: the call succeeds, showing the refusal is specific to the endpointConfig member.
