# SageMaker CreateTrainingJob is accepted but never executed: the job ends Failed with a no-container-runtime FailureReason and no model artifact, blocking the model-package-approval-to-endpoint-deploy flow

> _Note: this issue was identified against the code base at commit `444cbe40db1434e138785b95152adaa2e53ade67`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateTrainingJob

## Description
This issue bundles ONE root cause; it must be closed before submitting.

Cause 1 of 1: a well-formed CreateTrainingJob is accepted (200, TrainingJobArn returned) and the job is describable, but it is never executed. DescribeTrainingJob reports a terminal TrainingJobStatus of 'Failed' with an emulator-authored FailureReason, and no model artifact object is written under the request's OutputDataConfig.S3OutputPath. Consequence: the registry-centred deploy flow — train, register the artifact as an Approved versioned model package in a ModelPackageGroup, CreateModel from PrimaryContainer.ModelPackageName, CreateEndpointConfig/CreateEndpoint, InvokeEndpoint — cannot reach its first observable step. Failing check: sagemaker.e2e-model-package-approval-to-endpoint-deploy-flow.

AWS: Smithy (services/service-com-amazonaws-sagemaker-sagemaker/smithy-model/com-amazonaws-sagemaker-sagemaker.json): CreateTrainingJob requires TrainingJobName (@length 1-63, pattern ^[a-zA-Z0-9](-*[a-zA-Z0-9]){0,62}$), RoleArn (@length 20-2048, pattern ^arn:aws[a-z\-]*:iam::\d{12}:role/?[a-zA-Z_0-9+=,.@\-_/]+$) and OutputDataConfig; it returns only TrainingJobArn and models exactly ResourceInUse / ResourceLimitExceeded / ResourceNotFound (all 400) — there is no modeled error for 'this job cannot be run'. DescribeTrainingJob models ModelArtifacts, TrainingJobStatus, SecondaryStatus, StoppingCondition and CreationTime as REQUIRED output members, plus TrainingStartTime/TrainingEndTime/TrainingTimeInSeconds/SecondaryStatusTransitions/FinalMetricDataList and an OPTIONAL FailureReason (@length 0-1024). Recorded behavior: AWS drives an accepted, well-formed job from InProgress to TrainingJobStatus 'Completed' with SecondaryStatus 'Completed' and no FailureReason, materializes the trained model artifact under the declared OutputDataConfig.S3OutputPath, and returns ModelArtifacts.S3ModelArtifacts as an s3:// URI naming that object inside the caller's own output bucket/prefix. The artifact URI is then usable as InferenceSpecification.Containers[].ModelDataUrl of a CreateModelPackage version (ModelApprovalStatus 'Approved'), and CreateModel with PrimaryContainer={'ModelPackageName': <that package ARN>} yields an endpoint that reaches InService and serves InvokeEndpoint.

Emulator: CreateTrainingJob returns 200 and the job persists, but polling DescribeTrainingJob yields terminal TrainingJobStatus 'Failed' with FailureReason "This emulator has no container runtime, so the training job's algorithm image was never started and no model artifacts were written to the output S3 location". That whole sentence is fixed emulator-authored text with no variable part taken from the request or state — AWS never emits it; AWS's FailureReason for a genuinely failed job names the algorithm/container error, and for a successful job the member is absent. No object appears under the declared S3 output prefix, so ModelArtifacts carries no usable artifact.

Why: a client that polls DescribeTrainingJob for 'Completed' — the documented happy path, what every SDK training waiter and the SageMaker Python SDK's Estimator.fit do — always takes the failure branch, so train -> CreateModelPackage(Approved) -> CreateModel -> CreateEndpointConfig -> CreateEndpoint -> InvokeEndpoint is unusable. The model-registry surface is doubly hidden: because the valid job terminates 'Failed', a caller never gets an artifact URI to register, so CreateModelPackage/CreateModel's ModelPackageName-by-ARN indirection is never exercised, and a real refusal from those operations is indistinguishable from this never-executed job.

Fix: the training-job execution path in SageMaker state — the CreateTrainingJob handler and the job state machine read back by DescribeTrainingJob must advance an accepted job through InProgress to Completed (setting SecondaryStatus, SecondaryStatusTransitions, TrainingStartTime/TrainingEndTime/TrainingTimeInSeconds, and omitting FailureReason), synthesize a model artifact object at the declared OutputDataConfig.S3OutputPath in S3, and return ModelArtifacts.S3ModelArtifacts pointing at it, so the model-package and endpoint path downstream has a real artifact to consume. Files: services/service-com-amazonaws-sagemaker-sagemaker/src/ops/create_training_job.rs, .../src/ops/describe_training_job.rs, .../src/state.rs.
