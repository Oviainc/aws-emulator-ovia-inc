=== Cause 1 of 1: InvokeFlow is not routed to any mounted service, so the flow data plane answers UnknownService instead of an event stream ===
AWS: Smithy: InvokeFlow (AmazonBedrockAgentRunTimeService, apiVersion 2023-07-26, restJson1, eventStreamHttp over h2/http-1.1) is bound to POST /flows/{flowIdentifier}/aliases/{flowAliasIdentifier} with @http code 200; input members `flowIdentifier` and `flowAliasIdentifier` are @required @httpLabel, `inputs` is @required (FlowInputs, @length min 1 max 1), `enableTrace` is an optional Boolean; output member `responseStream` is @required @httpPayload @streaming (FlowResponseStream) and `executionId` is bound to the response header `x-amz-bedrock-flow-execution-id`. The service's awsService traits are endpointPrefix `bedrock-agent-runtime` with sigv4Name/arnNamespace `bedrock` — the signing name is deliberately NOT the endpoint prefix. Modeled errors: AccessDeniedException 403, BadGatewayException 502, ConflictException 409, DependencyFailedException 424, InternalServerException 500, ResourceNotFoundException 404, ServiceQuotaExceededException 400, ThrottlingException 429, ValidationException 400. Recorded behavior for a Prepared two-node passthrough flow (Input node -> Output node, Output input expression `$.data`) whose alias routes to a numbered version: the call answers HTTP 200 with Content-Type application/vnd.amazon.eventstream and the header-bound executionId, and iterating the stream yields exactly one `flowOutputEvent` whose `nodeName` is the flow's output node and whose `content.document` is byte-for-byte the document submitted in `inputs[0].content.document` (and which does NOT carry the `nodeType` key even though the model marks it @required), terminated by exactly one `flowCompletionEvent` with `completionReason` `SUCCESS` as the LAST event of the stream; `flowTraceEvent` members appear only when `enableTrace` is true, each invocation returns a distinct executionId, and an input addressed to a node name that is not a node of the prepared flow is refused as a stream-framed `dependencyFailedException` (424 DependencyFailedException) rather than a synchronous client error.
Emulator: the request never reaches any handler. It is refused with error code `UnknownService` and the emulator-internal message `no emulated service is registered for 'bedrock'` — the front door resolves a bedrock-agent-runtime request by its sigv4 signing name (`bedrock`) rather than by its endpoint prefix / routed service, and nothing is mounted under `bedrock`, even though the bedrock-agent-runtime crate is built into the emulator. Fixed text of the emulator message: "no emulated service is registered for '" / "'"; the variable part is the resolved service token taken from the request's credential scope (here `bedrock`). No HTTP 200, no event stream, no `x-amz-bedrock-flow-execution-id`, and `UnknownService` is not one of the nine errors InvokeFlow models.
Why: the whole flow data plane is unreachable, so nothing built on the bedrock-agent control plane (CreateFlow/PrepareFlow/CreateFlowVersion/CreateFlowAlias) can ever be executed. A client gets an error code no SDK models for InvokeFlow, so none of its error branches (ValidationException, ResourceNotFoundException, DependencyFailedException, AccessDeniedException) run; retry/backoff logic keyed on ThrottlingException or 5xx never engages either. Every downstream contract this check measures — single terminal flowCompletionEvent(SUCCESS), byte-fidelity echo of the input document, enableTrace gating of flowTraceEvent, per-invocation executionId uniqueness, and the stream-framed dependencyFailedException for an unknown input node — is unobservable, and a data-plane invocation cannot be shown to leave GetFlow.status at `Prepared`.
Fix: the emulator's endpoint/service router — resolve bedrock-agent-runtime requests to the mounted bedrock-agent-runtime service instead of to the sigv4 signing name `bedrock`, and register the POST /flows/{flowIdentifier}/aliases/{flowAliasIdentifier} route onto InvokeFlow's handler in services/service-com-amazonaws-bedrockagentruntime-amazonbedrockagentruntimeservice/src/ops/invoke_flow.rs; then InvokeFlow's response serializer must emit the FlowResponseStream event stream (flowOutputEvent then a single terminal flowCompletionEvent, flowTraceEvent only under enableTrace) with the header-bound executionId, and its handler/state must apply the unknown-input-node pre-condition as a stream-framed dependencyFailedException.
Traces: bedrock-agent-runtime.invoke-flow-stream-ends-on-a-single-completion-event-and-gates-traces.
