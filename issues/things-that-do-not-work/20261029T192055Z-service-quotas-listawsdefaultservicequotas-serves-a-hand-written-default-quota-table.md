# ListAWSDefaultServiceQuotas serves a hand-written default-quota table, not AWS's quota catalog

> _Note: this issue was identified against the code base at commit `5bf04d9c01ed3990fbed03ee0a0bc59641f482e6`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
ListAWSDefaultServiceQuotas

## Description
ListAWSDefaultServiceQuotas answers HTTP 200 with a well-formed body for every ServiceCode in the corpus, but the rows it serves come from a small hand-written table rather than AWS's default-quota catalog. 141 of the corpus's 151 divergence clusters are this one operation (every `service-quotas-catalog-list-aws-default-service-quotas-<ServiceCode>` fixture, step `task#1`); the status always matches, every divergence is in the `Quotas` payload. Seven distinct faults make up the defect; each is listed with example fixtures, and the fault holds for ALL 141 of those fixtures, not only the ones named.

Cause 1 of 7 - the default-quota set is truncated.
AWS: ListAWSDefaultServiceQuotas returns the complete set of AWS default quota values for the requested ServiceCode (Smithy: ListAWSDefaultServiceQuotas.ServiceCode required, output Quotas -> ServiceQuotaListDefinition, paginated on NextToken/MaxResults). Recorded responses carry dozens of rows per ServiceCode.
Emulator: for almost every ServiceCode it serves a handful of rows and the rest of the service's quota codes are absent. Example: for ServiceCode `access-analyzer` the recording carries L-5EFCE71D, L-4599575C, L-6F85FE0C, L-94099EDD, L-8750DAE0, L-2F63646F, L-FD4CD927 and AnalyzersPerRegion; the emulator answers None for each of them. For `acm` 43 quota codes are missing; for `acm-pca` 27 are missing.
Why: a client enumerating a service's default quotas to look up a code, a default value or an Adjustable flag finds the quota simply does not exist, so quota-driven capacity logic and any follow-up GetServiceQuota/RequestServiceQuotaIncrease on a real AWS quota code cannot be reached at all.
Fix: the service-quotas crate's default-quota catalog data (the static table the ListAWSDefaultServiceQuotas handler reads), not the handler's paging or serialization.
Traces: service-quotas-catalog-list-aws-default-service-quotas-access-analyzer#task#1, ...-acm#task#1, ...-acm-pca#task#1, ...-amplify#task#1.

Cause 2 of 7 - whole ServiceCodes have no table entry, so Quotas comes back empty.
AWS: each integrated ServiceCode that ListServices reports has a non-empty default-quota set.
Emulator: for some ServiceCodes every element of the expected list is reported missing from index 0 upward, i.e. the emulator serves an empty Quotas list. The replay clustered four such ServiceCodes together (airflow-serverless, awscloudmap, mediaconnect, proton) and three more (amplifyuibuilder, discovery, ivschat).
Why: a client cannot discover any quota for those services; the operation looks successful while returning nothing.
Fix: the same static catalog table - these ServiceCodes are absent from it entirely.
Traces: service-quotas-catalog-list-aws-default-service-quotas-airflow-serverless#task#1 (cluster also covers awscloudmap, mediaconnect, proton), ...-amplifyuibuilder#task#1 (cluster also covers discovery, ivschat).

Cause 3 of 7 - the table invents QuotaCodes AWS does not have.
AWS: a default quota's QuotaCode is the service's assigned identifier, in practice the `L-XXXXXXXX` form for the quotas in these recordings (Smithy: ServiceQuota.QuotaCode @pattern ^[a-zA-Z][a-zA-Z0-9-]{1,128}$ - the pattern admits other spellings, so this is recorded behavior: every QuotaCode in every recorded response is an L-code or a code AWS itself publishes).
Emulator: alongside the missing L-codes it emits extra rows keyed by invented CamelCase names that appear in no recording - `ScalingPlansPerRegion` (autoscaling-plans), `ProfilesPerAccount` (b2bi), `RepositoriesPerAccount` (codecommit), `ConfigRulesPerRegion` and `DeliveryChannels` (config), `TasksPerAccount` and `AgentsPerAccount` (datasync), `ApplicationsPerAccount` (emr-serverless), `ShardsPerRegion` (kinesis), `ApplicationsPerRegion` (kinesisanalytics), `ResourceGroupsPerAccount` (resource-groups), `ProtectionsPerAccount` (shield). Each is reported by the replay as `extra (expected None, got {...})`.
Why: a client that reads a QuotaCode from this listing and passes it to GetServiceQuota or RequestServiceQuotaIncrease is using an identifier real AWS rejects, so code written against the emulator breaks on AWS.
Fix: the static catalog table - drop the invented codes and key the rows on the service's real quota codes.
Traces: ...-autoscaling-plans#task#1, ...-b2bi#task#1, ...-codecommit#task#1, ...-config#task#1, ...-datasync#task#1, ...-emr-serverless#task#1, ...-kinesis#task#1, ...-kinesisanalytics#task#1, ...-resource-groups#task#1, ...-shield#task#1.

Cause 4 of 7 - Description is paraphrased rather than the service's own text.
AWS: ServiceQuota.Description is the quota description the service publishes (Smithy: ServiceQuota.Description, QuotaDescription @length 0..350).
Emulator: it serves a shortened rewrite. Pattern: AWS's sentence names the account/Region scope and the emulator's drops it. Examples - account-access L-42A1D874: AWS 'The maximum number of group entitlements that can be assigned to a single role in an application.' vs emulator 'The maximum number of group entitlements per role.'; acm-pca L-01B8608D: AWS 'The maximum number of CreateCertificateAuthority requests that can be performed in an account in the current Region each second.' vs emulator 'The maximum number of CreateCertificateAuthority requests per second.'; aco-automation L-1501440B: AWS 'Maximum number of ListAutomationRules requests you can make per second per account in the current region.' vs emulator 'The maximum number of ListAutomationRules requests per second.'; airflow L-67D41C6B: AWS 'The maximum number of environments per account per Region.' vs emulator a different sentence naming environment classes; aidevops L-4FF187E6: AWS 'Concurrent evaluations per agent space' vs emulator 'The maximum number of concurrent evaluations per agent space.'. The whole string is fixed text per quota code - it has no variable parts taken from the request.
Why: Description is what consoles and operators read to decide whether a quota is the one they mean; a rewritten sentence loses the account/Region scope that distinguishes per-account from per-Region quotas.
Fix: the static catalog table's Description values.
Traces: ...-account-access#task#1, ...-acm-pca#task#1, ...-aco-automation#task#1, ...-airflow#task#1, ...-aidevops#task#1.

Cause 5 of 7 - UsageMetric.MetricDimensions.Service carries the SDK id instead of AWS's dimension value.
AWS: MetricInfo.MetricDimensions is the name/value pair identifying the CloudWatch usage metric (Smithy: ServiceQuota.UsageMetric -> MetricInfo.MetricDimensions, map @length 0..10). The recorded `Service` dimension is the service's display name as AWS/Usage publishes it.
Emulator: it substitutes the SDK/model id. Examples - acm L-DD60D132: AWS 'Certificate Manager' vs emulator 'ACM'; agent-registry L-7F384C37: AWS 'Agent Registry' vs emulator 'AgentRegistry'; aiops L-EF31E0C4: AWS 'Amazon AI Operations' vs emulator 'AIOps'.
Why: the dimension value is the key a client uses to build a GetMetricData/GetMetricStatistics query against AWS/Usage; the wrong value selects no metric, so usage-vs-quota dashboards read zero.
Fix: the static catalog table's UsageMetric.MetricDimensions values.
Traces: ...-acm#task#1, ...-agent-registry#task#1, ...-aiops#task#1.

Cause 6 of 7 - the invented rows report wrong Adjustable, GlobalQuota, Value and ARN.
AWS: Adjustable says whether the quota can be increased, GlobalQuota whether it is global, Value is the default value, and QuotaArn is the quota's ARN - which for a default (account-level, regional) quota carries the Region and an empty account field.
Emulator: aiops L-EF31E0C4 is reported Adjustable=true where AWS reports false. On the invented rows the values are its own: kinesis `ShardsPerRegion` Value 500.0 where AWS's L-0918CF54 default is 20000.0; resource-groups `ResourceGroupsPerAccount` 1000.0 where AWS's L-2BAA18A0 is 100.0; config `ConfigRulesPerRegion` 150.0 where AWS's L-0BE82991 is 1000.0; codecommit `RepositoriesPerAccount` 1000.0 where AWS's L-81790602 is 5000.0. The shield row is additionally minted as GlobalQuota=true with a Region-less ARN `arn:aws:servicequotas:::shield/ProtectionsPerAccount`, where every recorded default quota ARN carries the Region (`arn:aws:servicequotas:<region>::<servicecode>/<quotacode>`).
Why: Adjustable drives whether a client even attempts RequestServiceQuotaIncrease, and Value is the number capacity planning is built on; a Region-less ARN does not resolve as a quota ARN for tagging or policy.
Fix: the static catalog table's scalar fields and ARN construction for default quotas.
Traces: ...-aiops#task#1, ...-kinesis#task#1, ...-resource-groups#task#1, ...-config#task#1, ...-codecommit#task#1, ...-shield#task#1.

Cause 7 of 7 - Period and UsageMetric blocks are omitted.
AWS: rate quotas carry Period (QuotaPeriod{PeriodValue, PeriodUnit}) and metered quotas carry UsageMetric (Smithy: ServiceQuota.Period, ServiceQuota.UsageMetric).
Emulator: none of the invented rows carry either block, and the missing L-code rows that should have carried them are absent, so no row in the emulator's answer exposes Period or UsageMetric for these services. Examples of rows that should carry them: acm L-8849A1A8 (Period SECOND/1 plus UsageMetric), agent-registry L-197AC8CB (Period MINUTE/5 plus UsageMetric), datasync L-1FEC79AD (Period SECOND/1), kinesis L-0918CF54 (Period MINUTE/5 plus UsageMetric), emr-serverless L-D05C8A75 (UsageMetric), resource-groups L-2BAA18A0 (Period MINUTE/5 plus UsageMetric).
Why: without Period a client cannot tell a per-second rate quota from an absolute count, and without UsageMetric it cannot locate the quota's usage metric at all.
Fix: the static catalog table must carry the Period/UsageMetric structures, and the ListAWSDefaultServiceQuotas serializer must emit them.
Traces: ...-acm#task#1, ...-agent-registry#task#1, ...-datasync#task#1, ...-kinesis#task#1, ...-emr-serverless#task#1, ...-resource-groups#task#1.
