# ELBv2 awsQuery action table at API version 2015-12-01 resolves no operations: every ELBv2 action is refused with InvalidAction (2 causes)

> _Note: this issue was identified against the code base at commit `1b15cfcf83a9fafcaa69f938ed17066b612a8ba0`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateTargetGroup

## Description
Two root causes, grounded in 108 failing behavioral checks whose id's leading token is 'elbv2'. Related already-open issues, which this issue does NOT duplicate: 20261023T004835Z-acm-elbv2-elbv2-createloadbalancer-is-not-dispatchable-could-not-find.md covers ONLY CreateLoadBalancer under the composite 'acm__elbv2' token and only one check id; 20261022T220446Z-elbv2-elastic-load-balancing-v2-is-unreachable-every-request.md describes an AmbiguousService refusal, a different symptom; 20261022T235108Z-cloudformation-stack-outputs-carry-no-outputvalue-failing-resources.md covers the CloudFormation symptoms for the 'cloudformation' token, not for these elbv2-token check ids. Neither carries the replay keys below.

Cause 1 of 2: the ELBv2 awsQuery action table is empty (or unregistered) for API version 2015-12-01, so EVERY action of the service is unreachable, not just CreateLoadBalancer.
AWS: Smithy com.amazonaws.elasticloadbalancingv2 service ElasticLoadBalancing_v10, version 2015-12-01, protocol awsQuery, endpointPrefix/sigv4Name 'elasticloadbalancing', xmlNamespace http://elasticloadbalancing.amazonaws.com/doc/2015-12-01/, 51 bound operations. A well-formed POST with Action=<Op>&Version=2015-12-01 is either served 200 with the modeled output or refused with one of the operation's modeled awsQuery errors, all HTTP 400 — e.g. CreateTargetGroup -> {TargetGroups} with errors DuplicateTargetGroupName / InvalidConfigurationRequest / TooManyTargetGroups / TooManyTags; CreateTrustStore -> {TrustStores} with errors CaCertificatesBundleNotFound / DuplicateTrustStoreName / InvalidCaCertificatesBundle / TooManyTrustStores; DescribeTargetHealth -> {TargetHealthDescriptions} with errors TargetGroupNotFound / InvalidTarget / HealthUnavailable(500); DescribeSSLPolicies -> {SslPolicies} with error SSLPolicyNotFound; SetIpAddressType -> {IpAddressType} with errors LoadBalancerNotFound / InvalidSubnet / InvalidConfigurationRequest; DescribeAccountLimits -> {Limits, NextMarker} with NO modeled errors. The code 'InvalidAction' is reserved for an action the service does not have at all.
Emulator: every one of those actions is refused with Error.Code 'InvalidAction' and a message of the form 'Could not find operation <Op> for version 2015-12-01' — observed for CreateTargetGroup, CreateTrustStore, CreateLoadBalancer, DescribeTargetHealth, DescribeSSLPolicies, DescribeTrustStores, SetIpAddressType and DescribeAccountLimits. The dispatcher resolved the version string and then found no operation bound to it, so nothing in ELBv2 can be created, read, modified, tagged or deleted. Checks that assert a modeled refusal see InvalidAction instead of the modeled code: 'UnhealthyThresholdCount=11 was answered InvalidAction, not ValidationError' (Smithy caps CreateTargetGroup.UnhealthyThresholdCount at @range min 2 max 10), 'expected InvalidConfigurationRequest, got InvalidAction', 'expected SSLPolicyNotFound, got InvalidAction', 'expected TrustStoreNotFound modifying a fabricated trust store, got InvalidAction', 'expected InvalidCaCertificatesBundle for a malformed CA bundle, got InvalidAction', 'expected the fake ARN to be genuinely absent before delete, got InvalidAction', and ('InvalidAction', 'Could not find operation SetIpAddressType for version 2015-12-01').
Why: a client cannot use Elastic Load Balancing v2 at all, and the refusal misreports the fault as the caller's — 'InvalidAction' tells an SDK the action does not exist, so retry/validation logic treats a well-formed request as a programming error instead of a server gap. Every downstream surface (listeners, rules, target registration, health, trust stores, mTLS, capacity reservation, resource policies, tagging) is blocked behind it.
Fix: the awsQuery operation dispatch/version table of the elasticloadbalancingv2 service crate (services/service-com-amazonaws-elasticloadbalancingv2-elasticloadbalancing-v10) — register the full set of operations bound to the service at version 2015-12-01 so requests reach their handlers; the per-operation validation and modeled errors above are what the handlers must then produce.
Traces: the 105 'elbv2.*' check ids listed in trace_ids excluding the three CFN ones named under Cause 2.

Cause 2 of 2: CloudFormation stacks that declare ELBv2 resources are unusable — stack Outputs carry no OutputValue, and a stack whose ELBv2 resource cannot be created still reaches CREATE_COMPLETE instead of rolling back.
AWS: a CloudFormation stack that reaches CREATE_COMPLETE exposes each declared Output with an OutputValue resolved from the created resource (a load balancer's Ref/attribute resolves to its real ELBv2 ARN/DNS name); a stack whose resource creation fails transitions CREATE_FAILED -> ROLLBACK_IN_PROGRESS -> ROLLBACK_COMPLETE. Recorded behavior only for the exact wording.
Emulator: DescribeStacks Outputs entries have no 'OutputValue' key at all (KeyError: 'OutputValue' raised by the checks when reading it), and a template naming a nonexistent subnet for an AWS::ElasticLoadBalancingV2::LoadBalancer reaches 'CREATE_COMPLETE' ('expected the bad-subnet stack to roll back, but it reached CREATE_COMPLETE').
Why: an infrastructure-as-code client cannot retrieve the ARN/DNS name of anything it deployed, and a broken template is reported as a successful deployment, so a deploy-then-use workflow silently proceeds against resources that do not exist.
Fix: the CloudFormation stack Output resolution and the resource-failure/rollback state machine, plus the AWS::ElasticLoadBalancingV2::* resource providers that must fail on an invalid subnet.
Traces: elbv2.deploy-cfn-alb-nonexistent-subnet-rejected, elbv2.deploy-elbv2-1-rule-update-tg-replace-deletion-protection, elbv2.deploy-elbv2-2-rule-priority-collision-update-rejected.
