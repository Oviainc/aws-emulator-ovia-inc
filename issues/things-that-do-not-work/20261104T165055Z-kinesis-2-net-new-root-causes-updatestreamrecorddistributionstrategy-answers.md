## Description
Both surviving failing checks in this sweep reach the emulator over the wire (unlike the earlier recording of the same checks, which died client-side in botocore) and are refused with HTTP 501 / `NotImplemented` by the UpdateStreamRecordDistributionStrategy scaffold, so neither the not-found refusal nor the capacity-mode refusal/success that AWS produces is observable. 2 net-new root causes are bundled here; a fixer must close BOTH before submitting.

Related open issue, which does NOT cover these two checks: 20261029T145828Z-kinesis-3-net-new-root-causes-updatestreamrecorddistributionstrategy-is.md — it was written when the harness SDK client had no `update_stream_record_distribution_strategy` attribute at all, so its replay keys are AttributeError keys recorded before the request was ever sent, and the suite does not report it as owning either check below. === Cause 1 of 2: an unknown stream ARN is answered 501 NotImplemented instead of 400 ResourceNotFoundException ===
AWS: Smithy (services/service-com-amazonaws-kinesis-kinesis-20131202/smithy-model/com-amazonaws-kinesis-kinesis-20131202.json) binds UpdateStreamRecordDistributionStrategy with input `StreamARN` required (@length 1..2048, @pattern ^arn:aws.*:kinesis:.*:\d{12}:stream/\S+$) and `RecordDistributionStrategy` required (enum RecordDistributionStrategy). Output shape is `Unit`, so a success is HTTP 200 with an empty body. The modelled errors are exactly six, all HTTP 400: AccessDeniedException, InvalidArgumentException, LimitExceededException, ResourceInUseException, ResourceNotFoundException, ValidationException. 501/NotImplemented is not among them. Recorded behavior: for a stream ARN that was never created the refusal is HTTP 400 with Error.Code `ResourceNotFoundException` and Error.Message `Stream <streamName> under account <accountId> not found.` — the fixed text is `Stream `, ` under account `, ` not found.`; `<streamName>` is the name segment after `stream/` in the request's StreamARN and `<accountId>` is the 12-digit account of the caller/ARN. Those two are request- and state-derived values, never literals from one run. The identical call against an existing ON_DEMAND stream is HTTP 200 with an empty body.
Emulator: the call is answered `An error occurred (NotImplemented) when calling the UpdateStreamRecordDistributionStrategy operation: operation UpdateStreamRecordDistributionStrategy is scaffolded but not implemented in this emulator` — an HTTP 501 with an error code the operation does not model, for the missing-stream ARN and for the real-stream positive control alike.
Why: a client cannot distinguish "this stream does not exist" from any other failure. 501/NotImplemented is classified by no SDK error path — it is not a throttle, not a validation failure and not a not-found — so retry/branching logic that keys on ResourceNotFoundException mis-handles it, and the positive control (strategy switch on a live on-demand stream) can never return 200, making the documented no-downtime switch workflow impossible.
Fix: the operation's handler and its validation in services/service-com-amazonaws-kinesis-kinesis-20131202/src/ops/update_stream_record_distribution_strategy.rs — resolve StreamARN against stream state, refuse an unknown stream with ResourceNotFoundException at HTTP 400 using the message template above, return the empty 200 Unit output on success, and remove the scaffold marker.
Traces: kinesis.update-stream-record-distribution-strategy-nonexistent-stream-rejected (asserted `code == 'ResourceNotFoundException'`, got `'NotImplemented'`).

=== Cause 2 of 2: no capacity-mode guard and no RecordDistributionStrategy in stream state / DescribeStreamSummary ===
AWS: recorded behavior — setting RecordDistributionStrategy=AUTO on a PROVISIONED stream is refused with HTTP 400, Error.Code `ValidationException` and Error.Message `Request is invalid. Stream <streamName> under account <accountId> is in Provisioned mode.` The fixed text is `Request is invalid. Stream `, ` under account `, ` is in Provisioned mode.`; `<streamName>` comes from the request's StreamARN and `<accountId>` is the caller's 12-digit account. The refusal must leave state untouched. Also recorded: DescribeStreamSummary's StreamDescriptionSummary OMITS `RecordDistributionStrategy` entirely for a provisioned stream, reports `USER_PARTITION_KEY` on a freshly created ON_DEMAND stream, and reports the new value after a successful update (AUTO and back to USER_PARTITION_KEY both round-trip). Model-vs-recording discrepancy to implement as recorded: the operation's prose mentions InvalidArgumentException for AUTO-on-provisioned and ValidationException's own doc is inverted, but the recording is ValidationException with the message above.
Emulator: every UpdateStreamRecordDistributionStrategy request, provisioned or on-demand, returns the same 501 `NotImplemented`, so the capacity-mode guard does not exist; the strategy is not part of stream state, so DescribeStreamSummary emits no RecordDistributionStrategy member for an on-demand stream and there is nothing for a successful update to persist or a poll to converge on.
Why: a client cannot tell that a provisioned stream does not support the setting (a 501 reads as an emulator/service outage, not as an input error), cannot read back the stream's current strategy to confirm a switch, and cannot discover the on-demand default — polling DescribeStreamSummary for the new value never converges.
Fix: the per-stream strategy belongs in the service's stream state (services/service-com-amazonaws-kinesis-kinesis-20131202/src/state.rs), defaulted to USER_PARTITION_KEY for ON_DEMAND streams and unset for provisioned ones; DescribeStreamSummary's handler/serializer must emit the member only when set; the provisioned-mode check and its ValidationException message belong in the UpdateStreamRecordDistributionStrategy handler's validation, ahead of any state mutation.
Traces: kinesis.update-stream-record-distribution-strategy-requires-on-demand (asserted `code == 'ValidationException'`, got `NotImplemented`; its later assertions on the USER_PARTITION_KEY default and the AUTO round-trip through DescribeStreamSummary are unreached).
