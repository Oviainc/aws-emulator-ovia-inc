# lifecycleStage is reported for a non-prioritized recommendation although the crate states the same Priority scoping that withholds it

_Filed: 2026-11-06T09:56:53Z_
_Operation: GetRecommendation | Class: wrong-behavior_

> _Note: this issue was identified against the code base at commit `dac07326602f9aba95bf6def628915eb769a9227`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Description

`crate::state` states ONE scoping rule for the recommendation members the model ties to Trusted Advisor Priority, and names four of them explicitly: a recommendation whose `type` is not `priority` "was produced automatically, has no Priority creation instant, and reports none — the same scoping that leaves `lifecycleStage`, `createdBy` and the `updatedOnBehalfOf…` members absent on such a recommendation" (src/state.rs:417-420).

Three of those four members are honoured by code: `createdAt` goes through the one helper that applies the scoping (`crate::state::priority_created_at`), and `createdBy` / `updatedOnBehalfOf` / `updatedOnBehalfOfJobTitle` are always absent. The fourth, `lifecycleStage`, is copied out of the store unscoped in every recommendation projection of this crate — `GetRecommendation` (src/ops/get_recommendation.rs:128), `ListRecommendations` (src/ops/list_recommendations.rs:150), `GetOrganizationRecommendation` (src/ops/get_organization_recommendation.rs:111) and `ListOrganizationRecommendations` (src/ops/list_organization_recommendations.rs:136). Nothing in the crate applies the rule its own state module states for that member; the responses agree with the rule only because the `SEED` table happens to leave `lifecycle_stage: None` on both `standard` rows (src/state.rs:1812, :1919).

The crate's own suite shows the divergence is real rather than hypothetical: `tests/all/shared_lifecycle_write.rs:317-387` takes the seeded PRIORITIZED recommendation of `PRIORITIZED_CHECK_IDS[0]` (seeded `lifecycle_stage: Some("pending_response")`, src/state.rs:1705), records a non-priority `type` on it the way "the part of Trusted Advisor that classifies a finding would", and then asserts that the read still reports the same `lifecycleStage` it reported while the entry was prioritized. So the state module says a `standard` recommendation reports no `lifecycleStage` and the suite asserts that it does — the two sides of this crate contradict each other on the one rule, and whichever side is wrong one of them has to move (either the four projections route the member through a scoping helper beside `priority_created_at`, or the sentence at src/state.rs:419-420 stops claiming the member is scoped).

No request of this API can reach the divergence on its own (both `Update…Lifecycle` handlers refuse a non-priority entry with 409 before writing, src/state.rs:723-735), which is why this is LOW: it is reachable only through state recorded out of band — which is how every non-seeded row of this reporting service arrives, including in the suite above.

1. Read src/state.rs:413-420: the crate states that the Priority scoping it applies to `createdAt` is "the same scoping that leaves `lifecycleStage`, `createdBy` and the `updatedOnBehalfOf…` members absent on" a recommendation whose `type` is not `priority`.
2. Grep the four recommendation projections for that member: `lifecycle_stage: entry.lifecycle_stage.clone(),` at src/ops/get_recommendation.rs:128, src/ops/list_recommendations.rs:150, src/ops/get_organization_recommendation.rs:111, src/ops/list_organization_recommendations.rs:136 — no scoping is applied, unlike `created_at` on the line beside it (get_recommendation.rs:135) and unlike `created_by` / `updated_on_behalf_of…` (get_recommendation.rs:140-142).
3. Confirm no helper exists for it: `crate::state` exports `priority_created_at` (src/state.rs:426) and nothing equivalent for the lifecycle stage.
4. Reproduce the divergence the way this crate's own suite records state: start the emulator with EMULATOR_TRUSTEDADVISOR_SUPPORT_PLAN=business, record `standard` as the `type` of the seeded recommendation of `low-utilization-ec2-instances` (whose seeded `lifecycle_stage` is `Some("pending_response")`, src/state.rs:1705) through the shared engine, exactly as tests/all/shared_lifecycle_write.rs:328-345 does.
5. GET /v1/recommendations/{that ARN}: the response reports `type: standard` with NO `createdAt` (the rule applied) and WITH `lifecycleStage: pending_response` (the same rule not applied) — the two halves of one sentence answered differently in one body.
6. Note that tests/all/shared_lifecycle_write.rs:379-387 currently asserts that second half, so the crate's state module and the crate's suite disagree about the rule and one of the two has to move.
