# cloudformation: AWS::PI::PerfReports is not a registered resource type — CreateStack refuses every Performance Insights analysis-report template with "Unrecognized resource types"

> _Note: this issue was identified against the code base at commit `ef76ab1e831abf4546de7a6143d684d5cb1e8445`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateStack

## Description
Cause 1 of 1: CloudFormation's template resource-type registry does not contain AWS::PI::PerfReports, so CreateStack refuses the whole template at template-format validation time and no Performance Insights performance-analysis report can ever be provisioned from infrastructure-as-code. Failing checks: cloudformation__pi__rds.deploy-pi-perfreports-round-trip-then-stack-delete, cloudformation__pi__rds.deploy-pi-perfreports-bad-service-type-rejected.

AWS: AWS::PI::PerfReports is a supported CloudFormation resource type (recorded behavior: both checks' recordings show CreateStack ACCEPTING a template whose only resource is of this type and returning a StackId). CloudFormation provisions the resource through the Performance Insights control plane (Smithy, pi: CreatePerformanceAnalysisReport — required input members ServiceType (enum), Identifier (IdentifierString @length 0..256 @pattern ^[a-zA-Z0-9-]+$) and StartTime (ISOTimestamp), optional EndTime and Tags (@length 0..200); output AnalysisReportId @pattern ^report-[0-9a-f]{17}$; modeled errors InvalidArgumentException 400, NotAuthorizedException 400, InternalServiceError 500). On the happy path the stack reaches CREATE_COMPLETE; Ref on the resource yields the report ARN in the form arn:<partition>:pi:<region>:<account>:perf-reports/<ServiceType>/<Identifier>/<AnalysisReportId> (every segment a value taken from the request, the stack's own partition, and the minted report id — the shape is the requirement, not any one run's values), and Fn::GetAtt exposes the read-only attributes AnalysisReportId, CreateTime and Status. The report is then readable independently through pi ListPerformanceAnalysisReports (ServiceType=RDS, Identifier=<DbiResourceId>, ListTags=true — carrying the stack's propagated tags) and pi GetPerformanceAnalysisReport, whose AnalysisReport echoes the templated Identifier, ServiceType, StartTime and EndTime and whose Status settles on SUCCEEDED. DeleteStack removes only the report: GetPerformanceAnalysisReport for the deleted AnalysisReportId is then refused with error code NotAuthorizedException and the message "The specified resource is not authorized for this account" (entirely fixed text, no variable part), while the backing RDS instance keeps answering DescribeDBInstances.

When the templated ServiceType is outside the ServiceType enum, AWS fails the type's PROPERTY_VALIDATION before any PI call is made: the stack settles ROLLBACK_COMPLETE, no report reaches PI (ListPerformanceAnalysisReports stays empty), and DescribeEvents reports exactly one VALIDATION_ERROR row with ValidationName PROPERTY_VALIDATION, ValidationStatus FAILED, ValidationFailureMode FAIL, ValidationPath /Resources/<logical-id>/Properties/ServiceType and ValidationStatusReason "<value> is not a valid enum value. Supported values: [RDS, DOCDB]" — the fixed text is " is not a valid enum value. Supported values: [RDS, DOCDB]", and the leading value is the rejected ServiceType taken verbatim from the submitted template (the recording's MYSQL is one such value, not part of the template).

Emulator: both CreateStack calls on the report template are refused outright, before any stack exists, with HTTP 400 and error code ValidationError, message "Template format error: Unrecognized resource types: [AWS::PI::PerfReports]" (fixed text "Template format error: Unrecognized resource types: [...]" with the type name taken from the template). No StackId is returned, so none of the downstream behavior is reachable: Ref/GetAtt, the PI read-backs, report status convergence, the per-resource delete semantics, the property-level enum validation, the rollback, and the DescribeEvents VALIDATION_ERROR row. The preceding RDS/EC2 DB stack in both checks is created fine, so the defect is scoped to the PI namespace's registration, not to templates in general.

Why: a client deploying Performance Insights analysis reports by template or CDK gets a hard ValidationError for a type AWS supports, so the entire IaC path for PI reports is unavailable — the resource cannot be declared, referenced from an output or another resource, nor deleted with its stack. The property-validation contract a client relies on to catch a bad ServiceType at deploy time (ROLLBACK_COMPLETE plus a VALIDATION_ERROR row naming the exact property path and the supported value set) never runs, and a client that retries will read the refusal as a malformed template rather than as an unsupported resource type.

Fix: CloudFormation's template resource-type registry and the resource provider that backs it — register AWS::PI::PerfReports (Create/Read/Delete, Ref returning the perf-reports ARN, GetAtt for AnalysisReportId/CreateTime/Status, and its property schema including the ServiceType enum used for PROPERTY_VALIDATION) and wire it to the pi CreatePerformanceAnalysisReport / GetPerformanceAnalysisReport / DeletePerformanceAnalysisReport handlers. Related but distinct open issues report the same missing-registration shape for other namespaces (20261109T115853Z-chime-sdk-media-pipelines-cloudformation-cloudformation-aws-chime-mediainsightspipelineconfiguration-is-not-a-registered.md, 20261109T114319Z-cloudformation-iam-imagebuilder-createstack-refuses-aws-imagebuilder-infrastructureconfiguration.md); none of them covers AWS::PI::*. The open pi issue 20261104T085941Z-pi-3-net-new-causes-the-db-metric.md owns the three pi-only checks in this run and does not cover the CloudFormation registration.

Traces: cloudformation__pi__rds.deploy-pi-perfreports-round-trip-then-stack-delete (happy-path deploy, PI read-back, report-only stack delete), cloudformation__pi__rds.deploy-pi-perfreports-bad-service-type-rejected (ServiceType enum rejection and rollback).

## Evidence
Expected (AWS): CreateStack on a template whose Resources are {"Report": {"Type": "AWS::PI::PerfReports", "Properties": {"ServiceType": "RDS", "Identifier": <DbiResourceId of a Performance-Insights-advanced RDS instance>, "StartTime": <ISO8601>, "EndTime": <ISO8601>, "Tags": [...]}}} is accepted and returns a StackId; the stack reaches CREATE_COMPLETE; Ref "Report" is arn:<partition>:pi:<region>:<account>:perf-reports/RDS/<Identifier>/<AnalysisReportId>; Fn::GetAtt AnalysisReportId / CreateTime / Status agree with pi GetPerformanceAnalysisReport; pi ListPerformanceAnalysisReports(ServiceType=RDS, Identifier=<Identifier>, ListTags=true) lists exactly that report with the stack's propagated tags; after DeleteStack, GetPerformanceAnalysisReport on the same AnalysisReportId is refused with code NotAuthorizedException and message "The specified resource is not authorized for this account" while DescribeDBInstances still returns the instance. With a ServiceType outside the enum, the same template instead settles ROLLBACK_COMPLETE, ListPerformanceAnalysisReports stays empty, and DescribeEvents carries exactly one VALIDATION_ERROR row (LogicalResourceId "Report", PROPERTY_VALIDATION / FAILED / FAIL, ValidationPath "/Resources/Report/Properties/ServiceType", ValidationStatusReason "<submitted ServiceType> is not a valid enum value. Supported values: [RDS, DOCDB]").

Actual (emulator): both checks abort on the report template's CreateStack call with
  botocore.exceptions.ClientError: An error occurred (ValidationError) when calling the CreateStack operation: Template format error: Unrecognized resource types: [AWS::PI::PerfReports]
HTTP 400, error code ValidationError. No stack is created, so DescribeStacks / DescribeStackEvents / DescribeEvents, every Ref and GetAtt output, and every pi ListPerformanceAnalysisReports / GetPerformanceAnalysisReport assertion are never reached. The preceding AWS::EC2::SecurityGroup + AWS::RDS::DBSubnetGroup + AWS::RDS::DBInstance stack in the same checks is accepted, isolating the failure to the AWS::PI::PerfReports type registration.

## Steps to Reproduce
1. Build and boot the emulator from this checkout.
2. Create a stack with a private MySQL AWS::RDS::DBInstance that has EnablePerformanceInsights=true and DatabaseInsightsMode="advanced"; wait for CREATE_COMPLETE and take the instance's DbiResourceId (Fn::GetAtt DbInstance.DbiResourceId).
3. Submit a second template whose only resource is {"Report": {"Type": "AWS::PI::PerfReports", "Properties": {"ServiceType": "RDS", "Identifier": "<DbiResourceId>", "StartTime": "<now-20m, ISO8601>", "EndTime": "<now-5m, ISO8601>", "Tags": [{"Key": "sim2real-report", "Value": "<any>"}]}}} with Outputs Ref "Report" and Fn::GetAtt Report.AnalysisReportId / Report.CreateTime / Report.Status:
   aws cloudformation create-stack --stack-name sim2real-pifr-report --template-body file://report.json
4. Observe HTTP 400 ValidationError "Template format error: Unrecognized resource types: [AWS::PI::PerfReports]" instead of a StackId, so no report is created and pi list-performance-analysis-reports --service-type RDS --identifier <DbiResourceId> stays empty.
5. Repeat step 3 with "ServiceType": "MYSQL": the identical CreateStack refusal occurs, instead of a stack reaching ROLLBACK_COMPLETE whose DescribeEvents carries one PROPERTY_VALIDATION VALIDATION_ERROR row at /Resources/Report/Properties/ServiceType reading "MYSQL is not a valid enum value. Supported values: [RDS, DOCDB]".
