Cause 1 of 3: GetCatalog's malformed-catalog-id ValidationException blames member 'catalogId' and echoes an UNANCHORED pattern, where AWS blames 'name' and echoes the anchored catalog-name pattern.
AWS: Smithy (services/service-com-amazonaws-glue-awsglue/smithy-model/com-amazonaws-glue-awsglue.json) models GetCatalog input {CatalogId: CatalogIdString @required @length(1,255) @pattern ^[\u0020-\uD7FF\uE000-\uFFFD\uD800\uDC00-\uDBFF\uDFFF\t]*$} — that modeled pattern does NOT forbid '.'; the dot rule belongs to CatalogNameString (@length(1,64) @pattern ^(?!(.*[.\/\\]|aws:)).*$), the shape CreateCatalog.Name targets. Recorded behavior: GetCatalog with a CatalogId whose catalog-name part contains '.' is refused HTTP 400 with error code ValidationException and the message '1 validation error detected: Value '<the CatalogId from the request>' at 'name' failed to satisfy constraint: Member must satisfy regular expression pattern: ^(?!(.*[.\/\\]|aws:)).*$'. Fixed text of this error class: the '1 validation error detected: Value ... at ... failed to satisfy constraint: Member must satisfy regular expression pattern: ...' template, the member name 'name', and the ANCHORED pattern literal ^(?!(.*[.\/\\]|aws:)).*$ . The only variable part is the rejected value, taken verbatim from the request's CatalogId.
Emulator: same status (400) and same code (ValidationException), but the message names the wire member and drops the anchors: '1 validation error detected: Value '<CatalogId>' at 'catalogId' failed to satisfy constraint: Member must satisfy regular expression pattern: (?!(.*[.\/\\]|aws:)).*' (observed with a per-run generated name filling the value slot).
Why: the message is the only statement of the rule on the wire. A client that parses the member path out of a Glue validation message is told the fault is the whole 'catalogId' input rather than its 'name' part, and a client that matches or re-applies the echoed regex gets an unanchored expression with different match semantics than AWS's; message-equality assertions never match.
Fix: the malformed-id branch of the GetCatalog handler (services/service-com-amazonaws-glue-awsglue/src/ops/get_catalog.rs, the `!crate::state::is_catalog_name(&reference.name)` guard) and the message builder it calls (crate::state::messages::malformed_catalog_id) — report the member as 'name' and echo the anchored CatalogNameString pattern exactly as the model spells it.
Traces: glue.catalog-invalid-name-rejected.

Cause 2 of 3: GetCatalog refuses a nested '<account-id>/<catalog-name>' CatalogId with ValidationException instead of resolving it and reporting the miss as EntityNotFoundException.
AWS: Smithy models GetCatalog.CatalogId as CatalogIdString, whose pattern permits '/' — the account-qualified nested form is a legal catalog reference, and GetCatalog models EntityNotFoundException (client, httpError 400, documented 'A specified entity does not exist'). Recorded behavior: GetCatalog with CatalogId '<the caller's account id>/<a catalog name that exists nowhere>' is refused HTTP 400 with error code EntityNotFoundException and the message 'Catalog not found.' — entirely FIXED text, interpolating nothing from the request.
Emulator: the same call is refused HTTP 400 with error code ValidationException (the malformed-catalog-id message of cause 1), because the name-grammar guard is applied to a string that still contains the '/' separator instead of to the parsed name component. The nested id never reaches the catalog lookup at all.
Why: the error CODE is wrong for the fault. A strongly typed SDK catching EntityNotFoundException to decide 'this catalog does not exist' does not catch ValidationException, so a caller concludes its request was malformed and never falls into its not-found path; the nested catalog form — the way account-qualified and federated catalogs are addressed — is unusable against the emulator even for existing catalogs.
Fix: the catalog-reference parsing and the malformed-id guard in the GetCatalog handler (services/service-com-amazonaws-glue-awsglue/src/ops/get_catalog.rs — crate::state::parse_catalog_reference must split the '<account>/<name>' form so `is_catalog_name` is applied to the name component only), after which the existing miss branch already raises EntityNotFoundException with the fixed 'Catalog not found.' constant.
Traces: glue.root-catalog-delete-rejected (its GetCatalog-of-root and DeleteCatalog-of-root assertions pass; it fails on the nested-id read).

Cause 3 of 3: GetMaterializedViewRefreshTaskRun answers HTTP 501 NotImplemented for a well-formed but unknown run id, where AWS answers a modeled EntityNotFoundException.
AWS: Smithy models GetMaterializedViewRefreshTaskRun input {CatalogId: CatalogIdString @required, MaterializedViewRefreshTaskRunId: UUIDv4 @required @pattern ^[0-9a-fA-F]{8}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{12}$} and errors AccessDeniedException, EntityNotFoundException, InvalidInputException, OperationTimeoutException (all client, httpError 400). Recorded behavior: with a MaterializedViewRefreshTaskRunId that is a well-formed UUID naming no task run, the call is refused HTTP 400 with code EntityNotFoundException and the message 'Materialized view refresh task run not found' — entirely fixed text, no value interpolated and no trailing period.
Emulator: the constraint-envelope half is right (a non-UUID id is already refused with ValidationException and AWS's pattern message), but once the id satisfies the modeled pattern the request reaches an unimplemented handler and is answered HTTP 501 with code NotImplemented — an error outside the operation's modeled set.
Why: the status is a server-fault class, so SDK retry logic treats the refusal as a transient server error and retries a request AWS answers deterministically; a caller probing whether a refresh task run exists can never get the not-found answer, and the error code it switches on is one no Glue client knows.
Fix: implement the handler in services/service-com-amazonaws-glue-awsglue/src/ops/get_materialized_view_refresh_task_run.rs (replace the `Err(crate::scaffolded::Scaffolded::not_implemented(...))` and delete the SCAFFOLDED marker) — look the run up in the service state and raise EntityNotFoundException with the fixed message above on a miss.
Traces: glue.get-materialized-view-refresh-task-run-invalid-id-rejected.
