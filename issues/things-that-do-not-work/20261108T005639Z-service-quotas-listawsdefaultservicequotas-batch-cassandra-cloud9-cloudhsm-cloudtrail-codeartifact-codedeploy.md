# ListAWSDefaultServiceQuotas batch cassandra cloud9 cloudhsm cloudtrail codeartifact codedeploy codepipeline default rows carry re-authored text and another quota's metadata

> _Note: this issue was identified against the code base at commit `f8ada2b69833d1b930b89852ccac9f51cdbe0c71`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
ListAWSDefaultServiceQuotas

## Description
The emulator's AWS default-quota catalog is not AWS's catalog: for eight ServiceCodes it returns HTTP 200 with the right number of rows, but the per-row metadata is emulator-authored rather than AWS's, and in many rows one quota's QuotaName/Description/Value/Unit is bound to a DIFFERENT QuotaCode. Smithy: ListAWSDefaultServiceQuotas -> ListAWSDefaultServiceQuotasResponse.Quotas (list of ServiceQuota); ServiceQuota members QuotaCode (pattern ^[a-zA-Z][a-zA-Z0-9-]{1,128}$), QuotaName, Description (@length max 350), Value (QuotaValue double), Unit, Adjustable (boolean, default false), GlobalQuota, UsageMetric (MetricInfo), Period (QuotaPeriod). The model fixes the SHAPE of a row but not its contents, so for the catalog values themselves this is recorded behavior only: the recorded AWS responses are the requirement, and QuotaCode is the key that identifies which quota a row's QuotaName/Description/Value/Unit/Adjustable/Period/UsageMetric describe. Eight distinct causes, one per ServiceCode; all are the same operation and are reached by a single ListAWSDefaultServiceQuotas call with that ServiceCode.

Cause 1 of 8 — ServiceCode 'batch' (fixture service-quotas-catalog-list-aws-default-service-quotas-batch, step task#1). AWS: for ServiceCode batch, L-E6A2743D.Description is 'Maximum job definition size (for RegisterJobDefinition API operations), measured in KiB.', L-144F0CA5.Description is 'Maximum number of compute environments per account, per region.', L-AD075A76 is QuotaName 'Job dependencies limit' / Description 'Maximum number of job dependencies per job.', L-80D92D24 is QuotaName 'Service environments per job queue' with Value 1.0, L-6B86CF1E is QuotaName 'Job payload size limit' with Value 30.0, and L-F9381E33 is QuotaName 'Maximum array size limit'. Emulator: it re-words every Description in its own voice ('The maximum size, in KiB, of one job definition.', 'The maximum number of compute environments in this account in the current Region.', 'The maximum number of jobs one job can depend on.'), and it shifts whole rows onto the wrong code — L-80D92D24 comes back as 'Maximum number of share identifiers per scheduling policy' with Value 500.0, L-6B86CF1E as 'Scheduling policy limit' with Value 100.0, L-F9381E33 as 'Service environment limit'. Why: a client that looks up a quota by QuotaCode (the documented way to find a quota) reads the name, description and numeric ceiling of a different quota, so capacity checks and quota-increase requests are built against the wrong limit. Fix: the ListAWSDefaultServiceQuotas default-quota catalog data for ServiceCode batch and the code->row binding that assembles Quotas rows in the operation's handler; the row text must be AWS's, not paraphrased. Traces: service-quotas-catalog-list-aws-default-service-quotas-batch#task#1.

Cause 2 of 8 — ServiceCode 'cassandra' (fixture service-quotas-catalog-list-aws-default-service-quotas-cassandra, step task#1). AWS: L-F90953AC.Description is 'The maximum number of child UDTs supported for a UDT.', L-17766544.Description is the read-throughput text ending in the devguide quotas URL, L-0659E12E.Description is the clustering-column text ending in the devguide quotas URL, L-7A88D508 is 'The maximum number of UDTs that can be created per region across all keyspaces.' with Value 256.0, and L-96FEFC6D is QuotaName 'Max number of UDTs per table' / Description 'The maximum number of UDTs that a table can reference.' with Value 50.0 and Adjustable true. Emulator: Descriptions are re-authored and the documentation URLs dropped, L-7A88D508.Value is 5000.0, and L-96FEFC6D is served as 'Max nested depth per UDT' with Value 5.0 and Adjustable false — plus Adjustable/Unit/Value divergences across roughly 25 further Keyspaces QuotaCodes. Why: Adjustable false tells a client the limit cannot be raised, so it never attempts RequestServiceQuotaIncrease; a 20x-wrong Value and a swapped QuotaName make the row unusable for sizing. Fix: the default-quota catalog data for ServiceCode cassandra and its QuotaCode binding in the ListAWSDefaultServiceQuotas handler. Traces: service-quotas-catalog-list-aws-default-service-quotas-cassandra#task#1.

Cause 3 of 8 — ServiceCode 'cloud9' (fixture service-quotas-catalog-list-aws-default-service-quotas-cloud9, step task#1). AWS: the Cloud9 rows name the service in the Description ('The maximum number of AWS Cloud9 SSH development environments that you can create in this account in the current Region.' for L-A29EDECE, the matching per-user text for L-5D26553C, the EC2 variants for L-8ECD6BDB and L-C1302C17) and L-65F36924 is QuotaName 'Members per development environment' / Description 'The maximum number of users that can participate in a single AWS Cloud9 development environment in this account in the current Region.'. Emulator: every Description is a paraphrase that drops the service name ('The maximum number of SSH development environments in this account in the current Region.', 'The maximum number of members one development environment can be shared with.') and L-65F36924.QuotaName is 'Shared environment members'. Why: a client or console that matches quotas by name or shows AWS's description to a user displays text AWS never returns, and name-based lookups miss. Fix: the default-quota catalog data for ServiceCode cloud9. Traces: service-quotas-catalog-list-aws-default-service-quotas-cloud9#task#1.

Cause 4 of 8 — ServiceCode 'cloudhsm' (fixture service-quotas-catalog-list-aws-default-service-quotas-cloudhsm, step task#1). AWS: L-4B16B391 carries UsageMetric.MetricDimensions.Resource 'Cluster'; L-95BA35D1 carries a UsageMetric (MetricName ResourceCount, MetricNamespace AWS/Usage, MetricDimensions Resource 'HSM'/Service 'CloudHSM'/Type 'Resource', MetricStatisticRecommendation Maximum); L-36814031 is QuotaName 'Keys per CloudHSM cluster' with Adjustable false; L-F9BBB650 is QuotaName 'Length of a password' / Description 'The maximum number of characters for a password.' with Value 32.0.
