# iam GetCredentialReport is not routed at all (InvalidAction 'unknown action'), so no credential report can ever be read

> _Note: this issue was identified against the code base at commit `485738b7dc7c0c61d237947a8376c6fee5331009`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
GetCredentialReport

## Description
REOPENS 20261029T192356Z-iam-acceptdelegationrequest-acquirerole-associatedelegationrequest-answer-notimplemented-and-generatecredentialreport.md: its fix left the call refused. That issue's Cause 2 wired GenerateCredentialReport (it now answers 200 with State=STARTED/INPROGRESS/COMPLETE), but the sibling read of the same feature, GetCredentialReport, was left unwired, so the check that issue was grounded in (iam.op-contract-generateCredentialReport) still fails — now on the Get call. The open issue 20261025T000319Z-iam-10-net-new-behavioral-root-causes-four.md describes the credential-report family in its Cause 3, but its replay key for that cause is `iam|GenerateCredentialReport|InvalidAction`; since Generate is now served the key no longer matches and the replay report marks none of the six checks below as OWNED or ALREADY FILED, so that issue does not cover them.

One root cause (1 of 1): GetCredentialReport is absent from the iam service's awsQuery action dispatch, so the framework answers it from the unroutable-operation path.

AWS: Smithy (com.amazonaws.iam) binds GetCredentialReport to AWSIdentityManagementV20100508. Input smithy.api#Unit; output GetCredentialReportResponse{Content: ReportContentType (blob), ReportFormat: ReportFormatType (enum, single value "text/csv"), GeneratedTime: dateType}. Modeled errors, with their awsQuery codes and statuses: CredentialReportNotReadyException (awsQueryError code ReportInProgress, HTTP 404, doc "The request was rejected because the credential report is still being generated."), CredentialReportNotPresentException (ReportNotPresent, HTTP 410, doc "The request was rejected because the credential report does not exist. To generate a credential report, use GenerateCredentialReport."), CredentialReportExpiredException (ReportExpired, HTTP 410, "the most recent credential report has expired"), ServiceFailureException (ServiceFailure, HTTP 500). The documented state machine is: GenerateCredentialReport starts a generation (STARTED/INPROGRESS) → GetCredentialReport refuses with ReportInProgress 404 until it completes → then answers 200 with ReportFormat text/csv and a GeneratedTime, served from cache (two immediate Gets return the same GeneratedTime and Content, they do not regenerate) → once the report ages past its validity window, Get is refused ReportExpired 410 and a fresh GenerateCredentialReport is required. Recorded behavior additionally shows the CSV body: its first line is the header beginning `user,arn,user_creation_time` and containing the `password_enabled` column, and it carries a `<root_account>` row whose `arn` is this account's root ARN, `arn:aws:iam::<account-id>:root` — the account id is a value read from the live account (STS GetCallerIdentity), the rest of the header and the `<root_account>` literal are fixed text. ReportInProgress is recorded as carrying an EMPTY message.

Emulator: every GetCredentialReport call is refused with awsQuery code `InvalidAction` and the message `unknown action: GetCredentialReport` — a code the IAM model declares for no operation, i.e. the answer of a service that does not have the API at all rather than one of the four modeled conditions. The cause is visible in the checkout: services/service-com-amazonaws-iam-awsidentitymanagementv20100508/src/ops/SKIPPED_STUBS.md line 27 lists `GetCredentialReport` as declined by the stub generator (Unit/absent input) and therefore "modeled-but-unwired", answered by the framework's unroutable-operation path; there is no src/ops/get_credential_report.rs, while its sibling src/ops/generate_credential_report.rs was hand-authored and wired via build.rs's `//! @op` header (SKIPPED_STUBS.md "Since hand-authored"). Generate already records the generation in state (crate::state::CredentialReportGeneration{requested, completes, reported_complete}) but no report CONTENT is ever produced, so the whole read half of the feature is missing.

Why: a client cannot read a credential report at all, and the error it receives says the IAM API does not exist rather than naming a condition it can branch on — InvalidAction is indistinguishable from a bad SDK/region/endpoint, and retrying never helps. Compliance and credential-audit tooling that enumerates users through the report is dead on arrival, and none of the three distinct refusals AWS uses (ReportInProgress 404, ReportNotPresent 410, ReportExpired 410) or the text/csv artifact are observable. The feature now also lies: Generate reports STARTED/COMPLETE for a report that can never be fetched.

Fix: the iam service's awsQuery action dispatch/routing table must bind GetCredentialReport (hand-author services/service-com-amazonaws-iam-awsidentitymanagementv20100508/src/ops/get_credential_report.rs with its types module, exactly as generate_credential_report.rs was done, so build.rs picks it up from the `//! @op GetCredentialReport` header), plus a handler that reads the generation record in src/state.rs and (a) refuses ReportNotPresent 410 when the account has never generated one, (b) refuses ReportInProgress 404 with an empty message while the generation is not yet due, (c) returns 200 with ReportFormat "text/csv", a stable GeneratedTime and a CSV body rendered from the account's live IAM users (header beginning user,arn,user_creation_time and including password_enabled, plus the <root_account> row with arn:aws:iam::<account-id>:root) cached so repeat Gets are identical, and (d) refuses ReportExpired 410 once the report passes its validity window.

Traces: iam.get-credential-report, iam.op-contract-getCredentialReport, iam.generate-credential-report, iam.credential-report-ready-then-expires, iam.credential-report-ttl-expiry-requires-regeneration, iam.op-contract-generateCredentialReport.

## Steps to Reproduce
1. Build and boot the emulator from this checkout and replay the behavioral suite.
2. Call iam:GenerateCredentialReport — it answers 200 with State (STARTED on a fresh account).
3. Call iam:GetCredentialReport (awsQuery Action=GetCredentialReport against the iam endpoint) immediately — observe `InvalidAction` / `unknown action: GetCredentialReport` instead of ReportInProgress 404 (empty message) or the completed report.
4. Poll GetCredentialReport until the generation completes — it keeps answering InvalidAction, so the text/csv report, its GeneratedTime and its `<root_account>` row are never observable, and the ReportNotPresent/ReportExpired legs cannot be reached either.
