# cloudformation__network-firewall: AWS::NetworkFirewall::FirewallPolicy and ::RuleGroup are never provisioned — the stack reaches CREATE_COMPLETE, Ref yields the declared name instead of the ARN, and an invalid policy is never refused (3 causes)

> _Note: this issue was identified against the code base at commit `e38416fc0970ac2ae0c65df6bda0d7aff4be2337`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateStack

## Description
Three distinct root causes on the CloudFormation x Network Firewall deploy surface. A fixer must close all three before submitting. They share one mechanism — the CloudFormation provisioner accepts the AWS::NetworkFirewall::* resource types but never drives the Network Firewall control plane — yet each is a separately observable defect and is listed separately below.

Cause 1 of 3: an AWS::NetworkFirewall::FirewallPolicy declared in a template is not created in Network Firewall, and Ref on it resolves to the declared policy name instead of the policy ARN.
AWS: CloudFormation provisions the resource by calling Network Firewall CreateFirewallPolicy (Smithy com.amazonaws.networkfirewall#CreateFirewallPolicy: input FirewallPolicyName (ResourceName, required, length 1-128, pattern ^[a-zA-Z0-9-]+$) + FirewallPolicy (required); output FirewallPolicyResponse with FirewallPolicyArn/FirewallPolicyId). After CREATE_COMPLETE the policy is returned by ListFirewallPolicies (an entry whose Name is the declared name and whose Arn is the policy ARN) and is readable with DescribeFirewallPolicy, carrying the template's StatelessDefaultActions/StatelessFragmentDefaultActions and its Tags plus CloudFormation's propagated aws:cloudformation:* tags. Per the resource's template reference, Ref returns the firewall policy ARN (arn:aws:network-firewall:<region>:<account>:firewall-policy/<name>) and Fn::GetAtt FirewallPolicyId returns the policy id.
Emulator: the stack reaches CREATE_COMPLETE, but ListFirewallPolicies has no entry with the declared name (the filtered list is empty), so DescribeFirewallPolicy is never reachable, and the stack Output fed by {"Ref": "Policy"} resolves to the bare declared policy name rather than any ARN. Hypothesis: the resource type is handled by a generic/no-op provisioner that mints a physical resource id equal to the declared name and performs no CreateFirewallPolicy call.
Why: every IaC path to Network Firewall is dead. A client that deploys a policy by template and then drives Network Firewall with the stack's Ref output gets a value that is not an ARN, and the policy it believes it created does not exist — follow-on CreateFirewall/AssociateFirewallPolicy calls, and the stack-delete-then-expect-ResourceNotFoundException contract, cannot work.
Fix: the CloudFormation resource provisioner for AWS::NetworkFirewall::FirewallPolicy — it must call the Network Firewall CreateFirewallPolicy handler, record the returned ARN as the physical resource id that Ref publishes, expose FirewallPolicyId via GetAtt, propagate the template Tags, and call DeleteFirewallPolicy on stack delete.
Traces: cloudformation__network-firewall.deploy-networkfirewall-firewall-policy-round-trip-and-delete.

Cause 2 of 3: the same for AWS::NetworkFirewall::RuleGroup — a STATEFUL rule group declared in a template is not created, and Ref resolves to the declared name instead of the rule-group ARN.
AWS: CloudFormation calls Network Firewall CreateRuleGroup (Smithy com.amazonaws.networkfirewall#CreateRuleGroup: RuleGroupName (required), Type (RuleGroupType enum, required), Capacity (required), RuleGroup; output RuleGroupResponse with RuleGroupArn/RuleGroupId). After CREATE_COMPLETE, ListRuleGroups(Type=STATEFUL) contains an entry whose Name is the declared name and whose Arn is the rule-group ARN, and DescribeRuleGroup reads back the declared Type, Capacity, RulesSource.RulesString and tags. Ref returns the rule group ARN; Fn::GetAtt RuleGroupId returns its id.
Emulator: the stack reaches CREATE_COMPLETE, ListRuleGroups(Type=STATEFUL) has no entry with the declared name, and the Output fed by {"Ref": "RuleGroup"} is the bare declared name.
Why: a template-declared stateful rule group cannot be attached to a policy or inspected, and the stack output cannot be used as the ARN AWS publishes.
Fix: the CloudFormation resource provisioner for AWS::NetworkFirewall::RuleGroup — call CreateRuleGroup, publish the returned ARN as the physical id, expose RuleGroupId via GetAtt, propagate tags, and DeleteRuleGroup on stack delete.
Traces: cloudformation__network-firewall.deploy-networkfirewall-stateful-rule-group-round-trip-and-delete.

Cause 3 of 3: because no Network Firewall call is made, an AWS::NetworkFirewall::FirewallPolicy whose StatelessDefaultActions names an unknown action is never refused — the stack reaches CREATE_COMPLETE instead of rolling back with the service's refusal on the resource event.
AWS: CreateFirewallPolicy refuses an unknown stateless default action with InvalidRequestException (Smithy: CreateFirewallPolicy declares InvalidRequestException, client error, HTTP 400). CloudFormation surfaces it on the resource's CREATE_FAILED event and the create rolls back to ROLLBACK_COMPLETE with no early template-validation row; the resource-handler reason is 'Resource handler returned message: "StatelessDefaultActions is invalid, parameter: [<action>], context: StatelessDefaultActions (Service: NetworkFirewall, Status Code: 400, Request ID: <request id>) (SDK Attempt Count: <n>)" (RequestToken: <token>, HandlerErrorCode: InvalidRequest)'. Fixed text: 'StatelessDefaultActions is invalid, parameter: [', '], context: StatelessDefaultActions (Service: NetworkFirewall, Status Code: 400, Request ID: ', ') (SDK Attempt Count: ', ')' and HandlerErrorCode 'InvalidRequest'; the variable parts are the rejected action value taken from the request, and the per-run request id / request token / attempt count (which the check masks and which are not part of the requirement). No policy by that name exists afterwards.
Emulator: the stack ends CREATE_COMPLETE; nothing is refused, no CREATE_FAILED resource event and no handler reason are produced.
Why: an invalid Network Firewall policy in a template deploys "successfully", so a client gets a green stack with no policy behind it and never sees the parameter error that names the offending property.
Fix: the same AWS::NetworkFirewall::FirewallPolicy provisioner (Cause 1) must route the create through the Network Firewall CreateFirewallPolicy handler so the service's InvalidRequestException drives the resource failure, and CloudFormation's rollback path must record the handler reason on the resource event.
Traces: cloudformation__network-firewall.deploy-networkfirewall-firewall-policy-invalid-default-action-rejected-and-rolled-back.

## Evidence
Cause 1 — expected ListFirewallPolicies to contain exactly one entry named <policy name> whose Arn equals the stack Output 'PolicyArn' (Ref Policy); actual AssertionError: "ListFirewallPolicies entries named '<policy name>': [], Ref '<policy name>'" — the list is empty and the Ref value is the declared name, not an arn:aws:network-firewall:...:firewall-policy/<name>.
Cause 2 — expected ListRuleGroups(Type=STATEFUL) to contain one entry named <rule group name> whose Arn equals the stack Output 'RuleGroupArn' (Ref RuleGroup); actual AssertionError: "ListRuleGroups entries named '<rule group name>': [], Ref '<rule group name>'".
Cause 3 — expected the stack created with StatelessDefaultActions ['aws:bogus-action'] to end 'ROLLBACK_COMPLETE' with no early-validation row and the resource-handler reason 'StatelessDefaultActions is invalid, parameter: [aws:bogus-action], context: StatelessDefaultActions (Service: NetworkFirewall, Status Code: 400, Request ID: <id>) (SDK Attempt Count: <n>)' / HandlerErrorCode 'InvalidRequest'; actual AssertionError: "rejected stack ended 'CREATE_COMPLETE'".
