# cloudformation: AWS::NeptuneGraph::Graph and AWS::NeptuneGraph::GraphSnapshot are rejected as unrecognized resource types, so neither a Neptune Analytics graph/snapshot stack nor its validation-rollback path can be deployed

> _Note: this issue was identified against the code base at commit `e38416fc0970ac2ae0c65df6bda0d7aff4be2337`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateStack

## Description
Cause 1 of 1: CloudFormation's template resource-type registry does not know the AWS::NeptuneGraph::* resource types, so CreateStack refuses at template validation every stack that declares a Neptune Analytics graph (alone or with a graph snapshot). Both failing checks die on their first CreateStack, so the whole graph/snapshot deploy surface — the happy-path round trip and the ProvisionedMemory-rejection rollback path — is unreachable.

AWS: CloudFormation publishes AWS::NeptuneGraph::Graph and AWS::NeptuneGraph::GraphSnapshot as first-class resource types, so CreateStack accepts a template declaring them and provisions them through the Neptune Analytics control plane (Smithy, com-amazonaws-neptunegraph-amazonneptunegraph: CreateGraph POST /graphs -> 201, required graphName @length 1..63 @pattern ^(?!g-)[a-z][a-z0-9]*(-[a-z0-9]+)*$ and provisionedMemory @range 16..24576, optional replicaCount @range 0..2, deletionProtection, publicConnectivity, tags; CreateGraphSnapshot POST /snapshots -> 201, required graphIdentifier @pattern ^g-[a-z0-9]{10}$ and snapshotName @pattern ^(?!gs-)[a-z][a-z0-9]*(-[a-z0-9]+)*$, returning id @pattern ^gs-[a-z0-9]{10}$; both model ValidationException -> HTTP 400). The Graph resource's Ref is the graph id and GraphArn is its ARN; stack tags and the resource's own Tags propagate to the graph and are readable through neptune-graph ListTagsForResource. When a declared property violates the service's own constraint, CloudFormation does NOT refuse at template validation — it accepts the stack, the resource create is refused by the service, the resource goes CREATE_FAILED and the stack rolls back to ROLLBACK_COMPLETE, and the StackEvent's ResourceStatusReason is the registry-handler envelope: Resource handler returned message: "<the service's own error message>" (RequestToken: <uuid>, HandlerErrorCode: <code>). For provisionedMemory below the modeled minimum the enveloped message is NeptuneGraph's validation text — fixed text "1 validation error detected: Value '<value>' at 'provisionedMemory' failed to satisfy constraint: Member must have value greater than or equal to 16 (Service: NeptuneGraph, Status Code: 400, Request ID: <request id>) (SDK Attempt Count: <n>)" with the offending value from the request and the request id / attempt count per-run — and HandlerErrorCode InvalidRequest. The rejected graph must not appear in ListGraphs.

Emulator: CreateStack is refused with HTTP 400, error code ValidationError and message "Template format error: Unrecognized resource types: [AWS::NeptuneGraph::Graph]" (graph-only template) or "...: [AWS::NeptuneGraph::Graph, AWS::NeptuneGraph::GraphSnapshot]" (graph + snapshot template). The fixed text is "Template format error: Unrecognized resource types: [" ... "]"; the bracketed list is the set of type names taken from the submitted template. That message/code shape is what AWS emits for a genuinely unknown type — the defect is that these types are classified as unknown at all. Consequently no stack id is minted, there is no CREATE_FAILED/ROLLBACK_COMPLETE path, no StackEvent reason, and no graph or snapshot is ever created.

Why: a client provisioning Neptune Analytics through IaC cannot create a stack at all. The synchronous ValidationError makes a correct template look malformed, so the caller debugs a template bug that does not exist; and because no resource create is ever attempted, the service's own validation refusals never surface as resource-level failures, so a pipeline that relies on CloudFormation to report and roll back a bad ProvisionedMemory gets no stack and no handler reason to read.

Fix: CloudFormation's template resource-type registry and the resource provisioners it dispatches to in the cloudformation service crate — the type table consulted during CreateStack template validation (services/service-com-amazonaws-cloudformation-cloudformation/src/ops/create_stack.rs and the provisioner it routes to), the per-type create/update/delete + Ref/GetAtt (GraphArn) handlers, tag propagation to the created graph, and the handler-error envelope the resource-failure StackEvent carries so a service-side ValidationException becomes a CREATE_FAILED resource with HandlerErrorCode InvalidRequest and a ROLLBACK_COMPLETE stack. Note: open issue 20261107T075601Z-cloudformation-ec2-ssm-cloudformation-ssm-aws-ssm-maintenancewindowtarget-unrecognised-ec2-ref.md reports the same class of gap for AWS::SSM::MaintenanceWindowTarget and does not cover the NeptuneGraph types.

Traces: cloudformation__neptune-graph.deploy-neptune-graph-snapshot-round-trip-and-delete and cloudformation__ec2__neptune-graph.deploy-neptune-graph-provisioned-memory-out-of-range-rejected (both listed under the cloudformation__neptune-graph heading; both error on their first CreateStack).

Check cloudformation__neptune-graph.deploy-neptune-graph-snapshot-round-trip-and-delete
Expected (AWS): CreateStack accepts a template with Graph (AWS::NeptuneGraph::Graph) and a GraphSnapshot (AWS::NeptuneGraph::GraphSnapshot) and returns a StackId; the stack reaches CREATE_COMPLETE and the graph/snapshot read back through neptune-graph.
Actual (emulator): botocore.exceptions.ClientError: An error occurred (ValidationError) when calling the CreateStack operation: Template format error: Unrecognized resource types: [AWS::NeptuneGraph::Graph, AWS::NeptuneGraph::GraphSnapshot]

Check cloudformation__ec2__neptune-graph.deploy-neptune-graph-provisioned-memory-out-of-range-rejected
Expected (AWS): CreateStack with Resources.Graph = {Type: AWS::NeptuneGraph::Graph, Properties: {GraphName:<name>, ProvisionedMemory: 1, ReplicaCount: 0, DeletionProtection: false, PublicConnectivity: false, Tags:[...]}} is ACCEPTED and returns a StackId; the stack ends ROLLBACK_COMPLETE; the Graph resource's CREATE_FAILED StackEvent carries ResourceStatusReason = Resource handler returned message: "1 validation error detected: Value '1' at 'provisionedMemory' failed to satisfy constraint: Member must have value greater than or equal to 16 (Service: NeptuneGraph, Status Code: 400, Request ID: <id>) (SDK Attempt Count: <n>)" (RequestToken: <uuid>, HandlerErrorCode: InvalidRequest); ListGraphs does not list the rejected name; and the same template with ProvisionedMemory 16 reaches CREATE_COMPLETE with Ref/GetAtt GraphArn matching GetGraph and the template+stack tags readable via ListTagsForResource.
Actual (emulator): botocore.exceptions.ClientError: An error occurred (ValidationError) when calling the CreateStack operation: Template format error: Unrecognized resource types: [AWS::NeptuneGraph::Graph] — refused synchronously, so no stack, no rollback and no handler reason exist.

## Steps to Reproduce
1. Boot the emulator and point botocore at it.
2. cfn = client("cloudformation").
3. CreateStack(StackName="sim2real-nggraph-<unique>", TemplateBody={"AWSTemplateFormatVersion":"2010-09-09","Resources":{"Graph":{"Type":"AWS::NeptuneGraph::Graph","Properties":{"GraphName":"<name>","ProvisionedMemory":16,"ReplicaCount":0,"DeletionProtection":false,"PublicConnectivity":false,"Tags":[{"Key":"k","Value":"v"}]}}},"Outputs":{"GraphId":{"Value":{"Ref":"Graph"}},"GraphArn":{"Value":{"Fn::GetAtt":["Graph","GraphArn"]}}}}) -> observe ValidationError "Template format error: Unrecognized resource types: [AWS::NeptuneGraph::Graph]" instead of a StackId.
4. Repeat step 3 with ProvisionedMemory 1 -> AWS accepts the stack and rolls it back with the NeptuneGraph handler reason; the emulator raises the same template-format ValidationError.
5. Repeat step 3 adding a second resource {"Snapshot":{"Type":"AWS::NeptuneGraph::GraphSnapshot","Properties":{"GraphIdentifier":{"Ref":"Graph"},"SnapshotName":"<snap-name>"}}} -> ValidationError lists both AWS::NeptuneGraph::Graph and AWS::NeptuneGraph::GraphSnapshot.
