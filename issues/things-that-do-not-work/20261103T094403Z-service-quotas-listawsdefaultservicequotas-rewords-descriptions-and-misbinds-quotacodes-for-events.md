## Description
BUNDLE OF 10 CAUSES, one per ServiceCode. All ten are the same shared fault in the emulator's built-in default-quota catalog for ListAWSDefaultServiceQuotas: for the ServiceCode asked about, the emulator returns HTTP 200 with a Quotas list whose per-row text is paraphrased rather than AWS's own Description/QuotaName strings, and whose rows are bound to the WRONG QuotaCode, so a given L- code carries another quota's name, Value, Unit, Period and UsageMetric. A fixer must close all TEN causes below before submitting.

General statement of the defect (applies to every cause):
AWS: ListAWSDefaultServiceQuotas returns the AWS-published default quota catalog for the requested ServiceCode. Smithy (services/service-com-amazonaws-servicequotas-servicequotasv20190624): ListAWSDefaultServiceQuotas input ServiceCode (required, @length 1..63, @pattern ^[a-zA-Z][a-zA-Z0-9-]{1,63}$), output Quotas -> ServiceQuotaListDefinition of ServiceQuota; ServiceQuota members ServiceCode, ServiceName, QuotaArn, QuotaCode (@length 1..128, @pattern ^[a-zA-Z][a-zA-Z0-9-]{1,128}$), QuotaName, Value (QuotaValue double, @range 0..10000000000), Unit, Adjustable (default false), GlobalQuota (default false), UsageMetric (MetricInfo), Period (QuotaPeriod), QuotaContext, Description (@length 0..350). The model does not enumerate the catalog contents, so the required per-row CONTENT is recorded behavior only: each QuotaCode identifies exactly one AWS quota, and QuotaName/Description/Value/Unit/Adjustable/Period/UsageMetric are that quota's AWS-published attributes. The Description and QuotaName are AWS's fixed text for that quota code -- they are not free-form prose the server may re-author.
Emulator: answers 200 but (a) substitutes its own paraphrase for AWS's Description/QuotaName on many rows, and (b) attaches whole rows to the wrong QuotaCode, so Value, Unit, Period and UsageMetric belong to a different quota; Period and UsageMetric are also dropped on rows where AWS populates them.
Why: Service Quotas is the authoritative source clients use to discover limits. A client reading these rows keys on QuotaCode: it sizes workloads, pre-flights capacity and raises increase requests against a Value and Unit that belong to a different quota (e.g. 50 TPS reported for a 5 TPS limit, 10240 MB/s reported for a 100-file-system count limit), and rate-limit logic breaks outright because Period/UsageMetric are missing. Paraphrased Descriptions/QuotaNames additionally defeat any consumer matching on AWS's documented text.
Fix: the service-quotas default-quota catalog data behind the ListAWSDefaultServiceQuotas handler -- restore AWS's verbatim per-QuotaCode rows (Description, QuotaName, Value, Unit, Adjustable, GlobalQuota, Period, UsageMetric) and correct the row-to-QuotaCode binding so no row is shifted onto a neighbouring code.
