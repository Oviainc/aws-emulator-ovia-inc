# DynamoDB: legal projection reads answered 501 NotImplemented, validation lost behind index stubs, and 8 control-plane / resource-policy divergences

> _Note: this issue was identified against the code base at commit `ce4f28f15b4841beefbad6c596b9d2158570753e`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
GetItem

## Description
Ten net-new root causes. Causes 1-2 are the emulator answering 501 for requests AWS serves or refuses with ValidationException; 3-7 are control-plane validation; 8-10 are the resource-policy surface. All ten must be closed before submitting.

Cause 1 of 10: legal ProjectionExpression / AttributesToGet requests are refused with NotImplemented (HTTP 501). AWS: ProjectionExpression is a modeled member of GetItem/Query/Scan/BatchGetItem (Smithy: Query.ProjectionExpression -> ProjectionExpression, AttributesToGet -> AttributeNameList) and these requests are SERVED with HTTP 200; a reserved word used bare, or Select=COUNT combined with ProjectionExpression, is refused with ValidationException. Emulator: answers 501 'An error occurred (NotImplemented) ... operation BatchGetItem with ProjectionExpression is scaffolded but not implemented in this emulator' (same for Scan with a ProjectionExpression path, Query with ProjectionExpression, BatchGetItem with a reserved-word projection). Why: 501 is not in the operation's modeled error set, so every SDK treats it as a non-retryable protocol fault and no projection read works at all. Fix: implement projection in the GetItem/Query/Scan/BatchGetItem handlers (the stub branches that raise NotImplemented). Checks: dynamodb.batch-get-item-expression-and-legacy-parameter-rules, dynamodb.ddb-ss-aliased-dotted-attribute-name-projects-the-top-level-attribute, dynamodb.query-and-put-item-placeholder-and-reserved-word-validation, dynamodb.ddb-wf-unaliased-reserved-word-projection-rejected, dynamodb.ddb-wf-select-count-with-projection-expression-rejected. (Related open issue 20261024T065715Z-dynamodb-iam-sts-dynamodb-data-plane-reads-are-never-authorized-identity.md covers other projection checks; it does not cover these.)

Cause 2 of 10: requests AWS refuses with ValidationException are answered 501 because the request validation runs AFTER the unimplemented index/legacy branch. AWS: 'The table does not have the specified index: <name>', a sort-key-only index condition, a string value for a numeric index key, ConsistentRead on a GSI, a QueryFilter/KeyConditions argument defect, Select=ALL_PROJECTED_ATTRIBUTES without IndexName, Select=ALL_ATTRIBUTES with a ProjectionExpression and a malformed TransactGetItems request are all 400 ValidationException -- they never reach an index read. Emulator: answers 501 NotImplemented ('operation Query with IndexName is scaffolded but not implemented in this emulator'). Why: an invalid request is indistinguishable from an unimplemented feature, and the refusal is not retryable or classifiable. Fix: hoist request validation ahead of the feature gate in the Query/Scan/TransactGetItems handlers. Checks: dynamodb.ddb-gsi-query-naming-an-absent-index-rejected, dynamodb.ddb-gsi-query-omitting-the-index-partition-key-rejected, dynamodb.ddb-gsi-query-on-numeric-index-key-with-a-string-value-rejected, dynamodb.query-capacity-gsi-rejects-consistent-read-lsi-accepts-it, dynamodb.select-non-specific-values-reject-projection-expression, dynamodb.legacy-queryfilter-scanfilter-keyconditions-argument-rules, dynamodb.transact-get-items-top-level-vs-cancellation-error-class.

Cause 3 of 10: the Select-rule refusal messages are not AWS's. AWS has exact ValidationException texts for Select=SPECIFIC_ATTRIBUTES without a projection and for Select=ALL_PROJECTED_ATTRIBUTES on a base-table scan. Emulator: 'One or more parameter values were invalid: Select type SPECIFIC_ATTRIBUTES requires the attributes to be listed in ProjectionExpression' and '...Select type ALL_PROJECTED_ATTRIBUTES is allowed only when an index is scanned'. Fix: Scan/Query Select validation messages. Checks: dynamodb.ddb-frc-specific-attributes-without-a-projection-rejected, dynamodb.ddb-ss-all-projected-attributes-on-a-base-table-scan-rejected.

Cause 4 of 10: CreateTable/UpdateTable accept schemas AWS refuses. AWS refuses: a GSI with ProjectionType INCLUDE and no NonKeyAttributes; a vector index whose Dimensions exceed the limit (4097); a single UpdateTable that pairs Create and Delete for a GSI; an UpdateTable whose AttributeDefinitions no longer cover live index keys; a PutItem whose vector attribute has the wrong dimension. Emulator: all succeed with HTTP 200 and a TableDescription. Why: an invalid table shape is created and only fails later, against real AWS, at deploy time. Fix: CreateTable/UpdateTable/PutItem schema validation. Checks: dynamodb.create-table-rejects-malformed-requests, dynamodb.create-table-vector-index-validation-rejected, dynamodb.ddb-gsi-create-and-delete-paired-in-one-update-rejected, dynamodb.update-table-gsi-attribute-definitions-track-live-keys, dynamodb.put-item-vector-write-validation-and-search-projection.

Cause 5 of 10: CreateTable/UpdateTable refusal messages diverge. AWS: 'Invalid KeySchema for index <name>: The <ordinal> KeySchemaElement is not a RANGE key type' is reported for the SECOND element onward and the ordinal follows AWS's numbering; the undeclared-index-key message lists the whole key schema of the FIRST invalid index ('...Keys: [TaskStatus, CreationTime], AttributeDefinitions: [...]'); 'One or more parameter values were invalid: ProvisionedThroughput must be specified when BillingMode is PROVISIONED'; 'One or more parameter values were invalid: ProvisionedThroughput cannot be specified when BillingMode is PAY_PER_REQUEST'; and deleting an absent GSI is a ValidationException, not a not-found. Emulator: 'The third KeySchemaElement is not a RANGE key type' for a HASH,RANGE,HASH schema, lists only the single missing attribute, 'Both ReadCapacityUnits and WriteCapacityUnits must be specified when BillingMode is PROVISIONED', 'Neither ReadCapacityUnits nor WriteCapacityUnits can be specified when BillingMode is PAY_PER_REQUEST', 'Invalid KeySchema: Some index key attribute have no definition', and ResourceNotFoundException 'Requested resource not found: Index not found for table <table>: <index>'. Fixed text is AWS's sentence; the variable parts are the index name, the key/attribute lists and the ordinal, taken from the request and the table's schema. Fix: CreateTable/UpdateTable validation messages. Checks: dynamodb.create-table-gsi-key-schema-hash-after-range-rejected, dynamodb.ddb-gsi-create-table-with-an-undeclared-index-key-rejected, dynamodb.vvd-key-schema-attribute-without-definition-rejected, dynamodb.vvd-on-demand-table-with-provisioned-throughput-rejected, dynamodb.update-table-throughput-on-on-demand-table-and-zero-capacity-rejected, dynamodb.update-table-delete-of-an-absent-gsi-rejected.

Cause 6 of 10: a CreateTable racing a table that is still CREATING reports the wrong refusal. AWS: while the table is being created, every other creator gets ResourceInUseException 'Attempt to change a resource which is still in use: Table is being created: <table>' (Smithy: CreateTable errors = ResourceInUseException, LimitExceededException, InternalServerError, InvalidEndpointException). Emulator: answers 'Table already exists: <table>' to all seven losers. Fix: CreateTable's duplicate-name branch and table-state machine. Checks: dynamodb.concurrent-create-table-single-winner, dynamodb.vvd-duplicate-table-name-rejected.

Cause 7 of 10: index lifecycle and vector metering. AWS: a newly created GSI reaches ACTIVE and DescribeTable reports it; a vector write meters VectorWriteRequestBytes with a 1024-byte floor and per-dimension cost, and reports VectorIndexes consumption. Emulator: the index never reached ACTIVE within the check's budget, and VectorWriteRequestBytes was absent (None). Fix: index state transitions in the table state and the consumed-capacity accounting for vector indexes. Checks: dynamodb.ddb-wf-warm-throughput-defaults-applied, dynamodb.vector-write-request-bytes-floor-and-per-dimension-cost.

Cause 8 of 10: PutResourcePolicy accepts policies AWS refuses, and uses the wrong error class for the size limit. AWS refuses: an action belonging to another service, a public ('*') principal, a principal that does not exist, and a policy document over 20480 bytes -- the last with ValidationException; a malformed document is 'One or more parameter values were invalid: Invalid policy document: This policy contains invalid Json'; a document with no Version is stored with the IAM default Version 2008-10-17 (Smithy: PutResourcePolicy errors = LimitExceededException, PolicyNotFoundException, ResourceInUseException, ResourceNotFoundException, InternalServerError, InvalidEndpointException -- plus the service-common ValidationException). Emulator: accepts the foreign-service action, the public principal and the nonexistent principal (returning a RevisionId), answers LimitExceededException for the oversized document, 'Resource-based policy is not valid JSON: EOF while parsing a string at line 1 column 234' for the malformed one, and stores the policy with no Version. Fix: PutResourcePolicy validation and storage. Checks: dynamodb.ddb-rbp-foreign-service-action-rejected, dynamodb.ddb-rbp-public-principal-policy-rejected, dynamodb.ddb-ltr-resource-policy-naming-a-nonexistent-principal-rejected, dynamodb.ddb-rbp-policy-over-20480-bytes-rejected, dynamodb.ddb-rbp-omitted-policy-version-defaults-to-2008-10-17, dynamodb.ddb-rbp-malformed-policy-json-rejected. (Open issue 20261029T180026Z-dynamodb-partiql-resource-policy-arn-addressing-crc32-header.md owns two other resource-policy checks; it does not own these.)

Cause 9 of 10: resource ARNs are mis-validated. AWS: an ARN naming another region is ValidationException 'One or more parameter values were invalid: Invalid resource Arn: <arn>' (and for DescribeTable "1 validation error detected: Invalid AWS region in '<arn>'"); an INDEX ARN is 'One or more parameter values were invalid: Invalid resource arn provided, only table or stream is accepted. Provided resource arn: <arn>'; a STREAM ARN is ACCEPTED and holds a policy independent of its table's. Emulator: answers 'Invalid TableArn: Invalid ResourceArn provided as input <arn>' for the cross-region, index AND stream cases -- so a stream policy can never be set -- and ResourceNotFoundException for the cross-region DescribeTable. Why: the stream policy surface is unreachable and the messages do not match. Fix: the ResourceArn parser/validator shared by Put/Get/DeleteResourcePolicy and DescribeTable. Checks: dynamodb.ddb-rbp-another-regions-table-arn-rejected, dynamodb.ddb-ltr-describe-table-with-another-regions-arn-rejected, dynamodb.ddb-rbp-index-arn-as-policy-resource-rejected, dynamodb.ddb-rbp-stream-and-table-hold-independent-policies, dynamodb.ddb-rbp-table-action-in-a-stream-policy-rejected.

Cause 10 of 10: the resource-policy not-found message names the ARN instead of the table, and a deleted principal hangs the call. AWS: 'Requested resource not found: Table: <table-name> not found' for a never-created or deleted table addressed by ARN. Emulator: 'Requested resource not found: ResourceArn: <full-arn> not found'. Separately, GetResourcePolicy after the grantee principal is deleted never answered -- the check timed out after 60.0s where AWS answers immediately with the principal rewritten to its unique id. Why: clients parse the table name out of this message, and a hang is worse than any wrong answer. Fix: GetResourcePolicy's not-found message and its principal-resolution path. Checks: dynamodb.ddb-rbp-never-created-table-arn-rejected, dynamodb.ddb-rbp-deleted-table-drops-out-of-the-policy-derivation, dynamodb.ddb-rbp-deleted-principal-is-lazily-rewritten-to-its-unique-id-without-revoking-the-grant.
