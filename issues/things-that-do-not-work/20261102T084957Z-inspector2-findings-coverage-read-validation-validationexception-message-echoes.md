# inspector2 findings/coverage read validation: ValidationException message echoes rejected value and misstates the constraint clause

> _Note: this issue was identified against the code base at commit `3879dd05c1f9087ace2750498c91b002c8086d49`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
ListFindingAggregations

## Description
SIX causes, all one shared defect in the inspector2 constraint-violation ValidationException message builder, reached from the findings/coverage/reporting READ operations. In every cause the HTTP status (400) and the error type (ValidationException) are correct and ONLY $.message diverges, in three consistent ways: (a) the emulator interpolates the REJECTED REQUEST VALUE into the sentence ("Value '<v>' at '<path>' ...") where AWS writes "Value at '<path>' ..." for these constraint classes; (b) for a constrained LIST member the emulator names the indexed element path and emits a single bare constraint clause, where AWS names the LIST member and nests ALL of the element's constraints inside "Member must satisfy constraint: [ ... ]"; (c) the enum value set and the quoted @pattern are reproduced in a form AWS does not use - AWS emits a fixed per-enum value-set ordering (and, for some enums, a membership that is not the model's declaration list), and AWS strips the ^ / $ anchors from the pattern it quotes.

The fixed text of each sentence is the requirement: "1 validation error detected: ", "Value at '", "' failed to satisfy constraint: ", "Member must satisfy enum value set: [", "Member must satisfy constraint: [", "Member must have length less than or equal to ", "Member must have length greater than or equal to ", "Member must satisfy regular expression pattern: ". The variable parts are the member path (from the request shape), the enum value list and the pattern/limits (from the service's enum and @pattern/@length, in AWS's emitted form). The rejected request value is NOT part of the message for any of these constraint classes, so a message that carries it changes with every distinct bad input where AWS's is request-value-independent.

Cause 1 of 6: ListFindingAggregations with an unmodelled aggregationType.
AWS: Smithy: ListFindingAggregations.aggregationType (required) -> AggregationType enum; modeled error ValidationException (httpError 400); http POST /findings/aggregation/list. Recorded response: 400, x-amzn-errortype ValidationException, message "1 validation error detected: Value at 'aggregationType' failed to satisfy constraint: Member must satisfy enum value set: [AWS_EC2_INSTANCE, PACKAGE, REPOSITORY, ACCOUNT, IMAGE_LAYER, AWS_LAMBDA_FUNCTION, FINDING_TYPE, AWS_ECR_CONTAINER, TITLE, LAMBDA_LAYER, SERVERLESS_FUNCTION, CONTAINER_IMAGE, VM_INSTANCE, AMI]". Fixed text: "1 validation error detected: Value at '" + <member path> + "' failed to satisfy constraint: Member must satisfy enum value set: [" + <value set> + "]". Variable parts: the member path (the top-level required member name, 'aggregationType') and the value set, which AWS emits in its own fixed order and WITHOUT the model's CODE_REPOSITORY member. The rejected value never appears.
Emulator: 400 / ValidationException with message "1 validation error detected: Value 'Ami' at 'aggregationType' failed to satisfy constraint: Member must satisfy enum value set: [FINDING_TYPE, PACKAGE, TITLE, REPOSITORY, AMI, AWS_EC2_INSTANCE, AWS_ECR_CONTAINER, IMAGE_LAYER, ACCOUNT, AWS_LAMBDA_FUNCTION, LAMBDA_LAYER, CODE_REPOSITORY, VM_INSTANCE, CONTAINER_IMAGE, SERVERLESS_FUNCTION]" - the rejected value is interpolated and the value set is dumped in model-declaration order, including CODE_REPOSITORY.
Why: a client or assertion harness matching AWS's wording for a bad aggregationType never matches, and the echoed value makes the message vary per request. The advertised value set also tells a client the wrong set of acceptable aggregation types.
Fix: the shared constraint-violation ValidationException message builder in the inspector2 service crate, scalar-enum branch, reached from ListFindingAggregations request validation (suppress the rejected value; emit AWS's value set and ordering for AggregationType rather than the model declaration list).
