# cloudformation: ExecuteChangeSet on a CREATE change set never leaves REVIEW_IN_PROGRESS, so every `cdk deploy` dies with ValidationError "Template does not exist for stack [...] in REVIEW_IN_PROGRESS state"

> _Note: this issue was identified against the code base at commit `0e907dd5f11711da470907c28603d7f862f446bd`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
ExecuteChangeSet

## Description
Cause 1 of 1: a stack created through the change-set path (CreateChangeSet with ChangeSetType=CREATE, then ExecuteChangeSet) is left in REVIEW_IN_PROGRESS indefinitely. The execute neither provisions the template's resources nor advances the stack's status, so the deploy tool's very next template read is refused and the deployment aborts having created nothing. Ten behavioral checks under this service heading fail on exactly this, at the first `cdk deploy` of their app, before any of the behaviour they actually assert (bootstrap/qualifier handling, recreate-past-ROLLBACK_COMPLETE, termination protection, default function/table props, grants, synth determinism, cross-stack export ordering, env rollback) is reachable.

AWS: CreateChangeSet(ChangeSetType=CREATE) creates a stack stub in REVIEW_IN_PROGRESS; ExecuteChangeSet is then accepted and the stack LEAVES that status — it goes CREATE_IN_PROGRESS and settles in a terminal create status (CREATE_COMPLETE, or CREATE_FAILED/ROLLBACK_COMPLETE if a resource fails), after which GetTemplate serves the executed template. Smithy: ExecuteChangeSet models only ChangeSetNotFoundException (404, awsQueryError ChangeSetNotFound), InsufficientCapabilitiesException (400), InvalidChangeSetStatusException (400) and TokenAlreadyExistsException (400) — none of them covers an accepted execute that leaves the stack in review. Smithy: GetTemplate's output member TemplateBody (@length min 1) is served once the stack has an executed template; its only modeled error is ChangeSetNotFoundException (404). The sentence 'Template does not exist for stack [<stack name>] in REVIEW_IN_PROGRESS state' is AWS's own ValidationError (HTTP 400, error code ValidationError) for reading the template of a stack that still has none: its fixed text is 'Template does not exist for stack [' + '] in REVIEW_IN_PROGRESS state', with the stack name taken verbatim from the request. Seeing it after a successful ExecuteChangeSet is the symptom; the defect is the stack never leaving REVIEW_IN_PROGRESS.

Emulator: after CreateChangeSet+ExecuteChangeSet the stack remains REVIEW_IN_PROGRESS with no resources and no template, so `cdk deploy` exits 1 with the tail '<stack>: creating CloudFormation changeset...\n<stack>: deploying... [1/1]\n failed to deploy\n ValidationError: Template does not exist for stack [<stack>] in REVIEW_IN_PROGRESS state'. Where a check reads the status directly instead of the template, it sees the same cause: cloudformation.cdk-deploy-replaces-a-rollback-complete-stack-with-a-new-one asserts the failed create settled ROLLBACK_COMPLETE and gets 'REVIEW_IN_PROGRESS'.

Why: no change-set-based deployment works at all. The CreateChangeSet/ExecuteChangeSet pair is the default path of the AWS CDK and of `aws cloudformation deploy`, so a client gets a stack that exists only as a review stub — no resources, no outputs, no terminal status to wait on, and no template to diff or roll back — while AWS would have provisioned it. Every behaviour layered on top of a deployed CDK stack is unreachable, and a client that polls for a terminal create status waits forever.

Fix: the ExecuteChangeSet handler and the stack state machine it drives in the CloudFormation service — the execute must take the stack out of REVIEW_IN_PROGRESS into CREATE_IN_PROGRESS, run the provisioner to a terminal create status, and install the executed change set's template as the stack's template so GetTemplate stops refusing.

## Evidence
Expected (AWS): ExecuteChangeSet on a CREATE change set is accepted and the stack leaves REVIEW_IN_PROGRESS for CREATE_IN_PROGRESS and then a terminal create status; GetTemplate(StackName=<stack>) returns TemplateBody; `cdk deploy` exits 0.
Actual (emulator): the stack stays REVIEW_IN_PROGRESS with no resources and no template. `cdk deploy` exits 1, tail: '<stack>: creating CloudFormation changeset...\n<stack>: deploying... [1/1]\n❌ <stack> failed to deploy\n‣ ValidationError: Template does not exist for stack [<stack>] in REVIEW_IN_PROGRESS state' — observed on all ten checks (only the generated stack name differs; that name is a per-run value, not part of the requirement). In the fixed text 'Template does not exist for stack [' ... '] in REVIEW_IN_PROGRESS state' only the bracketed stack name comes from the request.
Status-read variant: 'AssertionError: the failed create left \'REVIEW_IN_PROGRESS\'' where AWS would report ROLLBACK_COMPLETE (cloudformation.cdk-deploy-replaces-a-rollback-complete-stack-with-a-new-one).

## Steps to Reproduce
1. CreateChangeSet(StackName=<new stack name>, ChangeSetType=CREATE, TemplateBody=<any template with one resource>); DescribeStacks reports REVIEW_IN_PROGRESS (correct so far).
2. ExecuteChangeSet(ChangeSetName=<that change set>, StackName=<new stack name>) — accepted.
3. Poll DescribeStacks: the stack never leaves REVIEW_IN_PROGRESS and none of the template's resources exist.
4. GetTemplate(StackName=<new stack name>) is refused with HTTP 400 ValidationError 'Template does not exist for stack [<new stack name>] in REVIEW_IN_PROGRESS state'.
Equivalently: run `cdk deploy <stack> --require-approval never` for any CDK app; it exits 1 at step [1/1].
