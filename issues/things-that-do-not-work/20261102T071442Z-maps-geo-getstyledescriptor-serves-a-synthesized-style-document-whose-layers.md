=== Cause 1 of 2: the style document's layers are generated from the emulator's own layer model instead of the published style release, so filters, paint, layout, source-layer and zoom ranges are wrong across the whole layer list ===
AWS: Smithy (services/service-com-amazonaws-geomaps-mapsservice/smithy-model/com-amazonaws-geomaps-mapsservice.json) binds GetStyleDescriptor to GET /v2/styles/{Style}/descriptor with ColorScheme/PoliticalView/Terrain/ContourDensity/Traffic/TravelModes/Buildings/PoiDensity/PoiCategories as query knobs; GetStyleDescriptorResponse$Blob is the @httpPayload and is documented as "the body of the style descriptor which is in application/json format"; the operation models NO errors. Recorded behavior: for a given (Style, ColorScheme) plus option set, AWS returns 200 with ONE published MapLibre style document -- a static release artifact, identical in every region and account -- in which each layer carries the published filter expression, source-layer, zoom range and paint/layout stops. The requirement is the published document's layer content, not the status code (which already matches at 200).
Emulator: returns 200 with a document it composes itself, and the layer bodies disagree with the published ones everywhere. Representative diffs from the replay on Standard/Dark: $.layers[id="rail_tunnel"].filter[1][1][1] expected 'kind', got 'role'; filter[1][2][0] expected 'transit', got 'way'; filter[1][2][1] missing (expected 'rail'); filter[2][0] expected 'has', got '=='; filter[2][1] type_mismatch (expected 'is_tunnel', got ['geometry-type']); filter[2][2] extra ('LineString'); filter[3] missing (expected ['!', ['has', 'service']]); filter[4] missing (expected ['case', ['all', ['has', 'kind_detail'], ['==', ['get', 'kind_detail'], 'disused']], false, true]); filter[5] missing (expected ['==', ['geometry-type'], 'LineString']); paint.line-color expected 'hsl(196, 10%, 18%)', got 'hsl(213, 7%, 25%)'; paint.line-width[3] expected 15, got 12; [6] expected 1.5, got 3.0; [7] and [8] missing (expected 20 and 2). The same clustered key list covers hundreds of other layers -- admin_country, admin_country-disputed(-mask), admin_label_continent/country/region, admin_region(-disputed/-mask), airport_label, airport_runway(-casing), bridge_minor(-casing/-shadow), bridge_motorway-trunk(-casing/-link/-shadow) and on -- on their filter, layout, paint, source-layer, minzoom and maxzoom members. It reproduces on a second style and colour scheme too (Monochrome/Light, where the same rail_tunnel paint.line-color is expected 'hsl(228, 0%, 91%)' and the emulator returns 'hsl(228, 0%, 100%)'), so this is the style builder, not one style record. The colours, widths and zoom numbers quoted here are examples of the per-(style, colour-scheme) published values, not literals to hard-code.
Why: a MapLibre/MapLibre-GL client renders directly from this document. Wrong filter expressions select the wrong features for a layer (the emulator filters rail by 'role'/'way' where the published style filters by 'kind'/'transit'/'rail', and drops the service/disused/geometry-type guards entirely), and wrong paint stops and zoom ranges change line colours, widths and what appears at which zoom. The map a client draws against the emulator therefore differs from the one it draws against AWS: features appear that should be filtered out, tunnel/disused variants are not separated, and any client that diffs, caches or snapshot-tests the style document sees a document AWS never published.
Fix: the style-document builder and the published style records behind it, not the handler's status path.
Traces: geo-maps-style-descriptor-rich-options#task#1 (Standard/Dark) and geo-maps-style-descriptor-rich-options#task#2 (Monochrome/Light). === Cause 2 of 2: the descriptor's $.sprite asset base does not have the shape the recorded style document has, and it diverges even when every layer matches ===
AWS: Smithy binds GetSprites to GET /v2/styles/{Style}/{ColorScheme}/{Variant}/sprites/{FileName} with FileName @pattern ^sprites(@2x)?\.(png|json)$, so the style document's sprite member is the base of that route (the client appends .json/.png).
