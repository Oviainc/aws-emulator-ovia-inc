=== Cause 1 of 1: the SearchListings continuation token is a transparent, client-forgeable cursor instead of an opaque token ===
AWS: Smithy (model services/service-com-amazonaws-marketplacediscovery-awsmarketplacediscovery/smithy-model/com-amazonaws-marketplacediscovery-awsmarketplacediscovery.json): SearchListings POST /2026-02-05/searchListings, success 200, @paginated{inputToken: nextToken, outputToken: nextToken, pageSize: maxResults, items: listingSummaries}; output nextToken -> NextToken @length(0..8192) @pattern ^[a-zA-Z0-9+/=]+$, documented "If nextToken is returned, there are more results available. Make the call again using the returned token to retrieve the next page."; errors ValidationException(400)/AccessDeniedException(403)/ThrottlingException(429)/InternalServerException(500). A nextToken is a continuation token MINTED BY THE SERVICE: its bytes are opaque, carry no client-readable rendering of the request, and cannot be constructed by a caller, so a token the service never issued is refused (ValidationException) rather than served as a page. Recorded behavior: the response carries a non-empty opaque base64 continuation token whose literal bytes the corpus deliberately does not assert (the replay prints the expected value as '<shaped-not-asserted>'); what it does compare is that the served token is of the same kind as the recorded one, i.e. an opaque service-minted blob.
Emulator: 200 with the page and totalResults correct, but $.nextToken is the base64 of a readable internal cursor of the form "<row offset>:SearchListings/<locale>/<searchText>/<filters>/<sortBy>/<sortOrder>" — on this step it is 'MTpTZWFyY2hMaXN0aW5ncy9lbi1VUy9jbG91ZC8vUkVMRVZBTkNFL0RFU0NFTkRJTkc=', which base64-decodes to the plaintext '1:SearchListings/en-US/cloud//RELEVANCE/DESCENDING'. The offset, the locale, the caller's search text, the filter set and the sort key/direction are all recoverable from the token, and the same transparent token is emitted on the continuation step as well (the cluster's other member). Decoding is the exact inverse: any base64 of "<offset>:<query identity>" whose identity half equals the current request's is accepted, so a token the service never issued — e.g. one a caller writes by hand for an arbitrary offset of a query it is about to send — is honoured as a page position instead of refused.
Why: a client that treats the token as the opaque handle AWS specifies is fine on the happy path, but everything built on its opacity breaks. The token is a disclosure channel: anything that logs, stores or forwards a page token (a URL, a cache key, a test fixture) now carries the caller's search text and filters in recoverable form, which AWS's token does not. And because the cursor is forgeable, the emulator serves pages for positions it never issued, so a client (or a test) can reach an arbitrary offset without ever having been handed a token — the opposite of the refusal AWS gives for a token it did not mint. Any suite calibrated against the emulator therefore records transparent, hand-writable tokens as acceptable behavior while the real service rejects them.
Fix: SearchListings' pagination cursor — the shared token mint/validate pair in the service's state module (encode_page_token / decode_page_token and the page() helper it backs) plus SearchListings' use of it — so that the emitted token is opaque (no client-recoverable rendering of the request and no bare row offset) and so that only a token this service actually minted for this query is accepted, every other value being refused as ValidationException. Note the fix must stay inside NextToken's modelled @pattern ^[a-zA-Z0-9+/=]+$ and @length(0..8192), and the token must still round-trip as the cursor for the SAME query (the query-scoping behavior already present is correct and must be kept). Traces: services/service-com-amazonaws-marketplacediscovery-awsmarketplacediscovery/src/state.rs lines 1177-1226 (encode_page_token: "base64 of `<offset>:<query identity>`"; decode_page_token; page) and src/ops/search_listings.rs lines 218-235 (query_identity and the page() call that mints the output token).
