# SSM ValidationException text misrenders constraints: anchored patterns, dropped length errors, per-member paths

> _Note: this issue was identified against the code base at commit `133bbb645e9618d24e6206d20cee2b832cb9c7e9`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
DescribeInventoryDeletions

## Description
The emulator's shared ValidationException message builder for ssm renders constraint violations differently from AWS in three systematic ways, each reproduced by its own fixture step below. 10 CAUSES. (a) It publishes the Smithy @pattern literal, which carries the model's outer ^...$ anchors, where AWS prints the service-side regex WITHOUT those outer anchors. (b) When a value violates more than one constraint on the same member it emits only one of them, where AWS emits all of them ("N validation errors detected: ...; ..."). (c) For a list member it reports a per-element path (`<member>.1.member`) and the element's value, where AWS reports the LIST path (`<member>`), the whole list rendered as '[v1, v2]', and the member constraints aggregated as 'Member must satisfy constraint: [ ... ]'. Status (400) and error class are correct throughout; only the message body diverges. Message rule notes: the fixed text is '<N> validation error(s) detected: Value '<value>' at '<path>' failed to satisfy constraint: <constraint sentence>'; the variable parts are N, the rejected value, the member path and the constraint text, all taken from the request and the member's modelled constraints. No recorded id/timestamp is part of the requirement.

Cause 1 of 10 - DescribeInventoryDeletions.DeletionId anchored pattern. AWS: 400, message "1 validation error detected: Value 'not-a-valid-deletion-id' at 'deletionId' failed to satisfy constraint: Member must satisfy regular expression pattern: [a-f0-9]{8}-[a-f0-9]{4}-[a-f0-9]{4}-[a-f0-9]{4}-[a-f0-9]{12}" (Smithy: DescribeInventoryDeletions input DeletionId; recorded response for the pattern rendering). Emulator: same status and class but the pattern is printed as '^[a-f0-9]{8}-...-[a-f0-9]{12}$'. Why: a client that surfaces or matches the printed regex sees a pattern AWS never prints. Fix: the ssm validation layer's pattern-constraint message formatter (strip the model's outer anchors). Traces: ssm-describe-inventory-deletions-listing-and-lookup#task#2.

Cause 2 of 10 - GetOpsMetadata.OpsMetadataArn anchored pattern. AWS: 400, "1 validation error detected: Value '<arn>' at 'opsMetadataArn' failed to satisfy constraint: Member must satisfy regular expression pattern: arn:(aws[a-zA-Z-]*)?:ssm:[a-z0-9-\.]{0,63}:[a-z0-9-\.]{0,63}:opsmetadata\/([a-zA-Z0-9-_\.\/]*)". Emulator: prints the same regex wrapped in ^...$. Why/Fix: as cause 1. Traces: ssm-ops-metadata-error-paths#task#2, ssm-ops-metadata-invalid-arg-errors#task#1.

Cause 3 of 10 - UpdateOpsMetadata.OpsMetadataArn anchored pattern. AWS: 400 with the unanchored opsmetadata ARN regex, same fixed text as cause 2. Emulator: anchored form. Why/Fix: as cause 1. Traces: ssm-ops-metadata-invalid-arg-errors#task#2.

AWS: 400, "2 validation errors detected: Value at 'documentVersion' failed to satisfy constraint: Member must satisfy regular expression pattern: ([$]LATEST|[$]DEFAULT|^[1-9][0-9]*$); Value at 'documentVersion' failed to satisfy constraint: Member must have length less than or equal to 8" - note AWS omits the offending value for this member and reports BOTH constraints (Smithy: StartExecutionPreview.DocumentVersion @pattern ^([$]LATEST|[$]DEFAULT|^[1-9][0-9]*$)$, error ValidationException; the max-length-8 rule is recorded behavior only). Emulator: one error only, value echoed, pattern anchored. Why: callers that count or parse the reported violations see one of two.
