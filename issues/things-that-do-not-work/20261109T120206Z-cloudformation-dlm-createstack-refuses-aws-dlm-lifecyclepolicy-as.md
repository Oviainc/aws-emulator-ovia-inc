# cloudformation__dlm: CreateStack refuses AWS::DLM::LifecyclePolicy as an unrecognized resource type, so no Data Lifecycle Manager policy can be deployed from a template

> _Note: this issue was identified against the code base at commit `70b7c68145c683ae49b96a2a3a7ef8edad56294d`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateStack

## Description
One net-new root cause in the CloudFormation emulator's template resource-type registry, grounded in both failing behavioural checks under the cloudformation__dlm heading (0/2 passed): cloudformation__dlm.deploy-cfn-dlm-lifecyclepolicy-ebs-snapshot-round-trip-and-delete and cloudformation__dlm.deploy-cfn-dlm-lifecyclepolicy-cross-account-role-rejected. No open issue covers AWS::DLM::LifecyclePolicy: the existing "unrecognized resource type" issues name other types (AWS::MWAA::Environment, AWS::ImageBuilder::*, AWS::MediaTailor::*, AWS::Omics::*, AWS::NetworkFirewall::ContainerAssociation, AWS::InternetMonitor::Monitor, AWS::NetworkMonitor::*, AWS::NetworkManager::*, AWS::IVS::AdConfiguration, AWS::IoTCoreDeviceAdvisor::SuiteDefinition, AWS::NetworkSecurityManager::*, AWS::MWAAServerless::Workflow), and the open dlm issues are all about DLM's own API (tagging error codes, default-policy resource types, UpdateLifecyclePolicy validation), not about CloudFormation provisioning.

=== Cause 1 of 1: the template resource-type registry does not recognize AWS::DLM::LifecyclePolicy, so the stack is refused at template validation and no policy is ever provisioned ===
AWS:      recorded behavior only for CloudFormation (the CloudFormation Smithy model carries no resource-type registry; the supported type set is the service's own data). AWS::DLM::LifecyclePolicy is a supported CloudFormation resource type (https://docs.aws.amazon.com/AWSCloudFormation/latest/TemplateReference/aws-resource-dlm-lifecyclepolicy.html): its Properties are Description, State, ExecutionRoleArn, PolicyDetails (PolicyType, ResourceTypes, TargetTags, Schedules with CreateRule/RetainRule), Tags and friends; Ref publishes the policy id and Fn::GetAtt publishes Arn. A CreateStack whose template declares it is ACCEPTED: the call answers HTTP 200 with a StackId, the resource is provisioned through the DLM control plane the emulator already serves (Smithy com.amazonaws.dlm#DLM: CreateLifecyclePolicy POST /policies -> PolicyId matching ^policy-[a-f0-9]+$, GetLifecyclePolicy GET /policies/{PolicyId}, GetLifecyclePolicies GET /policies, DeleteLifecyclePolicy), and the stack then reaches CREATE_COMPLETE with the policy readable through DLM itself. CloudFormation's ValidationError "Template format error: Unrecognized resource types: [<types>]" — fixed text "Template format error: Unrecognized resource types: [" … "]", with the bracketed comma-separated type list taken verbatim from the submitted template — is the refusal AWS reserves for types it genuinely does not support, and AWS::DLM::LifecyclePolicy is not one of them.
Emulator: CreateStack is refused outright with HTTP 400, error code ValidationError and the message "Template format error: Unrecognized resource types: [AWS::DLM::LifecyclePolicy]". The sibling type in the very same template (AWS::IAM::Role) is accepted, so only the DLM type is missing from the set the template validator checks. The refusal happens before any resource is created: no StackId is issued, there is no stack to poll, and no DLM policy exists.
Why:      no DLM lifecycle policy can be provisioned as infrastructure-as-code against this emulator. That is the normal way EBS snapshot lifecycle policies are deployed, because the policy needs an IAM execution role created alongside it in the same stack. Every CloudFormation/CDK/SAM stack declaring one is rejected at submit time with a message telling the author their template is malformed, which it is not; the client cannot work around it or inspect a partial stack, because the failure is template validation rather than a resource create (no StackId, no StackEvents, nothing to roll back). It also makes the type's Ref (policy id) and Fn::GetAtt Arn contract unreachable, and it hides every downstream behaviour the two checks exist to verify: the templated PolicyDetails round-tripping through DLM GetLifecyclePolicy (PolicyType EBS_SNAPSHOT_MANAGEMENT, ResourceTypes [VOLUME], TargetTags, a count-based RetainRule reading back with the default Interval 0), the stack's tag propagation onto the policy, DeleteStack removing the policy so GetLifecyclePolicy answers ResourceNotFoundException (modeled, httpError 404) with "The resource {<policy-id>} was not found." (fixed text "The resource {" … "} was not found.", the brace-wrapped policy id taken from the request), and — in the rejection check — DLM refusing an ExecutionRoleArn that names a principal in another account, which must surface as a CREATE_FAILED resource reason of the form 'Resource handler returned message: "Cross-account pass role is not allowed. (Service: Dlm, Status Code: 403, Request ID: <id>) (SDK Attempt Count: <n>)" (RequestToken: <token>, HandlerErrorCode: AccessDenied)' and leave the stack ROLLBACK_COMPLETE with no policy created. Whether that 403/AccessDenied path is also wrong cannot be assessed at all while the type is unregistered.
Fix:      CloudFormation's template resource-type registry and the provisioning handler behind it in the cloudformation service crate: register AWS::DLM::LifecyclePolicy with its property schema, its Ref (policy id) and its GetAtt Arn, and back its create/update/delete lifecycle with the DLM state the dlm crate already owns (CreateLifecyclePolicy / GetLifecyclePolicy / UpdateLifecyclePolicy / DeleteLifecyclePolicy), propagating the stack's Tags onto the policy and mapping DLM's own refusals (including the cross-account pass-role 403) into the resource handler's CREATE_FAILED reason and a stack rollback. The "Unrecognized resource types" refusal path itself is correct and must stay for types AWS really does not support.
Traces:   cloudformation__dlm.deploy-cfn-dlm-lifecyclepolicy-ebs-snapshot-round-trip-and-delete and cloudformation__dlm.deploy-cfn-dlm-lifecyclepolicy-cross-account-role-rejected (both [error], both on the same refusal; the second submits two stacks and dies on the first CreateStack).

2.
