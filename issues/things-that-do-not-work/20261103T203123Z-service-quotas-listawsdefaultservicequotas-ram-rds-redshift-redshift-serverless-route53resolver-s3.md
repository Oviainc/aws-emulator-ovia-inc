## Description
The emulator's Service Quotas default-quota catalog is a hand-seeded table. ListAWSDefaultServiceQuotas answers HTTP 200 for every ServiceCode, but for the eight ServiceCodes below the body it serves is not the service's default-quota set: most AWS L- coded rows are absent, and the rows that ARE seeded carry emulator-authored Description / QuotaName text and, in several cases, a wrong Adjustable flag, a wrong Value or a wrong UsageMetric.MetricDimensions.Resource. This issue bundles EIGHT net-new causes, one per ServiceCode. All eight share one root cause family: the seeded default-quota catalog table that the ListAWSDefaultServiceQuotas handler reads, not the operation's wire framing.

Smithy (services/service-com-amazonaws-servicequotas-servicequotasv20190624): ListAWSDefaultServiceQuotas(ServiceCode required, NextToken, MaxResults) -> ListAWSDefaultServiceQuotasResponse { Quotas: list<ServiceQuota>, NextToken }; errors AccessDeniedException(403), IllegalArgumentException(400), InvalidPaginationTokenException(400), NoSuchResourceException(404), ServiceException(500), TooManyRequestsException(429). ServiceQuota members: ServiceCode, ServiceName, QuotaArn, QuotaCode (pattern ^[a-zA-Z][a-zA-Z0-9-]{1,128}$), QuotaName, Value (QuotaValue double, range 0..10000000000), Unit, Adjustable (boolean, default false), GlobalQuota (boolean, default false), UsageMetric (MetricInfo: MetricNamespace, MetricName, MetricDimensions, MetricStatisticRecommendation pattern ^(Sum|Maximum)$), Period (QuotaPeriod: PeriodValue, PeriodUnit), Description (@length 0..350). The model does NOT enumerate quota codes or their text, so the catalog CONTENT is recorded behavior only and the recordings are the requirement. In all eight causes AWS and the emulator both answer 200, so the divergence is purely in the response body.

General shape of the fault, visible across all eight causes: (a) AWS default quota codes have the form L-XXXXXXXX and the emulator omits most of them for these ServiceCodes; (b) where a row IS seeded, its Description and QuotaName are paraphrased by the emulator instead of carrying AWS's own text (AWS's wording is fixed text per quota code, not a per-run value); (c) the per-row Adjustable, Value, Unit, GlobalQuota, Period and UsageMetric.MetricDimensions must be the quota's own values, and QuotaArn must follow the template arn:aws:servicequotas:<region>::<serviceCode>/<quotaCode>. Region/account strings in the recordings are environment values, not requirements; the quota code, name, description, unit, value, adjustability and metric dimension of each row are.

Cause 1 of 8 - ServiceCode ram (ServiceName 'AWS Resource Access Manager').
AWS: returns the full RAM default set, including L-238C96EE 'Number of pending invitations' (Adjustable true, Unit None, Value 250, Description 'The maximum number of pending invitations.'), L-1F7F8A25 'Number of resource associations per resource share' (Adjustable false, Value 5000, Description 'The maximum number of resources that you can include in a resource share.'), L-275DAC00 'Number of principal associations per resource share' (Adjustable false, Value 5000, Description 'The maximum number of principals that you can specify in a resource share.') and L-9EBA15DD 'Number of custom permissions' (Adjustable true, Description 'The maximum number of custom permissions.'), each with a QuotaArn under arn:aws:servicequotas:<region>::ram/<quotaCode>. Emulator: L-238C96EE, L-1F7F8A25, L-275DAC00 and L-9EBA15DD are absent from Quotas; L-4A6CEE66.Description is re-authored as 'The maximum number of resource associations.' and L-2870BE9D.Description as 'The maximum number of custom permissions per resource type.'

Fix: the service-quotas default-quota catalog seed (the data table the ListAWSDefaultServiceQuotas handler reads) - add the missing rows and carry AWS's Description text verbatim.
