# ELB Classic DescribeInstanceHealth serializes InstanceStates as an empty element for a registered instance

> _Note: this issue was identified against the code base at commit `610eb4b5abbe12768656cecbe381c20cd7e570c7`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
DescribeInstanceHealth

## Description
DescribeInstanceHealth answers 200 but reports no instance state at all: the InstanceStates element is serialized as an empty scalar, so the instance the client registered with the classic load balancer is invisible to the health API and its health transition can never be observed. 1 cause.

Cause 1 of 1: DescribeInstanceHealth returns an empty InstanceStates element instead of one InstanceState per registered instance, and therefore never reports the OutOfService/Instance/UnhealthyThreshold triple (fixture elbclassic-instance-registration-health-deregistration-and-availability-zone-rejection, step task#8).
AWS: Smithy: DescribeInstanceHealth, input DescribeEndPointStateInput {LoadBalancerName (AccessPointName) required, Instances (list Instances)}, output DescribeEndPointStateOutput {InstanceStates targeting the list InstanceStates of structure InstanceState}; modeled errors AccessPointNotFoundException (awsQueryError LoadBalancerNotFound, HTTP 400) and InvalidEndPointException (awsQueryError InvalidInstance, HTTP 400). InstanceState members: InstanceId ("The ID of the instance"), State ("Valid values: InService | OutOfService | Unknown"), ReasonCode ("Valid values: ELB | Instance | N/A", documented as the cause of OutOfService instances) and Description, whose documentation enumerates the exact permitted sentences, one of which is "Instance has failed at least the UnhealthyThreshold number of health checks consecutively." On AWS, DescribeInstanceHealth for a load balancer that has registered instances returns one InstanceState per instance currently registered (or per instance named in the request), on this awsQuery/XML wire as repeated <member> elements under InstanceStates; the InstanceId is the instance the client registered, and once its health checks fail UnhealthyThreshold times consecutively the member carries State=OutOfService, ReasonCode=Instance and that exact Description sentence. The fixed text of that Description is the sentence above verbatim; the only request/state-derived value in the member is InstanceId (and the load balancer name in the request).
Emulator: the response body is `{'DescribeInstanceHealthResponse': {'DescribeInstanceHealthResult': {'InstanceStates': ''}, 'ResponseMetadata': {...}}}` — InstanceStates is an empty scalar where a list of InstanceState is modeled. Replay detail: "$.DescribeInstanceHealthResponse.DescribeInstanceHealthResult.InstanceStates: type_mismatch (expected {'member': {...}}, got '')" and, because no member ever appears, "$.…InstanceStates.member.Description: poll: not in ['Instance has failed at least the UnhealthyThreshold number of health checks consecutively.'] after 61 attempt(s) (expected that sentence, got None)" with "$: poll capped at 60s". Status matched (200/200); the entire instance-state collection is missing. Hypothesis: the handler serializes a constant/empty collection rather than reading the registered-instance set out of the load balancer's state (and does not derive health from it). Note that the same fixture's EC2 RunInstances setup step answers 400 (owned by the open issue 20261029T235636Z-ec2-runinstances-refuses-the-recorded-elb-classic-setup), so the registered instance may never have been recorded in state — but that is an upstream emulator defect too, and DescribeInstanceHealth must still serialize InstanceStates as a list (omitted when genuinely empty), never as an empty scalar.
Why: a client cannot see any instance's health. Registration verification loops, deregister-on-unhealthy logic, deploy health gates and every SDK waiter built on DescribeInstanceHealth either block until timeout or conclude the load balancer has no instances; and an empty scalar where a list is modeled breaks SDK parsing of the member (a string arrives where a list of structures is expected) rather than merely being empty.
Why this is not covered by an existing issue: the open issue 20261029T172824Z-elasticloadbalancing-elb-classic-describe-responses-serve-static-defaults-instead describes DescribeInstanceHealth returning a member frozen at State=InService/ReasonCode=N/A/Description=N/A; the current emulator returns no member at all, so the replay key set now includes $.…DescribeInstanceHealthResult.InstanceStates (a collection-shape divergence) which that issue does not carry. Fixing the frozen-health value alone leaves this step failing.
Fix: the DescribeInstanceHealth handler, its serializer and the per-load-balancer registered-instance/health state — the handler must enumerate the instances registered with the named load balancer (filtered by Instances when supplied), emit one InstanceState <member> per instance with InstanceId from state, and serialize InstanceStates as a list (no empty-scalar element); the stored per-instance health must be able to hold the OutOfService / ReasonCode=Instance / "Instance has failed at least the UnhealthyThreshold number of health checks consecutively." triple so State, ReasonCode and Description come from state rather than constants.
