# b2bi refusal messages diverge: AccessDeniedException omits the "on resource: <arn>" clause and CreateProfile's quota message is the emulator's own wording

> _Note: this issue was identified against the code base at commit `fb0a9c1858b32d12ecab08653c5d3b6198801bbb`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateProfile

## Description
TWO net-new causes, both on b2bi CreateProfile refusal paths. In both the HTTP status and the error code match AWS; only the message member diverges, because the emulator composes its own text instead of AWS's. Related open issue 20261029T193110Z-b2bi-composes-its-own-refusal-text-eight-error.md records the same CLASS of fault on eight other b2bi refusal paths, but neither cause below is one of its eight (its trace_ids do not include either check here), so neither is covered by it.

Cause 1 of 2: the AccessDeniedException raised when an identity-based policy explicitly denies the action omits the "on resource: <resource-arn>" clause.
AWS: Smithy com.amazonaws.b2bi#CreateProfile declares error AccessDeniedException (errorKind client, HTTP 403); com.amazonaws.b2bi#AccessDeniedException has one required member `message` (ErrorMessage, @length 10..1024). The model documents the exception only as "You do not have sufficient access to perform this action", so the message template is recorded behavior only; the recording shows AWS's fixed-text template for an explicit-deny refusal as: "User: " + the caller's identity ARN + " is not authorized to perform: " + the denied action in `<service>:<Operation>` form + " on resource: " + the ARN of the resource the action targets + " with an explicit deny in an identity-based policy". The variable parts are taken from the request and from the emulator's own state: the identity ARN of the signing session (for an assumed role, the `arn:aws:sts::<account>:assumed-role/<role-name>/<session-name>` form), the service/operation of the call, and the target resource ARN — for a collection-scoped create such as CreateProfile that is the account's profile collection, `arn:aws:<partition>:b2bi:<region>:<account>:profile/*`. The recorded example fills that template as 'User: arn:aws:sts::000000000000:assumed-role/sim2real-b2bi-toggle-role-f4aa49497071/sim2real-b2bi-check is not authorized to perform: b2bi:CreateProfile on resource: arn:aws:b2bi:us-west-2:000000000000:profile/* with an explicit deny in an identity-based policy' — the role name, session name, account, region and profile id in that string are per-run values that fill the template, not part of it.
Emulator: returns the right code (AccessDeniedException) and the right identity ARN and action, but drops the whole resource clause: 'User: <identity-arn> is not authorized to perform: b2bi:CreateProfile with an explicit deny in an identity-based policy' — i.e. " is not authorized to perform: b2bi:CreateProfile" is followed directly by " with an explicit deny in an identity-based policy", with no " on resource: <arn>" in between.
Why: the resource clause is the only part of an AWS authorization failure that tells a caller WHICH resource (or resource scope) the deny applied to. Tooling that parses AWS's denial text to report the offending resource, and tests/policy-debuggers that assert on the full AWS sentence, get nothing to parse and either mis-report or fail outright, even though the deny itself was evaluated correctly.
Fix: the authorization-denial message formatter on b2bi's request authorization path — the place that builds AccessDeniedException's `message` for an explicit identity-based deny. It must append " on resource: " plus the ARN of the resource the action targets (the collection ARN `.../profile/*` for a create that names no existing resource) before the " with an explicit deny in an identity-based policy" suffix.
Traces: b2bi.access-denied-missing-iam-permission-rejected.

Cause 2 of 2: CreateProfile's profile-quota refusal message is the emulator's own sentence and reports the numeric limit instead of the account id.
AWS: Smithy com.amazonaws.b2bi#CreateProfile declares error ServiceQuotaExceededException (errorKind client, HTTP 402); the shape requires `message` (ErrorMessage, @length 10..1024) plus resourceId, resourceType, serviceCode, quotaCode. The model documents the exception generically ("Occurs when the calling command attempts to exceed one of the service quotas") and does not state the text, so the message template is recorded behavior only: AWS refuses a CreateProfile past the account's profiles-per-account quota with "Profile limit reached for AWS account " + the caller's account id. The fixed text is "Profile limit reached for AWS account "; the only variable part is the account id, taken from the caller's identity (the recorded run shows account 000000000000 — a per-run value). AWS does NOT put the numeric quota value in the message; the limit is conveyed by the quotaCode/serviceCode members instead.
Emulator: returns HTTP 402 / ServiceQuotaExceededException correctly but with 'Account has reached the limit of 5 profiles' — different fixed wording, and it interpolates the limit (crate::state::MAX_PROFILES_PER_ACCOUNT) where AWS interpolates the account id. Observed on every losing racer of an over-subscribed concurrent CreateProfile race, so it is the single formatter, not a race artifact.
Why: a client or test that branches on AWS's quota text does not match, and because the emulator's text names a hard-coded 5 rather than the account, it also contradicts the customer-adjustable quota a caller reads from Service Quotas — a caller whose quota was raised is told "the limit of 5".
Fix: CreateProfile's quota-refusal message constructor (the `quota_exceeded()` helper that builds ServiceQuotaExceededException in this operation's handler): render "Profile limit reached for AWS account <account-id>" from the caller's account id and leave the numeric limit to the quotaCode/serviceCode members.
Traces: b2bi.profile-quota-enforced-under-concurrent-creation-rejected (see services/service-com-amazonaws-b2bi-b2bi/src/ops/create_profile.rs around lines 181-193 for the composed text).
