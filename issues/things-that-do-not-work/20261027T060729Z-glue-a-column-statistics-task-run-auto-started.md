# Glue: a column statistics task run auto-started by CreateColumnStatisticsTaskSettings also settles to FAILED with an emulator-authored ErrorMessage and computes no statistics

> _Note: this issue was identified against the code base at commit `b76363ba3639c1fb1d2b9b08f3e303f98ad8a036`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Description
One net-new root cause in the Glue Data Catalog's column-statistics surface, reached by a path the already-open issue does not cover.

Related but NOT covering: the open issue `20261025T170315Z-glue-2-net-new-root-causes-column-statistics.md` records the same family of defect for the runs started by an explicit `StartColumnStatisticsTaskRun` (its Issue-Keys are `glue.column-statistics-task-run-reaches-terminal-state`, `glue__s3.glue-column-statistics-computed-from-real-data-match-the-known-distribution` and `glue.create-column-statistics-task-settings-while-running-rejected`). Note also that the check below proves `CreateColumnStatisticsTaskSettings` is no longer a NotImplemented stub on this commit (the call succeeded and auto-started a run), so Cause 2 of that issue has moved while the run state machine has not.

=== Cause 1 of 1: the auto-started column statistics task run never reads the table's data and unconditionally settles FAILED ===
AWS: Smithy (com.amazonaws.glue) — `CreateColumnStatisticsTaskSettings` submitted with NO `Schedule` starts a column statistics task run for that catalog/database/table immediately, so `GetColumnStatisticsTaskRuns(DatabaseName, TableName)` lists that auto-started run and `GetColumnStatisticsTaskRun(ColumnStatisticsTaskRunId)` returns a `ColumnStatisticsTaskRun` whose `Status` is a `ColumnStatisticsState` enum (STARTING | RUNNING | SUCCEEDED | FAILED | STOPPED). `StartColumnStatisticsTaskRun` takes DatabaseName/TableName/Role (@required) plus ColumnNameList/SampleSize/CatalogID/SecurityConfiguration and returns ColumnStatisticsTaskRunId; its modelled errors are AccessDeniedException, ColumnStatisticsTaskRunningException, EntityNotFoundException, InvalidInputException, OperationTimeoutException, ResourceNumberLimitExceededException (all client, HTTP 400). The run is a Glue-managed computation over the objects behind the table's `StorageDescriptor.Location`. For a well-formed EXTERNAL_TABLE whose `Role` grants s3:GetObject/s3:ListBucket on that location, the run transitions STARTING -> RUNNING -> SUCCEEDED, `ErrorMessage` is ABSENT, and the computed statistics then become readable through `GetColumnStatisticsForTable(DatabaseName, TableName, ColumnNames)`: `Errors` is an empty list and `ColumnStatisticsList` has one entry per requested column, an int column carrying `StatisticsData.LongColumnStatisticsData` with the @required `NumberOfNulls`/`NumberOfDistinctValues` and a string column carrying `StatisticsData.StringColumnStatisticsData` with the same two members. Those counts equal the statistics of the bytes actually behind the table — for a CSV of N rows with D distinct values in a column and no empty cells, NumberOfDistinctValues == D and NumberOfNulls == 0. FAILED carrying an `ErrorMessage` is reserved for a run that genuinely could not compute (missing location, unreadable object, role without access).
Emulator: the run is recorded and then settled FAILED regardless of the table or the role. `GetColumnStatisticsTaskRun` reports `'Status': 'FAILED'` with `'ErrorMessage': "This emulator records column statistics task runs but reads none of the table's underlying data, so the run ended without generating statistics."`, together with `'SampleSize': 0.0`, `'NumberOfWorkers': 0`, `'DPUSeconds': 0.0`, and `EndTime` only ~0.5s after `StartTime`. The replayed check adopted the run that `CreateColumnStatisticsTaskSettings` auto-started (so this is not the explicit-start path the open issue cites) and still saw FAILED. That `ErrorMessage` text is itself a divergence: it is emulator-authored prose that AWS never emits for this operation; the whole string is fixed emulator text with no variable parts, whereas on the success path AWS emits no ErrorMessage at all. Because no statistics are ever produced, the check's downstream assertions on `GetColumnStatisticsForTable` (`Errors == []`, one entry each for the int and string column, their NumberOfDistinctValues / NumberOfNulls) are unreachable.
Why: a client that submits column statistics settings and waits for the auto-started run to reach a terminal state sees FAILED and concludes its table or its role is broken when neither is; the ErrorMessage it surfaces to an operator names the emulator rather than any AWS condition. Anything gated on catalog statistics — cost-based query planning, Athena/Spark optimiser input, data-quality pipelines, scheduled statistics refresh, operator dashboards — either aborts or silently proceeds with no statistics, and `GetColumnStatisticsForTable` stays empty forever. A caller that retries on FAILED retries forever. Because the FAILED verdict is unconditional, the genuine failure classes (unreadable location, denied role) are indistinguishable from the healthy path.
Fix: the StartColumnStatisticsTaskRun / GetColumnStatisticsTaskRun state machine and the catalog's column-statistics state, including the run that CreateColumnStatisticsTaskSettings auto-starts when no Schedule is given — the run must read the objects under the table's StorageDescriptor.Location, aggregate the requested columns, persist the resulting ColumnStatistics so GetColumnStatisticsForTable returns them, and settle to SUCCEEDED with no ErrorMessage; FAILED must be reserved for a real computation failure and must carry a message AWS actually emits.
Traces: glue.e2e-column-statistics-task-run-populates-stats-flow (mismatch: AssertionError at `assert task_run["Status"] == "SUCCEEDED"`).

## Evidence
Cause 1 of 1 — glue.e2e-column-statistics-task-run-populates-stats-flow

Expected (AWS): after CreateColumnStatisticsTaskSettings(DatabaseName, TableName, Role) with no Schedule auto-starts a run over an EXTERNAL_TABLE whose StorageDescriptor.Location holds a 20-row CSV with columns id:int (20 distinct values, no nulls) and category:string (4 distinct values, no nulls), and whose Role trusts glue.amazonaws.com and grants s3:GetObject/s3:ListBucket on that prefix:
  - GetColumnStatisticsTaskRun(ColumnStatisticsTaskRunId).ColumnStatisticsTaskRun.Status == "SUCCEEDED", with NO ErrorMessage member.
  - GetColumnStatisticsForTable(DatabaseName, TableName, ColumnNames=["id","category"]) returns Errors == [] and two ColumnStatisticsList entries; id -> StatisticsData.LongColumnStatisticsData with NumberOfDistinctValues == 20 and NumberOfNulls == 0; category -> StatisticsData.StringColumnStatisticsData with NumberOfDistinctValues == 4 and NumberOfNulls == 0. (20/4/0 are the statistics of the bytes the check itself uploaded, not AWS constants — the requirement is that the reported statistics equal the statistics of the data behind the table.)

Actual (emulator): the run settles terminal-FAILED about half a second after it starts and no statistics are ever computed:
  AssertionError: column statistics task run failed: {'CustomerId': '000000000000', 'ColumnStatisticsTaskRunId': '<id>', 'DatabaseName': '<db>', 'TableName': '<tbl>', 'ColumnNameList': ['id', 'category'], 'CatalogID': '000000000000', 'Role': 'arn:aws:iam::<acct>:role/<role>', 'SampleSize': 0.0, 'NumberOfWorkers': 0, 'ComputationType': 'FULL', 'Status': 'FAILED', 'CreationTime': <t0>, 'LastUpdated': <t0+0.5s>, 'StartTime': <t0>, 'EndTime': <t0+0.5s>, 'ErrorMessage': "This emulator records column statistics task runs but reads none of the table's underlying data, so the run ended without generating statistics.", 'DPUSeconds': 0.0}

Message classification: `Status` must be the enum literal "SUCCEEDED" and `ErrorMessage` must be absent. The diverging ErrorMessage above is 100% fixed emulator-authored text (no request- or state-derived parts) and matches no AWS message for StartColumnStatisticsTaskRun / GetColumnStatisticsTaskRun. The ids, database/table names, role ARN, account id and timestamps in that dict are per-run values and are not part of the requirement.

Note on the related open issue: in this replay CreateColumnStatisticsTaskSettings SUCCEEDED (the check found an auto-started run via GetColumnStatisticsTaskRuns and adopted it), i.e. it is no longer the NotImplemented stub described as Cause 2 of 20261025T170315Z-glue-2-net-new-root-causes-column-statistics.md. The run state machine is what still diverges, now also on the auto-start path.

## Steps to Reproduce
1. s3.create_bucket, then put_object a CSV at key "data/data.csv" containing 20 rows of "<i>,cat<i%4>" for i in 1..20 (20 distinct ids, 4 distinct categories, no empty cells).
2. iam.create_role with a trust policy allowing sts:AssumeRole for Service glue.amazonaws.com; attach arn:aws:iam::aws:policy/service-role/AWSGlueServiceRole and put an inline policy allowing s3:GetObject/s3:PutObject/s3:ListBucket on arn:aws:s3:::<bucket> and arn:aws:s3:::<bucket>/*.
3. glue.create_database(DatabaseInput={"Name": <db>}).
4. glue.create_table(DatabaseName=<db>, TableInput={Name:<tbl>, TableType:"EXTERNAL_TABLE", StorageDescriptor:{Columns:[{id,int},{category,string}], Location:"s3://<bucket>/data/", InputFormat:"org.apache.hadoop.mapred.TextInputFormat", OutputFormat:"org.apache.hadoop.hive.ql.io.HiveIgnoreKeyTextOutputFormat", SerdeInfo:{SerializationLibrary:"org.apache.hadoop.hive.serde2.lazy.LazySimpleSerDe", Parameters:{"field.delim":","}}}}).
5. glue.create_column_statistics_task_settings(DatabaseName=<db>, TableName=<tbl>, Role=<role arn>) with NO Schedule — on AWS this immediately starts a run.
6. glue.get_column_statistics_task_runs(DatabaseName=<db>, TableName=<tbl>) and take ColumnStatisticsTaskRuns[0].ColumnStatisticsTaskRunId (fall back to glue.start_column_statistics_task_run(DatabaseName, TableName, ColumnNameList=["id","category"], Role) if the list is empty).
7. Poll glue.get_column_statistics_task_run(ColumnStatisticsTaskRunId=<id>) until Status is in (SUCCEEDED, FAILED, STOPPED).
   -> Emulator: Status "FAILED" with ErrorMessage "This emulator records column statistics task runs but reads none of the table's underlying data, so the run ended without generating statistics.", SampleSize 0.0, NumberOfWorkers 0, DPUSeconds 0.0. AWS: Status "SUCCEEDED", no ErrorMessage.
8. glue.get_column_statistics_for_table(DatabaseName=<db>, TableName=<tbl>, ColumnNames=["id","category"]).
   -> AWS: Errors == [] and two entries — id with LongColumnStatisticsData NumberOfDistinctValues 20 / NumberOfNulls 0, category with StringColumnStatisticsData NumberOfDistinctValues 4 / NumberOfNulls 0. Emulator: no statistics exist, so the assertions are unreachable.
