# EC2 static catalogs serve emulator-authored instance-type and AMI metadata

> _Note: this issue was identified against the code base at commit `10d8f420d9792c6a92213c81068536eef787b058`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
DescribeInstanceTypes

## Description
Three net-new causes with one root: the instance-type and AMI catalogs are synthesized from formulas rather than carrying AWS's published values, so every attribute read diverges. The instance-type fault is replicated across the whole ec2-catalog-describe-instance-types-* fixture family (roughly eighty divergence clusters in this replay, one per instance-type page); the two causes below are its representatives, and a fix must be verified across that family, not only on these two steps. Existing open issues describe the same catalog from the static-surface pass (20261030T063325Z-ec2-static-catalogs-diverge-from-aws-instance-type.md, 20261030T124526Z-ec2-describeinstancetypes-serves-a-synthesized-instance-type-catalog.md, 20261030T210852Z-ec2-describeinstancetypes-synthesizes-instance-type-attributes-instead-of.md, 20261031T044610Z-ec2-describeinstancetypes-serves-emulator-authored-instance-type-metadata.md) — none of them carries a replay key for these fixture steps, which is why this issue is filed.

Cause 1 of 3 — DescribeInstanceTypes EBS, network and processor attributes are computed, not published.
AWS: each InstanceTypeInfo carries the published per-type values. For the recorded 16xlarge sizes ebsInfo.ebsOptimizedInfo is baselineBandwidthInMbps 20000 / baselineIops 80000 / baselineThroughputInMBps 2500.0 and the same maxima, ebsInfo.maximumEbsAttachments is 27, and networkInfo carries defaultNetworkCardIndex, maximumNetworkCards, networkCards, networkPerformance, enaSrdSupported, flexibleEnaQueuesSupport, secondaryNetworkSupported, trafficMirroringSupport and (for EFA-capable types) efaSupported true with efaInfo.maximumEfaInterfaces; the type also carries cpuBurstModel, phcSupport, rebootMigrationSupport, processorInfo.sustainedClockSpeedInGhz and a vCpuInfo.validCores list enumerating every legal core count.
Emulator: the EBS figures are scaled from a formula (13600/60000/1700 where AWS publishes 20000/80000/2500.0), maximumEbsAttachments is 28 instead of 27, the whole set of networkInfo members above is absent, efaSupported is reported false for an EFA-capable type, and cpuBurstModel/phcSupport/rebootMigrationSupport/sustainedClockSpeedInGhz/validCores are missing.
Why: instance-type selection, EBS-bandwidth sizing and EFA/network-card capability checks are exactly what this API is called for; every one of them is decided on invented numbers.
Fix: replace the computed instance-type attribute table with AWS's published catalog data, consumed by the DescribeInstanceTypes projection.
Traces: ec2-catalog-describe-instance-types-a1-c9g#task#14.

Cause 2 of 3 — the same catalog fault on the Graviton (c7g) page, including efaInfo.
AWS: c7g.16xlarge publishes efaSupported true with efaInfo.maximumEfaInterfaces 1, the 20000/80000/2500.0 EBS figures, maximumEbsAttachments 27 and the full networkInfo/validCores member set; c7g.medium and c7g.metal additionally publish per-interface IPv4/IPv6 address counts, nitroEnclavesSupport and nitroTpmSupport.
Emulator: efaSupported false, efaInfo absent, the same formula-derived EBS numbers, and the same missing members across every size in the page.
Why: the gap is in the catalog itself, so it reappears on every instance family page rather than on one type.
Fix: same catalog table.
Traces: ec2-catalog-describe-instance-types-a1-c9g#task#18.

Cause 3 of 3 — DescribeImages omits AMI metadata members for the Amazon Linux 2023 image.
AWS: the AMI item carries imdsSupport, deprecationTime, freeTierEligible, and inside blockDeviceMapping.ebs the iops and throughput of the backing volume alongside snapshotId/volumeSize/volumeType/encrypted/deleteOnTermination.
Emulator: imdsSupport, deprecationTime, freeTierEligible, ebs.iops and ebs.throughput are absent from the item.
Why: a client that picks an AMI by IMDSv2 support, filters out deprecated images or sizes the root volume's IOPS reads nothing to decide on.
Fix: the AMI catalog data plus the DescribeImages projection.
Traces: ec2-trajwire-deb-deb-al2023-ami-lookup-ssm-and-describe-images#task#4.
