# cloudformation__gamelift__iam__s3: 2 net-new causes — AWS::GameLift::Build and AWS::GameLift::Script are unregistered resource types, so CreateStack refuses every build/script template

> _Note: this issue was identified against the code base at commit `87192d19b1d499e8425d8cf541553378b48cc888`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateStack

## Description
CloudFormation's template resource-type registry contains no AWS::GameLift::Build and no AWS::GameLift::Script, so a template declaring either is refused at CreateStack with HTTP 400 ValidationError "Template format error: Unrecognized resource types: [<type>]" and no GameLift build or script can be provisioned, read back, validated or deleted through a stack. The two types are separate causes (separate handlers, Ref attributes and validation behavior) and must be closed separately.

Cause 1 of 2: AWS::GameLift::Build is not a registered resource type. Failing check: cloudformation__gamelift__iam__s3.deploy-gamelift-build-round-trip-and-delete.
AWS: CreateStack on a template declaring a Build with Properties Name, OperatingSystem, ServerSdkVersion and StorageLocation {Bucket, Key, RoleArn} (RoleArn being an AWS::IAM::Role in the same stack that can read the S3 object) is ACCEPTED (HTTP 200, a StackId) and the stack reaches CREATE_COMPLETE; the handler calls gamelift CreateBuild from the S3 storage location (Smithy: CreateBuild.Name @length 1..1024, Version @length 1..1024, StorageLocation an S3Location, OperatingSystem enum, ServerSdkVersion @length 0..128 @pattern ^\d+\.\d+\.\d+$, Tags @length 0..200; errors ConflictException/InvalidRequestException/TaggingFailedException/UnauthorizedException, HTTP 400). Ref resolves to the BuildId and Fn::GetAtt Build.Arn to arn:<partition>:gamelift:<region>:<account>:build/<build-id>; the build is then readable through DescribeBuild/ListBuilds with the templated Name, OperatingSystem and ServerSdkVersion and a Status of READY once ingested from S3, and deleting the stack calls DeleteBuild so DescribeBuild afterwards answers NotFoundException.
Cause 2 of 2: AWS::GameLift::Script is not a registered resource type. Failing checks: cloudformation__gamelift__iam__s3.deploy-gamelift-script-round-trip-and-delete, cloudformation__gamelift__iam__s3.deploy-gamelift-script-missing-nodejs-version-rejected-and-rolled-back.
AWS: a template declaring a Script with Name, NodeJsVersion and StorageLocation {Bucket, Key, RoleArn} is accepted and reaches CREATE_COMPLETE; the handler calls gamelift CreateScript (Smithy: CreateScript.Name @length 1..1024, StorageLocation an S3Location, NodeJsVersion @length 0..16 @pattern ^[0-9]+\.(?:x|[0-9]+)$; errors ConflictException/InvalidRequestException/TaggingFailedException/UnauthorizedException, HTTP 400). Ref resolves to the ScriptId and Fn::GetAtt Script.Arn to arn:<partition>:gamelift:<region>:<account>:script/<script-id>; DescribeScript/ListScripts then report the script with the templated name and runtime. Omitting NodeJsVersion is refused by the SERVICE call, so the stack ends ROLLBACK_COMPLETE and the Script resource's CREATE_FAILED ResourceStatusReason is the registry-handler reason Resource handler returned message: "The NodeJsVersion parameter is required. See the GameLift API Reference for CreateScript() for a list of supported runtime versions. (Service: GameLift, Status Code: 400, Request ID: <id>) (SDK Attempt Count: <n>)" (RequestToken: <uuid>, HandlerErrorCode: InvalidRequest) — the quoted sentence is fixed text, only the request id and attempt count vary — and no script by that name exists afterwards.

Emulator: all three checks are refused on CreateStack with HTTP 400 ValidationError and the message "Template format error: Unrecognized resource types: [AWS::GameLift::Build]" / "Template format error: Unrecognized resource types: [AWS::GameLift::Script]" (fixed text "Template format error: Unrecognized resource types: [" ... "]", the bracketed list being the submitted template's unrecognized types). No StackId is returned and no stack exists, so the build/script round trips, the Ref and Arn outputs, the S3-ingestion status, the missing-NodeJsVersion rollback reason and the deletes are all unreachable.

Why: a client that ships GameLift server builds or realtime scripts by template (console, CLI, CDK, Terraform's CFN resources) cannot deploy them at all, and the refusal is a template-FORMAT error that tells the client its template is malformed rather than that the provider is missing, so no retry or template edit can succeed. The negative path inverts: a failure AWS reports as a rolled-back stack with a per-resource InvalidRequest handler reason is instead reported before any stack exists, with a different code, status and message.

Fix: the CloudFormation service's template resource-type registry (the table template validation consults to decide a type is recognized) must register AWS::GameLift::Build and AWS::GameLift::Script, and a provisioning handler must be added for each that calls gamelift CreateBuild/DescribeBuild/DeleteBuild and CreateScript/DescribeScript/DeleteScript against the templated S3 StorageLocation (assuming the named RoleArn), publishes Ref (BuildId/ScriptId) and the Arn attribute from GameLift's own state, propagates stack and resource tags, and surfaces GameLift's InvalidRequestException for a missing NodeJsVersion as a CREATE_FAILED registry-handler reason with HandlerErrorCode InvalidRequest so the stack rolls back.

Traces: see trace_ids; all three checks fail on their first CreateStack call, after the S3 fixture upload but before any GameLift call.

## Steps to Reproduce
1. Build and boot the emulator; create an S3 bucket and upload a zip under key script.zip (or build.zip).
2. aws cloudformation create-stack --stack-name gl-script --capabilities CAPABILITY_NAMED_IAM --template-body '{"AWSTemplateFormatVersion":"2010-09-09","Resources":{"Script":{"Type":"AWS::GameLift::Script","Properties":{"Name":"demo-script","NodeJsVersion":"16.x","StorageLocation":{"Bucket":"<bucket>","Key":"script.zip","RoleArn":"<role-arn>"}}}},"Outputs":{"ScriptId":{"Value":{"Ref":"Script"}}}}'
3. Observe HTTP 400 ValidationError "Template format error: Unrecognized resource types: [AWS::GameLift::Script]" instead of an accepted CreateStack that reaches CREATE_COMPLETE.
4. Repeat with the NodeJsVersion property omitted: AWS rolls the stack back with the "The NodeJsVersion parameter is required..." handler reason (HandlerErrorCode InvalidRequest); the emulator gives the same unrecognized-type refusal.
5. Repeat with {"Build":{"Type":"AWS::GameLift::Build","Properties":{"Name":"demo-build","OperatingSystem":"AMAZON_LINUX_2023","ServerSdkVersion":"5.1.2","StorageLocation":{"Bucket":"<bucket>","Key":"build.zip","RoleArn":"<role-arn>"}}}}: observe "Unrecognized resource types: [AWS::GameLift::Build]".
