# dynamodb__lambda__s3__secretsmanager: the in-process Lambda Python runtime has no AWS SDK, so every handler that imports boto3 fails Runtime.ImportModuleError and 20 secret/S3/DynamoDB flows never run

> _Note: this issue was identified against the code base at commit `8bf126a687f579c23502fa67f92e47f7c7638042`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
Invoke

## Description
Cause 1 of 1: a python3.x Lambda function created with a deployment package whose handler module does `import boto3` cannot be invoked — the runtime cannot import the handler module at all because the AWS SDK is not present in the execution environment.

AWS: recorded behavior only (the Smithy model describes the Invoke wire, not the runtime contents). Smithy: Invoke POST /2015-03-31/functions/{FunctionName}/invocations, output StatusCode (httpResponseCode), FunctionError (header X-Amz-Function-Error), Payload (httpPayload). AWS's managed Python runtimes ship boto3 and botocore on the handler's module search path, so a handler that imports boto3 and calls secretsmanager/s3/dynamodb through it initialises normally; Invoke answers 200 with NO X-Amz-Function-Error header and the handler's own JSON document as Payload. A Runtime.ImportModuleError is reserved for a module the deployment package genuinely does not provide.

Emulator: every such invocation answers HTTP 200 with header `x-amz-function-error: Unhandled` and the payload `{"errorMessage":"Unable to import module '<handler module>': No module named 'boto3'","errorType":"Runtime.ImportModuleError","requestId":"<per-invocation id>","stackTrace":[]}`. Fixed text of that message is `Unable to import module '` + `': No module named '` + `'` with errorType `Runtime.ImportModuleError`; the variable parts are the handler module name taken from the function's Handler (observed as `index` and `lambda_function` in these checks) and the missing module name (`boto3`). requestId is a per-invocation value and is not part of the requirement. The handler never executes, so none of its side effects (GetSecretValue / PutSecretValue / DescribeSecret, the S3 PutObject, the DynamoDB write) ever happen.

Why: a client relying on AWS's managed runtime cannot run ANY SDK-using function on this emulator. Every cross-service scenario that reaches Secrets Manager, S3 or DynamoDB from function code is unobservable: positive paths produce no data, and negative paths (missing secretsmanager:GetSecretValue / kms:Decrypt / resource-policy deny / wrong ARN) can no longer distinguish an AccessDeniedException raised inside the function from the emulator's own import failure, so authorization fidelity in those flows is untestable. Checks that poll the handler's reply for a key then die on `KeyError: 'ok'` / `'current'` / `'secret_string'` because the error document is returned where the handler's document is expected.

Fix: the Invoke execution path's runtime environment in the Lambda service (services/service-com-amazonaws-lambda-awsgirapiservice) — the in-process python3.x runtime that runs the deployment package must expose the managed runtime's bundled dependency set (boto3 + botocore, configured against this emulator's endpoint and the function's execution-role credentials) on the handler's module search path, ahead of the package's own modules. Related: the fixed issue 20261029T233239Z-lambda-synchronous-invoke-data-plane-answers-501-notimplemented.md stood this runtime up (Invoke no longer answers 501), and the open issue 20261104T160000Z-cloudformation-iam-lambda-s3-six-causes-awaiting-the-lambda-provisioner-and-an-in-process-runtime.md still describes it as missing; neither covers the SDK gap reported here.

Traces: the 20 failing checks listed in trace_ids. Six of them surface the import document directly (`unexpected FunctionError: {... No module named 'boto3' ...}` / `('Unhandled', {...})`); the rest index into the returned document and raise KeyError on the handler's own reply key, or report `lambda invocation kept erroring` after retrying the same FunctionError.
