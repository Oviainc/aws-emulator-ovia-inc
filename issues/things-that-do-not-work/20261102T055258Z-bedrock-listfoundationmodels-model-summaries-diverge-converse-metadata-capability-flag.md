ListFoundationModels

## Description
ONE cause: the emulator's seeded foundation-model catalogue and the FoundationModelSummary projection ListFoundationModels builds from it are not what AWS serves. The status is right (200) and the envelope is right; the per-model summaries are wrong in three consistent ways — the whole `converse` metadata block is partly absent and partly wrong, several capability flags are serialized with the wrong TYPE (a bare boolean where AWS serves a structure), and catalogue membership itself still differs (entries present that AWS does not serve at that modelId, entries AWS serves that are absent).

Cause 1 of 1: ListFoundationModels (GET /foundation-models, 200) returns modelSummaries whose per-model members diverge from AWS across the whole catalogue.

AWS: 200 with one modelSummaries entry per catalogued model. Why: ListFoundationModels is the discovery entry point for the whole service. A client that selects a model here and then invokes it either cannot find the model it wanted, or makes capability decisions from wrong data: it reads converse limits (max tokens, image/document types, reasoning support, additional request fields) that do not match what the model accepts, so a subsequent Converse/InvokeModel call is built wrongly; and because featuresSupported.batchInference arrives as a boolean where the shape is a structure, a generated SDK deserializing the documented shape fails outright on that member rather than reading crossRegion/inRegion. Image-type ordering being swapped breaks clients that take the first supported type as the default.

Fix: the seeded foundation-model catalogue data plus the ListFoundationModels summary serializer — the catalogue rows must carry the converse metadata, batchSupported, explicitPromptCaching, intelligentPromptRouting, guardrailsSupported, inferenceAPIsSupported, modelFamily and modelLifecycle.startOfLifeTime values AWS serves for each modelId, and featuresSupported.batchInference must be serialized as the {crossRegion, inRegion} structure rather than a boolean.
