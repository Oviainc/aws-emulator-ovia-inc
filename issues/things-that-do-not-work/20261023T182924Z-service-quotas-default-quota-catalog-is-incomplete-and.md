# Service Quotas default-quota catalog is incomplete and contradicts AWS for nearly every ServiceCode

> _Note: this issue was identified against the code base at commit `3dc196f76d19116b5d570e1dc438e2b93d0e0d47`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
ListAWSDefaultServiceQuotas

## Description
The emulator serves a hand-maintained Service Quotas catalog (the static table behind ListAWSDefaultServiceQuotas and ListServices) that does not reproduce the AWS catalog: for most ServiceCodes the default-quota list is partially or entirely absent, a few entries exist that AWS does not publish, and the service inventory itself carries wrong ServiceName values and is missing service codes. Every response is HTTP 200, so no client sees an error — it just sees a quota catalog that is wrong. This bundle has 10 CAUSES; all ten must be closed before submitting.

SHARED MODEL BASIS (applies to causes 1-9): Smithy ListAWSDefaultServiceQuotas -> ListAWSDefaultServiceQuotasResponse.Quotas : ServiceQuotaListDefinition of ServiceQuota{ServiceCode, ServiceName, QuotaArn, QuotaCode, QuotaName, Value (double 0..1e10), Unit, Adjustable (bool, default false), GlobalQuota (bool, default false), UsageMetric : MetricInfo, Period : QuotaPeriod, Description (0..350)}; input ServiceCode is @required and the operation is @paginated(items: Quotas). The model does not enumerate catalog CONTENT, so the required content is recorded behavior only: each fixture records the full AWS default-quota set for one ServiceCode in us-west-2. SHARED FIX TARGET: the service-quotas default-quota catalog/seed data and the ListAWSDefaultServiceQuotas handler that reads it (plus the ListServices inventory for cause 10) — the catalog must be regenerated from the AWS data for every ServiceCode the corpus covers, not patched per fixture.

Cause 1 of 10 — ServiceCode access-analyzer, default quotas partially missing.
AWS: recorded behavior only — ListAWSDefaultServiceQuotas(ServiceCode='access-analyzer') returns the full access-analyzer default set, including QuotaCodes L-96F55078 (Policy generation CloudTrail time range, Value 90, Adjustable false), L-1E51937C (Archive rules per analyzer, 100, Adjustable true), L-5EFCE71D, L-4599575C, L-6F85FE0C and 6 more, each with ServiceName 'Access Analyzer' and QuotaArn arn:aws:servicequotas:<region>::access-analyzer/<QuotaCode>.
Emulator: 200 with a Quotas list in which 11 of those QuotaCodes are absent (replay reports each as `missing (expected {...}, got None)`).
Why: a client enumerating or looking up a default quota it knows exists (console-style quota browsing, drift checks, capacity tooling) finds no entry and concludes the quota does not exist for the account.
Fix: the default-quota catalog data for access-analyzer, read by the ListAWSDefaultServiceQuotas handler.
Traces: service-quotas-catalog-list-aws-default-service-quotas-access-analyzer#task#1.
