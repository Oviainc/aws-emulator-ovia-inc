# cloudformation__directconnect__ec2: CreateStack refuses AWS::DirectConnect::DirectConnectGateway and ::DirectConnectGatewayAssociation as unrecognized resource types, so no DX-gateway-to-VGW association can be deployed

> _Note: this issue was identified against the code base at commit `70b7c68145c683ae49b96a2a3a7ef8edad56294d`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateStack

## Description
One net-new root cause behind both surviving cloudformation__directconnect__ec2 failures.

Cause 1 of 1: the CloudFormation resource-type registry does not know AWS::DirectConnect::DirectConnectGateway or AWS::DirectConnect::DirectConnectGatewayAssociation, so CreateStack is refused up-front with a template-format ValidationError and no stack is ever minted — even though the rest of each template (AWS::EC2::VPC, AWS::EC2::VPNGateway, AWS::EC2::VPCGatewayAttachment) is supported.

AWS: CloudFormation supports both types and provisions them through Direct Connect's own control plane, which this emulator models. Smithy (com-amazonaws-directconnect-overtureservice): CreateDirectConnectGateway(directConnectGatewayName required, tags TagList) -> DirectConnectGateway; CreateDirectConnectGatewayAssociation(directConnectGatewayId required, gatewayId, virtualGatewayId, addAllowedPrefixesToDirectConnectGateway) -> DirectConnectGatewayAssociation, with errors DirectConnectClientException (client, HTTP 400) and DirectConnectServerException (500); plus DescribeDirectConnectGateways / DescribeDirectConnectGatewayAssociations for the read-back. So a template declaring these types is ACCEPTED by CreateStack: it returns a StackId, the stack reaches CREATE_COMPLETE, Ref Dgw yields arn:<partition>:directconnect::<account>:dx-gateway/<id>, Fn::GetAtt Dgw.DirectConnectGatewayId yields the minted gateway id, and the association resource is created by passing the stack's VPN gateway id as AssociatedGatewayId. When AssociatedGatewayId names a VPN gateway that does not exist, AWS accepts the TEMPLATE and fails the RESOURCE: the stack reaches ROLLBACK_COMPLETE and the association's CREATE_FAILED ResourceStatusReason is Direct Connect's own refusal, error code InvalidRequest with the message 'The VirtualGateway <vgwId> for owner <accountId> does not exist (Service: DirectConnect, Status Code: 400, Request ID: <id>) (SDK Attempt Count: <n>)' — the fixed text is 'The VirtualGateway ' / ' for owner ' / ' does not exist' plus the registry handler's '(Service: DirectConnect, Status Code: 400, Request ID: ...) (SDK Attempt Count: ...)' envelope; the vgw id comes from the request and the account id from the caller, and the request id and attempt count are per-run values. The rollback then deletes the gateway (Direct Connect reports directConnectGatewayState 'deleted'), the VPN gateway (EC2 State 'deleted') and the VPC (DescribeVpcs answers InvalidVpcID.NotFound). Recorded behavior only for the per-property mapping and the deleted-gateway tombstone.

Emulator: CreateStack answers HTTP 400 with error code ValidationError and the message 'Template format error: Unrecognized resource types: [<types>]'. The fixed text is 'Template format error: Unrecognized resource types: ' followed by the bracketed list of the template's unknown types taken from the request; in both checks that list is [AWS::DirectConnect::DirectConnectGateway, AWS::DirectConnect::DirectConnectGatewayAssociation]. No StackId is returned, so the whole deployment — the EC2 VPC/VGW/attachment, the association's associated-gateway representation, the invalid-gateway refusal and the rollback's cascading deletes — is unreachable.

Why: a client cannot deploy a Direct Connect gateway association as code, so the common hybrid-networking estate (VPC + VPN gateway + DX gateway association) cannot be provisioned at all, and the failure is reported as a malformed template rather than a missing provider. The negative path is additionally mis-shaped: AWS's resource-level InvalidRequest refusal with its exact message and the subsequent ROLLBACK_COMPLETE with cascading resource deletions are replaced by a single template-format rejection, so a client that tests rollback behaviour sees the wrong failure class, no stack events and no rolled-back resources.

Fix: the CloudFormation resource-type registry and its provisioners — register AWS::DirectConnect::DirectConnectGateway and AWS::DirectConnect::DirectConnectGatewayAssociation and wire each to the corresponding Direct Connect control-plane operation for create/read/delete, publishing the Direct Connect ARN as the physical resource id (so Ref resolves to the ARN and GetAtt resolves to DirectConnectGatewayId), and surfacing the Direct Connect service refusal as the failing resource's ResourceStatusReason so rollback proceeds normally. Note the association provisioner depends on CreateDirectConnectGatewayAssociation, which is itself still an unimplemented scaffold stub (covered by its own already-filed issue).

Note: no open issue covers this. The already-filed scaffold-stub issue for directconnect CreateDirectConnectGatewayAssociation covers the direct Direct Connect API call only, not CloudFormation's unregistered resource types; the closest open CloudFormation issues report the same registry gap for other services (e.g. 20261109T113512Z-cloudformation-ecs-network-firewall-createstack-refuses-aws-networkfirewall.md).

From the behavioral replay, both checks [error] on their first call, CreateStack:

- deploy-directconnect-gateway-association-invalid-gateway-rejected-and-round-trip: botocore.exceptions.ClientError: An error occurred (ValidationError) when calling the CreateStack operation: Template format error: Unrecognized resource types: [AWS::DirectConnect::DirectConnectGateway, AWS::DirectConnect::DirectConnectGatewayAssociation]
- deploy-directconnect-gateway-association-round-trip-and-delete: botocore.exceptions.ClientError: An error occurred (ValidationError) when calling the CreateStack operation: Template format error: Unrecognized resource types: [AWS::DirectConnect::DirectConnectGateway, AWS::DirectConnect::DirectConnectGatewayAssociation]

Expected: CreateStack returns a StackId for a template of AWS::EC2::VPC + AWS::EC2::VPNGateway + AWS::EC2::VPCGatewayAttachment + AWS::DirectConnect::DirectConnectGateway + AWS::DirectConnect::DirectConnectGatewayAssociation. With a valid AssociatedGatewayId the stack reaches CREATE_COMPLETE and the association is readable through Direct Connect. With AssociatedGatewayId naming a nonexistent VPN gateway the stack reaches ROLLBACK_COMPLETE, the Assoc resource's CREATE_FAILED ResourceStatusReason is error code InvalidRequest with message 'The VirtualGateway <vgwId> for owner <accountId> does not exist (Service: DirectConnect, Status Code: 400, Request ID: <id>) (SDK Attempt Count: <n>)', DescribeStackResources still lists exactly one created dx-gateway whose PhysicalResourceId is arn:aws<suffix>:directconnect::<account>:dx-gateway/<id>, and the rollback leaves that gateway in state 'deleted', the VPN gateway State 'deleted' and DescribeVpcs answering InvalidVpcID.NotFound "The vpc ID '<vpcId>' does not exist".
Actual: ValidationError 'Template format error: Unrecognized resource types: [AWS::DirectConnect::DirectConnectGateway, AWS::DirectConnect::DirectConnectGatewayAssociation]' at CreateStack, no stack exists, nothing downstream is exercised.
