# rbin EBS_SNAPSHOT retention is still unserved end to end: ec2 DeleteSnapshot refuses with 501 NotImplemented, and no rbin rule is consulted on snapshot deletion

> _Note: this issue was identified against the code base at commit `01ad7cf4d75cdcadee33f1733defefde67ff031f`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
DeleteSnapshot

## Description
Cause 1 of 1: a tag-level rbin retention rule for ResourceType=EBS_SNAPSHOT still has no effect on EBS snapshot deletion, and the workflow now aborts one step later than it used to: EC2 CreateSnapshot is served, but EC2 DeleteSnapshot answers 501 NotImplemented, so the retain/restore path is never reached. Failing check: rbin.ebs-snapshot-retained-in-recycle-bin-on-delete.

AWS: rbin CreateRule (Smithy doc, com.amazonaws.rbin#CreateRule, member CreateRuleRequest$ResourceTags) documents tag-level retention rules: "For each retention rule, you specify one or more tag key and value pairs. Resources (of the specified type) that have at least one of these tag key and value pairs are automatically retained in the Recycle Bin upon deletion." With such a rule available for EBS_SNAPSHOT, the counterpart surface is modelled in EC2: Smithy ec2 DeleteSnapshot (input SnapshotId required, output Unit, no modeled errors) succeeds and does NOT permanently delete a matching snapshot; ec2 ListSnapshotsInRecycleBin (output Snapshots -> SnapshotRecycleBinInfoList, paginated, filterable by SnapshotIds) then returns exactly one entry for that snapshot id carrying RecycleBinEnterTime; while the snapshot is resident in the bin it is no longer a live snapshot, so ec2 DescribeSnapshots(SnapshotIds=[<id>]) is refused with error code InvalidSnapshot.NotFound and message "The snapshot '<snapshot-id>' does not exist." — the fixed text is everything outside the quotes' contents, and <snapshot-id> is the id taken verbatim from the request; and ec2 RestoreSnapshotFromRecycleBin(SnapshotId=<id>) (Smithy: output SnapshotId/VolumeId/State/...) returns it to a normal snapshot that reaches State=completed.

Emulator: the check now gets past CreateSnapshot and the snapshot_completed waiter, then aborts on the delete. EC2 DeleteSnapshot answers HTTP 501 with code NotImplemented and the message "operation DeleteSnapshot is scaffolded but not implemented in this emulator" (botocore: An error occurred (NotImplemented) when calling the DeleteSnapshot operation). Only the operation name in that message comes from the request; the rest is wholly emulator-authored text that AWS never emits for this operation. Behind that refusal the rbin side remains inert: a created rule is recorded only in the rbin crate's own state and is read by no handler in any other service, so even once DeleteSnapshot is implemented a matching delete would permanently delete the snapshot, ListSnapshotsInRecycleBin would stay empty, DescribeSnapshots would not produce the InvalidSnapshot.NotFound refusal for a bin-resident snapshot, and RestoreSnapshotFromRecycleBin would have nothing to restore.

Why: a client that relies on Recycle Bin for EBS data protection gets the opposite of the guarantee it configured. Today every delete is refused outright (a 501 that no AWS SDK retry or error path expects, so data-protection tooling fails at the delete call); with the stub filled but the rule still inert, a delete AWS would have intercepted and made recoverable becomes an unrecoverable permanent delete, and rollback/restore logic reading ListSnapshotsInRecycleBin sees an empty bin and concludes nothing was retained — so retention policy tests pass vacuously.

Fix: two components. (1) EC2's DeleteSnapshot handler must be implemented (its scaffold stub is tracked by the open issue 20261023T060504Z-ec2-deletesnapshot-stub.md, whose Issue-Trace-Ids do NOT include this check, so closing that stub alone does not retire this check). (2) The rbin rule store needs an exported cross-service lookup ("which rules match resource type T and these resource tags") that EC2's DeleteSnapshot handler consults, plus snapshot recycle-bin state in the EC2 crate feeding ListSnapshotsInRecycleBin and RestoreSnapshotFromRecycleBin and suppressing the snapshot from DescribeSnapshots with the InvalidSnapshot.NotFound refusal while it is resident. Related already-open issues, neither of which covers this check's current refusal: 20261029T194803Z-rbin-retention-rules-do-not-retain-deleted-ebs.md (filed when the blocker was CreateSnapshot, Issue-Key rbin|CreateSnapshot|NotImplemented — that call now succeeds and the refusal has moved to DeleteSnapshot) and 20261024T155459Z-rbin-createrule-event-propagation.md (a static read of the inert-rule condition for EBS_VOLUME; it carries no behavioral replay key).

Traces: rbin.ebs-snapshot-retained-in-recycle-bin-on-delete.

## Evidence
Check rbin.ebs-snapshot-retained-in-recycle-bin-on-delete, verdict [error], service heading ### rbin.

Expected (AWS): ec2.create_volume + snapshot of it, then rbin.create_rule(ResourceType="EBS_SNAPSHOT", RetentionPeriod={"RetentionPeriodValue": 1, "RetentionPeriodUnit": "DAYS"}, ResourceTags=[{ResourceTagKey: <tag-key>, ResourceTagValue: <tag-value>}]) reaching Status=available; ec2.create_snapshot(VolumeId=<vol>, TagSpecifications=[{"ResourceType": "snapshot", "Tags": [{Key: <tag-key>, Value: <tag-value>}]}]) -> 200 SnapshotId; ec2.delete_snapshot(SnapshotId=<id>) -> 200 with an empty body, and the snapshot is RETAINED: ec2.list_snapshots_in_recycle_bin(SnapshotIds=[<id>]) returns exactly one entry whose SnapshotId == <id> and which includes RecycleBinEnterTime; ec2.describe_snapshots(SnapshotIds=[<id>]) is refused with Code=InvalidSnapshot.NotFound and Message="The snapshot '<id>' does not exist."; ec2.restore_snapshot_from_recycle_bin(SnapshotId=<id>) brings it back until describe_snapshots reports State=completed.

Actual (emulator): the check aborts at the delete step with botocore.exceptions.ClientError: An error occurred (NotImplemented) when calling the DeleteSnapshot operation: operation DeleteSnapshot is scaffolded but not implemented in this emulator (HTTP 501). Diverging status/code/message: 501 / NotImplemented / "operation DeleteSnapshot is scaffolded but not implemented in this emulator" where AWS returns a 200 empty DeleteSnapshot result. Fixed text in the emulator's message: "operation " ... " is scaffolded but not implemented in this emulator"; the only request-derived part is the operation name "DeleteSnapshot". Because the delete never happens, none of the downstream assertions (Recycle Bin residency with RecycleBinEnterTime, the InvalidSnapshot.NotFound refusal from DescribeSnapshots, the restore to State=completed) is exercised, and the rbin rule's interception is unobservable.

## Steps to Reproduce
1. Boot the emulator and point ec2 + rbin clients at it.
2. az = ec2.describe_availability_zones()["AvailabilityZones"][0]["ZoneName"]; vol = ec2.create_volume(AvailabilityZone=az, Size=1, VolumeType="gp3")["VolumeId"]; wait for the volume_available waiter.
3. rbin.create_rule(ResourceType="EBS_SNAPSHOT", RetentionPeriod={"RetentionPeriodValue": 1, "RetentionPeriodUnit": "DAYS"}, ResourceTags=[{"ResourceTagKey": "sim2real-rbin-test", "ResourceTagValue": "<unique>"}]) and poll rbin.get_rule until Status == "available".
4. snap = ec2.create_snapshot(VolumeId=vol, TagSpecifications=[{"ResourceType": "snapshot", "Tags": [{"Key": "sim2real-rbin-test", "Value": "<unique>"}]}])["SnapshotId"]; wait for the snapshot_completed waiter (this step succeeds today).
5. ec2.delete_snapshot(SnapshotId=snap) -> expected HTTP 200 with an empty body; actual HTTP 501 NotImplemented "operation DeleteSnapshot is scaffolded but not implemented in this emulator".
6. With the stub filled, the rest of the path still diverges: ec2.list_snapshots_in_recycle_bin(SnapshotIds=[snap]) -> expected one entry for snap with RecycleBinEnterTime, actual an empty snapshotSet because no handler outside rbin reads the rule store and the ec2 crate holds no snapshot recycle-bin state; ec2.describe_snapshots(SnapshotIds=[snap]) -> expected InvalidSnapshot.NotFound "The snapshot '<snap>' does not exist."; ec2.restore_snapshot_from_recycle_bin(SnapshotId=snap) -> expected the snapshot back at State=completed.
