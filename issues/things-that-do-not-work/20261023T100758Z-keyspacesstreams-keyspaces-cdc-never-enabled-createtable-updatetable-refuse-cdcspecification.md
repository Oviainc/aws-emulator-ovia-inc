# Keyspaces CDC never enabled: CreateTable/UpdateTable refuse cdcSpecification with 501 NotImplemented, so no stream ever exists and the whole KeyspacesStreams surface is unreachable

> _Note: this issue was identified against the code base at commit `3b7cd50bec204a941815a8ace6b2a1778291c65c`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateTable

## Description
Cause 1 of 1: a table cannot be created (or altered) with a CDC specification, so no CDC stream is ever brought into existence and every KeyspacesStreams check — ListStreams, GetStream, GetShardIterator, GetRecords, and the native-CQL change-record checks — dies on its very first setup call. Failing check ids for this cause: keyspacesstreams.cdc-batch-operation-decomposes-into-row-records, keyspacesstreams.cdc-concurrent-inserts-preserve-sequence-ordering, keyspacesstreams.cdc-keys-only-view-type-omits-images, keyspacesstreams.cdc-native-protocol-insert-update-delete-round-trip, keyspacesstreams.get-records-denied-by-iam-policy-rejected, keyspacesstreams.get-records-malformed-iterator-rejected, keyspacesstreams.get-records-max-results-out-of-range-rejected, keyspacesstreams.get-records-pagination-via-next-shard-iterator, keyspacesstreams.get-shard-iterator-missing-sequence-number-rejected, keyspacesstreams.get-shard-iterator-sequence-number-boundary-semantics, keyspacesstreams.get-shard-iterator-types-on-empty-stream, keyspacesstreams.get-stream-child-shards-filter-validation, keyspacesstreams.get-stream-nonexistent-arn-not-found, keyspacesstreams.get-stream-shard-structure-fields-and-pagination, keyspacesstreams.list-streams-pagination-across-multiple-streams, keyspacesstreams.list-streams-returns-created-stream, keyspacesstreams.list-streams-unfiltered-includes-created-stream, keyspacesstreams.stream-disabled-after-cdc-disable, keyspacesstreams.stream-enabled-after-cdc-create.

AWS: `cdcSpecification` is a normal optional input member of Keyspaces `CreateTable` and `UpdateTable` (Smithy: CreateTable.cdcSpecification -> CdcSpecification, member of CreateTableRequest; same member on UpdateTableRequest). `CdcSpecification` has required `status` (Smithy: CdcStatus enum ENABLED|ENABLING|DISABLED|DISABLING) plus optional `viewType` (Smithy: ViewType enum NEW_IMAGE|OLD_IMAGE|KEYS_ONLY|NEW_AND_OLD_IMAGES, documented default NEW_AND_OLD_IMAGES), `tags` and `propagateTags`. Supplying it on CreateTable is accepted (HTTP 200 with `resourceArn`); AWS then creates the table's CDC stream, `GetTable` reports `cdcSpecification` (CdcSpecificationSummary: status, viewType) and `latestStreamArn` (Smithy: GetTable output members, StreamArn pattern ^arn:(aws[a-zA-Z0-9-]*):cassandra:.+), and the KeyspacesStreams API then lists and serves that stream. CreateTable models exactly six errors — AccessDeniedException 403, ConflictException 409, InternalServerException 500, ResourceNotFoundException 404, ServiceQuotaExceededException 402, ValidationException 400 — and no not-implemented error of any kind, so a well-formed request carrying a modeled optional member must never be refused.

Emulator: `CreateTable` with `cdcSpecification` present is rejected outright with an unmodeled error code `NotImplemented` (HTTP 501). Recorded message, as an example: "CreateTable is implemented in this emulator, but not its cdcSpecification member(s): omit them, or the table would be stored with settings no operation here can report." The same refusal applies to `replicaSpecifications` and `warmThroughputSpecification`. Because no stream can be created, the KeyspacesStreams crate's write side (`enable_stream`/`append_change_record`/`split_shard`) is never driven by the control plane, and the entire KeyspacesStreams read surface answers for an always-empty store: 19 of 20 behavioral checks error at setup, before they reach any KeyspacesStreams operation at all.

Why: a client that enables CDC the documented way gets a 501 with an error code that is not in the operation's model, so no SDK error-matching branch catches it and the table is not created either. Every CDC consumer flow is impossible: enabling a stream on create, disabling it with UpdateTable, discovering it via GetTable.latestStreamArn/ListStreams, and reading change records with GetShardIterator/GetRecords. The service appears bootstrapped but no stream can ever be observed through it.

Fix: the Keyspaces control-plane CreateTable handler and its UpdateTable counterpart must accept `cdcSpecification`, store it on the table (status, viewType with its documented default), and drive the KeyspacesStreams state write side to enable/disable the stream and mint its shards; the Keyspaces GetTable serializer must then report `cdcSpecification` (CdcSpecificationSummary) and `latestStreamArn`. The refusal path in the CreateTable handler must be removed for this member rather than reworded, and the CDC/stream state must be shared between the keyspaces and keyspacesstreams service state so the stream the control plane enables is the one the data plane reports.

Note: the only open keyspaces-family issue, "Keyspaces catalog not seeded: system keyspaces and their system tables absent", is a different root cause (missing system catalog seeding) and does not cover this refusal.

Traces: all 19 failing keyspacesstreams checks listed above, each erroring with ClientError (NotImplemented) on CreateTable during setup. Code citations: services/service-com-amazonaws-keyspaces-keyspacesservice/src/ops/create_table.rs lines 246-274 (the NotImplemented refusal listing cdcSpecification) and lines 391-418 (the stored Table struct, which has no CDC field); services/service-com-amazonaws-keyspacesstreams-keyspacesstreams/src/state.rs lines 5-14 (module note that the write side lives here and is never called by the Keyspaces control plane).

## Evidence
Expected (AWS): keyspaces CreateTable(keyspaceName, tableName, schemaDefinition, cdcSpecification={status: ENABLED, viewType: NEW_IMAGE}) -> HTTP 200 {resourceArn: arn:aws:cassandra:...}; then GetTable reports status ACTIVE, cdcSpecification {status: ENABLED, viewType: NEW_IMAGE} and a latestStreamArn; keyspacesstreams ListStreams/GetStream report that stream as ENABLED with shards, and GetShardIterator/GetRecords serve its change records.

Actual (emulator): keyspaces CreateTable with cdcSpecification -> HTTP 501, error code NotImplemented. botocore: "An error occurred (NotImplemented) when calling the CreateTable operation: CreateTable is implemented in this emulator, but not its cdcSpecification member(s): omit them, or the table would be stored with settings no operation here can report." (message quoted as an example; the diverging requirements are the status 501 and the unmodeled code NotImplemented, where AWS returns 200). No stream is ever created, so all 19 keyspacesstreams checks error during setup and only 1 of 20 passes (5%).

## Steps to Reproduce
1. Boot the emulator and point boto3 at it.
2. keyspaces.create_keyspace(keyspaceName='ks1').
3. keyspaces.create_table(keyspaceName='ks1', tableName='tbl1', schemaDefinition={'allColumns': [{'name':'pk','type':'text'},{'name':'ck','type':'text'},{'name':'val','type':'text'}], 'partitionKeys': [{'name':'pk'}], 'clusteringKeys': [{'name':'ck','orderBy':'ASC'}]}, cdcSpecification={'status':'ENABLED','viewType':'NEW_IMAGE'}).
4. Observe HTTP 501 with error code NotImplemented instead of HTTP 200 with resourceArn.
5. Consequently keyspaces.get_table('ks1','tbl1') never reports cdcSpecification/latestStreamArn and keyspacesstreams.list_streams() returns no stream, so no GetStream/GetShardIterator/GetRecords flow can be exercised.
