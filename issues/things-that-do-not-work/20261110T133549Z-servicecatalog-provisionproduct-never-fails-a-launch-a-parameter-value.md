# ProvisionProduct never fails a launch: a parameter value outside the template's AllowedValues settles AVAILABLE/SUCCEEDED with no StatusMessage or RecordErrors

> _Note: this issue was identified against the code base at commit `5598dd881b8e225c34bc5a9814ddc1ff981b448f`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
ProvisionProduct

## Description
Cause 1 of 1: the Service Catalog emulator has no asynchronous FAILURE path for a provisioning request — every accepted ProvisionProduct eventually reports success regardless of whether the CloudFormation template it launches would accept the supplied ProvisioningParameters.

AWS: ProvisionProduct accepts the request synchronously (RecordDetail.Status 'CREATED', RecordErrors empty) and then performs the launch through CloudFormation. When a supplied provisioning parameter value violates the template's own declared constraint — here the template declares Parameters.Env with AllowedValues ['dev','prod'] and the request passes Env='staging' — CloudFormation refuses the stack and Service Catalog settles the launch as a FAILURE: DescribeProvisionedProduct reports ProvisionedProductDetail.Status 'ERROR' (Smithy: ProvisionedProductStatus enum AVAILABLE|UNDER_CHANGE|TAINTED|ERROR|PLAN_IN_PROGRESS; the member doc for ProvisionedProductDetail$Status defines ERROR as "An unexpected error occurred. The provisioned product exists but the stack is not running. For example, CloudFormation received a parameter value that was not valid and could not launch the stack.") with a non-empty ProvisionedProductDetail.StatusMessage, DescribeRecord(Id=LastRecordId) reports RecordDetail.Status 'FAILED' (Smithy: RecordStatus enum CREATED|IN_PROGRESS|IN_PROGRESS_IN_ERROR|SUCCEEDED|FAILED) and carries the same reason in RecordDetail.RecordErrors[].Description (Smithy: RecordError{Code,Description}), and GetProvisionedProductOutputs on that provisioned product is REFUSED with InvalidParametersException / message "Last Successful Provisioning Record doesn't exist." rather than answering an empty Outputs list (Smithy: GetProvisionedProductOutputs models InvalidParametersException, HTTP 400). Recorded behavior for the settled failure's message, as AWS words this error class: "AmazonCloudFormationException  Parameter '<ParameterKey>' must be one of AllowedValues (Service: AmazonCloudFormation; Status Code: 400; Error Code: ValidationError; Request ID: <request-id>; Proxy: null)" — the fixed text is everything but the variable parts: <ParameterKey> is the offending key from the request's ProvisioningParameters (here 'Env') and <request-id> is CloudFormation's own per-call request id (per-run, not a requirement). That same sentence appears both as ProvisionedProductDetail.StatusMessage and as the single RecordErrors[].Description.

Emulator: the launch is accepted (RecordDetail.Status 'CREATED', RecordErrors empty — those assertions pass) and then settles SUCCESSFULLY. DescribeProvisionedProduct reports Status 'AVAILABLE' for the out-of-range launch (check assertion: "the out-of-range launch settled at 'AVAILABLE', expected 'ERROR'"). Nothing in the state machine can produce a failed launch: Record::status returns RECORD_STATUS_CREATED before `completed_at` and RECORD_STATUS_SUCCEEDED after it with no third outcome, provisioned_product_status returns UNDER_CHANGE while the last record is CREATED and AVAILABLE otherwise, and ProvisionedProductDetail.status_message is hard-coded None. Consequently LastSuccessfulProvisioningRecordId is also populated for a launch that never deployed, so GetProvisionedProductOutputs has a 'successful' record to point at instead of refusing the question. Note the emulator DOES parse the template constraint correctly: DescribeProvisioningParameters reported Env's AllowedValues as ['dev','prod'] (that assertion passed) — the parsed constraint is simply never applied at launch time.

Why: a client that validates its templates and parameter plumbing against this emulator sees every launch succeed. Bad parameter values are reported as AVAILABLE provisioned products with SUCCEEDED records and no StatusMessage, so error handling, retry/rollback and alerting paths for failed launches are never exercised and a caller cannot distinguish a working deploy from a refused one; code that reads RecordErrors or StatusMessage to surface the reason gets nothing, and GetProvisionedProductOutputs answers for a stack that does not exist instead of raising InvalidParametersException.

Fix: the ProvisionProduct handler and the provisioning state machine. The handler (services/service-com-amazonaws-servicecatalog-aws242servicecatalogservice/src/ops/provision_product.rs) resolves product, path and artifact and then stores a Record/ProvisionedProduct with no reference to the artifact's template parameters, so the supplied ProvisioningParameters are never checked against the template's declared Parameters (Type/AllowedValues/AllowedPattern/Min-MaxValue/Min-MaxLength) that DescribeProvisioningParameters already reports. The state (src/state.rs) needs a failed outcome: Record must be able to settle FAILED with RecordErrors, ProvisionedProduct must be able to settle ERROR with a StatusMessage, the derivations in Record::status / provisioned_product_status / ProvisionedProductDetail.status_message must report it, LastSuccessfulProvisioningRecordId must stay unset when no provisioning record SUCCEEDED, and GetProvisionedProductOutputs must refuse with InvalidParametersException when there is none.

Traces: servicecatalog.provision-invalid-template-parameter-fails-asynchronously (the positive control in the same check — a legal value Env='prod' reaching AVAILABLE with EnvEcho='prod' — must keep passing). Related but distinct, already-open issues: 20261102T115233Z-servicecatalog-getprovisionedproductoutputs-stub.md covers GetProvisionedProductOutputs being an unimplemented stub; this issue is about the missing failure path, not that stub.

## Steps to Reproduce
1. Create an S3-hosted CloudFormation template whose Parameters block declares a parameter with an AllowedValues constraint, e.g. Env {Type: String, AllowedValues: ['dev','prod'], Default: 'dev'} plus one trivial resource and an Output that Refs Env.
2. CreateProduct (ProductType=CLOUD_FORMATION_TEMPLATE, ProvisioningArtifactParameters.Info.LoadTemplateFromURL = that URL), CreatePortfolio, AssociateProductWithPortfolio, AssociatePrincipalWithPortfolio, then ListLaunchPaths to get the PathId.
3. DescribeProvisioningParameters -> confirm Env's ParameterConstraints.AllowedValues == ['dev','prod'] (this already works).
4. ProvisionProduct(ProductId, ProvisioningArtifactId, PathId, ProvisionedProductName=<new>, ProvisionToken=<uuid>, ProvisioningParameters=[{Key:'Env', Value:'staging'}]).
5. Observe RecordDetail.Status == 'CREATED' with RecordErrors == [] (correct).
6. Poll DescribeProvisionedProduct(Id=<ProvisionedProductId>) until Status leaves UNDER_CHANGE/PLAN_IN_PROGRESS. Emulator reports 'AVAILABLE' with StatusMessage absent; AWS reports 'ERROR' with the AmazonCloudFormationException AllowedValues StatusMessage.
7. DescribeRecord(Id=<LastRecordId>): emulator reports 'SUCCEEDED' with no RecordErrors; AWS reports 'FAILED' with one RecordErrors entry carrying the same sentence.
8. GetProvisionedProductOutputs(ProvisionedProductId=<pp>): AWS raises InvalidParametersException "Last Successful Provisioning Record doesn't exist."
9. Repeat step 4 with Value='prod' — this must still settle AVAILABLE and expose Outputs EnvEcho='prod'.
