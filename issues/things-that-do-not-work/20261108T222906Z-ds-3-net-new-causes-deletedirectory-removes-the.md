# ds: 3 net-new causes — DeleteDirectory removes the record synchronously so Stage=Deleting is never observable, CreateAlias' not-Active refusal is emulator-authored, and the vpcSettings.subnetIds ValidationException message renders the wrong value and constraint list

> _Note: this issue was identified against the code base at commit `0e1e74bc7be9f02744aed6259c3be4e3b3293a9a`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
DeleteDirectory

## Description
THREE net-new root causes in the Directory Service (ds) control plane, all grounded in failing checks the suite lists under `### ds` that are neither ALREADY FILED nor OWNED by an open issue. All three are in one service, so they are bundled here; a fixer must close ALL THREE before submitting. Numbered causes below, each with its own failing check ids.

Cause 1 of 3: DeleteDirectory deletes the directory record synchronously, so the directory vanishes from DescribeDirectories instead of becoming readable at Stage=Deleting.
AWS: Smithy — DeleteDirectory(DirectoryId ^d-[0-9a-f]{10}$ required) returns DirectoryId and models ClientException / EntityDoesNotExistException / ServiceException; DirectoryStage enumerates Requested, Creating, Created, Active, Inoperable, Impaired, Restoring, RestoreFailed, Deleting, Deleted, Failed, Updating — i.e. the model declares Deleting and Deleted as stages a directory description can report. Recorded behavior: DeleteDirectory is asynchronous; it accepts the call (200, DirectoryId echoed) and the directory REMAINS readable through DescribeDirectories(DirectoryIds=[<id>]) with Stage=Deleting (then Deleted) for the duration of the teardown, which takes minutes. Only once removal completes does the id stop being described (the account's remembered-deleted id then yields an empty DirectoryDescriptions list for a filtered read). AWS never jumps straight from Active to 'absent'.
Emulator: the handler removes the record inside the same request — `store.directories.remove(&input.directory_id)` — and then only remembers the bare id, so the very next DescribeDirectories returns an EMPTY DirectoryDescriptions list. Two checks that poll for Deleting/Deleted after DeleteDirectory therefore never observe any stage at all: one reports 'directory <id> vanished from DescribeDirectories while waiting', the other times out with `last=None`. The Deleting and Deleted members of DirectoryStage are consequently unreachable for every directory.
Why: every client and IaC engine that deletes a directory confirms the delete by polling the directory's Stage until Deleting/Deleted; against this emulator that poll can only ever see the resource disappear, which such a poller treats as 'the id was never mine' / an unexpected EntityDoesNotExist-shaped condition rather than a normal in-progress delete. Code that distinguishes 'still tearing down' (do not delete the VPC/subnets yet) from 'gone' (safe to delete) loses that distinction entirely, and the documented two-phase teardown (directory to Deleting, ENIs released, then network deletes) cannot be exercised.
Fix: DeleteDirectory's handler (services/service-com-amazonaws-directoryservice-directoryservice-20150416/src/ops/delete_directory.rs) plus the directory state machine in src/state.rs — the delete must mark the stored directory Deleting and keep it describable, with the existing cascade (snapshots, trusts, shares, data-plane inventory) and final record removal happening on the subsequent stage transition rather than inside the delete call.
Traces: ds.microsoft-ad-create-delete-lifecycle, ds.tags-unicode-value-round-trip.

Cause 2 of 3: CreateAlias on a directory that has not reached Active refuses with the right class but an emulator-authored sentence that interpolates the directory id AWS keeps out of it.
AWS: Smithy — CreateAlias(DirectoryId required, Alias AliasName required) models ClientException, EntityAlreadyExistsException, EntityDoesNotExistException, InvalidParameterException (all client, HTTP 400). Recorded behavior: CreateAlias against a directory still in Requested/Creating/Created is refused 400 InvalidParameterException whose message template is entirely FIXED text — 'The directory must be active before an alias can be created for it. ' — followed by this service's ' : RequestId: <this call's request id>' suffix; the request id is the only variable part. No directory id and no stage name appears in it. The refusal attaches no alias, and the identical call succeeds once the directory is Active.
Emulator: answers the right class (InvalidParameterException) with a different sentence that also interpolates the id: 'Could not create alias as directory: <directory id> is not in Active state. : RequestId: <rid>'. The text comes from `crate::state::alias_stage_defect` (src/state.rs), reached from the stage-precondition branch of src/ops/create_alias.rs (lines ~194-205).
Why: the message is the only thing distinguishing this precondition from the other InvalidParameterException refusals CreateAlias can return (notably the already-aliased one); a client that matches AWS's fixed sentence to decide 'wait for Active and retry' matches nothing here, and one that parses the message gets an id injected into a template AWS keeps constant.
Fix: CreateAlias' stage-precondition refusal — `alias_stage_defect` in src/state.rs must carry AWS's fixed sentence with no interpolated id or stage.
Traces: ds.create-alias-before-active-rejected.

Cause 3 of 3: the ValidationException for a malformed subnet id in CreateMicrosoftAD renders only the offending member as the value and drops a constraint from the member-constraint list.
AWS: Smithy — CreateMicrosoftAD.VpcSettings targets DirectoryVpcSettings{VpcId @pattern ^(vpc-[0-9a-f]{8}|vpc-[0-9a-f]{17})$ required, SubnetIds: list of subnet ids required}; a subnet id that does not satisfy the member pattern is refused at input validation with ValidationException (before any resource semantics, which is why the same operation's same-AZ topology refusal is a separate ClientException). Recorded behavior: the message template is '<n> validation error detected: Value ' then the WHOLE submitted list rendered as '[<member1>, <member2>, …]' in request order, ' at ' the lowercase member path ''vpcSettings.subnetIds'' ' failed to satisfy constraint: Member must satisfy constraint: [Member must satisfy regular expression pattern: <the member pattern>, Member must not be null]'. Fixed text: the counted-errors preamble, the 'at'/'failed to satisfy constraint: Member must satisfy constraint:' scaffolding and BOTH bracketed member constraints, including the trailing 'Member must not be null'. Variable parts: the error count, the rendered list of submitted values, the member path and the pattern.
Emulator: serves the right class and path but a value that names only the bad element and a one-entry constraint list — 1 validation error detected: Value '[subnet-not-hex]' at 'vpcSettings.subnetIds' failed to satisfy constraint: Member must satisfy constraint: [Member must satisfy regular expression pattern: ^(subnet-[0-9a-f]{8}|subnet-[0-9a-f]{17})$] — i.e. the valid sibling subnet id submitted alongside it is omitted from the rendered value and ', Member must not be null' is missing from the bracketed constraint set.
Why: this message is the contract for list-member constraint violations across the service; a caller (or a test harness, or a human reading a CLI refusal) uses the rendered list to see WHICH list it submitted and in what order, and the constraint set to learn every constraint a member must satisfy. Rendering only the failing element makes the refusal look like it was raised against a one-element list the client never sent, and the missing nullability constraint understates the member contract.
Fix: the centralized input-validation envelope that formats list-member constraint violations for this crate's operations (the validate step feeding `crate::scaffolded::Scaffolded::validation`) — it must render the full submitted list as the value and emit the complete member-constraint set for a constrained list member.
Traces: ds.create-directory-rejects-single-az-vpc-settings.
