# cloudformation: AWS::Chime::MediaInsightsPipelineConfiguration is not a registered resource type — CreateStack refuses every Chime media-insights template with "Unrecognized resource types"

> _Note: this issue was identified against the code base at commit `86c25e3173c48b1c4d4a9173324e183693bfe876`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateStack

## Description
Cause 1 of 1: CloudFormation's template resource-type registry does not contain AWS::Chime::MediaInsightsPipelineConfiguration, so CreateStack refuses the whole template at validation time and no Chime SDK media-insights pipeline configuration can ever be provisioned from infrastructure-as-code. Failing checks: chime-sdk-media-pipelines__cloudformation.deploy-chime-media-insights-pipeline-config-invalid-name-rejected, chime-sdk-media-pipelines__cloudformation.deploy-chime-media-insights-pipeline-configuration-round-trip-and-delete.

AWS: AWS::Chime::MediaInsightsPipelineConfiguration is a supported CloudFormation resource type. CreateStack on a template that declares it (alongside AWS::S3::Bucket and AWS::IAM::Role) is accepted; CloudFormation provisions the configuration through the chime-sdk-media-pipelines control plane (Smithy, chime-sdk-media-pipelines: CreateMediaInsightsPipelineConfiguration POST /media-insights-pipeline-configurations, 201, required members MediaInsightsPipelineConfigurationName / ResourceAccessRoleArn / Elements; MediaInsightsPipelineConfigurationName @length 2..64 @pattern ^[0-9a-zA-Z._-]+$; modeled errors BadRequestException 400, NotFoundException 404, ForbiddenException 403). Ref on the resource yields the configuration's ARN, and the configuration is then readable through ListMediaInsightsPipelineConfigurations and GetMediaInsightsPipelineConfiguration; DeleteStack removes it, after which Chime refuses the ARN with NotFoundException. When the declared MediaInsightsPipelineConfigurationName violates that pattern, AWS fails the type's PROPERTY_VALIDATION before provisioning anything: the stack settles ROLLBACK_COMPLETE, the stack-level CREATE_FAILED event carries the fixed reason "Validation failed with 1 error(s). Call DescribeEvents to retrieve the full list of issues with resource and property details, resolve each error, then retry the operation.", DescribeEvents reports a VALIDATION_ERROR row (ValidationName PROPERTY_VALIDATION, ValidationStatus FAILED, ValidationFailureMode FAIL, ValidationPath /Resources/<logical-id>/Properties/MediaInsightsPipelineConfigurationName) whose reason is "Property value [<the name from the template>] does not match pattern: ^[0-9a-zA-Z._-]+$", and DescribeStackResources reports no resources. The bracketed name and the logical id are values taken from the submitted template; the surrounding text is fixed.

Emulator: CreateStack is refused outright, before any stack exists, with HTTP 400 and ClientError code ValidationError, message "Template format error: Unrecognized resource types: [AWS::Chime::MediaInsightsPipelineConfiguration]" (fixed text "Template format error: Unrecognized resource types: [...]", with the type name taken from the template). Both the positive (round-trip-and-delete) and the negative (invalid-name) check die on their first CreateStack, so no stack id is ever returned and none of the downstream behavior — Ref ARN, Chime read-back, property validation, rollback, stack events, DescribeEvents validation rows, DeleteStack cleanup — is reachable.

Why: a client deploying Chime SDK media-insights pipelines by template or CDK gets a hard ValidationError for a type AWS supports. The entire IaC path for this service is unavailable: no stack can be created, the resource cannot be referenced from an output or another resource, and the property-level validation/rollback semantics a client relies on to catch a bad configuration name at deploy time never run.

Fix: CloudFormation's template resource-type registry and the resource provider that backs it — register AWS::Chime::MediaInsightsPipelineConfiguration (Create/Read/Update/Delete plus Ref returning the configuration ARN and its property schema, including the MediaInsightsPipelineConfigurationName pattern used for PROPERTY_VALIDATION) and wire it to the chime-sdk-media-pipelines CreateMediaInsightsPipelineConfiguration / GetMediaInsightsPipelineConfiguration / DeleteMediaInsightsPipelineConfiguration handlers. Related but distinct open issues report the same missing-registration shape for other namespaces (e.g. 20261109T113214Z-cloudformation-ivs-mediatailor-createstack-refuses-aws-ivs-adconfiguration.md, 20261109T113428Z-cloudformation-mwaa-createstack-refuses-aws-mwaa-environment-as.md); none of them covers AWS::Chime::*.

Traces: chime-sdk-media-pipelines__cloudformation.deploy-chime-media-insights-pipeline-configuration-round-trip-and-delete (happy-path deploy + Chime read-back + stack delete), chime-sdk-media-pipelines__cloudformation.deploy-chime-media-insights-pipeline-config-invalid-name-rejected (property-validation rejection and rollback).

## Evidence
Expected (AWS): CreateStack on a template whose Resources include {"Config": {"Type": "AWS::Chime::MediaInsightsPipelineConfiguration", "Properties": {"MediaInsightsPipelineConfigurationName": <name>, "ResourceAccessRoleArn": {"Fn::GetAtt": ["Role","Arn"]}, "Elements": [{"Type": "S3RecordingSink", "S3RecordingSinkConfiguration": {"Destination": <bucket arn>, "RecordingFileFormat": "Wav"}}]}}} is accepted and returns a StackId; the stack reaches CREATE_COMPLETE and the configuration is listed/gettable through chime-sdk-media-pipelines with the template's name, role ARN and sink element. With a name outside ^[0-9a-zA-Z._-]+$ the stack instead reaches ROLLBACK_COMPLETE, the stack CREATE_FAILED reason is "Validation failed with 1 error(s). Call DescribeEvents to retrieve the full list of issues with resource and property details, resolve each error, then retry the operation.", DescribeEvents carries one VALIDATION_ERROR row (PROPERTY_VALIDATION / FAILED / FAIL, path /Resources/Config/Properties/MediaInsightsPipelineConfigurationName, reason "Property value [<name>] does not match pattern: ^[0-9a-zA-Z._-]+$"), and DescribeStackResources is empty.

Actual (emulator): both checks abort on the first CreateStack call with
  botocore.exceptions.ClientError: An error occurred (ValidationError) when calling the CreateStack operation: Template format error: Unrecognized resource types: [AWS::Chime::MediaInsightsPipelineConfiguration]
No stack is created, so DescribeStacks/DescribeStackEvents/DescribeEvents/DescribeStackResources and every Chime read-back assertion are never reached.

## Steps to Reproduce
1. Build and boot the emulator from this checkout.
2. Submit a CloudFormation template declaring an AWS::S3::Bucket, an AWS::IAM::Role trusted by mediapipelines.chime.amazonaws.com, and a resource of Type "AWS::Chime::MediaInsightsPipelineConfiguration" with Properties MediaInsightsPipelineConfigurationName (a name matching ^[0-9a-zA-Z._-]+$), ResourceAccessRoleArn = Fn::GetAtt Role.Arn, and Elements = [{"Type":"S3RecordingSink","S3RecordingSinkConfiguration":{"Destination":<bucket arn>,"RecordingFileFormat":"Wav"}}]:
   aws cloudformation create-stack --stack-name sim2real-micfg --template-body file://t.json --capabilities CAPABILITY_IAM
3. Observe HTTP 400 ValidationError "Template format error: Unrecognized resource types: [AWS::Chime::MediaInsightsPipelineConfiguration]" instead of a StackId.
4. Repeat with a MediaInsightsPipelineConfigurationName containing spaces (e.g. "sim2real behav bad name 1"): the same CreateStack refusal occurs, instead of a stack that reaches ROLLBACK_COMPLETE with one PROPERTY_VALIDATION VALIDATION_ERROR row and no resources.
