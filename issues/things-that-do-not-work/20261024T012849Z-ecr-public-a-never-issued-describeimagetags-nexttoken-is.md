=== Cause 1 of 1: the InvalidParameterException for a never-issued pagination token names the member in the wire-member casing and states a fabricated constraint rule ===
AWS: Smithy DescribeImageTags (model services/service-com-amazonaws-ecrpublic-spencerfrontendservice/smithy-model/com-amazonaws-ecrpublic-spencerfrontendservice.json) has input member `nextToken` -> shape `NextToken`, `maxResults` -> MaxResults @range 1..1000, `repositoryName` required, and is @paginated {inputToken: nextToken, outputToken: nextToken, items: imageTagDetails, pageSize: maxResults}. Its modeled errors are InvalidParameterException (client, httpError 400 [defaulted]), RepositoryNotFoundException (400), UnsupportedCommandException (400) and ServerException (500); InvalidParameterException is documented "The specified parameter is invalid. Review the available parameters for the API request." A syntactically well-formed but never-issued nextToken is refused with HTTP 400 and error code `InvalidParameterException`. The message is a deterministic function of the request, so its RULE is the requirement: ECR Public renders the fixed template "Invalid parameter at '<Member>' failed to satisfy constraint: '<violated rule>'", where the member path is the service's own PascalCase parameter name for the token (`NextToken`) and the rule states that the token itself is not a valid cursor. The recorded example is "Invalid parameter at 'NextToken' failed to satisfy constraint: 'Invalid next token provided'" — the quoted text is an example of that template, and the same template appears on this service's other input refusals (see cause 3 of 20261023T055032Z-ecr-public-getauthorizationtoken-is-not-authorization-gated-stored.md, which records 'PolicyText' / 'catalogData.description' rendered the same way), so the PascalCase member path is the service's convention and not an artifact of one recording.
Emulator: status 400 and code InvalidParameterException are BOTH correct — the only divergence is the rendered message, which comes back as "Invalid parameter at 'nextToken' failed to satisfy constraint: 'Member must be a token returned by a previous call'". Two things differ from the service's rule: the member path is the lower-camel WIRE member name `nextToken` instead of the service's `NextToken`, and the constraint clause is phrased as a prerequisite on the caller's behaviour ("Member must be a token returned by a previous call") instead of a verdict on the supplied token ("Invalid next token provided"). The refusal itself is right: the pagination walk in the same check succeeds as a positive control, the forged token changes no state, and the unpaginated read afterwards still lists the full tag set. NOTE this is NOT the generic "N validation error detected: Value '<rejected value>' at ..." framework-preamble defect already filed as cause 3 of 20261023T055032Z-ecr-public-getauthorizationtoken-is-not-authorization-gated-stored.md — this handler already uses the service template and populates it wrongly, so fixing that framework renderer will not close this cause.
Why: a client that surfaces field-level pagination errors keys off the member path quoted in the message to point the caller at the offending parameter, and a conformance or log-matching consumer matches the rule clause to distinguish "this cursor is stale/forged" from a different constraint failure on the same member. Against the emulator it extracts a member name that does not match the one AWS reports and a rule sentence that never occurs on AWS, so error presentation and any assertion pinned to the service's wording diverge even though the HTTP status and error code agree.
Fix: the shared pagination-token decoder this service's readers call — `crate::state::decode_page_token` in services/service-com-amazonaws-ecrpublic-spencerfrontendservice/src/state.rs, whose Err(message) is lifted into InvalidParameterException by describe_image_tags.rs — must render the service's template with the PascalCase member path for the token and a rule clause that states the token is invalid, rather than the wire member name and a caller-prerequisite sentence. Because the decoder is shared, every paginated ecr-public reader (DescribeImages, DescribeRepositories, DescribeImageTags, …) inherits the fix.
Traces: ecr-public.describe-image-tags-pagination-partitions-the-tag-set-exactly (handler: services/service-com-amazonaws-ecrpublic-spencerfrontendservice/src/ops/describe_image_tags.rs:185-188 and 228-233).
