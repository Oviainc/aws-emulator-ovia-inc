# cloudformation__opensearch: 2 net-new causes — a rolled-back stack records no PROPERTY_VALIDATION event, and AWS::OpenSearchService::Application is not a registered resource type

> _Note: this issue was identified against the code base at commit `44786d0c9f40e8c1d9dd84c42bcd4a9c51c55d07`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
DescribeEvents

## Description
This issue carries 2 root causes, both in the cloudformation__opensearch surface. BOTH must be closed before submitting.

Cause 1 of 2: a stack that CloudFormation rolls back because a resource property fails the resource type's schema validation emits no VALIDATION_ERROR operation event — DescribeEvents returns an OperationEvents list with no validation row at all, so the reason the stack was refused and the property it was refused on are unobtainable. Failing check: cloudformation__opensearch.deploy-domain-unsupported-property-rejected-before-any-domain-exists.

AWS: Smithy: DescribeEvents(StackName) -> OperationEvents (paginated on NextToken, items OperationEvents); OperationEvent carries EventType (enum EventType: STACK_EVENT|PROGRESS_EVENT|VALIDATION_ERROR|PROVISIONING_ERROR|HOOK_INVOCATION_ERROR), LogicalResourceId, ValidationName, ValidationStatus (enum), ValidationFailureMode, ValidationStatusReason and ValidationPath. Recorded behavior: a CreateStack whose AWS::OpenSearchService::Domain declares DeploymentStrategyOptions.DeploymentStrategy with a value outside the property's enum is caught by pre-provision property validation: the stack ends ROLLBACK_COMPLETE (which the emulator does produce) AND DescribeEvents carries exactly one EventType=VALIDATION_ERROR event for that resource, with ValidationName='PROPERTY_VALIDATION', ValidationStatus='FAILED', ValidationFailureMode='FAIL', ValidationPath pointing at the offending property, and ValidationStatusReason naming the rejected value and the supported set. Message template: fixed text '<value> is not a valid enum value. Supported values: [<the property's enum members, comma separated>]'; the value is taken from the request's template and the supported list from the resource type's schema. ValidationPath is built from the template: '/Resources/<LogicalId>/Properties/<...>/<Member>'.

Emulator: the stack does reach ROLLBACK_COMPLETE, but DescribeEvents(StackName=<stack id>) returns no OperationEvent whose EventType is VALIDATION_ERROR — the check's filtered row list is [] where AWS has one row.

Why: a client that deploys templates reads DescribeEvents to learn WHICH property was rejected and WHY. Against the emulator every schema-validation rollback is indistinguishable from any other failure and carries no property path or reason, so deploy tooling cannot surface the error, cannot retry with a corrected property, and cannot assert that validation happened before any resource was provisioned.

Fix: CloudFormation's operation-event recording for pre-provision resource-property validation — the DescribeEvents handler and the stack-operation state it reads must record a VALIDATION_ERROR event (ValidationName/ValidationStatus/ValidationFailureMode/ValidationStatusReason/ValidationPath populated) whenever a property fails the resource type's schema, alongside the stack events it already records. Similar open issues that do NOT cover this one: 20261109T124858Z-apigatewayv2-cloudformation-cognito-idp-2-net-new-causes.md and 20261109T142303Z-cloudformation-ssm-5-net-new-causes-no-resource.md.

Cause 2 of 2: AWS::OpenSearchService::Application is not a registered CloudFormation resource type, so CreateStack refuses every OpenSearch application template outright and no application-bearing stack — positive or negative — can be deployed. Failing checks: cloudformation__opensearch.deploy-opensearch-application-invalid-name-rejected, cloudformation__opensearch.deploy-opensearch-application-round-trip-and-delete.

AWS: AWS::OpenSearchService::Application is a documented CloudFormation resource type (https://docs.aws.amazon.com/AWSCloudFormation/latest/TemplateReference/aws-resource-opensearchservice-application.html) with properties Name, AppConfigs, IamIdentityCenterOptions and Tags, Ref resolving to the application Name and GetAtt Id/Arn resolving to the identifiers OpenSearch reports. Smithy (opensearch): ListApplications GET /2021-01-01/opensearch/list-applications -> ApplicationSummaries; GetApplication GET /2021-01-01/opensearch/application/{id} (id @pattern ^[a-z0-9]{3,30}$) -> id/arn/name (@pattern ^[a-z][a-z0-9\-]+$)/status (ApplicationStatus enum)/appConfigs, with ResourceNotFoundException for an id that does not exist. Recorded behavior: CreateStack ACCEPTS the template; a valid Name reaches CREATE_COMPLETE and the application reads back through GetApplication/ListApplications with status ACTIVE and its declared appConfigs and tags, while a Name that violates the id pattern rolls the stack back with the handler's own reason ('Invalid request provided: 1 validation error detected: Value ... at \'id\' failed to satisfy constraint: Member must satisfy regular expression pattern: ^(?!-)[a-z0-9\\-]{3,30}$ ...', HandlerErrorCode InvalidRequest) and leaves no application of that name listed.

Emulator: CreateStack is refused before anything is provisioned with HTTP 400 ValidationError and the message 'Template format error: Unrecognized resource types: [AWS::OpenSearchService::Application]' (fixed text 'Template format error: Unrecognized resource types: [' + the type names from the template + ']'). Both checks error on that CreateStack call.

Why: every stack that declares an OpenSearch application fails at submit time. A client cannot deploy, read back, tag, Ref/GetAtt or delete an application through CloudFormation, and the negative path (a bad Name producing a rolled-back stack with the OpenSearch handler's reason) is unreachable too, so an unregistered type masquerades as a malformed template.

Fix: CloudFormation's resource-type registry plus the AWS::OpenSearchService::Application resource handler — register the type, provision it against the OpenSearch application state (name, appConfigs, tags, status ACTIVE), resolve Ref to Name and GetAtt Id/Arn to the created application's identifiers, surface the OpenSearch handler refusal as the resource-status reason on a rejected Name, and delete the application on stack delete so GetApplication then answers ResourceNotFoundException ('Application does not exist').

Traces: cloudformation__opensearch.deploy-domain-unsupported-property-rejected-before-any-domain-exists (Cause 1); cloudformation__opensearch.deploy-opensearch-application-invalid-name-rejected, cloudformation__opensearch.deploy-opensearch-application-round-trip-and-delete (Cause 2).
