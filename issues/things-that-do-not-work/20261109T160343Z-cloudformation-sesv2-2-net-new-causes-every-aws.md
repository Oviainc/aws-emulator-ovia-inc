# cloudformation__sesv2: 2 net-new causes — every AWS::SES::* resource type except EmailIdentity/ConfigurationSet is refused as "Unrecognized resource types", and an EmailIdentity stack's Outputs come back with no OutputValue

> _Note: this issue was identified against the code base at commit `5b2a9eedb8fa287cac2318fd09ae07f52de03ab6`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateStack

## Description
Two net-new root causes in the CloudFormation-to-SESv2 provisioning surface. Both are grounded in the cloudformation__sesv2 deploy checks; none of them touches a 501 stub.

Cause 1 of 2: CloudFormation's template resource-type registry does not know the SESv2 resource types AWS::SES::ConfigurationSetEventDestination, AWS::SES::ContactList, AWS::SES::DedicatedIpPool, AWS::SES::MultiRegionEndpoint, AWS::SES::Tenant and AWS::SES::VdmAttributes, so template validation rejects the stack before any resource is provisioned. Failing checks: cloudformation__sesv2.deploy-cfn-ses-configuration-set-event-destination-round-trip-and-delete, .deploy-cfn-ses-contact-list-round-trip-and-delete, .deploy-cfn-ses-dedicated-ip-pool-round-trip-and-delete, .deploy-cfn-ses-dedicated-ip-pool-invalid-scaling-mode-rejected-and-rolled-back, .deploy-cfn-ses-multi-region-endpoint-round-trip-and-delete, .deploy-cfn-ses-tenant-round-trip-and-delete, .deploy-cfn-ses-tenant-invalid-name-rejected-and-rolled-back, .deploy-ses-vdm-attributes-invalid-value-rejected, .deploy-ses-vdm-attributes-singleton-functional-and-invalid-value-rejected.
AWS: all six types are registered CloudFormation resource types (aws-resource-ses-configurationseteventdestination, -contactlist, -dedicatedippool, -multiregionendpoint, -tenant, -vdmattributes). CreateStack returns a StackId, the stack settles CREATE_COMPLETE, and each resource is provisioned through the SESv2 control plane, so the SESv2 reads and the stack's Ref/GetAtt agree: AWS::SES::ConfigurationSetEventDestination -> CreateConfigurationSetEventDestination (Smithy com.amazonaws.sesv2: input ConfigurationSetName httpLabel required, EventDestinationName required, EventDestination required), Ref/GetAtt Id is the event-destination name and GetConfigurationSetEventDestinations reports Name/Enabled/MatchingEventTypes/CloudWatchDestination.DimensionConfigurations exactly as declared; an UpdateStack that drops the child clears only the destination and leaves the configuration set (and an out-of-band tag on it) intact; DeleteStack removes the set, after which GetConfigurationSet answers NotFoundException 'Configuration set <NAME> does not exist.' (fixed text 'Configuration set <' + '> does not exist.', the name taken from the request). AWS::SES::ContactList -> CreateContactList (ContactListName, Description, Topics[TopicName/DisplayName/DefaultSubscriptionStatus], Tags); Ref is the list name, GetContactList echoes Description and Topics, stack-level and resource-level tags both read back through ListTagsForResource on arn:<partition>:ses:<region>:<account>:contact-list/<name>, and after DeleteStack GetContactList answers NotFoundException "List with name: <NAME> doesn't exist." AWS::SES::DedicatedIpPool -> CreateDedicatedIpPool (PoolName, ScalingMode STANDARD|MANAGED, Tags); Ref is the pool name, GetDedicatedIpPool reports PoolName/ScalingMode, tags read back on arn:<partition>:ses:<region>:<account>:dedicated-ip-pool/<name>, and after DeleteStack GetDedicatedIpPool answers NotFoundException 'The requested pool <NAME> does not exist.' A ScalingMode outside the registry schema's pattern is caught by early (pre-provisioning) property validation: the stack ends ROLLBACK_COMPLETE, DescribeEvents carries one VALIDATION_ERROR row (LogicalResourceId 'Pool', ValidationName PROPERTY_VALIDATION, ValidationStatus FAILED, ValidationFailureMode FAIL, ValidationStatusReason 'Property value [<VALUE>] does not match pattern: ^(STANDARD|MANAGED)$', ValidationPath '/Resources/Pool/Properties/ScalingMode' — only <VALUE> and the logical id come from the template), and SESv2 never holds the pool. AWS::SES::MultiRegionEndpoint -> CreateMultiRegionEndpoint (EndpointName, Details.RoutesDetails[Region]); Ref is the endpoint name, the endpoint leaves CREATING/PROVISIONING for READY, GetMultiRegionEndpoint reports EndpointName/EndpointId/Routes covering the home and the declared secondary region, tags read back on arn:<partition>:ses:<region>:<account>:multi-region-endpoint/<name>, and after DeleteStack GetMultiRegionEndpoint answers NotFoundException with NO message at all. AWS::SES::Tenant -> CreateTenant; Ref is the tenant name, GetAtt Arn equals the TenantArn ListTenants/GetTenant report, tags read back on that ARN, and after DeleteStack GetTenant answers NotFoundException 'The requested tenant <NAME> does not exist.'; a TenantName failing the schema pattern is refused by early validation with a VALIDATION_ERROR row 'Property value [<VALUE>] does not match pattern: ^[\w\-_]+$' at '/Resources/Tenant/Properties/TenantName' and the name never appears in ListTenants. AWS::SES::VdmAttributes is the account singleton -> PutAccountVdmAttributes; a CREATE_COMPLETE stack leaves GetAccount().VdmAttributes = {'VdmEnabled':'ENABLED','DashboardAttributes':{'EngagementMetrics':<declared>},'GuardianAttributes':{'OptimizedSharedDelivery':<declared>}} and DeleteStack resets it to {'VdmEnabled':'DISABLED'}; an EngagementMetrics outside ENABLED|DISABLED fails template validation, the stack ends ROLLBACK_COMPLETE with the stack-level CREATE_FAILED reason 'Validation failed with 1 error(s). Call DescribeEvents to retrieve the full list of issues with resource and property details, resolve each error, then retry the operation.' (wholly fixed text) plus the VALIDATION_ERROR row 'Property value [<VALUE>] does not match pattern: ENABLED|DISABLED' at '/Resources/Vdm/Properties/DashboardAttributes/EngagementMetrics', and the account's VDM state is untouched.
Emulator: CreateStack never reaches provisioning. It answers 400 ValidationError with Message 'Template format error: Unrecognized resource types: [<type>]' naming exactly the SES type in the template (observed for AWS::SES::ConfigurationSetEventDestination, AWS::SES::ContactList, AWS::SES::DedicatedIpPool, AWS::SES::MultiRegionEndpoint, AWS::SES::Tenant and AWS::SES::VdmAttributes). No StackId is minted, so neither the happy-path SESv2 reads, the Ref/GetAtt identities, tag propagation, delete semantics, nor any of the three deployment-time rejection classes (bad ScalingMode, bad TenantName, bad EngagementMetrics) can be reached.
Why: a client that provisions SES through CloudFormation (console, CDK, any template-driven deploy) cannot deploy an event destination, contact list, dedicated IP pool, multi-region endpoint, tenant or VDM setting at all, and reads the refusal as 'my template is malformed' rather than 'the provider is missing'; the early-validation refusal taxonomy for these resources is equally unreachable.
Fix: register the six AWS::SES::* types in CloudFormation's resource-type registry / template validator and add their provisioning handlers, mapping create/read/update/delete to the SESv2 control-plane operations above, wiring Ref and the documented GetAtt attributes (event destination Id, tenant Arn) to the service-reported values, propagating stack tags to each taggable resource, and emitting the registry schema's PROPERTY_VALIDATION rows at the exact property path before provisioning. Open issue 20261109T125742Z-cloudformation-mailmanager-createstack-refuses-every-aws-ses-mailmanager.md reports the same registry gap for the AWS::SES::MailManager* types only; it does not carry these checks' replay keys and none of these six types appear in it.
Traces: the nine cloudformation__sesv2 checks listed above, all failing on the same CreateStack ValidationError.

Cause 2 of 2: an AWS::SES::EmailIdentity stack's Outputs are returned without OutputValue, so Ref and Fn::GetAtt on the identity resolve to nothing. Failing check: cloudformation__sesv2.deploy-cfn-ses-email-identity-round-trip-and-delete.
AWS: CloudFormation returns each requested Output as {OutputKey, OutputValue} (DescribeStacks Stack.Outputs; OutputValue is always present for a CREATE_COMPLETE stack). For AWS::SES::EmailIdentity, Ref resolves to the identity name SESv2 ListEmailIdentities holds, and the six documented GetAtt attributes DkimDNSTokenName1..3 / DkimDNSTokenValue1..3 resolve to the Easy DKIM CNAME pairs GetEmailIdentity reports — name '<token>._domainkey.<domain>' and value '<token>.<DkimAttributes.SigningHostedZone>' for each of the three DkimAttributes.Tokens (Smithy com.amazonaws.sesv2: GetEmailIdentity output DkimAttributes {Tokens, SigningHostedZone}).
Emulator: the stack is created (the type IS recognized here) and DescribeStacks returns Outputs rows that carry OutputKey but NO OutputValue member at all, so reading Outputs raises KeyError: 'OutputValue' before any SESv2 comparison runs; whether Ref/GetAtt would even resolve to the DKIM token pairs is therefore unobservable.
Why: every template-driven consumer of a stack output (nested stacks, Fn::ImportValue, CDK outputs, CI that reads DescribeStacks) gets a null value for a stack that reports CREATE_COMPLETE, so the deployed identity's name and DKIM records cannot be obtained from the stack at all.
Fix: the stack Outputs resolution/serialization in the CloudFormation service — each Outputs entry must carry OutputValue, resolved from the Ref/Fn::GetAtt the template declares against the provisioned resource's SESv2-reported attributes. Open issues 20261109T143402Z-cloudformation-mq-stack-outputs-for-aws-amazonmq-configuration.md and 20261109T141301Z-cloudformation-s3tables-cloudformation-stack-outputs-for-aws-s3tables-resources-are.md record the same missing-OutputValue shape for other resource types; neither carries this check's replay key nor mentions AWS::SES::EmailIdentity.
Traces: cloudformation__sesv2.deploy-cfn-ses-email-identity-round-trip-and-delete.
