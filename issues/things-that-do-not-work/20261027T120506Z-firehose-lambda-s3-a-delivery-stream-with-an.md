# firehose__lambda__s3: a delivery stream with an HttpEndpointDestinationConfiguration never issues an HTTP request, so the documented request envelope is unobservable (1 cause)

## Description
One net-new root cause, grounded in one failing behavioral check.

=== Cause 1 of 1: the HTTP endpoint destination has no delivery path — records accepted by PutRecordBatch never leave the service ===
AWS: Smithy (com.amazonaws.firehose#Firehose_20150804): HttpEndpointDestinationConfiguration models EndpointConfiguration (required), S3Configuration (required), BufferingHints, RetryOptions, S3BackupMode (HttpEndpointS3BackupMode: AllData | FailedDataOnly), ProcessingConfiguration, CloudWatchLoggingOptions and RequestConfiguration, whose members are ContentEncoding (enum NONE | GZIP) and CommonAttributes (list, @length 0-50). CreateDeliveryStream accepting that configuration is a PROMISE that the service will POST buffered records to the configured URL; AWS documents the envelope (https://docs.aws.amazon.com/firehose/latest/dev/httpdeliveryrequestresponse.html): request headers X-Amz-Firehose-Protocol-Version: 1.0, X-Amz-Firehose-Request-Id (an opaque 8-4-4-4-12 GUID), X-Amz-Firehose-Source-Arn (the DeliveryStreamARN the service itself reports), X-Amz-Firehose-Access-Key (the configured AccessKey copied verbatim), X-Amz-Firehose-Common-Attributes (JSON `{"commonAttributes": {<name>: <value>}}` built from the configured CommonAttributes), Content-Type: application/json, and NO Content-Encoding when ContentEncoding is NONE; the JSON body is `{"requestId": <same value as the header>, "timestamp": <epoch millis integer>, "records": [{"data": <base64 of the record bytes>}, ...]}` where each records[] entry has exactly the one member `data` and decodes to the put bytes with no added envelope or delimiter. A conforming 200 ends the attempt: nothing is written to the error prefix and, under S3BackupMode=FailedDataOnly, nothing is written to the backup prefix.
Emulator: PutRecordBatch answers 200 with FailedPutCount 0 and mints RecordIds, the stream reaches ACTIVE and DescribeDeliveryStream echoes HttpEndpointDestinationDescription.EndpointConfiguration.Url, but no HTTP request is ever sent to that URL. The check's capture endpoint (which records every request it receives into S3) receives nothing, so the poll for the records never converges and the check is cut off at the harness cap: `Error: Check timed out after 60.0s`. The check's own diagnosis for this shape is the message it would raise on its longer budget: `DATAPLANE_UNIMPLEMENTED?: the HTTP endpoint receives all 3 records ... did not happen. A target that accepts an HttpEndpointDestinationConfiguration and never issues an HTTPS request has no HTTP delivery path at all.`
Why: every HTTP-endpoint integration (Datadog, New Relic, Splunk, Dynatrace, any custom HTTPS sink) silently loses data against this emulator: the control plane reports a healthy ACTIVE stream and the data plane acknowledges each put, so a client has no signal that nothing was delivered. None of the documented envelope's requirements — the five X-Amz-Firehose-* headers, the requestId/header agreement, the records[].data base64 round trip, absence of Content-Encoding under ContentEncoding=NONE — can be satisfied or even observed, and neither can the retry/error-prefix semantics that depend on the endpoint's acknowledgement.
Hypothesis: the same inert-destination shape already filed for other destination families; only the S3 destination appears to have any flush path.
Fix: the HTTP-endpoint delivery path of the Firehose delivery engine — the buffer flusher must, for a stream whose destination is HttpEndpointDestinationConfiguration, assemble and POST the documented envelope to EndpointConfiguration.Url (headers and body as above, honoring RequestConfiguration.ContentEncoding and CommonAttributes and BufferingHints), interpret the response per the spec, and route failures to RetryOptions and then to the S3Configuration/S3BackupMode prefixes (the firehose service crate's delivery/flush module alongside services/service-com-amazonaws-firehose-firehose-20150804/src/ops/put_record_batch.rs).
