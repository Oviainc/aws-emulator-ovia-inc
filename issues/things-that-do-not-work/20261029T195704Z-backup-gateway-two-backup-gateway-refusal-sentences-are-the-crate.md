# Two backup-gateway refusal sentences are the crate's own words, not AWS's: the property-mappings not-found message and the metadata-sync access-denied message

> _Note: this issue was identified against the code base at commit `e22fc32f4dd53ee37fe3b4cc7fa000d8c822ec8a`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
GetHypervisorPropertyMappings

## Description
TWO net-new root causes, both in this crate's refusal-wording layer (the message constants in crate::state that handlers quote). Each must be closed before this issue is submitted. In both, the HTTP status class and the error CODE the emulator returns already match AWS; the Message — which is a requirement of the error class — is text this crate authored, in both cases justified in a doc comment by quoting the Smithy shape's own documentation instead of the sentence AWS sends.

Cause 1 of 2 — GetHypervisorPropertyMappings on a hypervisor that carries no property mappings sends the wrong sentence.
AWS: ResourceNotFoundException whose Message is exactly 'The hypervisor property mappings is not found.' — entirely FIXED text for this class (note AWS's own number disagreement 'mappings is'; it is part of the fixed string), with no variable part: it echoes neither the HypervisorArn nor any other request value. Smithy: GetHypervisorPropertyMappings input HypervisorArn (ServerArn, required, length 50..500, pattern ^arn:(aws|aws-cn|aws-us-gov):backup-gateway(:[a-zA-Z-0-9]+){3}\/[a-zA-Z-0-9]+$), errors = ResourceNotFoundException(@httpError 404), InternalServerException(500), ThrottlingException(429), ValidationException(400); ResourceNotFoundException$ErrorCode is documented 'A description of which resource wasn't found'. The model publishes no Message wording, so the sentence is recorded behavior (pinned by two behavioral checks).
Emulator: ResourceNotFoundException with Message 'The mappings are not found.' — the constant MAPPINGS_NOT_FOUND_MESSAGE, whose own doc comment (state.rs:277-280) says it is 'phrased like HYPERVISOR_NOT_FOUND_MESSAGE' and that 'this wording is an example', i.e. the crate treats the sentence as free choice when it is a requirement.
Why: both behavioral checks read this call as the ground-truth probe for 'no mappings configured' before and after a rejected Put. A client or test that asserts AWS's sentence, logs it, or surfaces it to an operator sees a different sentence for the same condition, and the two sentences are not interchangeable: AWS's names the hypervisor property mappings, the emulator's names an unqualified 'mappings'.
Fix: the message constant in crate::state that MissingResource::PropertyMappings resolves to (services/service-com-amazonaws-backupgateway-backuponpremises-v20210101/src/state.rs:275-280) must carry AWS's fixed sentence, so every operation refusing through that arm states it.
Related but not covering: open wire issue 20261029T192930Z-backup-gateway-not-found-and-validation-refusals-answer.md names this same sentence in its Cause 4 alongside the 404-vs-400 status and the ErrorCode token, grounded in wire fixture backup-gateway-hypervisor-property-mappings#task#3; it carries no behavioral replay keys, so the three checks listed here are not covered by it and must be re-replayed.
Traces: backup-gateway.put-hypervisor-property-mappings-fails-deterministically-without-gateway, backup-gateway.put-hypervisor-property-mappings-requires-trust-policy.

Cause 2 of 2 — StartVirtualMachinesMetadataSync's AccessDeniedException states the model's generic permissions sentence instead of AWS's mappings-not-configured sentence.
AWS: the sync is gated on the hypervisor's property mappings being configured, and the refusal is AccessDeniedException with Message exactly 'HypervisorPropertyMappings is not configured for the Hypervisor' — entirely FIXED text, no trailing period, no variable part. AWS sends that same sentence for a well-formed HypervisorArn that names nothing at all (the gate fires before any resource-existence lookup), so the sentence does not vary with whether the ARN resolves. Smithy: StartVirtualMachinesMetadataSync input HypervisorArn (required, ServerArn pattern as above), errors = AccessDeniedException(@httpError 403), ResourceNotFoundException(404), InternalServerException(500), ThrottlingException(429), ValidationException(400); AccessDeniedException$ErrorCode is required and documented 'A description of why you have insufficient permissions'. The Message wording is recorded behavior only (pinned by the check).
Emulator: AccessDeniedException (code matches) with Message 'The operation cannot proceed because you have insufficient permissions.' — the constant MAPPINGS_NOT_CONFIGURED_MESSAGE (state.rs:304-310), which its doc comment says is taken from AccessDeniedException's own Smithy documentation 'rather than in invented ones'. A shape's documentation string is not the message AWS sends for the condition, and here it drops the only diagnostic content: that the hypervisor's property mappings are not configured.
Why: this message is the sole thing telling the caller WHY the sync was denied. A client that branches on, or shows, 'HypervisorPropertyMappings is not configured for the Hypervisor' is instead told it lacks IAM permissions and will go audit its policy rather than call PutHypervisorPropertyMappings — the opposite remediation. The check asserts this sentence for both the ghost-ARN and the real-but-unconfigured-hypervisor legs.
Fix: the sentence belongs in the mappings-not-configured constant in crate::state (state.rs:304-310) that src/ops/start_virtual_machines_metadata_sync.rs:211-219 quotes; the handler's own module doc (lines 25-30) asserts the current wording is what the recorded unit pins, which this check disproves.
Not covering: open issue 20261029T192930Z-backup-gateway-hypervisor-sync-precondition-missing-and-system.md owns the separate defect that the gate is not applied at all to a hypervisor the store DOES hold (it answers 200) and its wire keys; this cause is the WORDING of the refusal that is emitted, which that issue does not carry a behavioral key for. Both must agree on the same sentence.
Traces: backup-gateway.start-metadata-sync-state-transition.
