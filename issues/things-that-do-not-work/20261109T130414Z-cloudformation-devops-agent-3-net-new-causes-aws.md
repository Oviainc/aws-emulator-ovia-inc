# cloudformation__devops-agent: 3 net-new causes — AWS::DevOpsAgent::AgentSpace, ::Association and ::PrivateConnection are not registered resource types, so CreateStack refuses every DevOps Agent template as "Unrecognized resource types"

> _Note: this issue was identified against the code base at commit `eaa123f65a60b02b9ee1461dec055a780335fce9`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateStack

## Description
The emulator's CloudFormation resource-type registry contains no AWS::DevOpsAgent::* type. Every template that declares one is refused at CreateStack, so no DevOps Agent resource can be provisioned, read back, updated or deleted through a stack, and none of the DevOps Agent deploy behavior behind those types is reachable at all. Three distinct resource types are missing; each needs registering AND provisioning against DevOps Agent's own state, so each is its own cause.

Cause 1 of 3: AWS::DevOpsAgent::AgentSpace is not a registered resource type.
AWS: CloudFormation accepts a template whose only resource is of type AWS::DevOpsAgent::AgentSpace with properties Name, Description, Locale and Tags; CreateStack returns a StackId and the stack reaches CREATE_COMPLETE. The resource is provisioned through DevOps Agent (Smithy com.amazonaws.devopsagent#DevOpsAgent, sdkId "DevOps Agent", restJson1: CreateAgentSpace POST /v1/agentspaces -> 201), so the created space is visible to an independent ListAgentSpaces (POST /v1/agentspaces/list) and GetAgentSpace (GET /v1/agentspaces/{agentSpaceId}) with the template's name/description/locale. Ref on the logical id yields the agentSpaceId; Fn::GetAtt <Logical>.Arn yields the space ARN, and ListTagsForResource (GET /tags/{resourceArn}) on it returns the template's own tags, the stack-level Tags propagated to the taggable resource, and the aws:cloudformation:* system tags (aws:cloudformation:stack-id equal to the StackId). Deleting the stack deletes the space, after which GetAgentSpace refuses with ResourceNotFoundException. Recorded behavior only for the exact wording of the stack-level refusal.
Emulator: CreateStack is refused, HTTP 400, error code "ValidationError", message "Template format error: Unrecognized resource types: [AWS::DevOpsAgent::AgentSpace]". Fixed text of that message is "Template format error: Unrecognized resource types: [" ... "]"; the bracketed list is the set of types taken from the submitted template, so the value shown is from the request, not part of the requirement. The whole check dies on the first call.
Why: a client (or CDK/SAM app) that deploys an agent space by template gets a hard ValidationError instead of a stack, so the entire provisioning path, the Ref/GetAtt contract and the tag propagation it relies on are unavailable; nothing distinguishes this from a genuinely malformed template.
Fix: CloudFormation's template validation / resource-type registry in the cloudformation service crate must register the type, and a provisioning handler for it must create, read, update, tag and delete the space through DevOps Agent's AgentSpace state (CreateAgentSpace / UpdateAgentSpace / DeleteAgentSpace), exposing Ref = agentSpaceId and the Arn attribute.
Traces: cloudformation__devops-agent.deploy-devopsagent-agent-space-round-trip-and-delete.

Cause 2 of 3: AWS::DevOpsAgent::Association is not a registered resource type (and with it the STS-role validation that must roll the stack back).
AWS: a template declaring an AWS::DevOpsAgent::AgentSpace, an AWS::IAM::Role and an AWS::DevOpsAgent::Association (properties AgentSpaceId, ServiceId, Configuration.Aws.{AccountId,AccountType,AssumableRoleArn}) is accepted by CreateStack with Capabilities=[CAPABILITY_NAMED_IAM]. The association is provisioned through DevOps Agent (Smithy AssociateService POST /v1/agentspaces/{agentSpaceId}/associations -> 201, ValidateAwsAssociations POST /v1/agentspaces/{agentSpaceId}/associations/validate -> 204); Fn::GetAtt <Logical>.AssociationId yields the associationId and ListAssociations (POST /v1/agentspaces/{agentSpaceId}/associations/list) reports it with serviceId "aws" and status "valid". When the assumable role's trust policy restricts aws:SourceAccount to another account, DevOps Agent's role validation refuses, the resource goes CREATE_FAILED with a ResourceStatusReason of the form "Error occurred during operation 'AWS::DevOpsAgent::Association: Invalid STS role configuration for session <sessionName>. Verify the role's trust policy. (Service: DevOpsAgent, Status Code: 400, Request ID: <id>) (SDK Attempt Count: <n>)'." (fixed text as quoted; <sessionName>, <id> and <n> are per-call values) carrying error code GeneralServiceException, and the stack ends ROLLBACK_COMPLETE with the already-created space removed — after rollback ListAgentSpaces no longer lists it and GetAgentSpace refuses ResourceNotFoundException.
Emulator: CreateStack is refused outright, HTTP 400, "ValidationError": "Template format error: Unrecognized resource types: [AWS::DevOpsAgent::AgentSpace, AWS::DevOpsAgent::Association]". No stack, no CREATE_FAILED event, no rollback and no refusal classification exist.
Why: the whole negative class is unobservable — a client cannot tell a role whose trust policy is wrong from a template that CloudFormation cannot parse, and the rollback contract (a failed association must leave no agent space behind) is never exercised.
Fix: register the type in CloudFormation's resource-type registry and implement its provisioning handler over DevOps Agent's association state, including the role-trust validation that produces the GeneralServiceException resource failure reason and therefore drives the stack's rollback path.
Traces: cloudformation__devops-agent.deploy-devopsagent-association-untrusted-role-rejected-and-rolled-back.

Cause 3 of 3: AWS::DevOpsAgent::PrivateConnection is not a registered resource type.
AWS: a template declaring AWS::EC2::VPC / Subnet / SecurityGroup plus an AWS::DevOpsAgent::PrivateConnection (properties Name, ConnectionConfiguration.ServiceManaged.{HostAddress,VpcId,SubnetIds,SecurityGroupIds,PortRanges}, Tags) is accepted and reaches CREATE_COMPLETE. The connection is provisioned through DevOps Agent (Smithy CreatePrivateConnection POST /v1/private-connections, ListPrivateConnections GET /v1/private-connections, DescribePrivateConnection GET /v1/private-connections/{name}, DeletePrivateConnection DELETE /v1/private-connections/{name}) and reads back with type SERVICE_MANAGED, the template's hostAddress and vpcId, and status ACTIVE. Ref on the logical id is the connection Name and Fn::GetAtt <Logical>.Arn is its ARN, on which ListTagsForResource returns the template's and the stack's tags. Deleting the stack deletes the connection, after which DescribePrivateConnection refuses ResourceNotFoundException.
Emulator: CreateStack is refused, HTTP 400, "ValidationError": "Template format error: Unrecognized resource types: [AWS::DevOpsAgent::PrivateConnection]".
Why: no private connection can be created, read back or deleted by template, so the service-managed connectivity path and its ACTIVE-status lifecycle are entirely unavailable to template-driven clients.
Fix: register the type in CloudFormation's resource-type registry and implement its provisioning handler over DevOps Agent's private-connection state (create -> ACTIVE, Ref = name, Arn attribute, tag propagation, stack delete -> DeletePrivateConnection).
Traces: cloudformation__devops-agent.deploy-devopsagent-private-connection-round-trip-and-delete.

Related but not the same cause: many open issues report the same missing-registration defect for other services' types (e.g. 20261109T113214Z-cloudformation-mediatailor-createstack-refuses-every-aws-mediatailor-resource.md, 20261109T113556Z-cloudformation-omics-createstack-refuses-every-aws-omics-resource.md). None of them covers the AWS::DevOpsAgent::* types.

Note on attribution: the suite lists these three checks under the heading `cloudformation__devops-agent`; the failing call is CloudFormation's CreateStack, and the resources to be provisioned belong to DevOps Agent.

## Steps to Reproduce
1. Boot the emulator and point botocore at it.
2. Agent space: cloudformation.create_stack(StackName=<unique>, TemplateBody=json of {"AWSTemplateFormatVersion":"2010-09-09","Resources":{"Space":{"Type":"AWS::DevOpsAgent::AgentSpace","Properties":{"Name":<unique>,"Description":"...","Locale":"en-US","Tags":[{"Key":"k","Value":"v"}]}}},"Outputs":{"AgentSpaceId":{"Value":{"Ref":"Space"}},"Arn":{"Value":{"Fn::GetAtt":"Space.Arn"}}}}, Tags=[{"Key":"sim2real","Value":<unique>}]) -> observe ValidationError "Template format error: Unrecognized resource types: [AWS::DevOpsAgent::AgentSpace]" instead of a StackId.
3. Association: create_stack with Resources = {Space: AWS::DevOpsAgent::AgentSpace, AssocRole: AWS::IAM::Role whose trust policy Condition is StringEquals aws:SourceAccount = 111122223333 and principal Service aidevops.amazonaws.com, Association: AWS::DevOpsAgent::Association with Properties {AgentSpaceId: {Ref: Space}, ServiceId: "aws", Configuration: {Aws: {AccountId: {Ref: AWS::AccountId}, AccountType: "monitor", AssumableRoleArn: {Fn::GetAtt: AssocRole.Arn}}}}} and Capabilities=["CAPABILITY_NAMED_IAM"] -> observe the same ValidationError naming [AWS::DevOpsAgent::AgentSpace, AWS::DevOpsAgent::Association]; no stack is created, so the expected ROLLBACK_COMPLETE + GeneralServiceException resource reason can never be observed.
