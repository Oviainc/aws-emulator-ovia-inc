# The /configurationManager/{ManagerArn} routes turn a deleted manager into 401 UnauthorizedException, so GetConfigurationManager never answers the modeled 404 ResourceNotFoundException

> _Note: this issue was identified against the code base at commit `15e353e8d16cdf1cbcccb99e604638b300a4e7ca`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
GetConfigurationManager

## Description
REOPENS 20261022T034519Z-ssm-quicksetup-error-paths-wrong-rejection-class-unvalidated.md: its fix left the call refused.

1 cause; it must be closed before this issue is submitted. Related open issues 20261101T001539Z-ssm-quicksetup-tag-plane-routes-refuse-an-arn-naming-no.md and 20261102T090000Z-ssm-quicksetup-tag-plane-routes-answer-an-arn-naming-no.md describe the SAME front-door stage on the /tags/{ResourceArn} route family only; neither covers the /configurationManager/{ManagerArn} family this issue is about, and the replay marks none of the nine checks below as owned by them (ssm-quicksetup.tag-resource-list-tags-roundtrip no longer even reaches its tag assertion: it now dies earlier, on GetConfigurationManager). Open issue 20261102T032525Z-ssm-quicksetup-routes-enforce-no-identity-policy-authorization.md is about a MISSING identity-policy check and is the opposite direction; it is not this.

Cause 1 of 1: the request-authorization stage that fronts the ARN-labelled routes decides entitlement purely by store presence, so an ARN in the caller's OWN account and the request's Region whose manager was deleted is refused as unauthorized instead of reaching the handler's modeled not-found branch.
AWS: GetConfigurationManager (GET /configurationManager/{ManagerArn}) binds ResourceNotFoundException, errorKind client, httpError 404 (Smithy: services/service-com-amazonaws-ssmquicksetup-quicksetup/smithy-model/com-amazonaws-ssmquicksetup-quicksetup.json; the operation binds AccessDeniedException 403, ConflictException 409, InternalServerException 500, ResourceNotFoundException 404, ThrottlingException 429, ValidationException 400 — no 401 and no UnauthorizedException shape exists anywhere in this service's model). Recorded behavior for this path: a caller that created a configuration manager, deleted it, and then reads the SAME ManagerArn is answered HTTP 404 with Error.Code ResourceNotFoundException and Error.Message built from the fixed template "Quick setup manager with arn: " + <the ManagerArn from the request path> + " could not be found." — the only variable part is the ARN taken from the httpLabel member ManagerArn; the rest is fixed text (the per-run account id, Region and manager uuid inside that ARN are fillers, not requirements). Hypothesis for the discriminator against the wire corpus, which records 401 Unauthorized for a manager ARN the caller is not entitled to: AWS's front door judges the ARN's own account/Region against the caller and the endpoint, not whether a manager is currently stored — an ARN of the caller's account and the endpoint's Region reaches the service and earns the modeled 404 even after the manager is gone. DeleteConfigurationManager and UpdateConfigurationManager (same URI) likewise answer the modeled 404 ResourceNotFoundException for the caller's own deleted manager, which is what makes a delete idempotent.
Emulator: the request never reaches the handler. services/service-com-amazonaws-ssmquicksetup-quicksetup/src/service.rs enrolls GetConfigurationManager, UpdateConfigurationManager, DeleteConfigurationManager (and UpdateConfigurationDefinition, plus the three tag-plane operations) in target_authorization_table, and TargetAuthorization::serves is nothing but a store lookup — store.settle(now) then store.manager_in(&region, arn).is_some(). A deleted manager is absent from the store, so the stage answers HTTP 401 with wire error code UnauthorizedException (x-amzn-errortype and __type) and body {"message": "Unauthorized"} (lowercase member, unlike this service's modeled Message). Replay: every one of the nine checks below dies on botocore ClientError "An error occurred (UnauthorizedException) when calling the GetConfigurationManager operation: Unauthorized" at the point where it reads, or waits for the disappearance of, a manager it itself deleted.
Why: the whole delete-then-verify and cleanup contract is broken. A client cannot distinguish "the resource is gone" from "your credentials are not entitled to it": SDK callers branch on ResourceNotFoundException to treat a delete as already done, to finish a teardown loop, and to decide a poll has converged, while 401 drives credential-refresh paths and is not in the operation's generated error union, so it surfaces as an unmatched generic ClientError. Idempotent cleanup therefore raises instead of completing, every lifecycle flow that deletes a manager and confirms it hangs or aborts, and no client can ever observe AWS's not-found sentence for this operation.
Fix: the request-authorization stage in the ssm-quicksetup service crate (services/service-com-amazonaws-ssmquicksetup-quicksetup/src/service.rs: TargetAuthorization::serves / refusal, target_authorization_table, the unauthorized() renderer and the module doc that states the rule). Its predicate must be the ARN's entitlement (the ARN's account and Region against the caller and the endpoint being served), not the presence of a row in the store; an ARN the caller owns in this Region must be passed through to the handler, which already has the modeled ResourceNotFoundException branch and the correct not-found sentence. Fixing the predicate here also unblocks the tag-plane causes already filed, which are observed through the same stage.
Traces: ssm-quicksetup.configuration-manager-create-get-delete-lifecycle, ssm-quicksetup.get-configuration-manager-not-found, ssm-quicksetup.create-configuration-manager-invalid-name-pattern-rejected, ssm-quicksetup.list-configuration-managers-pagination-max-items, ssm-quicksetup.tag-resource-list-tags-roundtrip, ssm-quicksetup.untag-resource-empty-tag-keys-rejected, ssm-quicksetup.untag-resource-removes-tag, ssm-quicksetup.update-configuration-definition-invalid-type-version-rejected, ssm-quicksetup.update-configuration-definition-triggers-redeployment.
