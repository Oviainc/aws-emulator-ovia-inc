# resiliencehub StartAppAssessment omits resiliencyScore.componentScore, so a finished assessment carries no scoring-component breakdown

> _Note: this issue was identified against the code base at commit `01ad7cf4d75cdcadee33f1733defefde67ff031f`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
StartAppAssessment

## Description
One root cause.

Cause 1 of 1: a successful app assessment reports a `resiliencyScore` with no `componentScore` member at all, so the per-scoring-component breakdown of the score is missing from every assessment this emulator produces (both from `StartAppAssessment` and from the `DescribeAppAssessment` read of the same record). Failing check ids: `resiliencehub.assessment-grades-app-against-policy-targets`.

AWS: Smithy `com.amazonaws.resiliencehub#ResiliencyScore` has three members — `score` (Double, required), `disruptionScore` (`DisruptionResiliencyScore` map, required) and `componentScore` (`ScoringComponentResiliencyScores`), documented as "The score generated by Resilience Hub for the scoring component after running an assessment." `ScoringComponentResiliencyScores` is a map keyed by `ResiliencyScoreType` (values: `Compliance`, `Test`, `Alarm`, `Sop`) to `ScoringComponentResiliencyScore{score, possibleScore, outstandingCount, excludedCount}`, where `score` is documented as "always less than or equal to the possibleScore" and `possibleScore` as the "Maximum possible score that can be obtained for the scoring component". `AppAssessment.resiliencyScore` is the "Current resiliency score for an application". Recorded behavior: for an assessment that reached `assessmentStatus` `Success`, AWS populates `componentScore` — the recording's invariants are that `possibleScore` summed over the component entries equals 1.0 (the components partition the whole of the possible score), and that `score` summed over the component entries equals the enclosing `resiliencyScore.score` (the components partition the score actually earned). The score itself is the per-disruption mean of `disruptionScore`, which this emulator already satisfies.

Emulator: the handler builds `ResiliencyScore { score, disruption_score, component_score: None }` unconditionally, with a doc comment stating componentScore "is left out" because the service records no tests, alarms or procedures to score. The serialized assessment therefore has no `componentScore` key, and a client that reads it fails: `components = score["componentScore"]` raises `KeyError: 'componentScore'`. Nothing else about the score diverged — the `score`/`disruptionScore` mean relationship and the compliance rollup both matched.

Why: a client that grades an application reads the breakdown to attribute the score to the scoring components — which part of the shortfall is compliance versus missing tests, alarms or SOPs, and how many recommendations are outstanding or excluded per component. Against this emulator that read raises a KeyError (or yields None in a typed SDK) on a `Success` assessment, so any code that renders or reduces the breakdown cannot run at all, and code that recomputes the total from the components silently sees 0. Having no tests/alarms/SOPs recorded is not an absent breakdown in AWS — it is a breakdown whose non-compliance components have earned 0 of their possible score, which is exactly the information the client wants.

Fix: the score computation in the `StartAppAssessment` handler — the `resiliency_score` helper that builds `ResiliencyScore` — must populate `component_score` with one `ScoringComponentResiliencyScore` entry per `ResiliencyScoreType` the assessment grades, with `possibleScore` values that sum to 1.0 and `score` values that sum to the assessment's `score`, and `outstandingCount`/`excludedCount` derived from the assessed version's state. Because the frozen assessment record is what `DescribeAppAssessment` replays, the same record must carry it on the read path, not just on the start response.

Traces: `resiliencehub.assessment-grades-app-against-policy-targets` — publishes a one-bucket app with a tight `CoreServices` policy, assesses the `release` alias, and fails at `score["componentScore"]` after every compliance and mean-score assertion passed. Code: `services/service-com-amazonaws-resiliencehub-awsresiliencehub/src/ops/start_app_assessment.rs` lines 425-458 (`resiliency_score`, `component_score: None` at line 456) and line 258 where it is attached to the assessment.

Note: the open issue `20261030T040357Z-resiliencehub-startappassessment-stub.md` lists this check id, but it covers `StartAppAssessment` being an unimplemented 501 scaffold; the operation is now implemented and answers 200, and this check now fails past it on the missing `componentScore`, which that issue does not describe.

## Steps to Reproduce
1. Boot the resiliencehub emulator.
2. CreateResiliencyPolicy with tier `CoreServices` and an objective for each of AZ, Hardware, Software, Region.
3. CreateApp naming that policyArn; CreateAppVersionAppComponent for a storage component and CreateAppVersionResource mapping one S3 bucket into it; ResolveAppVersionResources on `draft` and poll DescribeAppVersionResourcesResolutionStatus to `Success`; PublishAppVersion with versionName `v1`.
4. StartAppAssessment with appVersion `release`, then poll DescribeAppAssessment until assessmentStatus is `Success`.
5. Read `assessment.resiliencyScore` and observe it has `score` and `disruptionScore` but no `componentScore` key; AWS returns a `componentScore` map whose entries' `possibleScore` sum to 1.0 and whose `score` sum equals `resiliencyScore.score`.
