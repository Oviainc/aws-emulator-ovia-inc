# ListAWSDefaultServiceQuotas default catalog misbinds and omits AWS quota data for apigateway appconfig and eight more service codes

> _Note: this issue was identified against the code base at commit `a28b00726e6917844828701198c7c2f9a84a8d63`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
ListAWSDefaultServiceQuotas

## Description
This bundle carries TEN net-new causes, one per ServiceCode whose default-quota catalog diverges. All ten are the same class of defect in one component — the static default-quota table that ListAWSDefaultServiceQuotas serves — but each ServiceCode's catalog is separate data and each must be corrected and re-replayed before this issue is closed. Status and wire framing are correct everywhere (200 -> 200); the payload is wrong.

Shared model grounding (Smithy, com.amazonaws.servicequotas): ListAWSDefaultServiceQuotas takes a required ServiceCode and returns Quotas: ServiceQuotaListDefinition of ServiceQuota. ServiceQuota members include ServiceCode, ServiceName, QuotaArn, QuotaCode, QuotaName, Value (QuotaValue double), Unit, Adjustable (boolean, default false), GlobalQuota, UsageMetric (MetricInfo: MetricNamespace, MetricName, MetricDimensions, MetricStatisticRecommendation), Period (QuotaPeriod: PeriodValue, PeriodUnit) and Description (QuotaDescription, @length 0..350). The model does not enumerate the per-service default values, so the authority for the VALUES is the recorded AWS response for that ServiceCode: for a given ServiceCode, AWS returns one ServiceQuota per quota AWS defines, and within an entry QuotaCode is the stable identity to which QuotaName, Value, Unit, Adjustable, Description, Period and UsageMetric belong. Recorded behavior only for the data itself.

Cause 1 of 10: ServiceCode apigateway.
AWS: every returned ServiceQuota carries Description, and each QuotaCode carries its own QuotaName/Value/Adjustable (e.g. L-7D4D47CD is the PortalProducts-per-account quota with Value 500 and Adjustable false; L-B4D69DB7 is the per-portal custom-domain-name quota with Value 1; L-1D180A63 is the API-keys quota; L-F8A34CAF and L-95BA6EA5 are non-adjustable).
Emulator: Description is absent on every entry; Adjustable is reported true where AWS reports false (L-F8A34CAF, L-95BA6EA5, L-7D4D47CD, L-B4D69DB7, L-1D180A63); and several QuotaCodes are bound to a DIFFERENT quota's name and value — L-7D4D47CD comes back as 'Documentation parts per API' with Value 2000, L-B4D69DB7 as 'Private custom domain names per account per Region' with Value 120, L-1D180A63 as 'HTTP APIs per account per Region'.
Why: a client that looks a limit up by QuotaCode (the documented way, since QuotaCode is the stable identity) reads the wrong limit for the wrong resource, and sees adjustable quotas it cannot actually request increases for; Description is simply unavailable.
Fix: the default-quota catalog data for ServiceCode apigateway in the service-quotas crate (the seed table ListAWSDefaultServiceQuotas reads), not the handler's pagination or serializer, which frame the list correctly.
Traces: service-quotas-catalog-list-aws-default-service-quotas-apigateway#task#1.

Cause 2 of 10: ServiceCode appconfig.
AWS: each quota carries its Description, and rate/resource quotas additionally carry Period and UsageMetric (e.g. L-F59D302B 'Maximum number of deployment strategies' with Period PeriodUnit HOUR / PeriodValue 1 and a UsageMetric naming the DeploymentStrategy resource; L-B858C085 experiment definitions with Value 50).
Emulator: Description is absent on every entry; L-B858C085 Value is 10 instead of 50; L-F59D302B is named '...per Region' instead of the AWS name and omits Period and UsageMetric entirely, as do L-EEB0151E and L-FA210A1F; L-A52E46BE diverges in Period.PeriodUnit, Value and its UsageMetric dimensions (Resource/Service/Type), MetricName and MetricStatisticRecommendation.
Why: usage-vs-quota tooling keys off UsageMetric/Period to build the matching CloudWatch query, so an omitted or mis-dimensioned UsageMetric makes utilization uncomputable, and the wrong Value under-reports the real limit.
Fix: the default-quota catalog data for ServiceCode appconfig, including the Period/UsageMetric fields of its rate and resource quotas.
Traces: service-quotas-catalog-list-aws-default-service-quotas-appconfig#task#1.
