# cloudformation__pinpoint-sms-voice-v2: no AWS::SMSVOICE::* resource type is registered — CreateStack refuses every End User Messaging SMS/Voice template as "Unrecognized resource types"

> _Note: this issue was identified against the code base at commit `6c5e636bebc82ccd4609eb5d54ba0275e4ea7ff4`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateStack

## Description
Cause 1 of 1: CloudFormation's resource-type registry knows none of the AWS::SMSVOICE::* resource types, so CreateStack rejects the template at validation time and no End User Messaging SMS and Voice (pinpoint-sms-voice-v2) resource can ever be deployed, updated, rolled back or deleted through CloudFormation.

AWS: CloudFormation accepts the AWS::SMSVOICE::* resource types and provisions them through the End User Messaging SMS and Voice control plane. The three recordings exercise seven of them — AWS::SMSVOICE::ConfigurationSet, ::OptOutList, ::ProtectConfiguration, ::ResourcePolicy, ::RcsAgent, ::Registration and ::RegistrationAttachment. In the recordings CreateStack returns 200 with a StackId and the stacks then reach CREATE_COMPLETE (or ROLLBACK_COMPLETE when a declared property is refused by the service), each resource is readable back through the pinpoint-sms-voice-v2 API (DescribeConfigurationSets / DescribeOptOutLists / DescribeProtectConfigurations / GetResourcePolicy), Ref and Fn::GetAtt Arn resolve to the real identifiers the service minted, Tags (including the stack's propagated tags) are carried onto each resource, an UpdateStack that drops the AWS::SMSVOICE::ResourcePolicy detaches the policy (GetResourcePolicy then reads back the empty document "{}"), and DeleteStack removes each resource so the service answers ResourceNotFoundException for it afterwards. For the rejection recording, a ConfigurationSet naming a ProtectConfigurationId that was never minted makes the stack roll back and the Config resource's CREATE_FAILED ResourceStatusReason is a registry-handler reason of the form: Resource handler returned message: "Resource Not Found - ResourceType=\"protect-configuration\" ResourceId=\"<the ProtectConfigurationId from the template>\" (Service: PinpointSmsVoiceV2, Status Code: 400, Request ID: <id>) (SDK Attempt Count: <n>)" (RequestToken: <token>, HandlerErrorCode: NotFound) — the fixed text is everything but the bracketed values, which come from the request (the id) and the run (request id, token, attempt count). Smithy (com-amazonaws-pinpointsmsvoicev2): ResourceNotFoundException with members ResourceType/ResourceId backs that handler message; the CloudFormation resource schemas themselves are not in this repo's Smithy model, so for the template surface this is recorded behavior only.

Emulator: CreateStack is refused outright with HTTP 400 ValidationError and the message "Template format error: Unrecognized resource types: [<the template's AWS::SMSVOICE::* types>]" — observed as "[AWS::SMSVOICE::ProtectConfiguration, AWS::SMSVOICE::ConfigurationSet]", "[AWS::SMSVOICE::ProtectConfiguration, AWS::SMSVOICE::OptOutList, AWS::SMSVOICE::ConfigurationSet, AWS::SMSVOICE::ResourcePolicy]" and "[AWS::SMSVOICE::RcsAgent, AWS::SMSVOICE::Registration, AWS::SMSVOICE::RegistrationAttachment]" for the three checks. The stack is never created, so nothing downstream (stack events, Outputs, the service-side read-back, the update that detaches the policy, the delete) is reachable.

Why: a client that provisions End User Messaging SMS and Voice through CloudFormation or CDK cannot deploy at all against the emulator — the template is rejected before any resource is attempted, which looks to the client like a malformed template rather than a missing emulator capability. Rejection paths are equally lost: a template naming a nonexistent protect configuration cannot be shown to roll back with the service's refusal, so negative tests silently cannot run.

Fix: CloudFormation's template-validation resource-type registry (the table that decides "Unrecognized resource types") must carry the AWS::SMSVOICE::* types, and each needs a resource handler that creates/reads/updates/deletes through pinpoint-sms-voice-v2 state, resolves Ref and Fn::GetAtt Arn from the created resource, propagates stack tags, and surfaces the service's own error as a registry-handler ResourceStatusReason with HandlerErrorCode NotFound for a not-found reference.

## Evidence
Expected (recorded AWS): CreateStack on each template returns 200 with a StackId; the core-resources stack reaches CREATE_COMPLETE, its Outputs' Ref/Fn::GetAtt Arn values match what DescribeConfigurationSets / DescribeOptOutLists / DescribeProtectConfigurations list, GetResourcePolicy returns the attached document and "{}" after the policy is dropped by UpdateStack, and after DeleteStack each read answers ResourceNotFoundException with 'Resource Not Found - ResourceType="<kind>" ResourceId="<id>"'. The rejection stack reaches ROLLBACK_COMPLETE with the Config resource CREATE_FAILED reason 'Resource handler returned message: "Resource Not Found - ResourceType="protect-configuration" ResourceId="<id>" (Service: PinpointSmsVoiceV2, Status Code: 400, Request ID: <id>) (SDK Attempt Count: <n>)" (RequestToken: <token>, HandlerErrorCode: NotFound)'.

Actual (emulator): botocore.exceptions.ClientError: An error occurred (ValidationError) when calling the CreateStack operation: Template format error: Unrecognized resource types: [AWS::SMSVOICE::ProtectConfiguration, AWS::SMSVOICE::OptOutList, AWS::SMSVOICE::ConfigurationSet, AWS::SMSVOICE::ResourcePolicy] — and likewise [AWS::SMSVOICE::ProtectConfiguration, AWS::SMSVOICE::ConfigurationSet] and [AWS::SMSVOICE::RcsAgent, AWS::SMSVOICE::Registration, AWS::SMSVOICE::RegistrationAttachment] for the other two checks. HTTP 400, no stack created.

## Steps to Reproduce
1. Boot the emulator and point botocore at it.
2. cloudformation.create_stack(StackName=<unique>, TemplateBody=json.dumps({"AWSTemplateFormatVersion":"2010-09-09","Resources":{"Protect":{"Type":"AWS::SMSVOICE::ProtectConfiguration","Properties":{"DeletionProtectionEnabled":False}},"Config":{"Type":"AWS::SMSVOICE::ConfigurationSet","Properties":{"ConfigurationSetName":"<name>","ProtectConfigurationId":{"Ref":"Protect"}}}},"Outputs":{"ConfigRef":{"Value":{"Ref":"Config"}},"ProtectId":{"Value":{"Ref":"Protect"}}}}), Tags=[{"Key":"sim2real","Value":"<name>"}])
3. Observe ValidationError 'Template format error: Unrecognized resource types: [...]' instead of a StackId.
4. Repeat with AWS::SMSVOICE::OptOutList + ::ResourcePolicy, and with AWS::SMSVOICE::RcsAgent + ::Registration + ::RegistrationAttachment, for the other two namespaces the suite deploys.
