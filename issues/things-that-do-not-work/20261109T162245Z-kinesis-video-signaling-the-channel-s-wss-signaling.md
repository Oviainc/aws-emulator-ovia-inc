# kinesis-video-signaling: the channel's WSS signaling data plane is not served (WebSocket upgrade answered HTTP 404), so no MASTER peer can ever attach and SendAlexaOfferToMaster refuses with 404 ResourceNotFoundException where AWS returns an answer-less HTTP 200

## Description

=== Cause 1 of 1: the WSS endpoint advertised by GetSignalingChannelEndpoint rejects the WebSocket upgrade with HTTP 404, and the Alexa REST path turns 'no master connected' into a hard not-found ===
AWS: recorded behavior only for the WSS data plane (it is not in the Smithy model: the model describes only the two restJson1 operations). Smithy: SendAlexaOfferToMaster is POST /v1/send-alexa-offer-to-master, code 200; required ChannelARN (ResourceARN, @length 1..1024, @pattern ^arn:aws:kinesisvideo:[a-z0-9-]+:[0-9]+:[a-z]+/[a-zA-Z0-9_.-]+/[0-9]+$), required SenderClientId (ClientId, @length 1..256, @pattern ^[a-zA-Z0-9_.-]+$), required MessagePayload (@length 1..10000, @pattern ^[a-zA-Z0-9+/=]+$); output has a single OPTIONAL member Answer (@length 1..10000); modeled errors ClientLimitExceededException(400), InvalidArgumentException(400), NotAuthorizedException(401), ResourceNotFoundException(404). The recording shows the channel's real signaling data plane is a SigV4(query)-presigned secure WebSocket: the WSS URL that kinesisvideo GetSignalingChannelEndpoint returns for Protocols=[WSS] with Role=MASTER accepts the upgrade (HTTP 101) when the presigned URL carries the channel ARN, registers that connection as the channel's master peer, and brokers JSON signaling frames. With that master peer connected, SendAlexaOfferToMaster delivers the offer to it as {"messageType":"SDP_OFFER","senderClientId":<the request's SenderClientId>,"messagePayload":<the request's MessagePayload, byte-identical>} and returns HTTP 200 carrying the master's {"action":"SDP_ANSWER"} payload in Answer. With NO master connected, the identical call is still ACCEPTED: it blocks for the channel's redelivery window (bounded by SingleMasterConfiguration.MessageTtlSeconds) and then returns HTTP 200 with the Answer member ABSENT. The negative lives inside the 200; ResourceNotFoundException is reserved for a ChannelARN naming a channel that does not exist. Reconnecting a master makes the identical call answer again, so delivery is connectivity-gated, not channel- or account-gated.
Emulator: the WebSocket upgrade to the advertised WSS endpoint is rejected outright — websockets.exceptions.InvalidStatus: server rejected WebSocket connection: HTTP 404 — for the MASTER role, so no peer can ever register and no signaling frame is ever exchanged. Because the only writer of the crate's SignalingChannel.master_answer is that never-reachable path, SendAlexaOfferToMaster always takes its no-master branch and REFUSES with HTTP 404 ResourceNotFoundException whose message is "No master is connected to signaling channel <ChannelARN>, so the offer from <SenderClientId> cannot be delivered" (fixed text invented by the emulator; variable parts are the request's ChannelARN and SenderClientId) where AWS answers HTTP 200 with no Answer member. The check never reaches its phase-2/phase-3 assertions because phase 1's WSS connect already fails.
Why: WebRTC peering is the whole purpose of a signaling channel. A client can create a channel, see it ACTIVE and read its endpoints, but can never connect, offer, answer or exchange ICE candidates, so no session is ever established. And on the REST path a caller is told its channel does not exist (a 404 that sends it down a recreate-the-resource path) instead of AWS's "accepted, nobody was listening" — a 200 whose missing Answer means 'retry / wait for a master'.
Fix: the signaling data plane's WSS transport and SendAlexaOfferToMaster's delivery path. A WebSocket upgrade route must be served on exactly the host/path kinesisvideo GetSignalingChannelEndpoint advertises for Protocols=[WSS] (both Role=MASTER and Role=VIEWER), authenticating the presigned SigV4 query, resolving X-Amz-ChannelARN (plus X-Amz-ClientId for a viewer) against the channel store, registering the peer in its role and routing SDP_OFFER / SDP_ANSWER / ICE_CANDIDATE frames between the registered peers. The handler's no-master branch must then stop refusing: wait on the live master for the channel's MessageTtlSeconds window and return a 200 with Answer omitted when none answers, reserving ResourceNotFoundException for a channel that does not exist.

## Steps to Reproduce
1. Boot the emulator. Create a channel on the control plane: kinesisvideo CreateSignalingChannel(ChannelName=<name>, ChannelType=SINGLE_MASTER, SingleMasterConfiguration={MessageTtlSeconds: 5}); poll DescribeSignalingChannel(ChannelName=<name>) until ChannelInfo.ChannelStatus == ACTIVE.
2. Resolve both data-plane endpoints: kinesisvideo GetSignalingChannelEndpoint(ChannelARN=<arn>, SingleMasterChannelEndpointConfiguration={Protocols:[WSS], Role:MASTER}) and the same with Protocols=[HTTPS].
3. Presign the WSS URL with SigV4 query auth plus X-Amz-ChannelARN=<arn> and open a WebSocket to it -> the emulator rejects the upgrade with HTTP 404 (websockets InvalidStatus); AWS accepts it with HTTP 101.
4. With that master session open (it cannot be, which is the defect), call kinesis-video-signaling SendAlexaOfferToMaster(ChannelARN=<arn>, SenderClientId=<id matching ^[a-zA-Z0-9_.-]+$>, MessagePayload=<base64 SDP offer>) against the HTTPS endpoint -> AWS delivers {messageType:SDP_OFFER, senderClientId:<id>, messagePayload:<payload>} to the master and returns 200 with Answer = the master's base64 answer.
5. With no master connected, issue the identical SendAlexaOfferToMaster -> the emulator returns HTTP 404 ResourceNotFoundException "No master is connected to signaling channel <arn>, so the offer from <id> cannot be delivered"; AWS returns HTTP 200 with the Answer member absent after blocking up to MessageTtlSeconds.
6. Reconnect a master over WSS and repeat the identical call -> AWS returns 200 with the new Answer, proving the earlier empty result was connectivity-gated rather than a channel fault.
