# A/B-test data plane and CFN-deployed runtime invocation are unserved: both multi-step lifecycles stall instead of answering (2 causes)

> _Note: this issue was identified against the code base at commit `baf30d4927ba43bb30691a1e04213021d426cca6`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateABTest

## Description
Two bedrock-agentcore behavioral checks fail with no attributable response at all: each one drives a multi-step lifecycle whose load-bearing call the emulator refuses, and because each check wraps that call in a bounded retry/poll loop (the loop exists because real AWS is eventually consistent here), the refusal is swallowed and the check consumes its whole wall-clock budget — the suite reports `Check timed out after 60.0s` for both. 2 causes must all be fixed before this issue is closed. Neither cause is marked ALREADY FILED or OWNED in the replay report; related open issues are named per cause below and none of them carries these two check ids.

Cause 1 of 2: the whole A/B-test data-plane resource family is an unimplemented scaffold, so no A/B test can be created, read, updated or deleted.
AWS: Smithy (bedrock-agentcore) models the complete family — CreateABTest POST /ab-tests -> 202 with required abTestId (^[a-zA-Z][a-zA-Z0-9-_]{0,99}-[a-zA-Z0-9]{10}$), abTestArn, status (ABTestStatus) and executionStatus (ABTestExecutionStatus); GetABTest GET /ab-tests/{abTestId} -> 200 with abTestId/abTestArn/name/status/executionStatus/gatewayArn/variants/evaluationConfig/createdAt/updatedAt and optional description; UpdateABTest PUT /ab-tests/{abTestId} -> 202; DeleteABTest DELETE /ab-tests/{abTestId} -> 202. Modeled errors include ValidationException (400), ConflictException (409) and ResourceNotFoundException (404). Recorded behavior for the lifecycle: a create with enableOnCreate=false reports executionStatus NOT_STARTED and converges to status ACTIVE; UpdateABTest's description mutation reads back through GetABTest; after DeleteABTest, GetABTest is refused 404 ResourceNotFoundException whose message is the fixed text `AB test not found: abTestId=` followed by the abTestId from the request.
Emulator: CreateABTest, GetABTest, UpdateABTest and DeleteABTest are all unmodified scaffold stubs (each handler file still carries `//! SCAFFOLDED, NOT IMPLEMENTED:`), so each answers HTTP 501 NotImplemented, `operation <Name> is scaffolded but not implemented in this emulator`, and persists nothing. The prerequisite chain this lifecycle needs is refused before that: CreateOnlineEvaluationConfig in bedrock-agentcore-control is also a 501 scaffold, and the check retries it (IAM role-propagation retry, 60s budget) until the runner's own 60s limit expires — which is why the failure surfaces as a timeout with no error text rather than as the 501. The existing open issue 20261029T212239Z-bedrock-agentcore-control-createonlineevaluationconfig-stub.md covers that one prerequisite operation only; it names no A/B-test operation and does not carry this check id, and there is no open issue for CreateABTest/GetABTest/UpdateABTest/DeleteABTest at all.
Why: a client cannot create an A/B test, cannot observe the NOT_STARTED/ACTIVE lifecycle, cannot mutate one, and cannot observe the post-delete not-found refusal — every traffic-splitting workflow built on this family is unusable, and the 501 is not even a modeled error for these operations, so an SDK sees an unmodeled server error instead of a resource.
Fix: implement the A/B-test operations in their handlers — services/service-com-amazonaws-bedrockagentcore-amazonbedrockagentcore/src/ops/create_ab_test.rs, get_ab_test.rs, update_ab_test.rs, delete_ab_test.rs — backed by this service's state so status/executionStatus transitions, the description mutation and the post-delete ResourceNotFoundException (with AWS's `AB test not found: abTestId=<abTestId>` wording) are all state-derived, and delete the SCAFFOLDED marker line from each file as it is implemented. The A/B-test prerequisite CreateOnlineEvaluationConfig belongs to its own already-open issue.
Traces: bedrock-agentcore.abtest-lifecycle-transitions.

Cause 2 of 2: a CloudFormation-deployed AgentCore runtime is never invokable — InvokeAgentRuntime is refused, so the deployed runtime never answers.
AWS: Smithy models InvokeAgentRuntime as POST /runtimes/{agentRuntimeArn}/invocations -> 200 with a required Content-Type response header and a streaming `response` httpPayload; its modeled errors are ValidationException (400), ResourceNotFoundException (404), RetryableConflictException (409), RuntimeClientError (424), AccessDeniedException (403), ServiceQuotaExceededException (402), ThrottlingException (429) and InternalServerException (500). Recorded behavior: a runtime deployed from an S3 code artifact (AWS::BedrockAgentCore::Runtime, EntryPoint main.py, PYTHON_3_13) reaches CREATE_COMPLETE, and InvokeAgentRuntime against the stack's exported AgentRuntimeArn delivers the request payload to the container's POST /invocations and returns that container's response body — so the response echoes a per-run marker taken from the request payload, not a canned body.
Emulator: InvokeAgentRuntime is an unmodified scaffold stub (services/.../src/ops/invoke_agent_runtime.rs carries `//! SCAFFOLDED, NOT IMPLEMENTED:`) and answers HTTP 501 NotImplemented, `operation InvokeAgentRuntime is scaffolded but not implemented in this emulator`; in addition the CloudFormation AWS::BedrockAgentCore::Runtime resource provisions no runtime, so there is nothing behind the exported ARN to invoke. The check polls the invoke, swallowing the refusal, so the run ends as a 60s timeout. Related open issues: 20261023T113357Z-bedrock-agentcore-invokeagentruntime-stub.md (the stub, grounded in a different check id) and 20261029T212239Z-bedrock-agentcore-control-cloudformation-does-not-provision-agentcore-resources-aws-bedrockagentcore.md (the inert CFN resource types, filed against bedrock-agentcore-control); neither names this check, and neither asserts the end-to-end requirement that a deployed runtime's own code is what answers an invocation.
Why: infrastructure-as-code is the normal way an AgentCore runtime is created, and invocation is the only thing it is for. A client gets a green stack, an ARN, and an unmodeled 501 on every invocation — so a hosted agent can be deployed but never reached, and the failure is indistinguishable from a broken emulator rather than a missing feature.
Fix: implement the InvokeAgentRuntime handler so it resolves the agentRuntimeArn against bedrock-agentcore-control runtime state (404 ResourceNotFoundException when absent), delivers the request payload to that runtime's deployed entry point, and returns its response through the streaming `response` payload with the Content-Type header set; the CloudFormation provisioning of AWS::BedrockAgentCore::Runtime must register a runtime that this path can resolve.
Traces: bedrock-agentcore.deploy-agent-runtime-invokable-via-cfn.

## Evidence
Replay report (simparity-behavioral-aws-v1), both verdicts 'mismatch' with detail `Error: Check timed out after 60.0s`:
- bedrock-agentcore.abtest-lifecycle-transitions — the check builds its prerequisites (S3 code artifact, IAM roles, CreateAgentRuntime, log group, CreateOnlineEvaluationConfig, CreateGateway + two gateway targets) and then exercises CreateABTest -> GetABTest -> UpdateABTest -> DeleteABTest -> GetABTest. Its prerequisite call to CreateOnlineEvaluationConfig is wrapped in `_retry_role_propagation(..., timeout_s=60.0)`, which retries any ClientError, so the 501 NotImplemented is retried until the runner's 60s limit; no A/B-test call is ever reached. Source evidence in the checkout: `//! SCAFFOLDED, NOT IMPLEMENTED:` on line 4 of services/service-com-amazonaws-bedrockagentcore-amazonbedrockagentcore/src/ops/create_ab_test.rs, get_ab_test.rs, update_ab_test.rs and delete_ab_test.rs, and on line 4 of services/service-com-amazonaws-bedrockagentcorecontrol-amazonbedrockagentcorecontrol/src/ops/create_online_evaluation_config.rs.
  Expected (AWS): CreateABTest 202 with status/executionStatus, executionStatus 'NOT_STARTED' for enableOnCreate=false; GetABTest 200 reporting status 'ACTIVE' and the same abTestId; UpdateABTest 202 and the new description readable through GetABTest; after DeleteABTest, GetABTest refused 404 ResourceNotFoundException with message 'AB test not found: abTestId=<abTestId>' (fixed text 'AB test not found: abTestId=' plus the abTestId value from the request).
  Actual (emulator): HTTP 501 NotImplemented, 'operation <Name> is scaffolded but not implemented in this emulator', for every A/B-test operation, and the same 501 for the CreateOnlineEvaluationConfig prerequisite; the observable result is no response at all within the budget.
- bedrock-agentcore.deploy-agent-runtime-invokable-via-cfn — CreateStack with one AWS::BedrockAgentCore::Runtime (Code S3 bucket/prefix, EntryPoint ['main.py'], Runtime PYTHON_3_13, ProtocolConfiguration HTTP, NetworkMode PUBLIC) and output RuntimeArn = Fn::GetAtt Runtime.AgentRuntimeArn, then polls InvokeAgentRuntime (payload {'prompt': <per-run marker>}) for up to 280s, swallowing each failure.
  Expected (AWS): the invocation returns 200 and the body produced by the deployed container, i.e. {'result': 'sim2real-echo', 'received': {'prompt': <the marker sent in this request>}} — the marker is a per-run value from the request, the requirement is that the request payload reaches the deployed code and its response is returned.
  Actual (emulator): InvokeAgentRuntime answers HTTP 501 NotImplemented, 'operation InvokeAgentRuntime is scaffolded but not implemented in this emulator', on every attempt, and no runtime exists behind the stack's exported ARN; the check therefore never gets a response and is killed at 60s.
Hosts, bucket names, role names, stack names, generated ids and the per-run marker differ on every run and are not part of the requirement.
