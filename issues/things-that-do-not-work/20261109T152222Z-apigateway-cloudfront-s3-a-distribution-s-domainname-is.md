# apigateway__cloudfront__s3: a distribution's DomainName is published as <id>.cloudfront.net, so the CloudFront edge is unreachable (40 checks)

> _Note: this issue was identified against the code base at commit `39b863d101414613449d16e44f0b23fd775a8d87`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateDistribution

## Description
Cause 1 of 1: every CloudFront distribution the emulator creates publishes a DomainName on the AWS production host cloudfront.net, which the emulator does not serve, so no viewer request can ever be made to the edge.
AWS: CreateDistribution/GetDistribution return Distribution.DomainName, and a viewer reaches the distribution by issuing HTTP(S) to that domain; the edge then applies the distribution config (origins, OriginAccessControl/OAI signing, cache behaviors, viewer protocol policy, origin path, invalidations, signed URLs, access logging) and returns the origin's response or CloudFront's own refusal. (Recorded behavior only for the host form the emulator must publish: an address the emulator publishes has to be an address it is reached on.)
Emulator: DomainName is returned as "https://<generated-id>.cloudfront.net" (also used for CFN-deployed distributions and for distributions created through the CLI). The emulator announced an address other than the one it is reached on, so a client that reads DomainName and issues the viewer request is refused at egress before any request is sent: "endpoint_url was given https://<id>.cloudfront.net/<path> (published by the emulator or built by the check): its host is not one of the emulator's own hosts; a customer of the emulator needs http(s)://127.0.0.1:<port>/<resource path>, or http(s)://<own host>:<port>/<path> on a per-resource listener". The generated id and the port differ per run; the defect is the host, not any one value.
Why: the only documented way to use a distribution is to request its DomainName. Because that address is unreachable, the entire CloudFront edge data plane is unobservable for both positive and negative contracts: S3-origin and API-Gateway-origin delivery, OAC/OAI origin access and its 403 AccessDenied denials, bucket-policy and wrong-distribution denials, cache-behavior path routing and header/custom-header forwarding, viewer-protocol-policy redirects, origin-path prefixing, invalidation-after-update, signed-URL restriction, website-endpoint origins, access-log delivery, and public-bucket bypass. A caller cannot tell "CloudFront refused" from "CloudFront is not there".
Fix: the cloudfront CreateDistribution/UpdateDistribution/GetDistribution serializers (the DomainName member, and the CFN AWS::CloudFront::Distribution handler's DomainName attribute) must publish a host the emulator serves, and the edge data plane must answer viewer requests on it.

## Evidence
Expected: Distribution.DomainName names an emulator-served host, so GET https://<DomainName>/<path> reaches the edge and returns the origin's response (or CloudFront's 403/404 refusal for the negative cases).
Actual, identically for all 40 checks: "simparity.published.PublishedUrlRejected: endpoint_url was given https://<generated-id>.cloudfront.net[/<path>] (published by the emulator or built by the check): its host is not one of the emulator's own hosts; a customer of the emulator needs http(s)://127.0.0.1:<port>/<resource path>, or http(s)://<own host>:<port>/<path> on a per-resource listener" — raised in the client before the request is sent, from context.py endpoint_route/_published_target. Examples: cfn-deploy-cloudfront-apigw-stack-positive (https://d7823b493077fe.cloudfront.net/), cloudfront-s3-oac-origin-positive (https://dgzni4pnd7h2s3.cloudfront.net/index.html), cloudfront-apigateway-viewer-protocol-policy-positive (http://d0lc535g268ho1.cloudfront.net).

## Steps to Reproduce
1. Create an S3 bucket with an object, or a deployed REST API stage, as the origin.
2. cloudfront CreateDistribution (or deploy AWS::CloudFront::Distribution, or `aws cloudfront create-distribution`) over that origin and wait for Deployed.
3. Read Distribution.DomainName from the create/get response.
4. Issue HTTP(S) GET to https://<DomainName>/<object or route>.
Expected: the viewer request reaches the emulator's CloudFront edge and the configured behavior is applied. Actual: DomainName is <id>.cloudfront.net, a host the emulator does not serve, so the request is refused at egress and no edge behaviour can be observed.
