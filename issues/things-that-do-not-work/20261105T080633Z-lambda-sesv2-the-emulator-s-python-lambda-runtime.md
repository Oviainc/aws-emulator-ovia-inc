# lambda__sesv2: the emulator's python Lambda runtime has no boto3/botocore, so every SES v2 handler dies with Runtime.ImportModuleError and 57 interop checks fail

> _Note: this issue was identified against the code base at commit `ce1e7fa07219b3a065b602a90626dda6f8aa6c34`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
Invoke

## Description
One root cause behind all 57 net-new lambda__sesv2 failures (the 6 other failures in this service are already OWNED by other issues and are not included here).

Cause 1 of 1: the execution environment the emulator gives a python3.x Lambda does not contain the AWS SDK for Python, so the very first `import boto3` in the handler fails and the function never runs its body.

AWS: Smithy lambda `Invoke` (POST /2015-03-31/functions/{FunctionName}/invocations, success code 200) runs the function's deployment package and returns the handler's own response in the `Payload` httpPayload, with `X-Amz-Function-Error` (output member FunctionError) set ONLY when the handler itself raised. The content of a managed runtime is not in the model — documented AWS behavior / recorded behavior only: the python3.x managed runtimes (python3.12 here) ship boto3 and botocore preinstalled on the handler's module search path, so a ZipFile-only handler that does `import boto3` / `boto3.client("sesv2")` imports successfully without bundling the SDK. Every recording in this suite relies on exactly that: the handler imports boto3, calls one sesv2 API, and returns a small JSON object (e.g. {"ok": true, ...} or {"success": false, "errorCode": "AccessDeniedException"}).

Emulator: Invoke answers HTTP 200 but with `FunctionError: "Unhandled"` and a runtime-authored payload instead of the handler's response: {"errorMessage": "Unable to import module '<handler module>': No module named 'boto3'", "errorType": "Runtime.ImportModuleError", "requestId": "<per-run uuid>", "stackTrace": []}. The fixed text is `Unable to import module '<module>': No module named 'boto3'` and the errorType `Runtime.ImportModuleError`; the module name (`index`, `lambda_function`) comes from the request's Handler, and requestId is per-run. The handler body never executes, so no sesv2 call is ever made from inside a function.

Why: a client cannot run any realistic Lambda. Nothing that depends on a function's own AWS calls is observable: the SES v2 control/data-plane calls made from a function, the IAM execution-role permission outcomes the *-missing-permission-negative checks assert (the handler must catch AccessDeniedException and report it), the CFN `Ref`/`Fn::GetAtt` values delivered as environment variables, and the role-trust negatives all collapse into one opaque Unhandled import error. Downstream the checks see KeyError 'success'/'arn' (the runtime's error dict has no such keys) or, where the check retries invoke until FunctionError is absent, they burn the whole 60 s budget and report "Check timed out after 60.0s" — the same cause, not separate ones.

Fix: the Lambda Invoke data-plane runtime — the python execution environment the function-runtime path builds for a ZipFile package. It must preinstall the AWS SDK for Python (boto3 + botocore) on the handler's module search path, as AWS's managed python3.x runtimes do, and configure it so the SDK resolves to the emulator's own endpoints/credentials; only genuine handler exceptions may surface as FunctionError=Unhandled. Related for reference, neither covering these checks: open 20261105T022225Z-lambda-sesv2-lambda-invoke-refuses-every-real-invocation.md and fixed 20261029T233239Z-lambda-synchronous-invoke-data-plane-answers-501-notimplemented.md describe the older 501 refusal — Invoke now returns 200, so this is not that refusal reoccurring but the next layer: the runtime image lacks the SDK.

Traces: 57 failing checks, listed in trace_ids. Representative examples: lambda__sesv2.lambda-sesv2-get-account-positive (KeyError 'success' on the runtime's error dict), lambda__sesv2.cfn-deploy-lambda-sesv2-stack-positive ("function ... errored: {'errorMessage': \"Unable to import module 'index': No module named 'boto3'\" ...}"), lambda__sesv2.cfn-deploy-lambda-sesv2-env-configset-arn-resolution (times out retrying invoke until FunctionError clears).

## Evidence
Expected (AWS): Invoke returns 200 with no X-Amz-Function-Error and Payload = the handler's JSON, e.g. {"ok": true, "name": "<configuration set name from the request/stack>"} or {"success": false, "errorCode": "AccessDeniedException"} for the permission negatives.

Actual (replay): 200 with X-Amz-Function-Error: Unhandled and Payload {"errorMessage": "Unable to import module 'index': No module named 'boto3'", "errorType": "Runtime.ImportModuleError", "requestId": "<uuid>", "stackTrace": []} (module name is `lambda_function` where the check's Handler says so). Sample assertions from the suite report:
- lambda__sesv2.lambda-sesv2-create-contact-positive: AssertionError: lambda invocation errored: {'errorMessage': "Unable to import module 'index': No module named 'boto3'", 'errorType': 'Runtime.ImportModuleError', ...}
- lambda__sesv2.cli-lambda-sesv2-describe-email-identity: AssertionError: expected no FunctionError, got invocation result {'meta': {'StatusCode': 200, 'FunctionError': 'Unhandled', 'ExecutedVersion': '$LATEST'}, 'body': {'errorMessage': "Unable to import module 'index': No module named 'boto3'", 'errorType': 'Runtime.ImportModuleError', ...}}
- lambda__sesv2.lambda-sesv2-get-email-identity-missing-permission-negative: KeyError: 'success' (assert bad_body["success"] is False — the runtime error dict carries no such key)
- lambda__sesv2.lambda-iam-trust-policy-assume-role-positive: KeyError: 'arn'
- lambda__sesv2.cfn-deploy-lambda-sesv2-role-trust-positive / cli-lambda-sesv2-describe-function-config: "Check timed out after 60.0s" — the check polls invoke until FunctionError is not Unhandled, which never happens.
Function names, stack names, account ids and requestIds in these lines are per-run values; the requirement being violated is that the python runtime provides boto3 so the handler's own response is what Invoke returns.

## Steps to Reproduce
1. CreateFunction (directly or via a CloudFormation AWS::Lambda::Function with Code.ZipFile) with Runtime=python3.12, Handler=index.handler, and a handler whose first lines are `import boto3` / `from botocore.exceptions import ClientError`, then a single sesv2 call such as get_account() or get_configuration_set(ConfigurationSetName=os.environ["CONFIG_SET_NAME"]), returning {"ok": True, ...} on success and {"ok": False, "errorCode": e.response["Error"]["Code"]} on ClientError.
2. Wait until the function is Active, then call lambda Invoke (or `aws lambda invoke --function-name <fn> out.json`).
3. Observe HTTP 200 with X-Amz-Function-Error: Unhandled and the payload {"errorMessage": "Unable to import module 'index': No module named 'boto3'", "errorType": "Runtime.ImportModuleError", ...} instead of the handler's own JSON; a client that retries invoke waiting for FunctionError to clear never converges.
