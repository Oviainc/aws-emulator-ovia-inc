# artifact ListReports catalog enumeration omits nearly every published report from its first page

> _Note: this issue was identified against the code base at commit `0465eb394723049460d943d66b3411d762c72467`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
ListReports

## Description
One net-new root cause in the artifact READ plane: the report catalog that ListReports enumerates is almost empty, so the operation answers HTTP 200 with a well-formed envelope whose $.reports collection is missing several hundred distinct report resources that the recorded service enumerates on that same page.

Cause 1 of 1: ListReports first page (fixture artifact-catalog-list-reports, step task#1) answers 200 with the overwhelming majority of the catalog's report entries absent.

AWS: Smithy (services/service-com-amazonaws-artifact-artifact/smithy-model/com-amazonaws-artifact-artifact.json) - ListReports is restJson1 GET /v1/report/list, http code 200, @readonly, @paginated {inputToken=nextToken, outputToken=nextToken, pageSize=maxResults, items=reports}; input maxResults (@httpQuery maxResults, @range 1..300) and nextToken (@httpQuery nextToken, @length 1..2048); output {reports: ReportsList, nextToken: @length 1..2048}; modeled errors AccessDeniedException 403, ValidationException 400, ResourceNotFoundException 404, ServiceQuotaExceededException 402, ThrottlingException 429, InternalServerException 500. Each element is a ReportSummary: id (@pattern ^report-[a-zA-Z0-9]{16}$), arn (@length 1..2048), name, series, category, companyName, productName, description, state (PublishedState enum), version (@range min 1, long), periodStart / periodEnd (@timestampFormat date-time), uploadState, statusMessage, acceptanceType. ListReports is the enumeration of the service's whole report catalog: every report the service holds must appear in exactly one page of the enumeration, carrying its full ReportSummary, and a page is identified by the report's arn (report id plus a ':<version>' suffix). The model does not bound which reports exist, so catalog membership is recorded behavior only: the recording's first page enumerates several hundred distinct report arns spanning many compliance series (accessibility-conformance ACR/VPAT reports, a United Arab Emirates TDRA IAR information-assurance assessment, and many more), each PUBLISHED, PUBLIC-visibility and PASSTHROUGH acceptanceType, each with its own id, version, series, category, companyName, productName, description and period bounds. The recording also carries a 'visibility' member on each entry that this on-disk ReportSummary does not declare - recorded behavior only.

Emulator: HTTP 200 (no status divergence, no error), but $.reports does not contain those entries. The replay reports, once per missing report, '$.reports[arn="<report arn>"]: missing (expected {...full ReportSummary...}, got None)', for several hundred distinct arns on this single step (the cluster's divergence_key lists them all under keys=). No extra/unexpected $.reports entries and no nextToken divergence are reported, so the paging envelope is correct and the catalog behind it is near-empty: the handler serves a shape-valid page over a collection that was never populated with the service's report inventory.

Why: ListReports is the only discovery path for AWS Artifact reports - a client enumerates it, picks the report it needs, then calls GetTermForReport and GetReport to accept terms and download. A successful 200 whose page simply omits a report is indistinguishable from that report not existing, so a client concludes the compliance document is unavailable and never attempts the term/download flow for it; a client that pages to the end and caches the result silently persists a near-empty catalog. Nothing surfaces as an error, so there is no retry, fallback or alarm. Because almost the entire inventory is missing, every downstream artifact workflow keyed on a report id becomes unreachable.

Fix: the report catalog the ListReports handler enumerates - the catalog seed/materialisation in the artifact crate's state plus the ListReports handler that pages over it (services/service-com-amazonaws-artifact-artifact/src/state.rs and services/service-com-amazonaws-artifact-artifact/src/ops/). The pagination cursor and nextToken emission are not the defect here. The requirement is that every report the catalog holds is enumerated with its complete ReportSummary; the specific ids, versions, period timestamps and descriptions in the recording are that template's values, not the requirement.

2. Replay wire trace set simparity-wire-aws-v1.
3. Run fixture artifact-catalog-list-reports to step task#1: GET /v1/report/list (optionally with maxResults in 1..300), SigV4-signed for the artifact endpoint.
4. Expected: HTTP 200 whose $.reports enumerates the service's report catalog, each element a complete ReportSummary (id, arn, name, series, category, companyName, productName, description, state, version, periodStart/periodEnd, acceptanceType), with nextToken present when more pages remain.

6. To confirm a fix, re-replay artifact-catalog-list-reports#task#1 and require zero missing $.reports entries for that step (not merely the two example reports quoted above).
