# cloudformation__gamelift: 6 net-new causes — AWS::GameLift::Alias, ::Location, ::Fleet, ::GameSessionQueue, ::MatchmakingRuleSet and ::MatchmakingConfiguration are all unregistered resource types, so CreateStack refuses every GameLift template

> _Note: this issue was identified against the code base at commit `87192d19b1d499e8425d8cf541553378b48cc888`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateStack

## Description
CloudFormation's template resource-type registry contains no AWS::GameLift::* type, so each of the six types below is refused at CreateStack with HTTP 400 ValidationError "Template format error: Unrecognized resource types: [<type(s)>]" and no GameLift estate can be deployed, read back, validated or deleted through a stack. Each type is its own cause (its own handler, Ref/GetAtt attributes, validation and rollback behavior) and must be closed separately; the shared symptom is the unregistered-type refusal.

Cause 1 of 6: AWS::GameLift::Alias is not a registered resource type. Failing checks: cloudformation__gamelift.deploy-gamelift-alias-terminal-routing-round-trip-and-delete, cloudformation__gamelift.deploy-gamelift-alias-simple-routing-missing-fleet-id-rejected-and-rolled-back.
AWS: CreateStack on a template declaring an Alias with Properties Name and RoutingStrategy {Type: TERMINAL, Message: <text>} is accepted (HTTP 200, StackId) and reaches CREATE_COMPLETE; the handler calls gamelift CreateAlias (Smithy: CreateAlias.Name required @length 1..1024 @pattern ^.*\S.*$, RoutingStrategy required; errors ConflictException/InvalidRequestException/LimitExceededException/UnauthorizedException, HTTP 400). Ref resolves to the AliasId and Fn::GetAtt Alias.AliasArn to arn:<partition>:gamelift:<region>:<account>:alias/<alias-id>; the alias is then listable by name through ListAliases and readable through DescribeAlias with the templated routing type and message. A RoutingStrategy of Type SIMPLE with no FleetId is caught by CloudFormation's EARLY schema validation against the resource type's schema, so the stack ends ROLLBACK_COMPLETE and the resource records the registry handler reason Resource handler returned message: "Model validation failed (#/RoutingStrategy: #: only 1 subschema matches out of 2)\n#/RoutingStrategy: #: no subschema matched out of the total 2 subschemas (#/RoutingStrategy)" (RequestToken: <uuid>, HandlerErrorCode: InvalidRequest) — that text is the schema's fixed wording, only the property pointer varies with the offending property.

Cause 2 of 6: AWS::GameLift::Location is not a registered resource type. Failing check: cloudformation__gamelift.deploy-gamelift-custom-location-round-trip-and-delete.
AWS: a template declaring a Location with LocationName and Tags is accepted and reaches CREATE_COMPLETE; the handler calls gamelift CreateLocation (Smithy: CreateLocation.LocationName required @length 8..64 @pattern ^custom-[A-Za-z0-9\-]+$, Tags @length 0..200; errors ConflictException/InvalidRequestException/LimitExceededException/TaggingFailedException/UnauthorizedException/UnsupportedRegionException, HTTP 400). Ref resolves to the LocationName and Fn::GetAtt Location.LocationArn to arn:<partition>:gamelift:<region>:<account>:location/<location-name>; ListLocations then reports the custom location and its tags are readable through ListTagsForResource. Deleting the stack calls DeleteLocation, after which ListLocations no longer reports it.

Cause 3 of 6: AWS::GameLift::Fleet is not a registered resource type. Failing check: cloudformation__gamelift.deploy-gamelift-fleet-anywhere-round-trip-and-delete (the same template also declares a Location, so the refusal names both types).
AWS: a template declaring a Fleet with Name, ComputeType ANYWHERE and Locations [{Location: <custom location>}] (DependsOn the Location) is accepted and reaches CREATE_COMPLETE; the handler calls gamelift CreateFleet (Smithy: CreateFleet.Name required @length 1..1024, ComputeType enum, Locations @length 1..100; errors ConflictException/InvalidRequestException/LimitExceededException/NotFoundException/NotReadyException/TaggingFailedException/UnauthorizedException/UnsupportedRegionException, HTTP 400). Ref resolves to the FleetId and Fn::GetAtt Fleet.FleetArn to arn:<partition>:gamelift:<region>:<account>:fleet/<fleet-id>; DescribeFleetAttributes/DescribeFleetLocationAttributes then report the fleet in the templated location.

Cause 4 of 6: AWS::GameLift::GameSessionQueue is not a registered resource type. Failing checks: cloudformation__gamelift.deploy-gamelift-game-session-queue-round-trip-and-delete, cloudformation__gamelift.deploy-gamelift-game-session-queue-duplicate-name-rejected-and-rolled-back.
AWS: a template declaring a GameSessionQueue with Name and TimeoutInSeconds is accepted and reaches CREATE_COMPLETE; the handler calls gamelift CreateGameSessionQueue (Smithy: CreateGameSessionQueue.Name required @length 1..128 @pattern ^[a-zA-Z0-9-]+$, TimeoutInSeconds @range min 0; errors InvalidRequestException/LimitExceededException/NotFoundException/TaggingFailedException/UnauthorizedException, HTTP 400). Ref resolves to the queue Name and Fn::GetAtt Queue.Arn to arn:<partition>:gamelift:<region>:<account>:gamesessionqueue/<name>; DescribeGameSessionQueues reports the queue with the templated timeout. A second stack declaring a queue whose Name an existing queue already holds fails CloudFormation's PRE-CREATE name-conflict validation: the stack ends ROLLBACK_COMPLETE with a validation row of Type NAME_CONFLICT_VALIDATION on the resource and the message "Resource of type 'AWS::GameLift::GameSessionQueue' with identifier '<name>' already exists." — fixed text "Resource of type '", "' with identifier '", "' already exists." with the type name and the requested name filled in — and the original queue is left untouched.

Cause 5 of 6: AWS::GameLift::MatchmakingRuleSet is not a registered resource type. Failing check: cloudformation__gamelift.deploy-gamelift-matchmaking-ruleset-and-configuration-round-trip-and-delete.
AWS: a template declaring a MatchmakingRuleSet with Name and RuleSetBody is accepted and reaches CREATE_COMPLETE; the handler calls gamelift CreateMatchmakingRuleSet (Smithy: Name required @length 0..128 @pattern ^[a-zA-Z0-9-\.]*$, RuleSetBody required @length 1..65535; errors InvalidRequestException/LimitExceededException/TaggingFailedException/UnsupportedRegionException). Ref resolves to the rule-set Name and Fn::GetAtt RuleSet.Arn to arn:<partition>:gamelift:<region>:<account>:matchmakingruleset/<name>; DescribeMatchmakingRuleSets reports the rule set with the submitted body.

Cause 6 of 6: AWS::GameLift::MatchmakingConfiguration is not a registered resource type (same template as cause 5, so the refusal names both). Failing check: cloudformation__gamelift.deploy-gamelift-matchmaking-ruleset-and-configuration-round-trip-and-delete.
AWS: a template declaring a MatchmakingConfiguration with Name, AcceptanceRequired, RequestTimeoutSeconds, RuleSetName ({Ref} of the rule set) and FlexMatchMode STANDALONE is accepted and reaches CREATE_COMPLETE; the handler calls gamelift CreateMatchmakingConfiguration (Smithy: Name required @length 0..128 @pattern ^[a-zA-Z0-9-\.]*$, RequestTimeoutSeconds required @range 1..43200, AcceptanceRequired required, RuleSetName required @pattern ^([a-zA-Z0-9-\.]*|arn:.*:matchmakingruleset\/[a-zA-Z0-9-\.]*)$; errors InvalidRequestException/LimitExceededException/NotFoundException/TaggingFailedException/UnsupportedRegionException). Ref resolves to the configuration Name and Fn::GetAtt Config.Arn to arn:<partition>:gamelift:<region>:<account>:matchmakingconfiguration/<name>; DescribeMatchmakingConfigurations reports it bound to the stack's rule set, and deleting the stack deletes the configuration before the rule set it depends on.

Emulator: for every one of the seven checks CreateStack is REFUSED with HTTP 400 ValidationError and the message "Template format error: Unrecognized resource types: [<types>]" — observed as [AWS::GameLift::Alias], [AWS::GameLift::Location], [AWS::GameLift::Location, AWS::GameLift::Fleet], [AWS::GameLift::GameSessionQueue] and [AWS::GameLift::MatchmakingRuleSet, AWS::GameLift::MatchmakingConfiguration]. The fixed text is "Template format error: Unrecognized resource types: [" ... "]" and the bracketed list is the submitted template's unrecognized types. No StackId is returned and no stack exists, so every downstream observation (Ref/GetAtt resolution, the GameLift round trips, tag propagation, the SIMPLE-routing schema-validation rollback, the duplicate-name NAME_CONFLICT_VALIDATION row and the deletes) is unreachable.

Why: a client deploying any GameLift estate by template (console, CLI, CDK, Terraform's CFN resources) cannot create or manage aliases, custom locations, fleets, queues, rule sets or matchmaking configurations at all, and the refusal is a template-FORMAT error, which tells the client its template is malformed rather than that the provider is missing — so no retry or template edit can succeed. The negative paths also invert: failures AWS reports as a rolled-back stack with a schema-validation handler reason or a NAME_CONFLICT_VALIDATION row are instead reported before any stack exists, with a different code, status and message.

Fix: the CloudFormation service's template resource-type registry (the table template validation consults to decide a type is recognized) must register these six AWS::GameLift::* types, and a provisioning handler must be added for each that calls the corresponding gamelift Create*/Describe*/Delete* operations, publishes Ref and the modelled GetAtt attributes (AliasArn, LocationArn, FleetArn, Arn) from GameLift's own state, propagates stack and resource tags, routes RoutingStrategy's one-of requirement through CloudFormation's early resource-schema validation, and routes a duplicate queue Name through CloudFormation's pre-create name-conflict validation so the stack rolls back with a NAME_CONFLICT_VALIDATION row.

Traces: see trace_ids; all seven checks fail on their first CreateStack call, before any GameLift call is made.

## Steps to Reproduce
1. Build and boot the emulator.
2. aws cloudformation create-stack --stack-name gl-alias --template-body '{"AWSTemplateFormatVersion":"2010-09-09","Resources":{"Alias":{"Type":"AWS::GameLift::Alias","Properties":{"Name":"demo-alias","RoutingStrategy":{"Type":"TERMINAL","Message":"retired"}}}},"Outputs":{"AliasId":{"Value":{"Ref":"Alias"}},"AliasArn":{"Value":{"Fn::GetAtt":["Alias","AliasArn"]}}}}' -> observe HTTP 400 ValidationError "Template format error: Unrecognized resource types: [AWS::GameLift::Alias]".
3. Repeat with RoutingStrategy {"Type":"SIMPLE"} and no FleetId: AWS rolls the stack back with the Model-validation handler reason; the emulator gives the same unrecognized-type refusal.
4. Repeat for {"Location":{"Type":"AWS::GameLift::Location","Properties":{"LocationName":"custom-demo-loc"}}}; for a Location plus {"Fleet":{"Type":"AWS::GameLift::Fleet","Properties":{"Name":"demo-fleet","ComputeType":"ANYWHERE","Locations":[{"Location":"custom-demo-loc"}]},"DependsOn":"Location"}}; for {"Queue":{"Type":"AWS::GameLift::GameSessionQueue","Properties":{"Name":"demo-queue","TimeoutInSeconds":20}}}; and for {"RuleSet":{"Type":"AWS::GameLift::MatchmakingRuleSet","Properties":{"Name":"demo-rs","RuleSetBody":"{\"name\":\"demo\",\"ruleLanguageVersion\":\"1.0\",\"teams\":[{\"name\":\"alpha\",\"minPlayers\":1,\"maxPlayers\":4}]}"}},"Config":{"Type":"AWS::GameLift::MatchmakingConfiguration","Properties":{"Name":"demo-cfg","AcceptanceRequired":false,"RequestTimeoutSeconds":15,"RuleSetName":{"Ref":"RuleSet"},"FlexMatchMode":"STANDALONE"},"DependsOn":"RuleSet"}} — each is refused with the same unrecognized-type error naming its types.
5. Create a game session queue through the gamelift API, then deploy the queue template with that same Name: AWS rolls back with a NAME_CONFLICT_VALIDATION row; the emulator refuses CreateStack instead.
