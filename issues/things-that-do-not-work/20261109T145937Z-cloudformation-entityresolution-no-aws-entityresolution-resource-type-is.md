# cloudformation__entityresolution: no AWS::EntityResolution::* resource type is registered — CreateStack refuses every Entity Resolution template as "Unrecognized resource types"

> _Note: this issue was identified against the code base at commit `d115796fe5713602f1adc3e09d553e6de30aa6e5`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateStack

## Description
Cause 1 of 1: CloudFormation's resource-type registry in the emulator knows none of the AWS::EntityResolution::* resource types. Every template that declares one is rejected at template-validation time, so no Entity Resolution estate (schema mapping, matching workflow, ID namespace, ID mapping workflow, resource policy statement) can be deployed, updated, rolled back or deleted by a stack, and none of the downstream contracts (Ref/GetAtt values, read-back through the Entity Resolution API, handler-level rejection and rollback) is reachable at all. The five types the failing checks declare are AWS::EntityResolution::SchemaMapping, AWS::EntityResolution::MatchingWorkflow, AWS::EntityResolution::IdNamespace, AWS::EntityResolution::IdMappingWorkflow and AWS::EntityResolution::PolicyStatement. Failing checks: cloudformation__entityresolution.deploy-entityresolution-schema-mapping-lifecycle, cloudformation__entityresolution.deploy-entityresolution-schema-mapping-reserved-field-name-rejected, cloudformation__entityresolution.deploy-entityresolution-namespace-workflow-policy-lifecycle, cloudformation__entityresolution.deploy-entityresolution-id-mapping-workflow-lifecycle.

AWS: CloudFormation supports all five types and CreateStack with such a template returns 200 with a StackId; the stack then reaches CREATE_COMPLETE and each resource is provisioned through the Entity Resolution control plane.
  - AWS::EntityResolution::SchemaMapping -> CreateSchemaMapping (Smithy: POST /schemas; input schemaName required @length 1..255 @pattern ^[a-zA-Z_0-9-]*$, mappedInputFields required @length 2..60, description @length max 255; output schemaArn @pattern ^arn:(aws|aws-us-gov|aws-cn):entityresolution:<region>:<account>:schemamapping/<name>$). Ref resolves to the schema name; Fn::GetAtt SchemaArn resolves to that ARN. GetSchemaMapping then returns that schemaArn, the template's Description, hasWorkflows=false and mappedInputFields in template order.
  - AWS::EntityResolution::MatchingWorkflow -> CreateMatchingWorkflow (Smithy: POST /matchingworkflows; inputSourceConfig required @length 1..20, outputSourceConfig required @length 1..1, resolutionTechniques and roleArn required; output workflowArn @pattern ...:matchingworkflow/<name>). Ref resolves to the workflow name, Fn::GetAtt WorkflowArn to the ARN, and GetMatchingWorkflow reads back roleArn, resolutionTechniques (resolutionType RULE_MATCHING, ruleBasedProperties.attributeMatchingModel, rules) and outputSourceConfig[].outputS3Path as declared.
  - AWS::EntityResolution::IdNamespace -> CreateIdNamespace (Smithy: POST /idnamespaces; idNamespaceName and type required, inputSourceConfig @length 0..20, idMappingWorkflowProperties @length 1..1, roleArn @length 32..512 @pattern ^arn:aws:iam::\d{12}:role/?...; output idNamespaceArn @pattern ...:idnamespace/<name>, createdAt/updatedAt required). Ref resolves to the namespace name, Fn::GetAtt IdNamespaceArn to the ARN, and GetIdNamespace reads back type, roleArn, inputSourceConfig[].schemaName and idMappingWorkflowProperties[0].ruleBasedProperties (attributeMatchingModel, recordMatchingModels, ruleDefinitionTypes, rules).
  - AWS::EntityResolution::IdMappingWorkflow -> CreateIdMappingWorkflow (Smithy: POST /idmappingworkflows; workflowName, inputSourceConfig @length 1..20 and idMappingTechniques required; output workflowArn @pattern ...:idmappingworkflow/<name>). Ref resolves to the workflow name, Fn::GetAtt WorkflowArn to the ARN, GetIdMappingWorkflow reads back roleArn, idMappingTechniques.ruleBasedProperties (idMappingType RULE_BASED, attributeMatchingModel, recordMatchingModel, ruleDefinitionType, rules) and the SOURCE/TARGET inputSourceConfig entries pointing at the two namespace ARNs. An UpdateStack that removes only this resource leaves the namespaces in place: GetIdMappingWorkflow then refuses with ResourceNotFoundException and the message "IdMappingWorkflow Not Found", and ListIdMappingWorkflows no longer lists it.
  - AWS::EntityResolution::PolicyStatement -> AddPolicyStatement (Smithy: POST /policies/{arn}/{statementId}; arn @pattern limited to schemamapping|matchingworkflow|idmappingworkflow|idnamespace, statementId @length 1..64 @pattern ^[0-9A-Za-z]+$, effect/action/principal required). GetPolicy(arn=<workflow ARN>) then returns a policy document containing the statement with Sid=<StatementId>, Effect and the declared Action list.
  DeleteStack tears all of this down: GetSchemaMapping refuses with ResourceNotFoundException "SchemaMapping does not exist", GetIdNamespace with ResourceNotFoundException "IdNamespace Not Found" and GetMatchingWorkflow with ResourceNotFoundException "MatchingWorkflow Not Found" (fixed text per resource class; the entity name is the request's). Rejection path: a SchemaMapping whose MappedInputFields name the reserved identifier field RecordId is accepted by template validation (DescribeEvents reports NO VALIDATION_ERROR row) and refused by the resource handler, so the stack reaches ROLLBACK_COMPLETE with the Mapping resource CREATE_FAILED and the registry-handler reason template `Resource handler returned message: "SchemaMapping is not allowed to use reserved field names: recordid (Service: EntityResolution, Status Code: 400, Request ID: <id>) (SDK Attempt Count: <n>)" (RequestToken: <token>, HandlerErrorCode: InvalidRequest)` — fixed text "SchemaMapping is not allowed to use reserved field names: " followed by the offending field name lower-cased (here recordid) taken from the request, HTTP status 400, service name EntityResolution and HandlerErrorCode InvalidRequest; request id, request token and attempt count are per-run values and not part of the requirement. After the rollback the mapping does not exist (ListSchemaMappings omits it, GetSchemaMapping refuses with ResourceNotFoundException "SchemaMapping does not exist").

Emulator: CreateStack is refused outright with HTTP 400 and error code ValidationError, message `Template format error: Unrecognized resource types: [<list of the AWS::EntityResolution::* types in the template>]` — observed as "Template format error: Unrecognized resource types: [AWS::EntityResolution::SchemaMapping]", "[AWS::EntityResolution::SchemaMapping, AWS::EntityResolution::MatchingWorkflow, AWS::EntityResolution::IdNamespace, AWS::EntityResolution::IdMappingWorkflow]" and "[AWS::EntityResolution::SchemaMapping, AWS::EntityResolution::IdNamespace, AWS::EntityResolution::MatchingWorkflow, AWS::EntityResolution::PolicyStatement]". No StackId is returned, no stack and no resources exist, and the check dies on its first CreateStack.

Why: a client cannot express any Entity Resolution resource in infrastructure-as-code. Every CDK/CloudFormation template that provisions a schema mapping, matching workflow, ID namespace, ID mapping workflow or Entity Resolution resource policy fails at submit time with a template-format error, which a client reads as "my template is malformed" rather than "this emulator does not support the type". Deploy pipelines cannot stand up an Entity Resolution estate at all, the Ref/GetAtt identity contract (Ref = entity name, GetAtt = ARN) is unobservable, and the handler-level rejection contract (reserved field name -> ROLLBACK_COMPLETE with HandlerErrorCode InvalidRequest and no surviving mapping) is never exercised.

Fix: CloudFormation's resource-type registry / template validation (the component that produces "Template format error: Unrecognized resource types") must register AWS::EntityResolution::SchemaMapping, ::MatchingWorkflow, ::IdNamespace, ::IdMappingWorkflow and ::PolicyStatement, and each needs a resource provider/handler that on Create/Update/Delete calls the matching Entity Resolution control-plane operation (CreateSchemaMapping/DeleteSchemaMapping, CreateMatchingWorkflow/DeleteMatchingWorkflow, CreateIdNamespace/DeleteIdNamespace, CreateIdMappingWorkflow/DeleteIdMappingWorkflow, AddPolicyStatement/DeletePolicyStatement), reports the entity name as the physical resource id (so Ref yields the name) while exposing SchemaArn / WorkflowArn / IdNamespaceArn as GetAtt attributes, resolves intrinsics (Fn::GetAtt, Fn::Sub, Ref) in the resource properties before the call, and surfaces an Entity Resolution 400 refusal as a CREATE_FAILED ResourceStatusReason in the registry-handler format with HandlerErrorCode InvalidRequest so the stack rolls back and the partially-created resources are deleted. Note: the open issue 20261102T065110Z-entityresolution-id-namespace-lifecycle-unusable-createidnamespace-answers-403.md covers the Entity Resolution ID-namespace API itself answering 403/404 and does not register any CloudFormation resource type; no open issue covers these types.

Traces: all four cloudformation__entityresolution checks die on the identical CreateStack ValidationError — deploy-entityresolution-schema-mapping-lifecycle (single SchemaMapping lifecycle with Ref/GetAtt and delete), deploy-entityresolution-schema-mapping-reserved-field-name-rejected (positive control plus the RecordId rejection/rollback path), deploy-entityresolution-namespace-workflow-policy-lifecycle (IdNamespace + MatchingWorkflow + PolicyStatement with GetPolicy read-back), deploy-entityresolution-id-mapping-workflow-lifecycle (two IdNamespaces + MatchingWorkflow + IdMappingWorkflow, with a workflow-removing UpdateStack).

  botocore.exceptions.ClientError: An error occurred (ValidationError) when calling the CreateStack operation: Template format error: Unrecognized resource types: [AWS::EntityResolution::SchemaMapping, AWS::EntityResolution::IdNamespace, AWS::EntityResolution::MatchingWorkflow, AWS::EntityResolution::PolicyStatement]

   - Outputs.MappingRef == the schema name; ListSchemaMappings filtered to that name == [Outputs.MappingArn].

## Steps to Reproduce
1. Build and boot the emulator from this checkout.
2. cloudformation.CreateStack with TemplateBody:
   {"AWSTemplateFormatVersion":"2010-09-09","Resources":{"Mapping":{"Type":"AWS::EntityResolution::SchemaMapping","Properties":{"SchemaName":"<unique-name>","Description":"schema mapping <unique-name>","MappedInputFields":[{"FieldName":"CustomerId","Type":"UNIQUE_ID"},{"FieldName":"FullName","Type":"NAME"}],"Tags":[{"Key":"sim2real-er","Value":"<unique-name>"}]}}},"Outputs":{"MappingRef":{"Value":{"Ref":"Mapping"}},"MappingArn":{"Value":{"Fn::GetAtt":["Mapping","SchemaArn"]}}}}
   -> observe ValidationError "Template format error: Unrecognized resource types: [AWS::EntityResolution::SchemaMapping]" instead of a StackId.
3. Repeat with MappedInputFields[0].FieldName = "RecordId" -> same CreateStack refusal, so the expected ROLLBACK_COMPLETE / HandlerErrorCode InvalidRequest path is unreachable.
4. CreateStack a template adding AWS::EntityResolution::IdNamespace, AWS::EntityResolution::MatchingWorkflow and AWS::EntityResolution::PolicyStatement (Capabilities=["CAPABILITY_NAMED_IAM"], an AWS::IAM::Role supplying RoleArn) -> ValidationError listing all those types.
5. CreateStack a template adding AWS::EntityResolution::IdMappingWorkflow with SOURCE/TARGET AWS::EntityResolution::IdNamespace inputs -> ValidationError listing all those types.
6.
