# cloudformation__dataexchange: AWS::DataExchange::DataSet is not a registered resource type — CreateStack refuses every DataExchange data-set template with "Unrecognized resource types"

> _Note: this issue was identified against the code base at commit `00353ccf65811f65ad7f73dbcefa75ea121211d3`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateStack

## Description
Cause 1 of 1: the emulator's CloudFormation template-type registry does not know the resource type AWS::DataExchange::DataSet, so CreateStack refuses the template outright and no DataExchange data set can ever be provisioned, rolled back, or property-validated from a stack.
Failing checks: cloudformation__dataexchange.deploy-dataexchange-data-set-lifecycle, cloudformation__dataexchange.deploy-dataexchange-data-set-invalid-asset-type-rejected

AWS: recorded behavior only for the type registry (CloudFormation's supported resource types are not in the Smithy model; the cloudformation Smithy model only declares CreateStack with TemplateBody and the client error ValidationError/HTTP 400). The recordings show real AWS ACCEPTING a template whose only resource is {"Type": "AWS::DataExchange::DataSet", "Properties": {"AssetType", "Description", "Name"}}: CreateStack returns a StackId, the stack reaches CREATE_COMPLETE, Ref of the resource is the data set's ARN (equal to Fn::GetAtt Arn), Fn::GetAtt Id/Origin resolve to the DataExchange id and "OWNED", and the data set is real at DataExchange (ListDataSets Origin=OWNED and GetDataSet agree with the stack's outputs on Id/Arn/Name/Description/AssetType). DeleteStack removes the data set, after which GetDataSet refuses with ResourceNotFoundException / "The requested resource was not found.". For the same template with an AssetType outside the enum, AWS still accepts the template and instead fails the stack in early property validation: the stack ends ROLLBACK_COMPLETE with a validation row (LogicalResourceId "DS", ValidationName "PROPERTY_VALIDATION", Status "FAILED", FailureMode "FAIL", Reason "<value> is not a valid enum value. Supported values: <supported list>", Path "/Resources/DS/Properties/AssetType") and one CREATE_FAILED event on AWS::CloudFormation::Stack whose reason is the fixed text "Validation failed with 1 error(s). Call DescribeEvents to retrieve the full list of issues with resource and property details, resolve each error, then retry the operation."; no data set of that name exists afterwards.
Emulator: CreateStack is refused before anything is created. HTTP 400, error code "ValidationError", message "Template format error: Unrecognized resource types: [AWS::DataExchange::DataSet]" — the fixed text here is "Template format error: Unrecognized resource types: [" ... "]" and the variable part is the list of type names taken from the request's template; AWS emits that message only for types it genuinely does not support, which AWS::DataExchange::DataSet is not. Because the call never succeeds, no stack id, no CREATE_COMPLETE, no Ref/GetAtt values, no property-validation rows and no rollback path exist for this type.
Why: any client (CDK/SAM app, template, or test) that deploys a DataExchange data set through CloudFormation gets a hard ValidationError from the emulator where AWS creates the resource, so no infrastructure-as-code path to DataExchange works at all. The negative path diverges the same way: a client expecting an accepted template that rolls back with a PROPERTY_VALIDATION row for an out-of-enum AssetType instead sees the whole CreateStack call rejected, so its rollback and DescribeStackEvents handling is never exercised and it cannot distinguish "bad property value" from "unsupported resource type".
Fix: CloudFormation's template resource-type registry plus the provisioning/handler mapping for this type — register AWS::DataExchange::DataSet, give it a create/delete handler that calls DataExchange's own CreateDataSet/DeleteDataSet state so the data set is real at the owning service, resolve Ref to the data set ARN and GetAtt Id/Arn/Origin, and route an out-of-enum AssetType through the stack's property-validation path (ROLLBACK_COMPLETE + PROPERTY_VALIDATION row) rather than through template-format rejection.
Traces: cloudformation__dataexchange.deploy-dataexchange-data-set-lifecycle (happy path: Ref/GetAtt and the DataExchange read-back), cloudformation__dataexchange.deploy-dataexchange-data-set-invalid-asset-type-rejected (negative path: property validation + rollback). Note: this is the same family as the already-open per-service registry issues (e.g. 20261109T113428Z-cloudformation-mwaa-createstack-refuses-aws-mwaa-environment-as.md), but none of them covers the AWS::DataExchange::DataSet type.

## Evidence
Both checks fail on the first CreateStack call.
Expected (deploy-dataexchange-data-set-lifecycle): CreateStack accepted, stack CREATE_COMPLETE, Outputs DSRef == DSArn (the data set ARN), DSOrigin == "OWNED", DataExchange ListDataSets(Origin=OWNED)/GetDataSet returning the same Id/Arn/Name/Description/AssetType=S3_SNAPSHOT, and after DeleteStack GetDataSet -> ResourceNotFoundException "The requested resource was not found.".
Actual: botocore.exceptions.ClientError: An error occurred (ValidationError) when calling the CreateStack operation: Template format error: Unrecognized resource types: [AWS::DataExchange::DataSet]

Expected (deploy-dataexchange-data-set-invalid-asset-type-rejected): the control stack (AssetType=S3_SNAPSHOT) reaches CREATE_COMPLETE and reads back through DataExchange; the stack with the out-of-enum AssetType is accepted and ends ROLLBACK_COMPLETE with exactly one validation row ("DS", "PROPERTY_VALIDATION", "FAILED", "FAIL", "<bad value> is not a valid enum value. Supported values: <supported>", "/Resources/DS/Properties/AssetType") and one CREATE_FAILED event on AWS::CloudFormation::Stack with reason "Validation failed with 1 error(s). Call DescribeEvents to retrieve the full list of issues with resource and property details, resolve each error, then retry the operation.", and no OWNED data set with that name exists.
Actual: the same ValidationError / "Template format error: Unrecognized resource types: [AWS::DataExchange::DataSet]" on the control CreateStack, so neither the positive nor the negative assertion is ever reached.

## Steps to Reproduce
1. Build and boot the emulator; point botocore cloudformation and dataexchange clients at it.
2. Call CreateStack with TemplateBody = {"Resources": {"DS": {"Type": "AWS::DataExchange::DataSet", "Properties": {"AssetType": "S3_SNAPSHOT", "Description": "<any>", "Name": "<unique>"}}}, "Outputs": {"DSRef": {"Value": {"Ref": "DS"}}, "DSId": {"Value": {"Fn::GetAtt": ["DS", "Id"]}}, "DSArn": {"Value": {"Fn::GetAtt": ["DS", "Arn"]}}, "DSOrigin": {"Value": {"Fn::GetAtt": ["DS", "Origin"]}}}}.
3. Observe HTTP 400 ValidationError "Template format error: Unrecognized resource types: [AWS::DataExchange::DataSet]" instead of a StackId followed by CREATE_COMPLETE.
4. Repeat step 2 with "AssetType": "NOT_A_REAL_ASSET_TYPE" and observe the same template-format rejection instead of an accepted stack that ends ROLLBACK_COMPLETE with a PROPERTY_VALIDATION row on /Resources/DS/Properties/AssetType.
5. Re-replay cloudformation__dataexchange.deploy-dataexchange-data-set-lifecycle and cloudformation__dataexchange.deploy-dataexchange-data-set-invalid-asset-type-rejected to confirm a fix.
