# lambda__rds__secretsmanager: 2 net-new root causes — the in-process Lambda Python runtime provides no AWS SDK (boto3) and no CPython stdlib extension modules (_socket), so every function-driven RDS/Secrets Manager flow fails Runtime.ImportModuleError

> _Note: this issue was identified against the code base at commit `8bf126a687f579c23502fa67f92e47f7c7638042`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
Invoke

## Description
Two net-new causes, both in the runtime environment the Invoke path gives a deployment package.

Cause 1 of 2: a python3.x handler that does `import boto3` cannot be imported, so the function never runs.
AWS: recorded behavior only for the runtime contents (Smithy: Invoke POST /2015-03-31/functions/{FunctionName}/invocations; output StatusCode via httpResponseCode, FunctionError via header X-Amz-Function-Error, Payload via httpPayload). AWS's managed Python runtimes ship boto3 and botocore on the handler's module search path, so a handler that imports boto3 and calls rds / secretsmanager through it initialises; Invoke answers 200 with NO X-Amz-Function-Error header and the handler's JSON document as Payload. Runtime.ImportModuleError is reserved for a module the package genuinely does not provide.
Emulator: HTTP 200 with header `x-amz-function-error: Unhandled` and payload `{"errorMessage":"Unable to import module '<handler module>': No module named 'boto3'","errorType":"Runtime.ImportModuleError","requestId":"<per-invocation id>","stackTrace":[]}`. Fixed text: `Unable to import module '` … `': No module named '` … `'`, errorType `Runtime.ImportModuleError`; variable parts are the handler module from the function's Handler (observed `index`, `lambda_function`, `handler`) and the missing module (`boto3`). requestId is per-invocation and is not a requirement.
Why: no SDK-using function can run. Positive paths (DescribeDBInstances, GenerateDbAuthToken, GetSecretValue/PutSecretValue/DescribeSecret from function code) produce nothing, and the negative paths cannot distinguish the AccessDeniedException/ResourceNotFoundException the function should surface from the emulator's import failure — one check states exactly that: `expected a botocore ClientError, got errorType='Runtime.ImportModuleError'`.
Fix: the Invoke execution path's runtime environment in services/service-com-amazonaws-lambda-awsgirapiservice — the in-process python3.x runtime must expose the managed runtime's bundled dependency set (boto3 + botocore wired to this emulator's endpoint with the execution role's credentials) on the handler's module search path.
Traces: cli-create-lambda-role-trust-policy-lambda-service, cli-lambda-invoke-denied-without-rds-policy-negative, cli-lambda-invoke-with-rds-secret-missing-permission-denied, cli-lambda-update-env-with-secret-arn, deploy-cfn-lambda-rds-missing-permission-negative, lambda-execution-role-assumed-for-rds-proxy-auth-positive, lambda-rds-describe-db-instances-positive, lambda-rds-describedbinstances-positive, lambda-rds-missing-describedbinstances-permission-negative, lambda-rds-missing-permission-denied, lambda-rds-wrong-db-instance-arn-denied, lambda-secretsmanager-cross-account-secret-denied, lambda-secretsmanager-describe-secret-positive, lambda-secretsmanager-describesecret-positive, lambda-secretsmanager-get-secret-value-positive, lambda-secretsmanager-getsecretvalue-positive, lambda-secretsmanager-iam-missing-permission-rejected, lambda-secretsmanager-kms-decrypt-missing-permission-denied, lambda-secretsmanager-missing-permission-rejected, lambda-secretsmanager-put-secret-value-positive, lambda-secretsmanager-putsecretvalue-positive, lambda-secretsmanager-resource-policy-denies-principal-rejected, lambda-secretsmanager-rotate-secret-trigger-positive, lambda-secretsmanager-version-stage-awscurrent-positive, lambda-secretsmanager-wrong-arn-resourcenotfound-rejected, lambda-secretsmanager-wrong-secret-arn-denied; plus cli-lambda-rds-secret-end-to-end-setup, cli-lambda-rds-secretsmanager-end-to-end-invoke and lambda-rds-generate-db-auth-token-positive, which exhaust the run budget (`Check timed out after 60.0s`) inside an invoke-retry loop that retries while Invoke keeps reporting FunctionError — the same failure, surfaced as a timeout rather than an assertion.

Cause 2 of 2: the runtime's Python interpreter is missing CPython stdlib extension modules, so a handler that only needs the standard library also fails to import.
AWS: recorded behavior only. A managed python3.x runtime is a complete CPython: `socket` (and its `_socket` extension) are importable, so a packaged pure-Python DB driver that opens a TCP connection loads and the handler runs; Invoke answers 200 with no X-Amz-Function-Error.
Emulator: HTTP 200 with `x-amz-function-error: Unhandled` and `{"errorMessage":"Unable to import module '<handler module>': No module named '_socket'","errorType":"Runtime.ImportModuleError","requestId":"<per-invocation id>","stackTrace":[]}` — same message template as cause 1, with `_socket` as the missing module. This is a distinct cause from cause 1: shipping boto3 would not make the interpreter's stdlib extension modules importable.
Why: any function that does network I/O from its own code (here a TLS-vs-plaintext probe against an RDS proxy) cannot run at all, so no connection-level behaviour of the probed service is observable, and the probe's verdict reports the emulator's runtime rather than the service under test.
Fix: the same Invoke runtime environment — the interpreter used to execute the package must be a complete CPython with its stdlib extension modules (`_socket`, and by the same rule the rest of the stdlib C extensions) available.
Traces: deep-rds-3-proxy-require-tls-plaintext-rejected.
