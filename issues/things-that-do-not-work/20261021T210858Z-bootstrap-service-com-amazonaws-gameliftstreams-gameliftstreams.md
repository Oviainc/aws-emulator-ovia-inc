# Bootstrap the GameLiftStreams emulator

> _Note: this issue was identified against the code base at commit `7b44f3f32d1f58d662874eb8ca0f546e296cee00`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Description

Every one of the 30 operations in `services/service-com-amazonaws-gameliftstreams-gameliftstreams/src/ops/` is an unmodified scaffold that answers HTTP 501 `NotImplemented` and holds no state, so no client workflow can run at all. Implement a FIRST, SMALL stateful slice: the core Amazon GameLift Streams loop of "register a game build as an application -> create a stream group that hosts it -> start a stream session -> poll the session -> terminate it -> tear the group down".

Wire protocol is `restJson1`, sigv4 signing name `gameliftstreams` (README.md / OPERATIONS.md "Wire protocol").

## Happy path to implement (in order)

1. **CreateApplication** — `POST /applications` -> **201**. Required input: `Description`, `RuntimeEnvironment`, `ExecutablePath`, `ApplicationSourceUri`; optional `ApplicationLogPaths`, `ApplicationLogOutputUri`, `Tags`, `ClientToken` (@idempotencyToken). Must mint and PERSIST a new application: generate `Id` (matching `^[a-zA-Z0-9-]+$`, len 1..32, e.g. `a-1AB2c3De4`) and `Arn` (`arn:aws:gameliftstreams:<region>:<account>:application/<Id>`), set `CreatedAt`/`LastUpdatedAt` to now, `Status` = `READY` (model enum `ApplicationStatus`), and echo back the stored `Description`, `RuntimeEnvironment`, `ExecutablePath`, `ApplicationSourceUri`, `ApplicationLogPaths`, `ApplicationLogOutputUri` from the stored record (not from the request object). `AssociatedStreamGroups` starts empty.
2. **CreateStreamGroup** — `POST /streamgroups` -> **201**. Required input: `Description`, `StreamClass` (enum `StreamClass`, e.g. `gen5n_high`); optional `DefaultApplicationIdentifier`, `LocationConfigurations`, `Tags`, `ClientToken`. Must persist a stream group with generated `Id`/`Arn` (`:streamgroup/<Id>`), `Status` = `ACTIVE` (enum `StreamGroupStatus`), `CreatedAt`/`LastUpdatedAt`, `StreamClass` as given, `DefaultApplication` = `DefaultApplication{Id, Arn}` resolved from the stored application, `LocationStates` derived from the requested `LocationConfigurations` (each `LocationState{Location, Status: ACTIVE, AlwaysOnCapacity, OnDemandCapacity, ...}`), and `AssociatedApplications` containing the default application's ARN. A `DefaultApplicationIdentifier` that names no stored application must fail `ResourceNotFoundException` (404), not succeed.
3. **StartStreamSession** — `POST /streamgroups/{Identifier}/streamsessions` -> **201**. Required input: `Identifier` (@httpLabel, id OR ARN), `Protocol` (`WebRTC`), `SignalRequest`, `ApplicationIdentifier`; optional `Description`, `UserId`, `Locations`, `ConnectionTimeoutSeconds`, `SessionLengthSeconds`, `AdditionalLaunchArgs`, `AdditionalEnvironmentVariables`, `ClientToken`. Must persist a session keyed under its stream group: generated session id + `Arn` (`:streamsession/<stream-group-id>/<session-id>`), `StreamGroupId`, `ApplicationArn` resolved from the stored application, `Status` = `ACTIVATING`, `Protocol`, `Location` (first requested location, else the group's first location), the stored `SignalRequest`, `UserId`, `Description`, timeouts and launch args, and `CreatedAt`/`LastUpdatedAt`. Unknown stream group or application -> `ResourceNotFoundException` (404).
4. **GetStreamSession** — `GET /streamgroups/{Identifier}/streamsessions/{StreamSessionIdentifier}` -> **200**, `@readonly`. Must look the session up in state and return the SAME `Arn`, `StreamGroupId`, `ApplicationArn`, `UserId`, `Description`, `SignalRequest`, `ConnectionTimeoutSeconds`, `SessionLengthSeconds`, `AdditionalLaunchArgs`, `AdditionalEnvironmentVariables`, `CreatedAt` that StartStreamSession stored. The session should become `ACTIVE` with a non-empty `SignalResponse` and `WebSdkProtocolUrl` once placement completes (acceptable to advance `ACTIVATING -> ACTIVE` on first read or after a short dwell, driven by the stored `CreatedAt` — the status must come from state, never a constant). Unknown id -> `ResourceNotFoundException` (404).
5. **TerminateStreamSession** — `DELETE /streamgroups/{Identifier}/streamsessions/{StreamSessionIdentifier}` -> **204**, `@idempotent`. Must flip the stored session to `TERMINATED`/`TERMINATING` with `StatusReason` = `apiTerminated` and bump `LastUpdatedAt`, so a subsequent GetStreamSession observes the terminated status. Unknown id -> `ResourceNotFoundException` (404).
6. **DeleteStreamGroup** — `DELETE /streamgroups/{Identifier}` -> **204**, `@idempotent`. Must remove the group (and its sessions) from state so GetStreamGroup/StartStreamSession on it afterwards return `ResourceNotFoundException` (404).

`GetApplication` (`GET /applications/{Identifier}`), `ListApplications`/`ListStreamGroups` (both `@paginated(inputToken=NextToken, outputToken=NextToken, items=Items)`) and `DeleteApplication` read/write the same two maps and are cheap to land in the same slice; everything else (CreateStreamUrl/GetStreamUrl/RevokeStreamUrl/ListStreamUrls, Associate/DisassociateApplications, Add/RemoveStreamGroupLocations, UpdateApplication, UpdateStreamGroup, ExportStreamSessionFiles, CreateStreamSessionConnection, CreateStreamSessionAdminShell, ListStreamSessions*, ListApplicationShaderCaches, Tag/Untag/ListTagsForResource) stays 501 and will be filed as individual gap issues later.

No canned, hardcoded, or request-echoed responses: every field above must be read back out of the persisted record, and an id minted without being stored counts as a failure. Identifier inputs accept EITHER a bare id or a full ARN (`pattern ^(^[a-zA-Z0-9-]+$)|(^arn:aws:gameliftstreams:...)$`), so resolution must accept both forms for the same resource.

## Steps to Reproduce

1. Start the emulator and point an AWS SDK/CLI gameliftstreams client at it.
2. `CreateApplication` with Description='my-game', RuntimeEnvironment={Type:PROTON,Version:'20250101'}, ExecutablePath='game.exe', ApplicationSourceUri='s3://bucket/build/' — expect 201 with a generated Id and Arn and Status=READY (today: 501 NotImplemented).
3. `GetApplication` with that Id — expect 200 echoing the stored ExecutablePath/ApplicationSourceUri/CreatedAt.
4. `CreateStreamGroup` with Description='my-group', StreamClass='gen5n_high', DefaultApplicationIdentifier=<application Id>, LocationConfigurations=[{LocationName:'us-west-2',AlwaysOnCapacity:1}] — expect 201 with Id, Arn, Status=ACTIVE, DefaultApplication pointing at the created application, and LocationStates reflecting the requested location.
5. `StartStreamSession` on that stream group with Protocol='WebRTC', SignalRequest='<sdp offer>', ApplicationIdentifier=<application Id>, UserId='player-1', ConnectionTimeoutSeconds=120 — expect 201 with a session Arn, StreamGroupId, ApplicationArn and Status=ACTIVATING.
6. `GetStreamSession` with the stream group id + session id — expect 200 with the SAME Arn/UserId/SignalRequest/ConnectionTimeoutSeconds that were stored, and Status reaching ACTIVE with a non-empty SignalResponse.
7. `TerminateStreamSession` on it — expect 204; re-`GetStreamSession` and expect Status=TERMINATED/TERMINATING with StatusReason=apiTerminated.
8. `DeleteStreamGroup`, then `DeleteApplication` — expect 204 each; a following `GetStreamGroup`/`GetApplication` must return ResourceNotFoundException (404), and `ListApplications`/`ListStreamGroups` must no longer list them.
