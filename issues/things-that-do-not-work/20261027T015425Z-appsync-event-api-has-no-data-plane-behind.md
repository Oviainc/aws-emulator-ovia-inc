# AppSync Event API has no data plane behind Api$dns (REALTIME/HTTP) and emits no AWS/AppSync CloudWatch counters, so the namespace-lifecycle check never completes

> _Note: this issue was identified against the code base at commit `bed9f8e2d85c054efb957ff95014081869f003aa`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateApi

## Description
Cause 1 of 1: an AppSync Event API created by this emulator is a control-plane record only. `CreateApi` now succeeds and advertises both endpoints, but nothing serves them and nothing publishes the Event API's metrics, so the whole subscribe/publish/unsubscribe lifecycle and its CloudWatch counters are unreachable. The check stalls and is cut off by the suite's 60s budget (its own bounded waits are 90s for the realtime handshake and 600s for the metric polls), it never reaches an assertion.

AWS: Smithy `CreateApi` (POST /v2/apis) returns an `Api` whose `dns` member is documented as "The DNS records for the API. This will include an HTTP and a real-time endpoint", and `ChannelNamespace` carries `codeHandlers` / `handlerConfigs` — "The event handler functions that run custom business logic to process published events and subscribe requests" (Code, length 1..32768). Those two endpoints are live data planes: the REALTIME host accepts an RFC6455 upgrade at `/event/realtime` with subprotocol `aws-appsync-event-ws, header-<b64url(auth)>` and answers `connection_init` with `connection_ack`, then `subscribe` -> `subscribe_success` and `unsubscribe` -> `unsubscribe_success`; the HTTP host accepts `POST /event` with `{"channel":..., "events":[...]}` and answers HTTP 200 with `{"successful":[...],"failed":[]}`. Recorded behavior only for the metric contract (the check was measured against us-west-2 on 2026-10-01, there is no Smithy model for CloudWatch metric emission): namespace `AWS/AppSync` carries the namespace-scoped counters SubscribeSuccess, UnsubscribeSuccess, PublishHandlerInvocations, SuccessfulEvents, DroppedEvents and FailedEvents under EXACTLY the dimension set [EventAPIId, ChannelNamespaceName], and the connection-scoped counters ConnectSuccess, DisconnectSuccess, ActiveConnections and ActiveSubscriptions under EXACTLY [EventAPIId] (a connection belongs to no namespace); an event the namespace's onPublish handler filters out is counted as DroppedEvents, not FailedEvents, while SuccessfulEvents and PublishHandlerInvocations still count every published event.

Emulator: the appsync service crate serves the restJson1 control plane only (services/.../src/service.rs mounts just the generated model routing table; `override_operation` returns None and there is no WebSocket or `/event` route anywhere behind it). `CreateApi` mints the two hostnames in `state::api_dns` (`<label>.appsync-api.<region>.amazonaws.com` for `HTTP`, `<label>.appsync-realtime-api.<region>.amazonaws.com` for `REALTIME`) and stores the channel namespace with its `codeHandlers`, but no component ever accepts a realtime upgrade on that host, no component accepts a publish, no onPublish handler is ever evaluated, and nothing writes a datapoint into the CloudWatch `AWS/AppSync` namespace — ListMetrics for [EventAPIId] / [EventAPIId, ChannelNamespaceName] stays empty. The check therefore spins in a bounded retry loop (realtime connect, then the ActiveSubscriptions metric poll) and is reported as `Check timed out after 60.0s`. Hypothesis: the first stall is the realtime handshake, because `_connect_event_ws` retries for 90s before it would assert; the metric polls (600s) stall identically once reached. Neither the recording nor the model attributes the cut-off to one stage, but both stages are absent.

Why: a client that creates an Event API gets `dns`/`uris` pointing at endpoints that accept nothing, so no publisher or subscriber works at all — a WebSocket client gets a failed upgrade instead of `connection_ack`, a publisher gets no 200 with `successful`, and an onPublish handler that is supposed to filter events never runs. Anything that watches the API (a CloudWatch alarm, a dashboard, an autoscaling or on-call rule keyed on SubscribeSuccess/DroppedEvents/ActiveConnections) sees no data and reads as healthy-but-idle, and an emulator that later stamps the namespace dimension on every metric, or on none, is still wrong: which dimension set each metric lands under is itself the contract.

Fix: the Event-API data plane for the hostnames `CreateApi` publishes — a realtime WebSocket endpoint (connection_init/ack, subscribe/unsubscribe, data frames) and an HTTP `POST /event` publish endpoint — plus evaluation of the stored ChannelNamespace `codeHandlers.onPublish`, and the AWS/AppSync metric emission on that path writing into the cloudwatch service's metric store under the two dimension sets above.

Related open issue: 20261024T165547Z-appsync-createapi-returns-notimplemented-so-event-api-cloudwatch.md carries this same check id, but its premise no longer holds — `CreateApi` is implemented (services/service-com-amazonaws-appsync-awsdeepdishcontrolplaneservice/src/ops/create_api.rs) and no longer answers NotImplemented, and the failure has moved from a refusal on the first call to a stall on the absent data plane and metric emission. Fix them together; this issue records the current failure mode.

## Steps to Reproduce
1. Boot the emulator.
2. appsync CreateApi with a valid name and an eventConfig whose authProviders/connectionAuthModes/defaultPublishAuthModes/defaultSubscribeAuthModes are all API_KEY. Note `api.dns` HTTP and REALTIME hosts.
3. appsync CreateApiKey for that apiId, and CreateChannelNamespace with codeHandlers exporting `onPublish(ctx)` that returns `ctx.events.filter(e => e.payload.keep === true)`.
4. Open a WebSocket to wss://<REALTIME host>/event/realtime with subprotocol `aws-appsync-event-ws, header-<b64url({host:<HTTP host>, 'x-api-key':<key>})>`. Observe no HTTP 101 / no `connection_ack` where AWS acks the connection.
5. POST https://<HTTP host>/event with {"channel":"<ns>/room1","events":["{\"m\":\"a\",\"keep\":true}"]} and the x-api-key header. Observe no HTTP 200 with `{"successful":[...],"failed":[]}`.
6. cloudwatch ListMetrics Namespace=AWS/AppSync Dimensions=[{Name:EventAPIId,Value:<apiId>}] and GetMetricStatistics for SubscribeSuccess/UnsubscribeSuccess/PublishHandlerInvocations/SuccessfulEvents/DroppedEvents/FailedEvents (dims [EventAPIId, ChannelNamespaceName]) and ConnectSuccess/DisconnectSuccess/ActiveConnections/ActiveSubscriptions (dims [EventAPIId]). Observe an empty catalogue and no datapoints.
7. Replay appsync__cloudwatch.obs-appsync-2-event-api-namespace-lifecycle-counters.
