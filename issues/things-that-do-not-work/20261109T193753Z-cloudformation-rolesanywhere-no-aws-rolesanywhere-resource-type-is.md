# cloudformation__rolesanywhere: no AWS::RolesAnywhere::* resource type is registered — CreateStack refuses every trust-anchor/CRL/profile template as "Unrecognized resource types"

> _Note: this issue was identified against the code base at commit `7e082a9dfef7650059a714e1b731386462df20dc`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateStack

## Description
Cause 1 of 1: CloudFormation's template resource-type registry contains no AWS::RolesAnywhere::* types, so template validation inside CreateStack refuses any template that declares AWS::RolesAnywhere::TrustAnchor, AWS::RolesAnywhere::CRL or AWS::RolesAnywhere::Profile. Failing checks: cloudformation__rolesanywhere.deploy-rolesanywhere-trust-anchor-crl-and-profile-round-trip-then-delete, cloudformation__rolesanywhere.deploy-rolesanywhere-trust-anchor-non-ca-certificate-rejected.

AWS: recorded behavior only for the CloudFormation side (resource-type coverage is not in the Smithy model). Real CloudFormation accepts these three types and returns 200 with a StackId from CreateStack, then provisions them through RolesAnywhere: AWS::RolesAnywhere::TrustAnchor (Name, Enabled, Source.SourceType=CERTIFICATE_BUNDLE, Source.SourceData.X509CertificateData, Tags; Ref -> trustAnchorId, GetAtt TrustAnchorArn -> arn:<partition>:rolesanywhere:<region>:<account>:trust-anchor/<trustAnchorId>), AWS::RolesAnywhere::CRL (Name, CrlData, Enabled, TrustAnchorArn, Tags; Ref -> crlId) and AWS::RolesAnywhere::Profile (Name, Enabled, RoleArns, DurationSeconds, Tags; Ref -> profileId, GetAtt ProfileArn -> arn:<partition>:rolesanywhere:<region>:<account>:profile/<profileId>). The underlying control-plane calls are modelled: Smithy CreateTrustAnchor POST /trustanchors (201, name @length 1-255 @pattern ^[ a-zA-Z0-9-_]*$, source required), ImportCrl POST /crls (201, crlData required @length 1-300000, trustAnchorArn required @pattern ^arn:aws(-[^:]+)?:rolesanywhere(:.*){2}(:trust-anchor.*)$), CreateProfile POST /profiles (201, roleArns required, durationSeconds @range 900-43200) — each with ValidationException (400) and AccessDeniedException (403). A trust anchor whose certificate bundle carries a non-CA certificate is refused by the RolesAnywhere handler, not by early template validation: the stack settles ROLLBACK_COMPLETE, no PROPERTY_VALIDATION event is recorded, and the TrustAnchor resource's CREATE_FAILED ResourceStatusReason is "Incorrect basic constraints for CA certificate. (Service: RolesAnywhere, Status Code: 400, Request ID: <id>) (SDK Attempt Count: <n>)" with error code InvalidRequest. In that message the fixed text is "Incorrect basic constraints for CA certificate." plus the SDK suffix shape "(Service: RolesAnywhere, Status Code: 400, Request ID: ...) (SDK Attempt Count: ...)"; Request ID and attempt count are per-run values, and Service/Status Code are fixed for this error class.

Emulator: CreateStack is refused before any resource is processed with HTTP 400 ValidationError and message "Template format error: Unrecognized resource types: [AWS::RolesAnywhere::TrustAnchor, AWS::RolesAnywhere::CRL, AWS::RolesAnywhere::Profile]" for the full template, and "Template format error: Unrecognized resource types: [AWS::RolesAnywhere::TrustAnchor]" for the trust-anchor-only template. In that message the fixed text is "Template format error: Unrecognized resource types: [...]" and the bracketed list is the set of declared types the registry does not know — here it is non-empty only because the three RolesAnywhere types are missing. No stack is ever created, so nothing downstream of CreateStack (Ref/GetAtt outputs, the RolesAnywhere round-trip, child-dropping UpdateStack, the handler-level non-CA refusal and its rollback) can be exercised at all.

Why: a client cannot deploy IAM Roles Anywhere through CloudFormation at all. Any stack, CDK app or SAM template that declares a trust anchor, a CRL or a profile fails at CreateStack with a template-format error, which reads to the client as a malformed template rather than as missing emulator coverage; templates that mix RolesAnywhere with other resources fail wholesale, and the negative path (a non-CA certificate) can never surface the handler's refusal or the ROLLBACK_COMPLETE it is supposed to produce.

Fix: CloudFormation's template resource-type registry plus the three RolesAnywhere resource handlers — register AWS::RolesAnywhere::TrustAnchor, AWS::RolesAnywhere::CRL and AWS::RolesAnywhere::Profile, and back each with a handler that provisions through the RolesAnywhere service state (CreateTrustAnchor / ImportCrl / CreateProfile), publishes Ref as the resource id and the GetAtt Arn attributes, propagates stack-level and resource-level Tags, deletes on stack delete and on removal from an update, and surfaces the service's own 400 refusal (code InvalidRequest, message with the SDK "(Service: RolesAnywhere, Status Code: 400, ...)" suffix) as the resource's CREATE_FAILED reason so the stack rolls back instead of being refused at validation time.

Traces: cloudformation__rolesanywhere.deploy-rolesanywhere-trust-anchor-crl-and-profile-round-trip-then-delete (errors on the first CreateStack with the three-type list), cloudformation__rolesanywhere.deploy-rolesanywhere-trust-anchor-non-ca-certificate-rejected (errors on the positive-control CreateStack with the single-type list). Both are reported under the suite heading `### cloudformation__rolesanywhere`; neither is marked ALREADY FILED or OWNED. No existing open issue covers the RolesAnywhere types — the closest filed items are the same-shaped registry gaps for other services (e.g. 20261109T155230Z-cloudformation-groundstation-no-aws-groundstation-resource-type-is.md, 20261109T145937Z-cloudformation-entityresolution-no-aws-entityresolution-resource-type-is.md), which do not cover these three types.

## Evidence
Check cloudformation__rolesanywhere.deploy-rolesanywhere-trust-anchor-crl-and-profile-round-trip-then-delete:
Expected: CreateStack accepts the template (StackId returned), the stack reaches CREATE_COMPLETE, Outputs expose TrustAnchorRef/CrlRef/ProfileRef matching ListTrustAnchors/ListCrls/ListProfiles ids and TrustAnchorArn/ProfileArn matching GetTrustAnchor/GetProfile, an update dropping the CRL and profile removes both (GetCrl/GetProfile -> ResourceNotFoundException "The item doesn't exist. arn: <arn> ; aborting."), and DeleteStack removes the trust anchor (GetTrustAnchor -> ResourceNotFoundException "TrustAnchor not found").
Actual: botocore.exceptions.ClientError: An error occurred (ValidationError) when calling the CreateStack operation: Template format error: Unrecognized resource types: [AWS::RolesAnywhere::TrustAnchor, AWS::RolesAnywhere::CRL, AWS::RolesAnywhere::Profile]

Check cloudformation__rolesanywhere.deploy-rolesanywhere-trust-anchor-non-ca-certificate-rejected:
Expected: the positive control (a true CA certificate) reaches CREATE_COMPLETE and the trust anchor reads back through ListTrustAnchors/GetTrustAnchor; the same template with a non-CA certificate settles ROLLBACK_COMPLETE with no PROPERTY_VALIDATION event and the TrustAnchor CREATE_FAILED reason "Incorrect basic constraints for CA certificate. (Service: RolesAnywhere, Status Code: 400, Request ID: <id>) (SDK Attempt Count: <n>)" / code InvalidRequest, and no trust anchor of that name is listed.
Actual: botocore.exceptions.ClientError: An error occurred (ValidationError) when calling the CreateStack operation: Template format error: Unrecognized resource types: [AWS::RolesAnywhere::TrustAnchor]

Both failures are raised by CreateStack itself, so neither check ever reached a stack, an event or a RolesAnywhere call.

## Steps to Reproduce
1. Build and boot the emulator from this checkout (both cloudformation and rolesanywhere are stood up).
2. Generate a self-signed CA certificate (BasicConstraints ca=true, KeyUsage keyCertSign+cRLSign) as PEM.
3. Call CreateStack with a template whose Resources declare only:
   TrustAnchor: {"Type": "AWS::RolesAnywhere::TrustAnchor", "Properties": {"Name": "<name>", "Enabled": true, "Source": {"SourceType": "CERTIFICATE_BUNDLE", "SourceData": {"X509CertificateData": "<ca pem>"}}}}
   Observe HTTP 400 ValidationError "Template format error: Unrecognized resource types: [AWS::RolesAnywhere::TrustAnchor]" instead of a StackId.
4. Repeat with a template that also declares AWS::RolesAnywhere::CRL (CrlData + TrustAnchorArn via Fn::GetAtt) and AWS::RolesAnywhere::Profile (RoleArns via Fn::GetAtt on an AWS::IAM::Role, DurationSeconds 3600) and Capabilities=["CAPABILITY_NAMED_IAM"]; the same ValidationError lists all three types.
5. Replay the two checks: cloudformation__rolesanywhere.deploy-rolesanywhere-trust-anchor-crl-and-profile-round-trip-then-delete and cloudformation__rolesanywhere.deploy-rolesanywhere-trust-anchor-non-ca-certificate-rejected.
