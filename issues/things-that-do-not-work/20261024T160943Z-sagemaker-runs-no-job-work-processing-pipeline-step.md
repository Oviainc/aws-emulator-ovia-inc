# SageMaker runs no job work: processing, pipeline-step, hyperparameter-tuning and AutoML executions never execute, so every job ends Failed/never Completed (4 causes)

> _Note: this issue was identified against the code base at commit `7b95de6c4fc8fc0be292d7fb35e4aa81be419d0a`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateProcessingJob

## Description
Four independent execution gaps in SageMaker's asynchronous job surfaces. Each is its own root cause and its own work item; this issue bundles FOUR causes and all four must be closed before submitting. These are distinct from the already-filed CreateTrainingJob stub issue (20261022T120642Z-sagemaker-createtrainingjob-stub.md) and from the transform-output cause already carried by 20261022T210606Z-sagemaker-associatetrialcomponent-deletenotebookinstance-createpipeline-from-s3-answer-notimplemented.md: the four job kinds below are accepted by implemented Create* handlers and then never advance to a successful terminal state.

Cause 1 of 4: a processing job is accepted but never runs, so DescribeProcessingJob never reports Completed and nothing is written under ProcessingOutputConfig.
AWS: Smithy: CreateProcessingJob requires ProcessingJobName/ProcessingResources/AppSpecification/RoleArn and returns ProcessingJobArn (errors ResourceInUse/ResourceLimitExceeded/ResourceNotFound, 400); DescribeProcessingJob returns the required ProcessingJobStatus enum plus ProcessingStartTime/ProcessingEndTime. Recorded AWS drives an accepted job InProgress -> Completed, reads the ProcessingInputs from S3 and materializes the declared S3 output objects under ProcessingOutputConfig.Outputs[].S3Output.S3Uri.
Emulator: the job stays in a non-Completed state and reports FailureReason "This emulator has no container runtime, so the processing job's container image was never started"; no output object appears under the declared S3 prefix.
Why: every client that polls DescribeProcessingJob to Completed and then reads its outputs hangs or takes the failure branch; a negative scenario that must distinguish a permission/KMS failure from success (the CFN+KMS check) cannot establish its positive control at all, so a real refusal and a never-ran job are indistinguishable.
Fix: the processing-job execution path in SageMaker state - at minimum drive the accepted job's status machine to Completed and materialize the declared output objects from the declared inputs (CreateProcessingJob's handler plus the job state it writes, read back by DescribeProcessingJob).
Traces: s3__sagemaker.sagemaker-processing-job-reads-s3-input, s3__sagemaker.sagemaker-processing-job-s3-input-positive, s3__sagemaker.sagemaker-processing-job-s3-output-positive, s3__sagemaker.sagemaker-processing-job-writes-output-to-s3-positive, s3__sagemaker.sagemaker-processing-job-writes-s3-output-positive, s3__sagemaker.cfn-deploy-sagemaker-endpoint-config-s3-kms-negative. Handler/state: services/service-com-amazonaws-sagemaker-sagemaker/src/ops/create_processing_job.rs, .../describe_processing_job.rs, .../src/state.rs.

Cause 2 of 4: a pipeline execution runs no step at all - it is accepted and then ends Failed, every step Failed, with no step Metadata.
AWS: Smithy: StartPipelineExecution returns PipelineExecutionArn (errors ConflictException/ResourceLimitExceeded/ResourceNotFound, 400) and PipelineExecutionStatus has values Executing|Stopping|Stopped|Failed|Succeeded|CompletedWithFailures; ListPipelineExecutionSteps returns PipelineExecutionStep entries carrying StepStatus AND Metadata (PipelineExecutionStepMetadata, whose ConditionStepMetadata member carries the required Outcome enum for a Condition step). Recorded AWS executes the declared steps - a Lambda step invokes the function (its side effects, e.g. an S3 object, are observable) and OutputParameters are mapped back - and the execution reaches Succeeded; a step whose RoleArn does not exist fails with a FailureReason naming that role as nonexistent.
Emulator: the execution ends PipelineExecutionStatus 'Failed' with reason "The pipeline execution was accepted but no step of it ran: this emulator has no runtime that performs a pipeline step's work (training, processing, transform, Lambda or callback), so the execution ended Failed rather than reporting work that did not happen", the same text appears as every step's FailureReason, and a Condition step's entry omits the Metadata member entirely (consumer raises KeyError: 'Metadata').
Why: pipelines are unusable end to end - no step side effect happens, no branch is selected, OutputParameters are never produced, and a deliberately broken step (missing role, denied lambda:InvokeFunction) is indistinguishable from a healthy one because both end Failed with the same emulator-specific reason. A client cannot tell "my pipeline is wrong" from "the service did nothing".
Why (secondary): because Metadata is absent, any consumer reading ConditionStepMetadata.Outcome or the step's LambdaFunction/TrainingJob metadata crashes rather than reading a documented member.
Fix: the pipeline execution engine in SageMaker state (StartPipelineExecution's handler plus the step executor that resolves step Arguments, performs the step's work for at least the Lambda/Callback/Condition/Fail step types, records per-step Metadata, resolves the step RoleArn and drives the execution status to Succeeded/Failed), and ListPipelineExecutionSteps' serializer for the Metadata member.
Traces: lambda__s3__sagemaker.sagemaker-pipeline-execution-runs-its-lambda-step-and-writes-the-declared-output, lambda__s3__sagemaker.sagemaker-pipeline-step-denied-lambda-invoke-fails-and-writes-no-marker, sagemaker.create-pipeline-missing-role-not-found, sagemaker.pipeline-condition-step-outcome-selects-exactly-one-declared-branch. Handlers: services/service-com-amazonaws-sagemaker-sagemaker/src/ops/start_pipeline_execution.rs, .../list_pipeline_execution_steps.rs, .../describe_pipeline_execution.rs. (The condition-step check's own header states its Condition/Fail step shapes are hypotheses not yet confirmed against a real replay; the missing Metadata member itself is modeled, so treat the Outcome value as Hypothesis: the branch actually taken is the one whose Conditions evaluate true.)

Cause 3 of 4: a hyperparameter tuning job launches no training jobs, so it ends Failed and writes no best-model artifact.
AWS: Smithy: CreateHyperParameterTuningJob requires HyperParameterTuningJobConfig (+ TrainingJobDefinition/TrainingJobDefinitions) and models ResourceInUse/ResourceLimitExceeded (400); recorded AWS launches the training jobs the definition describes, evaluates the objective metric, reaches HyperParameterTuningJobStatus Completed and exposes a BestTrainingJob whose model artifact exists under the declared S3 output path.
Emulator: HyperParameterTuningJobStatus 'Failed' with reason "This emulator does not run training jobs: no training job was launched for this hyperparameter tuning job, so no objective metric was evaluated and no model artifacts were written to the output S3 location."
Why: the whole tuning surface (best job selection, objective metrics, artifact location) is unobservable, and a caller polling for Completed only ever sees Failed.
Fix: the tuning-job execution path in SageMaker state - launch the child training jobs from the tuning definition, record per-job objective metrics and the BestTrainingJob, and drive the tuning job's status (CreateHyperParameterTuningJob's handler plus the training-job state it depends on).
Traces: s3__sagemaker.sagemaker-hyperparameter-tuning-job-s3-artifacts-positive. Handler: services/service-com-amazonaws-sagemaker-sagemaker/src/ops/create_hyper_parameter_tuning_job.rs.

Cause 4 of 4: an AutoML (Autopilot) job generates no candidates, so it ends Failed and writes no candidate/data-exploration artifacts.
AWS: Smithy: CreateAutoMLJobV2 requires AutoMLJobInputDataConfig, OutputDataConfig and AutoMLProblemTypeConfig and models ResourceInUse/ResourceLimitExceeded (400); recorded AWS runs the candidate-generation pipeline, reaches AutoMLJobStatus Completed, exposes BestCandidate and writes the candidate-definition and data-exploration notebooks under OutputDataConfig.S3OutputPath.
Emulator: AutoMLJobStatus 'Failed' with reason "This emulator does not run Autopilot model training: no candidate was trained or evaluated for this AutoML job, so no model artifact, candidate notebook or data-exploration notebook was written to the output S3 location."
Why: every Autopilot flow (inspect candidates, deploy the best one) is blocked, and the job's terminal status is the opposite of AWS's for a well-formed request.
Fix: the AutoML job execution path in SageMaker state (CreateAutoMLJobV2's handler plus the candidate/artifact materialization read back by DescribeAutoMLJobV2).
Traces: s3__sagemaker.sagemaker-autopilot-job-writes-candidates-to-s3. Handler: services/service-com-amazonaws-sagemaker-sagemaker/src/ops/create_auto_ml_job_v2.rs.
